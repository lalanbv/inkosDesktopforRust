## 1. 取证（修前两腿分叉）

1678 号只统一了「认哪些章文件」（三种命名形态），刻意留下「拒绝还是放行」未动：

- **Node 腿**：`readBookExportSource` → `buildChapterFileLookup` 对全量索引做源一致性校验，四类细节任一非空即抛 `ChapterExportSourceError`（code=`CHAPTER_EXPORT_SOURCE_MISMATCH`），studio 服务端两处（GET /export 与 POST /export-save）映射 409，响应体三键 `{error, code, details}`。
- **产品引擎（Rust）**：`build_export_artifact` 静默容忍——未入索引的 .md 丢弃、缺文件章跳过、同章双形态取 `select_chapter_files` 胜者，永不 409；三个调用方把 `Err(String)` 统一吞掉：GET 面 500 `{"error":"Export failed"}`、export-save 500 裸串、exporter 工具 `error_result("Export failed")`。
- 同一本书（索引列 2 章、盘上缺第 2 章）：Node 腿 409 拒绝；产品引擎 **200 导出缺章残本**——静默数据丢失。
- 既有 409/500 映射形态本身两腿已同形（GET 面 500 文案 `Export failed` 同字、save 面裸错误串同形），缺的只是 Rust 侧没有校验源。

## 2. 产品定线（1678 出口的产品判断，本轮定）

**两腿统一「拒绝」**：源不一致（缺章/同章双形态/索引重复章号/盘上孤儿）即 409 + 对账指引。理由：

1. 静默部分导出=用户拿到缺章/错章的书且无任何提示——导出物是发布、打印的下游输入，属数据完整性事故；
2. 同章双形态的择优（旧稿 vs 新稿）是需要用户裁决的状态，静默取正典把选择藏起来；
3. Node 腿（上游 2.0 语义）已是拒绝——对齐上游而非相反。

**边界澄清（取证中实证）**：「缺章书」在 Node 腿走不到导出面——`resolveDurableStoryProgress` 的读面守卫对缺文件 fail-closed（三种形态），书架接口整页 500（1678 号备案的既有不对称：两腿读守卫有无是 2.0 起刻意保留的）。因此「缺章 409」在产品引擎侧由单测/HTTP 层测试直造存储状态验证；对跑夹具必须选「书架可读但导出校验拒绝」的状态（双形态书、未入索引旧命名文件——两者的 `orphaned` 检查只看正典形态，书架放行）。

## 3. 实现

### TS 腿（行为面唯一变化=排序尺子）

- `chapter-files.ts`：`compareByCodePoint` 改 export（854 号立的尺子首次跨文件复用）。
- `export-artifact.ts`：校验逻辑从私有 `buildChapterFileLookup` 抽成公开纯函数 **`checkChapterExportSource(files, indexedNumbers) → details | undefined`**（golden 向量需要不依赖 StateManager 夹具的直接入口）；`unindexedFiles` 排序从裸 `sort()`（UTF-16 码元序）改 `compareByCodePoint`——增补平面字符（emoji 文件名）与码点序相反，裸 sort 下双端错误消息数组顺序会漂移。校验通过后的 lookup 重建行为等价（四类细节全空 ⇒ 每个索引章号必有唯一文件）。

### Rust 腿（本轮主体）

`export_artifact.rs`：

- 新增 `ExportSourceMismatch`（四字段，对齐 TS details 键名）+ `details_json()`（**手拼键序**——serde_json 未开 preserve_order，Map 是字母序，会与 TS 构造序漂移；数组用 `serde_json::to_string` 紧凑同 `JSON.stringify`）+ `message()`（TS 模板逐字镜像）+ `details_value()`（HTTP 响应用）。
- 新增 `ExportError`：`NoChapters` / `SourceMismatch(...)` / `Other(String)`，`Display` 分别为 TS 同文案 / 完整消息 / 裸串。
- 新增 `check_export_source(files, indexed_numbers)`：与 TS `checkChapterExportSource` 同构——索引重复章号 → 码点序扫目录（`.md` 结尾、`leading_number` 同一把尺子、0 号与超 u32 落未入索引）→ missing = indexed − covered。
- `build_export_artifact` 返回改 `Result<ExportArtifact, ExportError>`：目录读取改 `read_chapter_dir_names`（缺失 → `Other`，对齐 TS readdir ENOENT → 500，而非静默当空目录）；校验与择优共用同一份目录快照；校验面对**全量索引**（部分导出/approved-only 不豁免未勾选章的对账，TS 同口径）。
- 三个调用方映射：GET /export（`books_routes.rs`）`SourceMismatch → 409 {error, code, details}`、其余维持 500 `Export failed`；export-save（`books_state_routes.rs`）`SourceMismatch → 409`、其余 500 裸串（`Display`）；exporter 工具（`sub_agent_tool.rs`）错误直出 `Display`（对齐 TS 异常 message 冒泡——不再吞成 "Export failed"）。
