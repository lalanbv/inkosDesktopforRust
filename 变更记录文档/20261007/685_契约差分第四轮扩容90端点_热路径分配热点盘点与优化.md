## 三、面 B：热路径分配热点盘点与优化

### 盘点方法

bench-baseline 均值排序定位头号热点：`title_dedup/resolve_duplicate_hit_200` = **389.5µs**（第二名 52.7µs 的 7.4 倍，每章两次调用：writer 输出+持久化装配）。逐函数审计 `post_write_validator.rs` 标题去重链路，发现四处分配反模式：

1. `detect_duplicate_title`：`strip_punct(&normalized)`（正则 replace_all+String）**循环内逐迭代重算**（不变量未提升）+ 每标题 `to_lowercase` 分配——每轮探测 200×2 次正则+分配。
2. resolve 流程对同一列表多轮探测（初检/重生成复检/计数器循环/折叠复检）——每轮全量重归一化，O(probes×titles)。
3. `extract_chinese_title_terms`：对 200 标题连接体逐 (start,size) 三元组 **String 分配 + Vec 线性去重**（~8400 次 alloc + O(n²) 比较）——hit 情形主热点。
4. `detect_title_collapse`：**为取末 3 个标题把全列表 200 个 trim+collect**。

### 优化（语义逐字保持，golden_leaf.rs TS 向量锁）

- `TitleIndex` 预归一化索引：lower/strip/original 三平行 Vec 一次构建，探测面纯借用比较；新标题 strip 惰性 memo（初检精确比较阶段断掉时不付 regex 成本）；original 携带原始引用保 violation 文案回显语义。
- `extract_chinese_title_terms` → HashSet（blocked 仅成员判断无序消费）+ 分段借用切片 + 候选缓冲复用（clear/extend 零分配）+ contains-先判免重复候选 to_string 分配。
- `detect_title_collapse` 倒扫取 3 个非空即止（200 alloc → 3 alloc）。
- pub 签名不变（detect_duplicate_title/resolve_duplicate_title）；内部 detect_duplicate_title_indexed 承载。

## 六、教训

1. **bench 均值排序是最便宜的分配热点探测器**：389µs 对 52µs 的 7.4 倍差距一眼定位 title_dedup；「每章两次调用」的乘数把绝对值不大的热点放大成真实成本。
2. **分配热点四反模式**（本号逐一实例化）：循环内不变量重算 / 多轮探测重复归一化 / 候选生成逐个 String 分配+线性去重 / 为取尾部物化全列表——结构性修复（索引化+缓冲复用+HashSet）比局部微优化高一个量级。
3. **语义保持的安全网顺序**：先确认 golden 向量存在（TS 锁）再动手；violation 文案回显原始形态这类「非算法语义」最容易在索引化时丢（本号第一次实现就用 existing_norm 回显，靠写注释时回查修正）。
4. **canonicalize 与 strip_prefix 的根必须同源**：符号链接平台（macOS /tmp、/var）上 canonicalize 后的路径对原始根 strip_prefix 必然失配——要么都 canonical 要么相对化对 canonical 根做。
5. **id 非确定端点入列差分的通用形态**：创建面动态解析（$占位）+ 响应体身份值归一化（%TID%）——创建走双腿各自语义、比对按腿归一，与 %ROOT% 同纪律。
6. **版本范围 override 对 optional peer 可能产生「整体退出」而非「原地升级」**——效果等价甚至更好（攻击面收缩），但必须核验源码 import 面+类型面+运行时门禁三层后才可接受；残留孤儿目录要干净重建清除。
7. **满载红灯三步法再次生效**（683 教训复用）：先看引擎日志（AddrInUse 实锤）→ 隔离复跑（绿）→ 全量复跑（绿）=环境竞态非回归；duel 并行端口选择的 bind 竞态窗口在 45 目标并行下偶发是基建已知形态，不是每次红都值得修代码。
