# 1572 回环代理劫持修复轮（2026-11-19）

## 定性

用户叫停纯文档巡航后首次实跑找 BUG 轮。全量实跑测试（挂起 sweep + 双 crate 全量 + TS 十腿），浮出 1 个真实用户面缺陷并双栈同族清偿。

## 缺陷：回环探活/本地端点被系统代理劫持

- **Rust 腿（实证红→绿）**：`cargo:testgate` 浮出 `supervisor_integration::health_probe_succeeds_when_server_up` 失败（mock 200 服务已起，探活 3s 恒超时）。根因：reqwest 默认启用系统代理（macOS System Configuration），本机系统代理 127.0.0.1:1082 开启且豁免名单含 `localhost` 但**不含 `127.0.0.1`** → 探 `http://127.0.0.1:{port}` 被送进代理，代理回连不了本机临时端口 → 恒超时。生产影响：启动门误判 sidecar 不健康（main.rs 以 health_probe 通过才 eval 加载 WebView）；watcher `probe_once` 恒假死 → 误 kill/重启风暴；`SseClient` 恒连不上通知流。
- **TS 腿（同族预判清偿）**：`fetchWithProxy` 读 `HTTPS_PROXY` 等 env 代理，覆盖全部 LLM 调用面；本地推理端点（Ollama 127.0.0.1:11434 / LM Studio 127.0.0.1:1234）与代理 env 共存时同被劫持。

## 修复

1. `src-tauri/src/supervisor.rs`：`health_probe` / `probe_once` 加 `.no_proxy()`（回环目标恒不走代理）。
2. `src-tauri/src/observer/sse.rs`：`SseClient::new` 加 `.no_proxy()`。
3. `packages/core/src/utils/proxy-fetch.ts`：新增 `isLoopbackTarget`（localhost / *.localhost / 127.0.0.0/8 / ::1，支持 string/URL/Request 输入），`fetchWithProxy` 对回环目标旁路代理；非回环私网地址仍走代理（边界锁定）。
4. `packages/core/src/__tests__/proxy-fetch.test.ts`：3 枚新回归锁（127.0.0.1 旁路含 dispatcher 不在场断言；localhost/[::1]/URL 对象/显式代理入参旁路；192.168 私网仍走代理的边界对照）。

## 归属豁免（正确保留系统代理的外网站点，勿误扩）

`updater/engine.rs`（GitHub release 下载）、`engine/node/mod.rs`（Node 引导 tarball 镜像下载）、`plugin/registry.rs::NoRedirectClient`（插件市场，SSRF 守卫另有）、engine-rs 全部（LLM 上游/notify 外发，无回环自探运行面）。

- TS：`gate:ts` 十腿全绿（build 19.6 / typecheck 19.5 / test 110.8 / audit:npm 4.8 / rust-bin 0.3 / smoke 35.9 / diff 36.0 / epub 35.1 / alternation 5.1 / routes 0.1），proxy-fetch 6/6（3 既有远端红路对照 + 3 新回环锁）。
