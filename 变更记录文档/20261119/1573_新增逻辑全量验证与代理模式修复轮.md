## 1572 根因勘误（表述修正，修复本身正确且必要）

- 修正前表述：「豁免名单不含 127.0.0.1 → 恒劫持恒超时」。
- 源码实证（hyper-util 0.1.21 `matcher.rs` mac::with_system）：reqwest 只读 SCDynamicStore 的 HTTP/HTTPS 开关，**完全不读 ExceptionsList**——scutil 豁免名单对 reqwest 无效，`localhost` 写了也救不了字面 IP。
- 行为实证（Node/Rust 双探针）：代理守护进程**健康**时回环请求经代理直连规则转发成功（+~2ms 往返，可用但脆弱）；**降级窗口**内全灭——昨日 supervisor_integration 红即此窗口，同 gate 内 SSE 测试绿是因落在窗口外。故障形态是**窗口性**（间歇），比恒定故障更难诊断；修复价值不变：`.no_proxy()` 移除的是「本地探活对第三方代理守护进程的隐性运行时依赖」这一依赖类。

## 修复一：engine-rs 同族暴露（双栈镜像对齐）

- 机制：reqwest `auto_sys_proxy` 无条件开（async_impl/client.rs:419 非特性门控），hyper-util `from_env()` 恒读 env 代理；engine-rs 虽关 `system-proxy`（不读 macOS 系统代理），**env 代理（HTTPS_PROXY 等）仍生效** → 本地 Ollama/LM Studio 在设 env 代理的用户机上被劫持，与 TS 腿（已有 isLoopbackTarget）构成双栈漂移。
- 新单一真源 `engine-rs/src/utils/loopback_proxy.rs`：`is_loopback_base_url`（localhost/*.localhost/127.0.0.0/8/::1/未指定地址 0.0.0.0/::；url crate WHATWG 归一化，IPv6 host_str **带括号**需剥后解析——实测 2.x 行为）+ `no_proxy_if_loopback`。17 案表驱动单测（含 127.1 短形归一化、v4 映射不判回环、私网/解析失败不旁路）。
- 接入四站：`streaming_client::new`（生产 LLM 主路径）、`probe_models_from_upstream`、`cover::http_client`（7 调用点，base_url 可配可指回环；下载路径 origin 守卫另管不动）、`notify_client`（webhook 用户可配，本地 ntfy 场景）。外网站点（materials SSRF 拒回环、LLM 默认外网）保留代理。
- 活体测试 `tests/llm_loopback_no_proxy_live.rs`（独立进程防 env 外泄）：死代理 env（127.0.0.1:1）+ 控制红（默认 builder 必须真走死代理而失败=红路前提活体）+ 主绿（StreamingChatClient 回环直连流出正文）。**红路四拍实证**：撤修复→红→复原→绿。

## 修复二：TS 代理模式在新运行时整体死亡（活体测试抓出的真潜伏缺陷）

- 矩阵实证（Node 26.13.1 本机）：npm undici 6.29.1（core 原钉版本）的 ProxyAgent **全接口死亡**（fetch/request 均恒挂，连接从未发出）；undici 7.30.2 同挂；全局 fetch×npm undici6 agent 抛 "invalid onError"（DispatcherBase catch 吞原始异常）；**undici 8.12.4 全接口可用**且 engines `>=22.19.0` 恰等于本项目 node_min。plain fetch/plain Agent（无 dispatcher）各版本均正常——缺陷面精确锁定在 ProxyAgent×新 Node 内核。
- 影响：设 env 代理（INKOS_LLM_PROXY_URL/HTTPS_PROXY）的用户在 Node 26 开发机上，全部非回环 LLM 调用必然失败——属用户当下真实环境缺陷（1572 的回环旁路恰好躲开了这条死路）。
- 修复：core undici `6.29.1`→`8.12.4`；`fetchWithProxy` 代理模式改走 **undici 自家 fetch**（版本一致配对，跨 major dispatcher 协议错位在构造上不可能发生）；`buildProxyFetchInit` 导出契约保持（补契约锁测试）。全局 undici-types 与 npm undici 8 跨包 Dispatcher 类不结构兼容，边界处显式收窄（零行为变化）。
- 传递性 peer 警告备案：openai 7.19.0 欲 peer undici ^6，its proxy path 走全局 fetch+u8 agent（Node 26 实证可用），install exit 0 不阻塞。
- 测试：单测重构（undici fetch 桩，7 枚含契约锁）+ 活体 3 枚（真实 undici 8：loopback/localhost 直连 200 + **标记代理法**证非回环真过代理=599 命中，undici bad-port 清单避开）。**红路活体**：撤旁路→loopback 两枚红→复原→绿。verify-service 代理测试改钉新缝（6/6）。
