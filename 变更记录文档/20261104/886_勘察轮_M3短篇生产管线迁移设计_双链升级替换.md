## 一、核心判定：M3 是「旧链升级替换」，不是从零移植

双链并存格局（本轮最重要勘察结论）：

- **Rust 旧链（78 号，产品引擎活体）**：`engine-rs/src/agents/short_fiction.rs` 1010 行
  （六代理含审纲/修纲——2.0 已合并掉、`=== TAG ===` 块解析、无 structured tool call）+
  `engine-rs/src/pipeline/short_fiction_runner.rs` 830 行（直落 out_dir 文件目录+status.json，
  **无 work 域**）+ `server/agent_production.rs` 旧意图面接线（`run_short_fiction_production`
  直调实证 L1804-1812）。
- **TS 2.0 链（M3 目标形态）**：`pipeline/short-fiction-runner.ts` **1773 行**（真正的编排器
  ——勘察起点误报为 agents 层 877 行，实为 agent 层+pipeline 层双层）+ `agents/short-fiction.ts`
  877 行（四代理全走 `BaseAgent.submitStructured` 结构化 tool call + validate 重试环 +
  `submitSourcedReview` observations 契约）+ work 域深度集成（ensureShortWork/四阶段
  acceptPaths 同步/production-state 幂等重放/书锁/失败恢复 candidate 记录）。
- **用户可见价值差**：旧链产物=裸文件目录（桌面 /works 恒空）；2.0 链产物=work 实体
  （WorkInspector 活体+episodes+幂等续跑+交付合同观察）。Rust 引擎短篇创作当前**没有
  work 化形态**——695 号最大未迁域的 L2 层本体。
- **替换策略备案**：TS short_run 意图已直连 work 域工具（server.ts:1238→
  createShortFictionRunTool→runShortFictionProduction），旧链在 TS 侧无生产消费者；
  Rust 替换=agent_production.rs 短篇分支切新链后旧实现按 695 纪律退役（先并行 duel
  对照绿后退役，不在 M3 第一轮）。

## 三、分解建议（881 §五「M3 最大」成立，≈3850-4800 行 Rust+测试）

M3a 纯函数+schema 层（≈700-900，金标准锁+变异三类）→ M3b submit_structured 基座
（≈450-600，mock duel 请求形态对齐+重试环变异）→ M3c 四代理+prompts+reviser 新形态
（≈900-1100，逐代理 golden）→ M3d runner 编排层（≈1200-1400，幂等重放变异+mock 端到端）
→ M3e 服务面接线（≈600-800，确认卡→能力动作+runtimes 四路路由+旧链退役 duel）。

## 四、fail-closed 移除清单（884 号边界 → M3 兑换）

- `short-manuscript`（authority 再生投影族）与 `short-package`（sales 三件投影）分支：
  **M3a 兑换**（纯函数齐即接通，不依赖 runner）；
- `translation-*`/`story-graph` 分支**不在 M3**（各自属翻译/影游管线），移除后注释
  收窄声明范围；
- adopt 的 title_override 占位（884 注释「M3 接通」）→ M3a 接通 storyTitle 覆写。

## 六、M3 端到端验收句（M3e 完成判据）

Rust 引擎下：确认卡 direction → short_fiction_run → work 创建（work.json+episode）→
四阶段（mock，幂等+断点续跑可证）→ 交付合同观察 → 产物七件落 works/<id>/source/；
同 direction TS 引擎重放双腿产物形态一致；fail-closed 短篇分支移除后 Rust adopt
authority 再生投影与 TS 等价；交替互证扩展腿绿。
