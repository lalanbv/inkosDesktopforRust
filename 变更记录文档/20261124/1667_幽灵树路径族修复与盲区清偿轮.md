# 1667 号：fork 读写面「幽灵树」路径族修复（701-707 号批次）+ 路由覆盖盲区清偿 28 条

> 日期：2026-11-24 ｜ 类型：缺陷修复轮 + 测试清偿轮（1664 号盲区清单的直接产出）
> 定位：为清偿盲区基线去读 fork 契约写面的处理器，读出比「缺测试」严重得多的问题——701-707 号批次回收的 1.x 处理器对 2.0 原生书读写一棵**幽灵树**。本轮修掉其中 13 处并把盲区基线从 32 条清到 4 条。

## ① 发现：`join(root, "books", id, …)` 幽灵树族

- **根因**：701-707 号批次回收的 1.x 处理器沿用 `join(root,"books",id,…)`（server.ts 共 32 处、24 个路由作用域），而 2.0 规范书目录是 `state.bookDir(id)` = `works/<id>/source`。对 Studio 2.0 新建的**原生书**（没有 `books/<id>` 树），这些端点读写的是一棵不存在的树。
- **按消费方分三层**：
  - **真失效**（有 works 路径的消费方）：
    - `roster/confirm` 恒写 `books/<id>`，而读面 `roster-candidates` 对原生书读 works——用户确认候选后读面永远看不到，候选恒为「新实体」，还多出一棵 `books/<id>` 杂树。
    - timeline API 读写 `books/<id>/story/timeline.json`，而管线 `timeline-settle.ts` 读 `bookDir` 下的同名文件——时间线页的编辑对写作链不可见。
    - best-of-n / auto-beats / series-id / chapter-review-mode 对**存在的书**报 not found，或把配置写进残缺的幽灵 `book.json`。
    - series-backfill 的源书正典恒从 `books/<sourceBookId>` 读（路由前一步却用 works 布局的 `loadBookConfig` 判存在）→ 恒 400「no canon files」。
  - **无消费方的回显存储**：`anti_ai_rules.json`、`experience.json`、`bestOfN` 在 2.0 core 里没有任何读取方——设置能存能读、UI 能显示，但不产生效果（1.x 管线消费方随 688 号合并退役，701 号只救回了端点）。**立案**。
  - **additive 读**（promises / truth，legacy 文件存在才并入）：无碍。
- **为什么差分器抓不到**：差分器的 TS 夹具是「legacy 书经迁移注册」——迁移实现是把 `books/<id>` **拷贝**进 works 并保留原目录，读写恰好落在内容相同的两棵树上。共享面 86 对比 / 0 分歧是这个形态下的盲区。
- `"books"` 其余用法复查：仅备份根目录清单一处（`books` 与 `works` 并列），无遗漏。

## ② 修复：一条规则，单源定位

`server.ts` 加一组定位函数：`legacyBookPath` / `bookDataPath` / `readBookDataFile` / `writeBookDataFile`。

- **读 = works 优先、legacy 兜底**（迁移书的存量数据不丢）。
- **写 = 恒 works，原子替换**。
- `roster/confirm` 与读面**同分支**：legacy 账本（`books/<id>/story/memory.db`）在位走 books/ 树，原生书走 works 树。
- `best-of-n`：缺书 → 404（此前在幽灵树写出只含 `governance` 的残缺 book.json）；配置损坏 → 拒写（此前把损坏文件覆写成残缺配置 = 静默丢书）。
- 应用于 13 处：best-of-n / anti-ai-rules / roster-confirm / experience 三面 / timeline / timeline-auto-beats / series-id / series-backfill 三面 / `loadRawBookConfig` / chapter-review-mode。
- **动手前排除的风险**：把这些键写进 works 下真正的 `book.json` 是否会让 strict schema 拒收、整本书不可加载？核实 709 号已把 `writing.autoTimelineBeats` / `governance.bestOfN` / `seriesId` 补进 `BookConfigSchema`——安全，且写进真配置后 `StateManager` 加载即可读到。

- `image-settings` 对不存在的 run 会建目录：上游 2.0 的面，与 1664 号立案 (a)「幽灵书写入」同族。
