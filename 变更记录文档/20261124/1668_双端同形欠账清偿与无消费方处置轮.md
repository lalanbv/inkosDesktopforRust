## ① (b) `POST …/versions/:versionId/restore` 查找失败：500 → 404（双端同改）

- **现象**：同一个版本 id，`GET …/versions/:versionId` 回 404，`POST …/restore` 回 500 裸串。非法章节号、非法版本 id、缺文件、书不存在四种查找失败都和「替换事务失败」一并落进外层 catch。
- **根因**：两条腿都是忠实移植 1.x TS——`readChapterVersion` 的 assert 错误落在路由的外层 catch，Rust 端 `restore_chapter_version` 用 `internal_error(...)` 同形收口。资源不存在是客户端可纠正的问题，不是内部错误。
- **修复**：
  - TS `server.ts`：只把 `readChapterVersion` 包进内层 try，失败 → `404 { error: message }`；替换事务仍在原位（失败照旧 500）。
  - Rust `books_state_routes.rs`：非法章节号与 `read_chapter_version` Err 两处改 `(StatusCode::NOT_FOUND, Json(json!({ "error": … })))`；`execute_chapter_replace` 失败仍走 `internal_error`。
- **测试**：
  - Rust 新增 `tests/chapter_workspace_not_found.rs`（独立 `runtime()` / `fixture()` / `app()`，books49 同构夹具）：非法 id / 格式合法但不存在 / 非法章节号三类各 404 且正文逐字节不动，再打一次成功路径 200——防「一律 404」的假绿。`books49_e2e::restore_version_replaces_content_and_broadcasts` 里「缺失版本 → 500」的旧断言翻转为 404。
  - TS `book-data-path-family.test.ts` 章版本用例扩成四类查找失败表（含幽灵书），各 404 且正文不动，再成功恢复。
- **变异**：Rust 回退 `books_state_routes.rs` 后新文件两测全红；TS 回退 `server.ts` 后四类查找失败用例红。

## ③ (d) `POST …/play/runs/:worldId/:runId/generate-image`：TS 对齐 Rust

- **现象（实跑）**：缺 work 时回 `400 { code: "ENOENT", error: "ENOENT: no such file or directory, open '/var/folders/…/works/w1/work.json'" }`——本地绝对路径原样回显给客户端。
- **根因**：请求体不校验即进工具锁域；`executeExplicitCapabilityTool` 第一步 `loadWorkManifest` 的 ENOENT 被处理器外层 catch 以裸串返回。
- **Rust 侧不改**：`post_play_generate_image` 的次序与文案已是目标契约，`e2e_write_next_contract.rs:12366` 起已有四条断言（缺 entityId 400 / 实体不存在 404 / 未配置生图链 400 needsCoverConfig / scene 无文本 400）。
- **修复（TS，进工具前只读前置判定，次序同 Rust）**：
  - `entityId` 缺失或空白 → `400 { error: "entityId is required for an entity image" }`
  - scene 且无当前场景投影 → `400 { error: "no current scene to illustrate" }`
  - entity 且 world 或 run 的 `play.db` 不存在 → `404 { error: "entity not found: {id}" }`（Rust 对缺 work/run 取空图，结论相同）
  - 工具内 `PLAY_ENTITY_NOT_FOUND` → 同码同文（此前 400「Select an existing entity to illustrate」）
  - 响应一律扁平 `{ error }`，不再挂 `code` 键；文件系统错误只报类别（`500 Play image generation failed (ENOENT)`）；`BookWriteLockError` → 409 `BOOK_BUSY` 信封（与全文件锁冲突口径一致）。
- **顺带消掉的幽灵写**：此前工具内 `PlayDB` 构造会 `mkdirSync(runDir)`——对一个不存在的 run 建出目录与库文件。前置判定只读。
- **测试**：`route-baseline-batch2.test.ts` 把弱断言（`>= 400`）换成一条精确契约：缺 work 四形态 → 世界在 run 不在 → run 在实体不在（走工具）→ 实体在而生图链未配置（扁平 400）。
- **变异**：去掉前置判定 → 500 红；去掉工具错误映射 → 400「Select an existing entity」红。
- **未动（如实立案）**：Rust 生图失败回 `200 { ok:false, status:"failed" }` 而 TS 回 400（UI `PlayHud` 两种形状都处理）；Rust 接受 `sceneText` / `sceneKey` 请求体而 TS 工具不接。

### 为什么不「接消费方」

2.0 的审稿契约与 1.x 根本不同——`AuditResult` 是证据化观察项 `{ code, summary, evidence }`（`pipeline/runner.ts:1118 reviewChapter`、`pipeline/chapter-review.ts`），没有 1.x 的 `issues / severity / overallScore`。best-of-N 的「首版分数低于门槛」在 2.0 管线里连判据都不存在。接消费方是一次带评分方案设计的移植，不是补调用点。挂接点已定位：`runner.ts:1267` / `:1659` 上下文装配、`:2463` 上下文源数组。
