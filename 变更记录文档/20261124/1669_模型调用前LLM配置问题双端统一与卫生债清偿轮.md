# 1669 号：「模型调用前检出的 LLM 配置问题」双端统一 400 `LLM_CONFIG_ERROR` + 测试临时目录泄漏与门禁日志保留期清偿

> 日期：2026-11-24 ｜ 类型：契约统一轮（双端）+ 卫生债清偿轮
> 定位：清偿 1668 号立案的 (c)——同一类配置问题在 TS 腿三形态并存、Rust 腿没有这一错误类；验收 = `INKOS_DUEL=1` 对跑探针双腿同码同文。顺带清偿 1668 号清场时量得的两笔卫生债。

## ① 取证（实跑，两变体）

**TS 腿**：给一个未配置的项目（无 `inkos.json` / 有配置但缺 key）打七个模型调用面，同一类问题三形态并存：

| 面 | 改动前 |
|---|---|
| write-next、books/create | 400 `LLM_CONFIG_ERROR` 信封（错误冒泡到了全局 `onError`） |
| audit、revise、foundation/revise、daemon/start | 500 裸串 `LLMConfigurationError: …`（处理器自带 try/catch） |
| agent | 500 `INKOS_ACTION_ERROR` 信封；缺 key 时根本不报配置错，要等请求发出才以模型错误（502）失败 |

**Rust 腿**：全仓没有这一错误类。`BooksRuntime::effective_router` 在项目配置不可用时**静默回退启动路由器**，未配置只在实际请求里以连接拒绝的传输错误暴露（后台任务 → SSE `write:error`；同步面 → 500）。而桌面壳直启引擎不注入任何 `INKOS_LLM_*`（src-tauri 零处设置），所以产品路径上启动路由器恒为 bin 的 env 缺省哨兵（discard 端口 + 空 key）。

**协议锚**：UI 文案表（`core/llm/error-copy.ts`）对 `MISSING_API_KEY` 的英文原文**逐字匹配**做本地化——这句是双端都必须原样发出的锚文本。

## ② TS：失败归一化单源

- `llmConfigErrorBody` / `llmConfigResponse`：非 LLM 配置错误返回 `null`，各处原有失败口径逐字保留；全局 `onError` 改走同源。
- 三组 `replace_all` 接入 54 处逐字相同的裸 500 catch 点（`String(e)` 48 / `e instanceof Error ? e.message : String(e)` 5 / `String(error)` 1）。
- `translations/:id/run`：`500 INKOS_TRANSLATION_ACTION_FAILED` 信封前加映射。
- `/agent`：外层与确认动作内层 catch 各加映射；聊天轮入口加缺 key 前置检查（`llmConfigProblem` 与管线同一解析路径，`requireApiKey` 缺省），带 `response` 文本给聊天气泡。

结果：七个面两变体一律 `400 { error: { code: "LLM_CONFIG_ERROR", message } }`。

### 落地前的自查修正

首版把 agent 的检查**无条件**放在处理器开头。复核时发现 agent 面还承接「确认式生产动作」，其中有不走文本模型的——`generate_cover` 走封面服务、`remove_node` / `connect_choice` 是纯结构操作。只配了封面服务的项目上，这些动作会被聊天模型的缺 key 误拦成 400。

修正（两腿同改）：**只守聊天轮**（它必然调用模型），检查位置移到会话查找之后（未知会话仍先 404，顺序同改动前）。实跑佐证：确认式 `generate_cover` 在缺 key 项目上以自身的载荷校验错误收场（TS `400 CONFIRMED_ACTION_PAYLOAD_INCOMPLETE` / Rust `502 AGENT_ACTION_FAILED`），不是 `LLM_CONFIG_ERROR`。

## ③ Rust：配置前置守卫

- `LlmEndpointConfig::is_unconfigured_placeholder` + 常量 `LLM_UNCONFIGURED_BASE_URL`（bin 缺省改引同源）。
- `effective_router` 拆出 `resolve_project_llm`：路由器构造与前置检查共用**同一份**可用性判定；回退语义不变（单测锁定）。
- 新增 `server/llm_config_guard.rs`：判定 = 项目配置不可用 **且** 启动路由器是未配置占位。env 配置的引擎（开发 / 冒烟脚本）不拦。
- 接入点：
  - 组合层 `llm_guarded`：write-next 与 books 域九个模型面（plan / settle / draft / revise / rewrite / resync / compose / consolidate / repair-state）。write-next 的守卫只能在组合层加——`WriteNextRuntime` 不持有启动路由器。
  - `audit_chapter` 处理器内：检查在 `audit:start` 之前，不留无终态的广播。
  - `post_agent` 聊天轮分支（确认意图分流之后）。

## ⑤ 卫生债

- **测试临时目录泄漏**：五个 studio 测试文件的 `afterEach` 是**空转的伪清理**——循环体只有一句 `void root`，注释写着「tmpdir 清理交由进程退出」，但进程退出并不删临时目录；另两个文件完全没清理。系统 tmp 累计 1486 个同类根。改为真 `rmSync`；验证 = 跑前跑后根数不变（1486 → 1486）。
- **门禁日志无保留期**：`cargo-test-gate` 每跑一次留一个日志目录、从不清理（累计 200 个）。改为只留最近 10 份，5 分钟内改动过的在用目录一律不动（并行会话可能有门禁在跑），并加两幕必红自检。首版自检夹具的期望值写错（保留份数含在用的那 1 个，应删 6 不是 5）——被自检自己判红后更正；去掉在用保护的突变让第二幕判红「多删 2 个在用目录」。
