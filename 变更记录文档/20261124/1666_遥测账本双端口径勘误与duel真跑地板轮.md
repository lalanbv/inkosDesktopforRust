## ① run-log 口径勘误（TS 腿折叠）

- **证据**：新增 `engine-rs/tests/run_log_call_site.rs`（写入点此前零测试，只有纯函数 golden）5/5——同模型 `429→429→200` 三次上线 = **一条** `{ok, attempt_index:0, round:1, took_over:false}`；链层接管才是第二条 `{attempt_index:1, took_over:true}`。TS 修前（1663 自带测试 15/15 钉死）：同负载 **2 条**，命中轮 `round:2, tookOver:true`。
- **根因**：1663 口径备案「Rust 逐次 `chat_once` 记」不成立——Rust 在 `chat` 的 (chain_idx, round) 层记，`chat_transient` 内环的同模型退避重试不单列。逐轮记 = 把同模型重试记成「接管」、把已恢复的调用记成「失败」，两条腿的 total / tookOverCount / failureCount 各说各话。
- **修复**：`chatCompletion` 记在 `withTransientLLMRetry` 之外（403 号 runAndRecord 原语义）；`observeModelStream` 仅最外层持探针，重试流的终态经外层 `forward` 汇入；预中止不计。TS `run-log-writer` 18/18，与 Rust 测试共用同一负载表、条目口径逐元组相等。

## ④ 账本加固（usage + prompt 版本，双端）

- **并发追加丢行**：TS 20 路并发追加后只剩 **1 行**；Rust 32 路只剩 **2 行**。「读旧 + 拼 + 原子写」的原子性只管单次写。修复：TS `runSerially` / Rust `utils/jsonl_ledger.rs`（按路径互斥）。
- **读错误 ≠ 空账本**：账本读不出来（权限/IO）时追加照常「成功」= 用只有新行的内容覆盖整本历史；读面把「读不到」报成「0 用量 / 没有版本」。修复：只有缺失才是空；读不出来追加中止、读面上抛（预算端点 500 而非静默报 0）。
- **形状守卫**：缺字段的「像行的对象」此前被收下，投影求和出 NaN。按 Rust serde 同款丢弃。

## ⑥ duel 真跑地板（本轮最重要的门禁发现）

- **实测**：TS 腿没有 `/api/v1/health` 路由 → 1663 迁过去的守卫判据对 TS 腿恒判「上游 2.0」→ 11 个受守卫的对跑全部早退却计 `ok`。libtest 报 **13 passed，真跑 2**。且 `cargo test` 默认捕获测试的 stderr——守卫「响亮记账」的 `eprintln!` 在门禁日志里**从未出现过**。
- **强制打开守卫实测**：13 个对跑 **6 真绿 / 7 真红**。7 红 = 4 个 `write_fixture` 仍是 1.x `books/` 布局（TS 2.0 按 works 清单发现作品）+ 1 个 mock LLM 不回 `finish_turn` + 3 个真实契约分歧（`/project` 的 `temperature`、series-backfill extract 200/400、会话读面形状）。
- **机制**：`strangler_duel.rs` 落台账（门禁经 `INKOS_DUEL_LEDGER` 指定；`duel_enabled()` 写 `start`、守卫早退写 `exempt`）；`cargo-test-gate` 以「start 数 = 测试总数」做通道存活握手，`真跑 = start − exempt ≥ 2`、`豁免 ≤ 11`（双向棘轮），必红自检 12 条。
- **自检也被真实日志证伪过一次**：首版按「节」取 `running N tests`，合成夹具全过，真实日志取到 0——门禁把 cargo 的 stdout / stderr 分采后拼接，`Running <binary>`（stderr）与 `running N`（stdout）不相邻。改为序号对应 + `passed+failed+ignored === N` 交叉验证；哑二进制（`harness = false` 的 bench、examples）排在所有 `tests/*` 之后，不影响对跑的序号，错位一律判红。历史全量日志 3 份验证。
- **端到端**：`duel 真跑 2 / 豁免 11（地板 2 / 上限 11）：…` 首次在真实门禁里如实报出。
