## 一、范围

1. **情节线重命名/删除**：纯函数 `buildTimelineAfterRenamePlotline`（trim、空输入幂等保留原名）/ `buildTimelineAfterRemovePlotline`（按 id 连节拍移除，删空后视图回退单线兜底）+ 线头入口（可编辑态线头常显小按钮：重命名内联输入 + 删除两步确认「删除 → 确认删除?」）。
2. **按此节拍写下一章（write-next context 双端接线）**：
   - 取证：TS `writeNextChapter` 第 4 参本就是 `externalContext`；Rust `write_next_chapter` 的 `external_context` 非空时替换自动 plan——**两侧管线能力早已存在，缺的只是 HTTP 契约暴露**（与 175 号「abort 接线」同构）。
   - Rust：`WriteNextBody` 加 `context: Option<String>`；`WriteNextRunner` 签名第 6 参；bin 闭包 `external_context: context.as_deref()`。
   - TS：write-next body 解析加 `context` → `writeNextChapter(id, wordCount, undefined, body.context)` 透传。
   - UI：编辑弹窗加「按此节拍写下一章」——beat 文本组装为规划输入（`时间线节拍【线名 · 第N章】标题：备注`），带伪会话 `sessionId` 发起（174/175/176 号检查点与可停止随之激活），发起后弹窗内提示「已在后台按节拍写作」。

## 三、过程记录

1. python 片段替换大量静默失配（anchor 与实际文件有出入时 replace 不报错），导致组件一度处于「引用已插入、声明缺失」的破损态——**碎片化编辑多 anchor 的文件时，替换后必须立即 typecheck 并核验每个 anchor 命中**（本批后半改用 assert 断言 anchor 存在）。
2. `vi.hoisted` 之外新记录：Playwright `fill` 对 React 受控组件生效，但断言值要用 `evaluate(el => el.value)`（attribute 与 property 不同步）。
3. write-next 的 context 语义沿用管线既有定义：非空 external_context 替换自动 plan——UI 文案「按此节拍写下一章」与引擎「下一章按节拍规划」对齐。
