## 一、缺口分析（写路径 LLM 失败恢复面）

| 面 | Node（core provider.ts） | Rust（engine） |
|---|---|---|
| 瞬时重试 | `withTransientLLMRetry`：2 次重试 + 线性退避（800ms/1600ms），`isRetryableLLMError` 四类判定 | **零重试**——`AgentRouter::chat` 一次失败直接抛 |
| 判定函数 | isTransientLLMHttpError / Transport / Incomplete / PartialResponseError | `is_transient_llm_http_error` 已移植但**零调用**（dead port） |

**后果**：连续写作（write-next 多 agent 长链）中一次 429/502/网关抖动 = 整章失败；Node 回退端会退避重试——默认引擎（Rust）可靠性反而低于回退端。典型场景：限流窗口、网关瞬时 503、流首事件超时（网关挂起）。

其余复查面（无缺口）：流 deadline 已对齐（300s/180s 管线默认，env 可覆盖，130 号）；`PartialResponseError` 语义已对齐（中断流不"打捞"半截内容）；章级失败面有快照回滚与 state-degraded 防线。

## 二、实施

### `is_retryable_llm_error`（llm/provider.rs，205 号新增）

对齐 TS `isRetryableLLMError` 的文本面子集（输入为 chat 链字符串化的错误文本）：
- `is_transient_llm_http_error`（已有：429/502/503/504 + 限流短语，排除 `model_not_available`）
- 传输层瞬时（reqwest 文本形态）：`error sending request` / `operation timed out` / `connection reset` / `connection closed` / `broken pipe` / `socket hang up`
- 流不活动超时（`StreamError::Inactivity` 文本逐字）：首事件窗/空闲窗
- 协议层空响应/缺终态（TS `isIncompleteLLMResponseError` 逐字）：`LLM returned empty response` / `reasoning without a final answer`

### `AgentRouter::chat` 重试循环（llm/agent_router.rs）

- 原 `chat` 主体拆出 `chat_once`（单次尝试）；`chat` 包重试循环：**2 次重试（共 3 次尝试）+ 线性退避 800ms×attempt**（对齐 TS 注释「Linear is enough for a 2-retry budget」），每次重试完整重新生成（messages 每次 clone——技能注入只做一次）。
- 开关：`INKOS_LLM_TRANSIENT_RETRY=0|false|off` 关闭（诊断快测面，对齐 TS `options.retry=false`）；默认开。
- 与 TS 的两个刻意差异：①无 `onTextDelta` 禁用面——Rust `progress_hook` 是进度事件（对齐 TS `onStreamProgress` 不禁重试的语义）；②无 signal 中止面——用户中止在阶段边界生效（175 号），重试期间最长 ~2.4s 退避不与之冲突。
- 重试时 `tracing::warn!` 记录 agent/attempt/错误文本（观测面可见）。

## 三、验证

- 单测 +2（provider）：可重试面全覆盖（429/503/传输/不活动/空响应文本）与非瞬时拒绝（model_not_available/401/404/未知）。
- 集成测 +3（agent_router，可编程失败次数的 mock LLM）：429×1→重试成功（hits=2）；503×∞→耗尽如实失败（hits=3）；500 model_not_available→不重试直败（hits=1）。
- 全门禁：engine lib **1282**（+5）/ 集成 **194+70+10**、clippy --all-targets -D warnings 零告警、INKOS_DUEL=1 strangler_duel **10/10**。
- **真机冒烟（生产形态）**：flaky mock（第 1 次 429、之后 SSE 200）+ bin `INKOS_LLM_BASE_URL` 指向它——`POST /books/b1/plan` 返回 **200 成功**（落盘 chapter-0001.intent.md），mock 命中序列 `1→429, 2→200`——**生产装配链的瞬时重试真实生效**（对照：无重试时 429 直接失败，203 号冒烟先例）。

## 四、有意排除项

- Rust 无 per-call retry 开关参数（TS `options.retry`）：Rust 的诊断探测面（doctor）不走 `AgentRouter::chat` 的 LLM 探测尚无先例——env 全局开关已覆盖需求；引入 per-call 参数会波及全 agent trait 面，等真实需要再议。
- 请求级 signal/AbortSignal 贯通（TS 的 abortableDelay）：与用户中止的阶段边界设计（175 号）重复，不引入。
