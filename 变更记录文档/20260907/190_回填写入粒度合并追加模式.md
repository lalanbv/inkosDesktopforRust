# 190 号：系列书回填写入粒度——合并追加模式（默认维持覆盖）

- 日期：2026-09-07
- 分支：develop
- 关联：184 号（回填向导）、186 号（diff 预览）、185 号（契约 duel）、175 号（ApplyBody camelCase 教训）
- 决策待确认：179 号分解文档遗留的「C3 回填写入粒度」产品决策（追加合并 / 维持整体覆盖 / 逐项自选）。本批次按**最保守可回退**方案落地：**默认维持整体覆盖不变，新增可选「合并追加」模式**——不改变任何现有调用方行为；若用户最终选择其他方案，改默认值即可。

## 一、变更内容

### 语义定义

- `overwrite`（默认，原语义）：`series_backfill.md` 整体重写为勾选条目，未勾选的既有条目被移除。
- `merge`（新增）：解析既有文件条目 → 勾选项按 **(category, title)** 去重后追加 → 重渲染整文件。同题条目**不覆盖旧内容**；既有条目永远在前。

### 引擎（engine-rs，series_backfill_routes.rs）

1. `ApplyBody` 新增 `mode: Option<String>`（缺省/其他值 → overwrite，旧客户端形态零影响）。
2. `parse_backfill_items`：解析本端点机器渲染格式的条目（`## [category] title` 开节、多段 content 保真、头部忽略、id 合成 `existing-N`）。
3. `merge_backfill_items`：既有在前 + 勾选去重追加（纯函数）。
4. apply 响应 additive 扩展：`"mode"`、`"total"`（合并后文件条目数；applied 仍为勾选数）。
5. 新增测试模块（此前该文件无单测，契约面仅由 duel 覆盖）：
   - 渲染→解析→再渲染逐字 roundtrip；
   - 多段 content 与头部忽略；
   - merge 去重（同题跳过、既有在前）；
   - 路由级 apply merge（既有文件保留 + 同题不覆盖，axum oneshot 真盘）；
   - 路由级默认模式维持覆盖（不带 mode 字段的旧形态）。

### Node 回退端（server.ts）

6. apply 端点同步 merge 语义（解析/合并/渲染与 Rust 逐字对齐），响应同 additive 字段。
7. **顺带修复既有缺陷**：Node apply 头部渲染缺「（sourceBookId）」双写（Rust/TS 渲染面自 184/186 号起为 `来源：《id》（id）`，Node 只有 `来源：《id》`）——本次对齐；server.test.ts 断言头部逐字一致。

### Studio

8. `series-backfill-diff.ts`：新增 `parseBackfillItems` / `mergeBackfillItems`（与 Rust 纯函数对齐）；模块文档更新为双粒度语义。
9. `SeriesBackfillPanel.tsx`：预览区新增「写入粒度」选择（整体覆盖 / 合并追加 两个 chip + 实时提示语）；diff 预览按所选粒度即时重算；apply 请求携带 mode。
10. i18n：`backfill.modeLabel` / `backfill.modeOverwrite` / `backfill.modeMerge` / `backfill.modeOverwriteHint` / `backfill.modeMergeHint`（zh/en）；`backfill.diffHint` 文案改为粒度中立表述。

## 三、影响面与备注

- **默认行为零变化**：不带 mode 的请求与 186 号完全一致（专门测试防护）。
- merge 模式的头部行仍由当前草稿渲染（来源/抽取时间刷新为本次抽取值）——既有条目内容不受影响；条目 id 不持久化（文件无 id 概念），去重键为 (category, title)。
- 产品决策若最终选定「逐项自选」，可在本模式基础上把粒度选择下沉到条目级（UI 已有勾选框架）。
