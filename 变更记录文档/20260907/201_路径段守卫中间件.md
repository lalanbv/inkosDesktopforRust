## 一、缺口分析（安全性复查，聚焦 189–200 增量面）

复查范围：最近 12 个批次（189–200）新增的 HTTP 端点（timeline-auto-beats、series-backfill extract/apply merge、doctor bookIssues）与文件写入/删除面（原子写 temp 文件、runtime 工件 prune）。

### 逐面结论

| 面 | 结论 |
|---|---|
| series-backfill 文件名 | `name` 来自 `read_dir` 枚举，非请求体——安全 |
| story 真相文件读/写 | `resolve_truth_file_path` 白名单守卫已有——安全 |
| 原子写 temp 文件 | 同目录 temp+pid+seq+rename，无外部输入参与路径——安全 |
| runtime prune | 清理路径由后缀+章号构造，章号来自内部索引——安全 |
| **bookId / projectId 路径段** | **缺口：Rust 端 HTTP 入口无统一校验** |

### 缺口详情

- **威胁**：axum `Path<String>` 提取时对路径段做 percent-decode，`..%2F..` 注入 `:id` 后经 `root.join("books").join(book_id)` 即越出项目根（读/写项目根之外任意文件）。
- **现状不对称**：Node studio 侧早有统一中间件（`app.use("/api/v1/books/:id"*)` + `isSafeBookId` → 400 INVALID_BOOK_ID）；Rust 端守卫函数 `utils::is_safe_book_id` 完备（golden 对齐 TS）但仅**点状**应用于部分路由（books_state 4 处、translation 3 处、interactive_film 2 处），books 主路由面（书详情/章节/write-next/series-backfill/export）与 projects 面无校验。
- **暴露评估**：引擎仅绑 127.0.0.1 + 回环 Origin 守卫（170/173 号）已挡浏览器面；但守卫可 env 关闭、且本机进程直连（无 Origin 放行形态）时路径穿越直达文件系统——回环守卫管**网络面**，文件面缺纵深。

## 二、实施

### Rust（engine-rs/src/server/segment_guard.rs 新建）

- `guarded_segment(path)`：提取 `/api/v1/{books|projects}/{seg}` 的原始（未解码）段。
- `guard` 中间件（`from_fn` 无状态）：percent-decode（与 axum Path 提取同用 percent-encoding crate，解码值一致）→ `is_safe_book_id`；decode 失败（非法 UTF-8）同样 400。
- 保留段 `create`（`/api/v1/books/create` 是创建端点而非 id）；无段（列表）/非两命名空间放行。
- 错误码对齐既有契约：books=`INVALID_BOOK_ID`（对齐 Node 中间件）/ projects=`INVALID_ID`（对齐双端 story-graph 端点既有码——初版用 INVALID_PROJECT_ID 曾红一个既有测试，勘误后回归既有契约）；消息中原始值经 serde_json 转义防注入。
- 挂载：`router_with_runtime` 末尾 `.layer(from_fn(guard))`——单点覆盖全部已注册路由；handler 内既有 `is_safe_book_id` 点状校验保留（非 HTTP 入口的内部调用仍受保护），构成纵深。

### Node（packages/studio/src/api/server.ts）

- 补 `/api/v1/projects/:id` 与 `/api/v1/projects/:id/*` 两个中间件（对齐既有 books 中间件形态，错误码 INVALID_ID）——projects 段同样以 id 拼 interactive-films/翻译项目路径。

### 测试

- Rust `segment_guard.rs` 内嵌 3 用例：percent-encoded 穿越/空格/非法 UTF-8 双命名空间 400、合法 id（含中文编码形态）/列表/create 保留段/health 放行、`guarded_segment` 提取边界。
- Node `server.test.ts` 加 1 用例：`/api/v1/projects/..%2Fetc%2Fpasswd` → 400 INVALID_ID。
- 既有 story-graph 穿越 400 测试（期望 INVALID_ID）不改即过——中间件只是把拦截层提前，响应契约不变。

## 四、有意排除项与遗留

- `:num/:chapter/:versionId` 段未纳入守卫：数字段 parse 失败自然 4xx、versionId 由服务端生成——风险面闭合，不扩。
- SSE `/api/v1/events/:sessionId`：sessionId 为内存态键不拼文件路径，不扩。
- handler 内点状校验与中间件语义一致（同一 `is_safe_book_id`），无双检成本问题（中间件先 400 短路）。
