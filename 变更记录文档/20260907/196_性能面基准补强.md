## 一、缺口分析结论

推送核验：origin/develop 仍停在 173 号（37958463），本地领先 23 提交；两项默认值未见答复，维持现状。

本轮聚焦**性能面**：177 号 bench 门禁建成后覆盖 2 组基准（sensitive_words + sse_broadcast），但 **write-next 每章必经的非 LLM 纯 CPU 路径**无基准覆盖——长书（数百章）场景下这些路径的规模敏感性无从守护。

选型（每章调用频度 × 规模变量）：
1. **标题去重**（`resolve_duplicate_title`）：每章**两次**调用（writer 输出 + 持久化装配），遍历既有标题数组——长书 200 章为规模锚点；
2. **段落形态扫描**（`detect_paragraph_shape_warnings`）：落盘后每章一次，正文 3000 字；
3. **章节索引反序列化**（`Vec<ChapterMeta>` JSON parse）：`load_chapter_index` 每章至少两次，长书 index 数百条。

有意排除：`analyze_long_span_fatigue`（async fs 读，criterion 需要 async harness，量级受 IO 主导，基准意义弱）；`build_length_spec/warnings`（常数时间）。
