## 一、范围与设计

对标 Sudowrite「系列书从既有正文回填设定」，交互按分解文档推荐默认 **「预览 + 逐项勾选」（用户不确认则零写入）**：

- **抽取**：`POST /api/v1/books/:id/series-backfill/extract`（body `{sourceBookId}`）——读源书 canon（story_bible.md / outline/story_frame.md / roles 主要+次要角色，单文件截断 6k 字），LLM 摘要为结构化 items（category 限 worldview/character/plot/style，6-12 条），落盘目标书 `story/series_backfill_draft.json` 并返回。**同步长请求 + 草稿落盘即检查点**——单次 LLM 调用引入异步任务架构收益不足，草稿持久化天然可恢复（决策理由登记）。
- **应用**：`POST .../apply`（body `{itemIds?}`，缺省全量）——勾选子集渲染为 `story/series_backfill.md`（**独立文件，不改写任何既有真相文件**，用户可自行合并）；无草稿 400、空勾选 400。
- **宽松解析**：LLM 输出经「首个 `{` 到末个 `}`」截取再解析（容忍 ```json 围栏与前后缀说明）；空 items / 不可解析 → 可读错误。
- **双端实现**：TS 侧同款双端点（buildPipelineConfig client + chatCompletion，严格对齐 inspiration 端点模式）——绞杀者双端同水位。
- **UI**：ImportManager 新「系列书回填」tab（SeriesBackfillPanel：源/目标下拉 → 抽取（loading 态）→ 按 category 分组预览 + 全选/单选勾选 → 写入所选，成功提示写入条数）；Dashboard 系列分组组头加「回填设定」入口；命令面板加导航命令。

## 三、过程记录

1. **`#[serde(rename_all)]` 只作用于结构体字段**——ApplyBody 的 `itemIds` 需要 camelCase rename 才能收下 JS 载荷；缺失时反序列化为 None（= 全量语义），静默把「勾选 1 条」变成「全量写入」。幸好「预览勾选」测试断言了排除语义——**带副作用的默认值（None=全量）必须有显式的排除性测试**。
2. 新端点双注册（生产 mod.rs + 测试内部 router）延续 181 号教训；extract 的 LLM 前校验分支（400 们）不依赖 LLM，集成测试可覆盖。
3. TS 侧 `chatCompletion` 返回 `LLMResponse` 对象（`.content` 取文本），与 Rust `outcome.content` 对齐；`c.req.json().catch(() => ({}))` 的 catch 形态会让联合类型丢失字段——catch 分支也要返回同形对象（`{ itemIds: undefined }`）。
