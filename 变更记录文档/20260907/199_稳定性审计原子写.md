## 一、审计结论（稳定性专项）

1. **多文件事务已有**：章节 + 真相文件落盘走 `commitAtomicFileSet`（116 号，TS/Rust 双端）——写中途崩溃要么全落、要么全不动。
2. **单文件配置面全部 `fs::write` 直写**——进程在写入中途被杀/崩溃 → 目标文件截断。后果分级：
   - **book.json 截断 = 整本书不可加载**（最严重，且 load 无自愈）；
   - **timeline.json 截断 = GET 按「无时间线」静默吞掉**（181 号语义，用户可感数据丢失）；
   - **chapters/index.json 截断** = 重建自愈，但丢 reviewNote/审计元数据（195 号分析已确认自愈面）；
   - series_backfill_draft.json / series_backfill.md = 检查点文件，损坏可重新抽取，但仍是用户可感数据丢失。
3. 其余直写面（story 真相 markdown、快照、radar store、轨迹日志）有快照/回放/自愈机制或非结构化，**有意不动**（避免无谓扩大改动面）。

### 引擎（engine-rs）

1. **`utils/atomic_file_set.rs`** 新增 `write_file_atomic(path, content)`：同目录唯一临时文件（`.名.tmp-{pid}-{seq}`，AtomicU64 序号防并发撞名）→ `rename` 就位（同文件系统原子）；rename 失败清理临时文件。**+2 单测**（覆盖替换且无孤儿临时文件 / 父目录缺失失败路径无残留）。
2. 替换 7 处直写：`save_book_config`（book.json）、`save_chapter_index_at`（index.json）、`put_review_mode` / `put_timeline_auto_beats`（book.json）、`put_timeline`（timeline.json）、backfill `extract`（draft）/`apply`（md）。

### Node 回退端（core + studio server）

4. **`studio/api/server.ts`**：`writeFileAtomic` helper——替换 chapter-review-mode PUT（book.json）、timeline-auto-beats PUT（book.json）、timeline PUT、backfill draft、backfill apply 共 5 处。
