# 188 · 用户体验修复：空草稿自动重试与友好文案 + 停止操作的中性呈现

- 日期：2026-09-07
- 模块：engine-rs（pipeline/write_next.rs、server/write_next_route.rs）、packages/studio（pages/BookDetail.tsx、hooks/use-i18n.ts、BookTimeline.test.tsx 断言适配）
- 类型：fix（用户报告的两类真实体验问题）
- 关联：175/176 号（停止能力）、182 号（验证时同类错误首次观察）

## 一、问题与修复

### 问题 1：`review cycle failed: chapter content check failed at draft generation: chapter content is empty`

**根因**：LLM 服务偶发返回空正文/纯空白（服务抖动、中转异常、只回 reasoning 不回 content）——管线在 review cycle 的空内容检查点直接报晦涩错误，无重试、无用户指引。

**修复**：
1. **writer 空正文自动重试一次**（write_next.rs）：`write_chapter` 输出 trim 后为空即重试一次（LLM 瞬时抖动大概率恢复）；仍空则由 review cycle 检查兜底报错。重试对 auto/manual 两种审查模式同效。
2. **错误文案加用户指引**：空内容错误追加「（模型未返回有效正文，请检查模型服务是否正常或更换模型后重试）」。

### 问题 2：`Operation aborted: the user requested to stop this task.` 被当失败呈现

**根因**：175 号停止能力的快照/广播沿用 error 文案，UI 以红色失败横幅呈现——用户主动停止却被报「失败」。

**修复**：
1. **路由层语义区分**（write_next_route.rs）：错误消息含 `Operation aborted` → 快照与广播文案改中性「写作已按您的要求停止。」（不再经 `write chapter failed:` 包装）。
2. **UI 中性呈现**（BookDetail 横幅）：aborted 类 lastError 用次要色（非 destructive 红）+ 文案「写作已按您的要求停止。」；其他错误维持红色失败样式。

## 三、过程记录

1. 复现「空正文」需区分 LLM 客户端层与管线层的两道防线：纯空流式响应被客户端「empty response from stream」前置拦截（到不了管线）；**纯空白字符**（全角空格等）可通过客户端、在管线净化后变空——重试与文案正是为后者设计。
2. aborted 的识别沿用消息文本匹配（`contains "Operation aborted"`）而非类型传递——runner 签名返回 String 的既有约束下最小改动；若未来 aborted 语义复杂化（如区分用户停止/系统停止），再考虑 runner 返回结构化错误。
