## 一、范围与交互设计

- **兜底单线（无 timeline.json）只读**：格点击仍是「去阅读」；页头出现「编辑时间线」按钮——点击经 `initializeTimelineFromChapters` 初始化（每章一个 cell）并 PUT，进入可编辑多线态。
- **可编辑态（timeline 存在）**：
  - 格点击弹 `TimelineEditDialog`（受控组件：节拍标题/备注输入 + 打开章节 + 保存/取消，保存中禁用）；
  - 该线该章无节拍的空位渲染虚线占位格（「添加节拍」），点击 = 新建 cell——添加节拍与编辑共用弹窗；
  - 「+ 添加情节线」内联表单（名称输入 → 追加空线）。
- **保存链路**：编辑逻辑全部经纯函数层 `timeline-edit.ts`（`buildTimelineAfterCellEdit` / `initializeTimelineFromChapters` / `buildTimelineAfterAddPlotline`）生成下一个文档 → 乐观渲染 → `PUT /api/v1/books/:id/timeline` → 成功 refetch 对齐服务端；失败回滚（放弃本地 doc 回服务端真值）+ 错误提示条。
- **编辑语义**：patch 字段留空即清除（空 cell 仅剩 chapter 合法，schema 允许占位）；未出现字段保留原值。

## 三、过程教训

1. **双源异步加载的渲染竞态**：book 与 timeline 两个 useApi 独立加载——timeline 未到时组件按兜底渲染可点击格，快速点击会误跳章节阅读器。修复：`!timelineLoading` 进网格就绪判定（两源齐再出格）。异步双源页面的「过渡态可交互性」要在设计期排查。
2. **vi.mock 工厂对象的立即求值陷阱**：工厂里 `putApi: putApiMock` 是属性值求值（vi.mock 提升 → TDZ 报错），而 `useApi: (path) => useApiMock(path)` 是闭包延迟所以同类写法无恙——同文件两种形态并存时极易踩中，规范解法 `vi.hoisted`。
3. **占位格是编辑体验的一半**：C4-a/c 两轮都把「空位」当背景处理（181 号甚至 filter 掉空线），到加线场景才发现「空线/空位不可见 = 无法添加节拍」。网格类 UI 的空态占位是一等公民，不是背景裁剪。
