## ① 取证

- 回收站现状（1679 端点 + 1683 界面）只进不出，除了手动清空；保留期三个未决面：多少天 / 配置项 / 清空前提示。
- **平铺条目没有删除时刻**：`chapters/.trash/` 散文件来自章删除与结构合并（`chapter-delete.ts` / `chapter-structure.ts`），文件 mtime 是内容时刻——今天驳回一章，正文可能是四十天前写的；拿 mtime 判保留期会让「刚进回收站的内容」下次启动就被清掉。不可接受，直接定死了设计边界。
- **读端点零写**（1682 定线）→ 自动清空不能挂 GET 列表；触发点只能是装配点：Node `startStudioServer`（`recoverAtomicFileSets` 之后）+ 产品引擎 bin `main`（bind 之前）。
- **strict 根教训**（709/1429/1602 族）：Rust 写进 inkos.json 的新键，TS zod strict 根不认 = Node 回退腿对碰过的项目 boot 即崩 → 新键必须双端登记。
- 配置端点模板 = writing-goal（R51/1654）；写入拒绝面由 config-write-parity.json 数据驱动（两腿 pins 13 行 / 87 格）。
- `spawn_rust_engine` 是**进程内装配**（不跑 bin main）——对跑要咬「装配点真的扫了」必须起真 bin（`spawn_engine_bin`，RAII 守卫 + 就绪等待）。

## ② 定线

- **键位**：inkos.json 根段 `trash.retentionDays`（正整数天；超 36500 封顶=100 年，cutoff 计算两端都有界；非法值缺省 30）。TS zod `trash: z.object({retentionDays: 正整数.optional()}).optional()`；Rust `ProjectConfig.trash: Option<TrashConfig>`（`skip_serializing_if` → 键面夹具与键面 parity 不动）。
- **范围**：只有「有删除时刻记录」的条目参与保留期——书级条目 `{id}--{ts}` 与回滚批次 `rollback-{ts}-{target}`（时刻都在名字里）；**平铺条目永不自动清**（备案：将来若要参与，须在入站时写删除时刻标记文件，本轮不做）。批次过期整批 rm；认不出的形态本就不进列表也就不清（与「清空只删列出来的」同一纪律）。
- **判定式**（两腿同一条，向量表两端同读）：`compact(trashedAt) ≤ compactTimestamp(now − days×86400000)`——回收时刻本来就是秒粒度，与毫秒比较式精确等价，且免去 Rust 侧 ISO 解析；恰等于 cutoff = 过期（到点就走）；now 减法下限 0 两腿同式。
- **各腿只清自己列得出来的书**（TS `listWorkManifests→bookDir`；产品引擎 `StateManager::list_books→book_dir`——另一棵树的章级回收站由另一腿清，对跑断言取并集）。清不掉逐条跳过，清扫永不阻塞启动。
- **端点**：GET `/api/v1/project/trash-retention` 读面降级（缺失/损坏 → 30，配置契约注释同款——清扫绝不因配置缺失/损坏而拒跑）；PUT 是 /project 族写入点：非法值平铺 500 两腿同文 `retentionDays must be an integer between 1 and 36500`（只认 JSON 数字，不 Number() 强转，与 `Value::as_u64` 同式）、missing/corrupt → INTERNAL_ERROR 信封、根非对象 → PROJECT_CONFIG_INVALID、合法值写 `trash.retentionDays`（保留段内其余键）。两腿同契约进对照表。
- **清空前提示** = 界面：两面板描述行加「保留 N 天，到期自动清空」（章级另注平铺不参与）；条目/批次头倒计时徽标「剩 N 天 / 已到期」（≤7 天或已到期红色档）；平铺条目永无徽标。保留天数 GET 失败 → 退回既有描述、无徽标。
