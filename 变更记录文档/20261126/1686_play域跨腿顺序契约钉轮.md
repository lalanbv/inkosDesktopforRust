# 1686 号：play 域跨腿顺序契约钉（1684 立案取证撤案 + 对跑扩断言）

日期：2026-11-26。基线：61d5c8d2（docs(1684) 追记之后）。主树直开（无并行会话在途）。

## ① 取证：1684 立案不成立，撤案

1684 号立案「play 实体/边 Rust `sort_by_key(id_of)` vs **Node 读取面无显式排序**——1675 投影对齐只覆盖键面」。本轮全量取证两腿读面：

- **TS**：`createPlayDB` 只有 sqlite 后端（`PlayDB`），`snapshot()` 四集合全部 SQL `ORDER BY`（entities/edges/stateSlots `ORDER BY id`、events `ORDER BY turn, id`；sqlite TEXT 比较默认 BINARY = 字节序 = 码点序）；文件图谱只在**全新库首开**时经 `readFileGraph` 按列投影导入（1675），之后读序由 SQL 决定。
- **产品引擎**：`play_graph_snapshot` 双后端——sqlite `ORDER BY` 同款；文件后端内存排序（play.rs `snapshot_from_file` sort_by_key、play_graph.rs `snapshot()` HashMap+sort）。
- **结论**：两腿读面早已同序（码点序 + (turn,id)）。1684 表述只看了 Rust 侧就下了「Node 无显式排序」的判断——**未取证 Node 侧**，正是 [[merge-loss-endpoint-without-writer]] 记忆里「定性必须附实跑证据」警告的形状。立案撤，改为**把这条从未被钉住的跨腿顺序升为契约钉**。

**既有对跑的空档**：三个互动叙事对跑（1673 Node 建 / 1675 引擎建 / storage_roots 两树对账）对图谱只断言**数量**（shape 元组），从未断言**顺序**——顺序漂移（某腿丢了显式排序）不会被任何门禁咬住。

## ② 契约钉：对跑扩第 ⑤ 步

`interactive_world_engine_created_world_is_shared_duel`（1675，共享 sqlite 库——迁移后两腿读同一 play.db，这正是用户可见的跨腿面）末尾加一步：经引擎真实写入面（`open_play_graph_db` 的 `record_event`/`upsert_entity`/`upsert_edge`/`upsert_state_slot`）**乱序到达**四类记录——事件 z-5(t5) 先于 a-4(t4)、实体 😀门/B-锚/a-灯 混插、边 b-链、槽 B-槽/！槽——然后两腿 GET 逐一断言**精确 id 序**：

- entities `["B-锚","a-灯","engine-gate","engine-hero","late-hero","node-hero","😀门"]`（码点序：ASCII 大小写 < 小写 ASCII < 高位 BMP 全角 < 增补平面 emoji——1684 的边界向量继续用）
- edges `["b-链","rel-gate"]`、stateSlots `["B-槽","slot-mood","！槽"]`（码点序）
- events `["e1","a-4","z-5"]`（(turn, id) 序——到达序是 [z-5, a-4]，丢排序就退回到达序）

夹具两处踩坑（都是 TS schema 严于 Rust 校验器）：槽 `value` 必须是原始值（对象 → TS parse 炸成 500 INTERNAL_ERROR，引擎侧照单全收）；实体 `type` 是枚举（`prop` 不在列，换 `item`）——「样本走生产写入面」的对子「读侧 schema 以 TS strict 为准」，引擎校验器宽松≠两腿都收。

## ③ 变异验证（4 个，全部咬红后还原；净还原单独验证绿）

1. TS `snapshot()` entities 摘 `ORDER BY id` → 红（退回 rowid 到达序）。
2. Rust `snapshot_from_sqlite` entities 摘 `ORDER BY id` → 红。
3. TS events `ORDER BY turn, id` 改 `ORDER BY id` → 红（[a-4,e1,z-5] ≠ [e1,a-4,z-5]）。
4. Rust events 同款改法 → 红。

教训：变异 3 还原后没重建 core/dist 就做变异 4——dist 仍是变异 3 内容，变异 4 的红**混杂**了两个变异；重演「净还原」（还原源+重建 dist+对跑绿+`git diff` 只剩本轮文件）才算收口。TS 侧变异要进对跑必须先重建 core/dist（tsx 跑 server.ts 但 core 走 dist——1684 刚记过的同一条）。

**未钉面（定性记录）**：Rust 文件后端排序（play.rs `snapshot_from_file`/play_graph.rs `snapshot`）不经共享库对跑——它只服务迁移前的引擎独读（单腿面，无跨腿比对）；排序代码在位（事件按 (turn,id)、其余按 id）已逐一核对。TS 侧文件导入路径的到达序=文件键序（serde_json BTreeMap 序列化天然有序），实体序因此在该路径上「碰巧」同序——真正咬住 TS 实体排序的是 sqlite 原生路径的乱序到达（本对跑第 ⑤ 步）。
