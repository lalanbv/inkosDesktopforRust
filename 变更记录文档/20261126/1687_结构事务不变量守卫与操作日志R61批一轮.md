## ② 纯函数（双端逐字镜像，golden 锁）

- `contentFingerprint`：章内容 UTF-8 sha256 前 16 hex（chapterSetRevision 同族；只在结构操作时计算）。golden 真哈希 5 向量锁算法。
- `structureInvariant(op, before, after)`：清单级判定，违反项逐条点名（章号 + before 文件名 + 前后指纹）。语义按施工图：**reorder = 号集合相等 + 指纹多重集相等**（内容只换位不改写——首版实现误写成按号配对保指纹，被 reorder-passes 向量当场咬出，施工图原句即多重集）；split 被拆号（at）允许变、新号 at+1 出现、其余 +1 移位保指纹；merge 被并号（removed）消失、keep 号（removed-1）允许变、其余 -1 移位保指纹。多指纹违反按指纹字典序输出（TS keys().sort() ≡ Rust BTreeMap——两腿消息逐字一致）。
- golden `packages/studio/src/__tests__/golden/structure-invariant-vectors.json`：指纹段（真值）+ 判定段 8 向量（每 op 各一过一违），TS readFileSync / Rust include_str! 同读。

## ③ 事务接线（两侧同构，提交点各异）

- **TS**：三事务单提交面（commitAtomicFileSet）——入口采**操作前全书指纹清单**，提交前从 planned writes + nextIndex 构造提交面清单 → `assertStructureInvariants`（含内容级：split 两片拼回原文）→ 抛在提交之前=**零落盘天然成立**；提交成功后 `appendStructureOpsLog`。
- **Rust**：staging 两相——入口同样采 before；提交钩子（save_chapter_index_at 之前）从**盘面**读 after 清单 + structure_invariant + 内容级 check（split 拼回）→ 违反/读盘失败走 `rollback_structure_tx`（新提炼 helper：删 written → 逆序撤 executed_renames → restore_from_staging——与既有 rename_fail 路径同一序列）；staging 目录已被提前回收的场景同样完备（executed_renames + written 覆盖全部已发生盘面）。
- 操作日志行 `{ts, opId, kind, before, after, undone:false}`：只有章号/文件名/指纹，无正文；读改写整文件 + 原子写（writing-log 同族）。**日志写失败不回滚已提交事务**（内容面已落盘），记 stderr——批二撤销遇缺日志走负路径拒绝并说明原因。
