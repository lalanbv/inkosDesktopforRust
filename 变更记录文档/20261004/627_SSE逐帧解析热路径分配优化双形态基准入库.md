# 627 号：SSE 逐帧解析热路径分配优化——类型化单次解析 + 消费式解构 + 零拷贝缓冲推进（-67%/-60%，双形态基准入库）

> 目标（用户）：自主持续开发 TS、Rust 客户端与 Rust 桌面程序——重构、优化、改进；最佳高性能 0GC 可实施执行；按真实需求开发。
> 本号 = 路线图清空后（R30–R46 全落地、唯 R36 会话树待产品需求）的**软件分析驱动工程质量增量**：扫描双端热路径分配形态，锁定引擎最热纯 CPU 路径（SSE 逐帧解析，每 token 数次）的四重分配浪费并消除，以新增双形态 criterion 基准给出可测量证据。

## ① 分析（热路径选型）

- 既有 12 基准覆盖：敏感词扫描/SSE 广播分发/write-next 三面/工具注册表；**SSE 逐帧解析未覆盖**——而它是 streaming_client 每 chunk 必经的最热纯 CPU 路径（每个 LLM token 数次调用）。
- 逐行审计 `engine-rs/src/llm/sse_parser.rs` 发现每帧四重分配：
  1. `parse_sse_block`：`serde_json::from_str::<Value>` 建整棵 Value DOM；
  2. `parse_openai_chunk`：`serde_json::from_value(value.clone())` **深拷贝整棵 DOM 后再二次解析**；
  3. 同函数对 content/reasoning/finish_reason 逐字段 `.clone()`/`.to_string()`；
  4. `SseStreamParser::push`：每帧 `pending.drain(..).collect::<String>()` 一次 block String 分配。

## ② 实施（语义零变更）

- **类型化单次解析**：`from_str::<OpenAiChunk>(payload)` 直达目标类型——消 Value DOM、消深拷贝、消二次解析；畸形/形态不符载荷 parse 失败即跳过，与旧 `unwrap_or(空 chunk)` 逐例等价（非法 JSON/非对象 `[1,2,3]`/`"ok"`/`42`/字段类型不符 `{"choices":5}`、usage 类型错——新测试全锁死）。
- **消费式解构**：`parse_openai_chunk(chunk: OpenAiChunk)` 直接 move 出 content/reasoning/finish_reason 事件载荷，免逐字段 clone（分配只发生在 serde 解析一次）。
- **零拷贝缓冲推进**：`push` 先在借用切片 `&self.pending[..end]` 上解析（事件持有 owned String，借用即止）再 `drain`——免每帧 block String collect。
- 11 既有单测全部零改动通过（事件输出逐字节等价）；`push_chunked` 跨块缓冲/CRLF/comment 行语义不动。

## ⑥ 教训

1. **「解析两次 + DOM 深拷贝」是 serde 生态最典型的隐性分配热点**：`from_value(value.clone())` 形态把一次解析的代价放大三倍（DOM 构建+克隆+二次转换）；类型化 `from_str` 直达是零风险等价替换——前提是边界语义（畸形载荷跳过）用测试锁死。
2. **基准先行是优化增量的诚实性锚**：先在旧码上跑出 before 再动手，criterion 的 run-to-run change 只对上一次运行负责——跨提交对比必须自己留档 before 数。
3. **12 旧基准连续四轮全改善**（-3.4%~-17.8%）无漂移趋势——机器静默期采样可信度高，基线登记时机安全。
