## 二、真缺陷：analysis `arcs` 响应形状偏差（253 号移植遗漏）

- TS `analyzeEmotionalArcs`（emotion.ts L35）返回**包装对象** `{arcs: [...], truncated: boolean}`；
- Rust 函数返回 `(Vec<EmotionalArc>, bool)` 元组本身正确，但**路由层**解构后裸序列化 `"arcs": arcs`，丢掉包装与 `truncated`；
- UI `AnalysisPanel → EmotionArcChart` 读 `arcs.arcs.slice(0, …)` → Rust 端恒崩、TS 端正常——**默认引擎影游图谱页白屏级缺陷**，且旧 e2e 断言把错误形状固化（`parsed["arcs"].as_array()`），机械对照因组件形状理解偏差漏过（呼应 222 号「grep 逐行对照漏报」教训：形状类契约必须对 UI 消费端验证）。

**修复**：路由层按 TS 逐字包装 `json!({"arcs": {"arcs": arcs, "truncated": truncated}, …})`；e2e 断言更新为 `parsed["arcs"]["arcs"]` + `["truncated"]` 断言。
