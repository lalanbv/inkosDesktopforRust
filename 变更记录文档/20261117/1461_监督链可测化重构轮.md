## 实施

①**`SupervisorCore` 决策状态机**（supervisor.rs）：每轮一步的纯逻辑
（`step(alive, &mut policy) -> SupervisionAction`：Continue/Respawn{cooldown,
attempt}/Halt）；main.rs watcher 降为纯接线（sleep/探测/通知/重跑）。

②**状态分置定案（编写中抓出的真实设计缺陷）**：初版 core 内嵌
RespawnPolicy——若 main.rs 换代时新建 core，**重启计数随换代归零=上限
永不触发，崩溃风暴防护失效**。修正：core 只持代内 failures（判死→换代
→新 core 自然归零）；policy 由调用方跨代持久持有（main.rs `RespawnState`
托管）。类型文档显式锁此语义。

③**测试四面**（全判定路径覆盖）：
- 瞬态容忍：阈值-1 次失败恢复全程 Continue，代内计数清零语义
- 跨代接力到 Halt：三代模拟（gen0 Respawn(attempt=1)→gen1 共享 policy
  Respawn(attempt=2)→gen2 Halt）——同时锁「新代 failures 归零须重新满
  阈值」与「policy 计数跨代累计」两个分置语义
- probe_once 判活：真 TcpListener 2xx 微服务=活 + 无服务 ephemeral 口=死
  （HTTP 客户端语义真路径，非 mock）

④**判死时机语义钉定**：第 [`RESUPERVISE_FAILURE_THRESHOLD`]**次**连续
失败当轮即判死（failures==阈值，非 N+1 轮）——测试首轮边界写错
（`0..THRESHOLD` 循环内 Continue 断言）暴露的语义歧义，随测试修正在
文档与测试注释双重钉定（与 1460 watcher 原语义一致）。
