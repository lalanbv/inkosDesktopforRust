# 813 号：章节文件识别单一真源——双形态源头预防（writer 清理）+ 重建去重 + TS 计数口径对齐

日期：2026-11-02。前置：807 号登记（rust 重建不按章号去重，同章双形态产两条目；TS 三站严格口径 getPersistedChapterCount / saveChapterIndex 空索引守卫 / durable 扫描与 rust 宽容口径并存，计数 TS 1 vs rust 2 待定）。

## 一、先找源头：双形态怎么产生

双侧 writer 落章时清理「同章旧文件」用 `starts_with("NNNN_")`（严格下划线前缀）——重写一个 legacy 章（`0001-旧.md`）时写出 `0001_新.md`，旧文件因前缀不匹配**幸存** → 同章双形态。此后若索引丢失/损坏，宽容重建（双侧均无去重）对每个匹配文件各产一行 → 两条同号条目。807 号原则「读侧认什么为章，删侧与写侧必须认同一集合」在 writer 清理这一站漏网。

## 二、修复（双侧同口径）

**源头预防**：writer 同章旧文件按**前导章号**识别（正典 `NNNN_` / legacy `NNNN-` / 裸 `NNNN.md` 同集）：rust `crate::state::manager::leading_number(file) == Some(chapter_number)`；TS `chapterFileNumber(file) === output.chapterNumber`。数值比较同时修正了前缀匹配的隐患（`0001_` 前缀不会误配 `00011_`，但换成章号比较后语义更明确）。

**恢复兜底**：索引重建按章号去重——`select_chapter_files` / `selectChapterFiles`：同一章号多文件时**正典 `NNNN_` 优先，其次文件名序**，章号 0 跳过，按章号升序。rust 重建改为先收集文件名再遍历选中集（mtime 改走 `tokio::fs::metadata`）；TS 同步。

**TS 计数口径对齐**：新建 `packages/core/src/utils/chapter-files.ts` 作 TS 侧单一真源（`chapterFileNumber` / `isCanonicalChapterFile` / `selectChapterFiles`），`getPersistedChapterCount` 与 `saveChapterIndex` 空索引守卫改用之——与 rust 807 号 `get_persisted_chapter_count` 宽容口径对齐（legacy 书不再计 0）。**durable 扫描 `^\d+_` 保持上游严格设计**（698/700 号播种注释明示「TS 扫描不认连字符」，属 2.0 进度链语义，不在本仓单方改动范围）——定性为保留并登记。

rust `save_chapter_index_at` 的空索引处理是「重建兜底」（非拒绝）设计，与 TS「拒绝守卫」殊途同归（空索引 + 章文件在场 → 以文件为准），不改。

## 六、教训

1. **找源头再做兜底**：807 修了删侧、813 发现写侧（writer 清理）仍是旧口径——双形态的生产者是 writer，不先堵它，重建去重只是在擦地。
2. **单一真源文件比"逐站改正则"更稳**：TS 新建 `chapter-files.ts` 后，四个消费站只能用同一判定，后续再加站点不会再漂移；rust 以 `leading_number` 一处定义达到同效。
3. 上游设计明示的严格口径（durable 扫描）不在对齐范围——「对齐」的边界是本仓拥有的语义，不是上游拥有的。
