# 806 号：检索终态口径定案——可检索 vs 回收压力两谓词分离（deferred 仍是正典）

日期：2026-11-02。前置：805 号登记（rust `recycle_terminal_re` 排 deferred/paused/hold 而 TS searchableHooks 只排 resolved+superseded；rust 行内注释「休眠种子仍可检索」与正则自相矛盾，待定口径）。

## 一、考古定性（同 804/805 方法论）

- rust `is_recycle_terminal_status`（memory_retrieval.rs）来自 e27428b4（08-14 移植 planner 数据供给层）——移植当时 TS `isRecycleTerminalStatus` 正则 `^(resolved|closed|done|已回收|已解决|deferred|paused|hold|延后|延期|搁置|暂缓)$` **逐字同款** → 忠实移植。
- TS harness v2（7aed0d82，08-30）删除该函数与 `computeRecyclableHooks`，searchableHooks 改为 `status !== "resolved" && status !== "superseded"`，注释：「Every unresolved hook remains searchable canon. The semantic selector decides relevance for the current task; status does not imply urgency.」
- 结论：**可检索集**的 deferred 排除是移植漂移（rust→TS 对齐）。

## 二、第一版修复被 golden 拦截——口径分裂的实证

初版把 deferred 组整体从 `recycle_terminal_re` 移出 → testgate 拦截 `tests/golden_leaf.rs compute_recyclable_hooks_matches_ts` 用例 `terminal-excluded`：输入 H01 `已解决` + H02 `paused`，期望回收压力集为空；改后 H02 进入 → 失败。

golden 编码的是正确产品语义：**显式延后的承诺没有回收压力**（≠ 逾期），但它**仍然存在、仍可被检索**。`compute_recyclable_hooks` 为 rust 独有 planner 回收面（TS v2 已无），其终态口径由 golden 锁定；而 searchable 集的口径由 TS v2 定义。两者此前共用一个谓词=口径混用——这才是 805 登记的「注释与正则自相矛盾」的真根因。

## 三、定案：两个口径两个谓词

| 谓词 | 终态集 | 消费者 | 依据 |
|---|---|---|---|
| `is_searchable_terminal_status` | resolved 组 + superseded 组 | `searchable_hooks`（FTS 文档集 + 入选候选） | TS v2 searchableHooks |
| `is_recycle_terminal_status` | 上述 + deferred/paused/hold 组 | `compute_recyclable_hooks`（回收压力） | golden `terminal-excluded` |

`select_relevant_hooks` 入选条件=被检索命中 **或** 活跃：deferred 钩子非活跃（`filter_active_hooks` 仍排 deferred），只有被查询命中才入选——正是「选择器决定相关性」。

## 四、测试

- 谓词级 `terminal_predicates_split_searchable_from_recycle_pressure`：三组（终态/活跃/延后）对两个谓词的交叉断言。
- 检索级 `retrieve_memory_selection_keeps_deferred_hooks_searchable`（tokio，md 路径）：H01 open / H02 deferred / H03 resolved（H02、H03 备注同文）+ goal 命中 → `hooks` 含 H02 不含 H03；`active_hooks == [H01]`；H02 不进 `recyclable_hooks`。
- **反向验证**：临时把 deferred 加回可检索终态 → 该测试失败（仅 H01 入选），还原后通过——测试有判别力，非凑巧通过。
- golden `compute_recyclable_hooks_matches_ts` 恢复通过（回收口径未动）。

## 七、教训

1. **golden 拦截是口径分裂的信号，不是要改 golden**：第一反应该是问「这两个消费者是不是本就两个口径」。rust 独有面（回收压力）的语义由 golden 锁定，TS 对偶面（可检索）的语义由上游定义——各自对齐各自的真源。
2. **「自相矛盾的注释」往往指向共用谓词的两个语义**：注释写的是其中一个消费者的意图，正则写的是另一个——拆谓词比改注释或改正则都对。
3. 同款考古三步（移植提交→`git show` 当时 TS→上游后改提交）第三次复用，定向零争议。
