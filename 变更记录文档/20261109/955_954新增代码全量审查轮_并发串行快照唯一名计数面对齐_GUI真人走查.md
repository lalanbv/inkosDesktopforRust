## 一、静态审查定型（P1-P6）

- **P1 同毫秒快照覆盖患**：双端快照名 `pre-restore-${Date.now()}.tar` /
  `pre-restore-{millis}.tar`，同一毫秒两次确认恢复时后写覆盖前一份（TS
  writeFile 覆盖 / Rust rename 覆盖）——回滚保险**静默丢失**（954 双端
  rollback 用例断言快照数=2，本机 fsync 慢才绿，实为潜伏 flaky）。修复=
  `allocateSnapshotName` / `allocate_snapshot_millis`：持锁自 now 起探测首
  个未占用毫秒名（任意类型占用均跳过——同名目录也会令 rename 失败；非
  ENOENT 错误直接上抛不空转），探测上限 1000 病态防护。时钟经注入缝
  （TS `vi.spyOn(Date,"now")` / Rust `run_import_with_clock(now: fn)`）固
  定毫秒确定性复现。
- **P2 并发恢复不设防**：确认段（覆盖面盘点→快照→写回）无锁——两次并发
  确认恢复在 await 点交错写回成混合态；Rust 同毫秒共写
  `.pre-restore-<ms>.tmp` 撕裂快照。修复=双端 per-root 恢复串行锁
  （TS `withRestoreLock` 尾 Promise 链排队+队空即删条目；Rust
  `restore_lock` OnceLock<Mutex<HashMap>>，spawn_blocking 线程内 std
  Mutex 阻塞合法，中毒 into_inner 恢复——锁内数据 () 无不变式可破）。
  **覆盖面盘点移入锁内**（锁外盘点与写回间他者恢复新建的文件会漏出快照
  =回滚面缺口）；预览只读不持锁。Rust 快照名在锁内取 `now()`——排队等
  锁的恢复不会以更早的请求时刻命名更晚的快照。
- **P3 名形态双端分叉**：954 版 TS `Number.isSafeInteger` vs Rust
  u64 parse——16-19 位名 TS 判「invalid snapshot name」/Rust 判「not
  found」且列举可见。**954 文档与提交消息中「超大数溢出双端同拒」系错
  误表述，此处勘误**。修复=规范形态纯串级判定（`0|[1-9]\d{0,15}`，1-16
  位无前导零；名与毫秒一一对应），不依赖任何数值语义；双端断言**同一
  golden 向量表** `packages/studio/src/__tests__/golden/
  backup-snapshot-name-vectors.json`（Rust include_str / TS readFile，
  atomic-write-vectors 同款先例；7 accept / 23 reject / 排序向量）。
  BackupPanel 时间展示同步收紧 `\d{1,16}`（越界毫秒→Invalid Date→回退
  原名展示）。
- **P4 列举排序错序**：954 版纯字典序在位数不同名上错序
  （`pre-restore-9.tar` 排在 13 位新快照之前）。修复=(长度,字典序) 即
  数值序（规范形态同前后缀），双端同算法 `compareSnapshotNames` /
  `compare_snapshot_names`。
- **P5 TS 腿恢复写非原子**：Rust 779（恢复写 `write_file_atomic_sync`）
  /782（快照 tmp+sync_all+rename）早已硬化，TS 腿 954 迁移时仍
  writeFile 直写（780 号普查面为 core 包，studio server 的恢复路径为
  954 新增面）。修复=快照落盘与恢复写回统一走 core `writeTextAtomic`
  （tmp+fsync+rename+重试，782/779 镜像）。
- **P6 回滚面≠列举面**：954 版 Rust `fs::read` / TS `readFile` 跟随符
  号链接——列举不可见的链接名可被直接回滚（举例：链接指向真快照即可
  绕过列举面操作其内容）。修复=回滚先 `symlink_metadata`/`lstat` 判常
  规文件（与列举同判据：DirEntry::metadata/lstat 均不跟随），非常规=
  not found。附带两处小项：Rust snapshots handler JoinError 由吞成 200
  空列表改为 500（panic 不得伪装成「无快照」，与同文件 import/rollback
  一致）；Rust 写回循环逐条目 `format!` 拼名比对改零分配
  `is_manifest_entry`（strip_prefix 链）。

## 二、真引擎活体反挖（P7，生产形态 env 8902+静态面）

真人流（种子真实感项目→export→改书→import 预览→并发 confirm→列举）
前三步全对，但**预览显示 `fileCount:6, newFiles:1` 而实际无新文件**、
确认 restored=5——**954 前计数面把 manifest 元数据计入**。深察定型：
- **计数面**：fileCount/newFiles 含 manifest → 预览总数比确认 restored
  多 1、「新增 1」永不兑现（用户看到的两个数字矛盾）。修复=计数面=数
  据条目（manifest 除外）=写回面，双端对齐；单测口径从「3/2（954 口
  径注释）」改为 2/1 并补「预览总数=restored」断言。
- **根目录同名 backup-manifest.json（用户自有文件）=快照不可回滚患**：
  954 版把它计入覆盖面（写回却跳过——永不覆盖但预览误报「将覆盖」），
  confirm 时以裸名入快照、与快照自身 manifest **同名并存**；回滚时
  manifest 查找先命中用户文件，generator 先验失败=**该快照永远 400 不
  可回滚**（tsx 探针实证：954 逻辑下 rollback preview=
  `unsupported backup generator/version`）。修复=manifest 条目不参与覆
  盖面与快照（与写回跳过一致）；用例锁「不入覆盖面不入快照、快照仍可
  回滚、用户文件原样保留」。
- **manifest 选取对齐**：954 版 TS 取「首个任一名条目」，Rust 前缀名优
  先裸名兜底——两名并存的包双端可能选中不同 manifest。修复=TS 同 Rust
  选取序。
- 活体终态：并发两 confirm 双 200 restored=5，**两份快照独立毫秒名**且
  内容分别=第二稿/原稿（谁先谁后可辨），现网回原稿，tmp 零残留；
  NEUTER 中和恰红：Rust 计数患 3 红（预览口径/根目录 manifest/快照
  fileCount），TS 计数患 2 红；tsx 双探针对照。
