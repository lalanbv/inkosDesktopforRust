## 3. loopback 实测结论

### 3.1 默认绑定行为（消解架构 §14.1 实测项）

T7 commit `cad9a04c` Step 1 实测：

```
$ nohup node packages/cli/dist/index.js studio > /tmp/inkos-sidecar.log 2>&1 &
$ curl -sI http://127.0.0.1:4567/ | head -1   # → HTTP/1.1 200 OK
$ curl -sI http://192.168.31.192:4567/ | head -1  # → HTTP/1.1 200 OK  ⚠️ LAN IP!
$ lsof -nP -iTCP:4567 -sTCP:LISTEN
→ node  12u  IPv6  TCP *:4567 (LISTEN)
```

**结论**：inkos Studio 经 `@hono/node-server` 默认监听 `*:4567`（dual-stack IPv6 socket 同时接 IPv4），同网段 `curl <LAN-IP>:4567` 返回 200。loopback 加固必要性成立。

### 3.2 M1 加固实现（占位 + 降级）

| 平台 | M1 实现 | 权限要求 | M1 行为（非特权用户） | 强制方案 | 目标里程碑 |
|------|--------|----------|----------------------|----------|------------|
| macOS | `pfctl -a inkosdesktop -f -`（anchor） | root | `lock()` 返回 `Err` → log 警告，sidecar 仍绑 `*:4567` | SMJob / launchd privileged_helper_tool | **M2** |
| Linux | `iptables -A INPUT ... ! -i lo -j DROP` | CAP_NET_ADMIN | 同上降级 | setuid / polkit / nftables | **M3** |
| Windows | `netsh advfirewall firewall add rule ...`（占位） | 管理员 | 同上降级 | **⚠️ WFP filter with loopback exempt**（netsh `block localport=` 会同时挡 127.0.0.1，破坏 SPA 加载——精度缺陷） | **M3** |

**M1 接受的风险**：非特权用户启动时 sidecar 仍监听 `0.0.0.0`，同网段可访问。架构 §8 / §14.1 已知风险，待 M2/M3 特权 helper 闭环。

**架构 §14.1「loopback 项」消解**：
- 默认行为实测确认 = `0.0.0.0` 暴露 ✅
- 加固机制设计就位（trait + 平台派发 + 占位实现）✅
- 运行时强制 = **pending M2/M3 特权 helper**（明确声明）

## 5. pnpm 版本注意（必须锁 pnpm 10）

**现象**：inkos 上游 `pnpm-lock.yaml` 由 pnpm 10 生成，记录了 `pnpm.overrides`。pnpm 11 的破坏性变更——**不再读取 `package.json` 的 `pnpm.overrides` 字段**，导致 `pnpm install --frozen-lockfile` 在 pnpm 11 下报：

```
[ERR_PNPM_LOCKFILE_CONFIG_MISMATCH] Cannot proceed with the frozen installation.
The current "overrides" configuration doesn't match the value found in the lockfile
```

`engines.pnpm: ">=9.0.0"` 不能拦截 pnpm 11（语义版本满足），但行为已不兼容。

**用户本机现状**：全局 pnpm `11.9.0` 不兼容；本次所有构建/冒烟用 `npx pnpm@10`（实跑 `pnpm 10.34.5`，秒过 frozen-lockfile，1012 包，7.6s）。

**处理建议（按优先级，均零修改 inkos 源码）**：
1. **corepack 锁版本（推荐）**：用户在仓库根 `corepack enable && corepack prepare pnpm@10.34.5 --activate`，本机永久锁 pnpm 10。
2. **降级全局 pnpm**：`npm i -g pnpm@10`。
3. ⚠️ **不要**改根 `package.json` 加 `"packageManager": "pnpm@10.34.5"`——违反 M1「零交叉」纪律（package.json 是 inkos 上游文件）；若上游主动加该字段则随之同步即可。

**写入项目文档**：见 `src-tauri/README.md`「环境要求」段（M1 运行说明的一部分）。

## 6. TOCTOU flaky 测试修复

### 6.1 现象（parked 来源）

`supervisor::tests::pick_free_port_returns_bindable_port` 在并行 `cargo test` 偶发失败（实测约 1/3）。T4 报告首次标记为「TOCTOU 由 spawn 兜底」；T6 / T7 报告再次确认，parked 至 T8 修复。

### 6.2 根因（TOCTOU = Time-of-Check / Time-of-Use）

原测试：
```rust
let p = pick_free_port(DEFAULT_STUDIO_PORT).expect("应找到空闲端口");
assert!(TcpListener::bind(("127.0.0.1", p)).is_ok());  // ⚠ racy
```

`pick_free_port` 内部 `bind` 成功后立即 `drop` 释放端口，返回端口号。到测试再 `bind` 同一端口时，存在窗口期——并发 `cargo test` 下另一测试的 `pick_free_port` 完全可能抢同一端口，使「再 bind 复核」偶发失败。

### 6.3 修复

**策略**：放宽断言为「返回 `Some(p)` 且 `p ∈ [start, start+1000)`」，**不再 re-bind**（re-bind 本就是 racy）。同步在 `pick_free_port` doc 注明其固有 TOCTOU 与调用方容忍策略（`main.rs` setup 中 `health_probe` 兜底已就位）。

**Diff 摘要**（`src-tauri/src/supervisor.rs`）：
```rust
// 改前
let p = pick_free_port(DEFAULT_STUDIO_PORT).expect("应找到空闲端口");
assert!(TcpListener::bind(("127.0.0.1", p)).is_ok());

// 改后
let start = DEFAULT_STUDIO_PORT;
let p = pick_free_port(start).expect("应找到空闲端口");
assert!(
    (start..start.saturating_add(1000)).contains(&p),
    "返回端口 {p} 应落在探测区间 [{start}, {})",
    start.saturating_add(1000)
);
```

`pick_free_port` 文档同步加 TOCTOU 段落，明确「探测瞬间可用，不保证后续仍可用；调用方容忍策略 = `main.rs` setup 中 `health_probe` 兜底」。

### 6.4 顺带修复：macos.rs doctest

`pf_anchor_rules` 的 doctest 断言串漏了 `quick` 关键字（实际规则含 `block in quick proto tcp ...`），原本被 `pick_free_port` 测试失败掩盖。本次同步修正：

```diff
-assert!(s.contains("block in proto tcp from !lo0 to any port = 4567"));
+assert!(s.contains("block in quick proto tcp from !lo0 to any port = 4567"));
```
