# 插件市场：发布工具（生产端签名 + 注册表条目生成）

> 日期：2026-08-07
> 范围：`src-tauri/src/bin/publish-plugin.rs`（新）
> 目标：补全市场「消费 + 生产」生态——发布方签 bundle + 生成 `RegistryEntry` TOML

## 背景

市场消费端完整（浏览/安装/更新/版本选择/离线缓存），但缺少**生产端**工具：发布方如何产出消费端能验签安装的签名 bundle + 注册表条目。本工具填补该缺口，复用既有 `sign-bundle.rs`（engine bundle 签名）的模式。

## 变更

`bin/publish-plugin.rs`：
- **`build_entry(bundle, manifest, signing_key, download_url, min_host_version)`**（可测核心）：`sha256` + Ed25519 签 bundle + 从 `PluginManifest` 构造 `RegistryEntry` + `validate`（id 白名单 / version semver / url https / sha256+signature 格式 / capability 语法）。
- **`run`**（CLI）：`publish-plugin <bundle.tar.gz> <plugin.toml> <private-key-hex> <download-url> [min-host-version]` → 读 bundle + 清单 + 解析私钥 → `build_entry` → 输出 `[[plugins]]` 条目 TOML（stdout）+ 对应公钥（hex）。
- 复用 `sig::sign`/`sha2`/`manifest::PluginManifest`/`registry::RegistryEntry`，不重造。CI 沙箱友好（只处理命令行参数，同 `sign-bundle`）。

## 设计

- **build 与 sign 分离**：发布方自行打包 tar.gz（须根级 `plugin.toml` + `.wasm`，匹配消费侧 `safe_extract_tar_gz` 约定），本工具只签名 + 生成条目。职责单一。
- **发布侧早校验**：`build_entry` 调 `RegistryEntry::validate`，发布时即暴露字段问题（非法 id / 非 https url / 坏 semver），而非到消费端才失败。
- **id 白名单一致**：`validate` 内的 `is_safe_plugin_id` 与消费侧 `parse_manifest` 共用——发布端产出的 id 必能被消费端接受。

## 端到端信任链

发布方私钥签 bundle → `RegistryEntry.signature`（hex）+ `sha256` → append 到 `registry.toml` →（注册表本身另签 `.sig`）→ 消费端 `cmd_fetch_plugin_registry` 验签注册表 → `cmd_install_from_registry` 下载 bundle → `verify_bundle`（**配置公钥**）→ `safe_extract_tar_gz` → `install_plugin`。发布私钥与消费配置公钥配对——闭环。

## 验证

- `cargo clippy --all-targets -D warnings`：clean
- `cargo test --bin publish-plugin`：**3 测试全过**——`build_entry_produces_verifiable_registry_entry`（产出条目字段合法 + 消费侧 `verify_bundle` 接受）、`build_entry_rejects_unsafe_id`（`../pwned` 拒）、`build_entry_rejects_non_https_url`（http 拒）

## 市场生态（完整）

- **消费端**：浏览（最新版，离线回退）→ 安装 → 检查更新 → 更新 → 版本选择（锁定/回滚）。
- **生产端**：`publish-plugin` 签 bundle + 生成注册表条目；`sign-bundle`（既有）签 engine bundle；注册表 `.sig` 经发布方私钥签。

全链路 Ed25519 双层验签 + 配置公钥信任锚 + id 白名单 + 下载限流 + tar-slip 防护 + 多版本 + 离线缓存。
