## 变更

从注册表安装插件——**插件市场特性弧端到端闭环**：

- **`plugin/registry.rs`**：
  - `safe_extract_tar_gz(archive, dest)`——解压 tar.gz 到目录，**防 tar-slip 路径逃逸**。
  - `is_safe_relative(path)`——深度折叠守卫：`Normal +1`/`ParentDir -1`，负值=逃逸；拒 `RootDir`/`Prefix`（绝对/跨盘）。每个条目 `unpack_in` 前调用。
  - 关闭权限位保留（`set_preserve_permissions(false)`，跨平台一致，防 setuid 等危险位）。
- **`commands/registry.rs`**：`cmd_install_from_registry(entry)`——双 State（`AppState` 取配置公钥 + `PluginState` 取 manager）：下载 tar.gz → `verify_bundle`（sha256+Ed25519，**配置公钥**）→ `safe_extract_tar_gz` 到临时目录 → 复用既有 `install_plugin`（解析 plugin.toml + 复制到 plugins_dir）。
- **`main.rs`**：注册命令。
- **`settings.html`**：市场条目加「安装」按钮 → `installFromRegistry(entry)` → 成功后刷新已装列表；i18n zh/en + a11y + 状态消息。

## 安全设计

### 信任链（端到端）
注册表验签（`cmd_fetch_plugin_registry`）→ entry 可信 → bundle 用**配置的 registry 公钥**验签 → 安全解压 → install。

**抗前端篡改**：即便前端被攻破传入伪造 `entry`，其 bundle 签名必须用**配置公钥**通过 `verify_bundle`——攻击者无私钥，无法构造可通过的包。信任锚始终是配置公钥，不信任前端传入的签名归属。

### tar-slip 双层防护
1. **创建侧**：Rust `tar` Builder 拒绝构造含 `..`/绝对路径的归档（"paths in archives must not have `..`"）。
2. **解压侧**：`is_safe_relative` 在每条目 `unpack_in` 前拦截（单测钉死）；防御其他工具产出的恶意归档 + 未来密钥泄露场景。

### 持锁守则
命令单次取 config 锁仅提取公钥/超时后释放，再做网络 I/O（同 `update_config` H1 修复）。`plugin_state.manager` 锁仅在 `install_plugin`（文件复制）期间持有，临时目录活到函数末尾（复制完成后才 drop）。
