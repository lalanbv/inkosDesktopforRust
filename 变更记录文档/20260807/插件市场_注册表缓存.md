# 插件市场：注册表缓存（离线韧性 + 网络效率）

> 日期：2026-08-07
> 范围：`src-tauri/src/config/paths.rs`、`src-tauri/src/commands/registry.rs`
> 目标：离线韧性（网络失败回退缓存）+ 避免每次浏览重拉已验签注册表（网络效率）

## 变更

- **`config/paths.rs`**：`registry_cache()` → `app_data/config/registry-cache.toml`。
- **`commands/registry.rs`**：
  - `registry_source_and_client` 现返回 `cache_path`（4 命令解构）。
  - `fetch_registry_index(url, pubkey, client, cache_path)`：网络成功 → `toml::to_string` 序列化**已验签**索引写缓存（best-effort，写失败仅 warn）；网络/验签/解析失败 → 回退读本地缓存 + `PluginRegistryIndex::parse`（离线韧性）。无缓存则报错。
  - `cmd_check_plugin_updates` 重构用 `fetch_registry_index`（修 slice 16 漏重构 + 获得缓存）。

## 信任链（不变）

- 缓存内容来自**上次已验签**的注册表索引（写入前已通过 `fetch_registry` 的 Ed25519 验签）。
- install/update **仍用配置公钥** `verify_bundle`——即便本地缓存被篡改（误导 browse 显示假条目），也无法安装恶意包（bundle 签名验不过配置公钥）。browse 误导是本地信任边界内的可接受取舍。
- 缓存回退语义：当前注册表无法获取/验签时，服务上次已知良好版本（离线/被篡改时的优雅降级）。

## 验证

- `cargo clippy --all-targets -D warnings`：clean
- `cargo test`：lib **380 passed / 0 failed**（+`registry_cache` 路径断言）+ 全集成 0 失败
- 命令级缓存逻辑（cache-on-success / fallback）由代码审查 + 既有 `fetch_registry`/`parse` 单测覆盖；I/O 层端到端属集成测试范畴

## 插件市场特性弧（完整）

浏览（最新版，离线可回退）→ 安装 → 检查更新 → 更新 → 版本选择（锁定/回滚）。全链路 Ed25519 验签 + bundle 校验 + 安全解压 + id 白名单 + 下载限流 + 多版本 + 离线缓存。
