# 插件市场：依赖解析（传递闭包 + 后序拓扑 + 环检测）

> 日期：2026-08-07
> 范围：`src-tauri/src/plugin/registry.rs`
> 目标：plugins 声明 `dependencies`（`HashMap<id, version_req>`）但安装时未解析——补齐依赖解析逻辑

## 变更

`plugin/registry.rs`：
- **`resolve_dependencies(entry, registry) -> Result<Vec<RegistryEntry>>`**：返回**后序拓扑**（依赖在前、entry 自身最后）的安装顺序。
  - **传递闭包**：递归解析每个依赖。
  - **环检测**：DFS 路径栈（`stack`），遇回到路径中的 id → `Err("插件依赖循环")`。
  - **version_req 匹配**：`find_matching` 用 `find_all_versions`（降序）取**最新满足** `semver::VersionReq` 的版本。
  - **幂等**：`installed` 集对钻石依赖去重（同一 id 只入序一次）。
- **`find_matching(registry, dep_id, req)`**：注册表中 `dep_id` 最新满足 req 的版本。

## 设计

- **后序 DFS**：依赖先于依赖者入序 → 调用方按序安装即可保证被依赖者先就位。
- **环检测用路径栈**（非全局 visited）：仅当前 DFS 路径上的回边才算循环（钻石依赖不是环）。
- **version_req**：复用 `semver::VersionReq`（`^1.0.0` 等），与 `RegistryEntry.dependencies` 的字符串约定一致。
- **纯函数**：`resolve_dependencies(entry, registry)` 无副作用，单测钉死行为。

## 验证

- `cargo clippy --all-targets -D warnings`：clean
- `cargo test`：registry 子模块 **30 测试全过**（+3：`test_resolve_dependencies_post_order_and_version_req`（x→y(^1.0.0 选 1.5.0 非 2.0.0)→z，后序 [z,y,x]）、`test_resolve_dependencies_detects_cycle`（a↔b 循环 → Err）、`test_resolve_dependencies_missing`（缺 w → Err））
