# 插件市场：安装流审查修复（H1/H2/M1/M2/M3/M4）

> 日期：2026-08-07
> 范围：`plugin/{manifest,registry}.rs`、`commands/registry.rs`、`config/validation.rs`
> 触发：ecc:rust-reviewer 对市场代码（`2cec4a48..c01d2250`）独立审查发现 2 HIGH + 4 MEDIUM

## 修复

### H1 — `manifest.id` 路径逃逸（HIGH）
`install_plugin` 把 `manifest.id` 直接 `join` 进 `plugins_dir`，无字符白名单。经签名的 bundle 含 `id="../pwned"` 或 `id="/etc/cron.d/x"` 会写到 plugins_dir 之外；新 install-from-registry 让此路径首次经网络可达（签名是唯一门槛）。

**修复**：`is_safe_plugin_id`（字母数字 / `-` / `_`，≤64），`parse_manifest` 与 `RegistryEntry::validate` 共用同一份校验。

### H2 — 下载无大小上限 → OOM（HIGH）
`http_fetch` 用 `resp.bytes()` 载入全响应体，无字节上限；签名 registry/`download_url` 指向超大文件可触发 OOM（30s 超时下可拉数 GB）。

**修复**：`http_fetch(client, url, max_bytes)` —— Content-Length 预检 + `resp.chunk()` 流式累加超限中止（防伪造 Content-Length 的真实放大）。常量 `MAX_REGISTRY_BYTES = 8 MiB`（registry.toml+.sig）、`MAX_BUNDLE_BYTES = 64 MiB`（插件包）。

### M1 — `cmd_install_from_registry` 未重新校验前端 entry（MEDIUM）
前端传入的 `RegistryEntry` 跳过 `validate()`（`verify_bundle` 是真信任闸，但字段校验为纵深防御 + 直观错误）。

**修复**：`RegistryEntry::validate` 提 `pub`；命令入口 `entry.validate()?`。

### M2 — `validate_registry` URL 校验过浅（MEDIUM）
仅前缀检查可通过 `https:///x` 等异常值。

**修复**：加 host 非空校验（`://` 后须非空且不以 `/` 开头）。

### M3 — 配置 pubkey 仅 hex 长度校验（MEDIUM）
`0000…`（全零）通过 hex 检查，首 fetch 时含糊失败。

**修复**：`validate_registry` 内 `VerifyingKey::from_bytes` best-effort 合法点校验（捕获不可解压的点，给清晰早错误）。权威校验仍在 verify 时 fail-closed。注：`[0;32]` 等可解压退化值不在其反例范围（empirical：from_bytes 接受），故测试用真实 key 验合法路径，不针对退化点断言。

### M4 — 文档与实现不一致：单/双 key 模型（MEDIUM）
`verify_bundle` 注释称 pubkey「可独立或共用」，但实现是单 key（配置 registry 公钥）。

**修复**：注释改为明确「使用配置的 registry 公钥（单 key 模型）」+ 未来分离 key 的扩展路径。

## 推迟（LOW，记录）

- **L1** symlink containment：tar 0.4.46 `unpack_in` + `validate_inside_dst` 已覆盖；`is_safe_relative` 为冗余纵深防御（注释说明）。
- **L4** 每命令新建 `reqwest::Client`（perf，建议 AppState 复用）。
- **L5** 错误消息含 FS 路径（webview 受信，XSS 风险低）。
- **L6** `{url}.sig` 字符串拼接（query string 场景错位；当前无人这么用）。

- **L3** "`mut mgr` 不必要"：实际 `merged()` 是 `&mut self`（懒重算），`mut mgr` **必需**，跳过。
