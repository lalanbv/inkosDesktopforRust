# 安全：沙箱关键面审查修复（tar-bomb / symlink / 6to4·NAT64 SSRF）

> 日期：2026-08-07
> 范围：`src-tauri/src/plugin/registry.rs`、`src-tauri/src/plugin/host_api.rs`
> 触发：单 security-reviewer 顺序审查 SSRF 栈 + tar 解压 + 签名验签（6 项发现）
> 威胁模型：声明范围内（「签了但恶意/畸形」——密钥泄露 / 发布方工具链意外）

## 修复（4 项可操作）

### R4（MEDIUM）tar-bomb DoS —— 解压累计上限

`safe_extract_tar_gz` 此前无解压侧上限。下载侧 `MAX_BUNDLE_BYTES=64MiB` 仅限**压缩**字节；gzip 对重复数据压缩比 1000×+ → 64MiB 压缩可解压为数十 GB 写盘。

加 `MAX_EXTRACTED_BYTES=256MiB`（累计 header 声明 size）+ `MAX_TAR_ENTRIES=4096`（条目数），超限 `bail!` fail-closed。属声明威胁模型（签了但恶意）内的 DoS 防线。

### R5（LOW，闭环 R1）symlink / hardlink 条目拒绝

`is_safe_relative` 仅查条目自身路径，不查 symlink target。tar 0.4.46 `validate_inside_dst` 仅防**解压期**经链接逃逸，不阻止 symlink **落地**——落地后被 `write_file` 经字面 `starts_with` 校验利用（`docs/security-audit.md` R1 残留）。

`safe_extract_tar_gz` 显式拒 `entry_type().is_hard_link() || is_symlink()`，闭环 R1。

### R1'（LOW）6to4 / NAT64 SSRF 旁路

`is_internal_ip_addr` V6 分支已处理 IPv4-mapped，遗漏同族过渡机制：
- **6to4**（`2002::/16`）：封装 IPv4 在 segs[1..3]
- **NAT64**（`64:ff9b::/96`）：封装 IPv4 在 segs[6..8]

OS 启用 6to4/NAT64（IPv6-only 企业网 / 移动运营商）时，这些可路由到内网 IPv4。V6 分支解封装后复用 v4 判定。

### R3（INFO）误导注释修正

`is_internal_ip` doc + `http_get` 注释称「DNS rebinding 为残留向量」——但 `ssrf_resolve` 已实现连接期 IP pinning（resolver 过滤后的公网 IP 连接，ureq 不重解析），DNS rebinding **实已缓解**。改注释为「纵深一层，非残留」，避免误导维护者去「修」已正确的东西。

## 新增测试（3）

- `test_safe_extract_rejects_symlink`：构造 symlink 条目（raw `Builder::append` + Symlink header，绕过 append_data 的常规文件假设）→ 拒绝 + symlink 不落地。
- `test_safe_extract_rejects_too_many_entries`：4097 空条目 → 第 4097 触发条目数上限中止。
- `test_is_internal_ip_classification` 扩展：6to4 封装内网（`2002:c0a8:0101::`→192.168.1.1）/ NAT64 封装 loopback（`64:ff9b::7f00:1`→127.0.0.1）应拦；6to4 封装公网（`2002:0808:0808::`→8.8.8.8）应放行（非误拦）。

## 遗留（经审查评估，暂不修，记录在案）

- ~~**R2（extract_host userinfo/方括号 IPv6 解析）**~~：**已于后续提交闭环**（见下「R2 闭环」）——无新依赖改写解析。
- **R6（签名重放/降级）**：`fetch_registry` 不校验 `generated_at` 时效，理论上可重放旧注册表（需 MITM 注册表通道）。最小「绝对年龄」修复有已知缺口（旧 toml 的旧时间戳匹配旧签名）；真正修复需客户端单调记录上次 generated_at（transparency log 风格）。暂不修：需 MITM 前提 + 操作者可强制 https，留作后续 transparency 改造。

## R2 闭环（extract_host 正确解析）

无新依赖（`url` 非直依赖）改写 `extract_host`：authority 取首个 `/` `?` `#` 前 → 剥最后一个 `@` 后的 userinfo → 方括号 IPv6（`[::1]:443`→`::1`）/端口（`host:port`→`host`）。

效果：`https://u:p@127.0.0.1/`→`127.0.0.1`（非 `u`，防 userinfo 伪装白名单域）；`https://[2002:c0a8:0101::]/`→`2002:c0a8:0101::` → is_internal_ip 层现可拦方括号 6to4 内网（恢复 SSRF 2 层纵深，此前 `[` 非 IP 致该层失效，仅靠 ssrf_resolve 兜底）。

新增 `test_extract_host` 断言：userinfo(user:pass@ / user@ / allowed@evil)、方括号 IPv6(::1 / 6to4)。
