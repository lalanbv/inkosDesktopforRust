# 插件市场：注册表索引地基（签名 + 校验）

> 日期：2026-08-07
> 范围：`src-tauri/src/plugin/registry.rs`（新）、`src-tauri/src/plugin/mod.rs`、`src-tauri/src/plugin/manifest.rs`
> 目标：插件市场/分发第一 slice——可信注册表索引（types + 解析 + 全量校验 + 验签），为后续发现/下载/安装打地基

## 背景

插件市场需要一个**可信来源**：客户端能列出可装插件并确认条目未被篡改。本 slice 实现注册表索引的数据层——签名 TOML，列出插件元数据 + 下载位置 + 完整性/签名 + 兼容性。复用既有 `updater::sig`（Ed25519）、`semver`、`manifest::parse_capability`，不另起架构。

## 设计

### 两层签名模型（纵深防御）

1. **注册表签名**（detached Ed25519，over `registry.toml` 原始字节）：客户端用受信公钥验签整个索引；失败拒绝整个注册表（防篡改条目/注入）。→ `PluginRegistryIndex::verify_signature`
2. **条目 bundle 签名**（`RegistryEntry::signature`，over 插件包字节）：下载后安装前验签单个包（复用 `sig::verify`）。本 slice 仅做格式校验；安装期验签属后续 slice。

### 字段对齐 + 强约束

- 字段与 `PluginManifest` 对齐（`capabilities` 用相同字符串语法），便于下载后生成 manifest 比对一致性。
- `download_url` 强制 `https://`（TLS，防 MITM 下载链）。
- `version`/`min_host_version` 用 semver 校验（兼容性判断的基础）。
- `sha256` 须 64 位 hex；`signature` 须 128 位 hex（Ed25519 64 字节）。
- v1 约束：每个 `id` 唯一（一条目=最新版）；多版本列表为未来扩展。

## 变更

| 文件 | 变更 |
|------|------|
| `plugin/registry.rs`（新） | `PluginRegistryIndex` + `RegistryEntry`（serde TOML）；`parse`（from_str + validate）；`validate`（格式版本/id 唯一/逐条目字段）；`verify_signature`（复用 `sig::decode_hex`+`sig::verify`）；`find(id)`；`is_hex_of_len` 工具 |
| `plugin/mod.rs` | 声明 `pub mod registry` + 重导出 `PluginRegistryIndex`/`RegistryEntry` |
| `plugin/manifest.rs` | `parse_capability` 提为 `pub(crate)`，供 registry 校验条目 capability 语法一致（DRY） |

### 错误消息设计取舍

`entry.validate()` 的消息已含插件 id（如「插件 X version 非法 semver」），故外层不再套 `with_context`——避免 anyhow `to_string()` 只露外层 context、把根因埋进 cause 链（既不利诊断，也让断言失效）。
