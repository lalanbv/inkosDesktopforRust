# 插件市场：自动更新后端（check + update）

> 日期：2026-08-07
> 范围：`plugin/registry.rs`、`plugin/manager.rs`、`commands/registry.rs`、`main.rs`
> 目标：完成市场生命周期（browse → install → **update**）后端

## 变更

- **`plugin/registry.rs`**：
  - `UpdateInfo { id, installed_version, available_version }`。
  - `check_updates(installed: &[(id, version)], registry) -> Vec<UpdateInfo>`——纯函数，按 id 查注册表条目（v1 id-唯一=最新版），semver 比较 `available > installed`。版本不可解析的跳过（不 panic）。
- **`plugin/manager.rs`**：`update_plugin(source)`——与 `install_plugin` 相同但跳过「已安装」检查，清理旧目录 + 复制新版 + 重新注册。**原子性优于「卸载后安装」**（无中间缺失态：若复制失败，旧目录已被清理但新目录部分写入——与 install 同级风险，无额外窗口）。
- **`commands/registry.rs`**：
  - `cmd_check_plugin_updates`——fetch 注册表 → 取已装（`list_plugins`）→ `check_updates` → 返回 `Vec<UpdateInfo>`。
  - `cmd_update_plugin_from_registry(entry)`——download → verify → extract → `update_plugin`（覆盖）。
  - **重构**：提取 `registry_source_and_client`（读 config 来源 + 构 client）+ `download_verify_extract`（下载+验签+解压）两个共享 helper，4 个命令（fetch/install/update/check）共用——安全关键逻辑（验签/解压）单点定义，避免双处维护漂移。
- **`main.rs`**：注册 `cmd_update_plugin_from_registry` + `cmd_check_plugin_updates`。

## 设计

- **更新判定**：注册表 v1 为 id-唯一（=最新版），故 `check_updates` 按 id 查条目，semver `available > installed` 即有更新。多版本注册表（未来扩展）只需改 `find` 为「按 id 取最高版本」。
- **DRY 重构**：install 与 update 仅差最后一步（`install_plugin` vs `update_plugin`，前者拒已装、后者覆盖）；config 读取 + 下载验签解压经共享 helper 单点定义。
- **信任链不变**：update 复用 `download_verify_extract`（`verify_bundle` 用配置公钥 + `safe_extract_tar_gz` 防 tar-slip），与 install 同等安全。

## 验证

- `cargo clippy --all-targets -D warnings`：clean
- `cargo test`：lib **379 passed / 0 failed**（+`test_check_updates`：旧版→有更新、同版/更新版/不在注册表→无）+ 全集成 0 失败
- 命令本身不可单测（`tauri::State`），端到端由集成测试覆盖；`check_updates` 纯函数已单测，`update_plugin` 镜像已测的 `install_plugin`
