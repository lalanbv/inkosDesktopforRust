# 插件运行时：WASM 编译实例缓存（避免每次 execute 重编译）

> 日期：2026-08-07
> 范围：`src-tauri/src/plugin/manager.rs`
> 依赖：Linker 复用（`846c8625`）
> 目标：「高性能 0GC」——消除 WASM 路径每次 execute 的 Cranelift AOT 重编译（最大 perf 开销）

## 问题

`PluginManager::execute_plugin_inner` 的 WASM 路径每次调用 `WasmPlugin::new(metadata, &entry, &plugin_dir)`——而 `new` 用 `Component::from_file` 做 **Cranelift AOT 编译**（WASM 路径的 dominant 开销，≫ 实例化 ≫ 执行）。进程隔离路径已缓存长驻进程（`self.running`），但 WASM 路径每次重编译。

## 变更

`PluginManager` 加 `wasm_cache: HashMap<String, WasmPlugin>`：
- **`execute_plugin_inner` WASM 路径**：miss → `WasmPlugin::new`（编译）+ 缓存；hit → 复用。消除每次重编译。
- **evict**：`uninstall_plugin`、`disable_plugin`、`update_plugin` 都 `wasm_cache.remove(id)`——卸载/禁用/更新后旧编译实例失效（新版 .wasm 需重编译）。

## 设计

- **缓存键 = id**：WasmPlugin 绑定 (metadata, plugin_dir, .wasm)。同 id 的插件在这些不变时可安全复用；install/update 改变文件 → evict 强制重编译。
- **状态隔离不变**：每 execute 仍 `create_store()`（新 Store + 新 PluginState + 新 fuel/epoch）。缓存的是编译产物 + Engine + Linker，不含执行状态。
- **与 Linker 复用叠加**：前次（`846c8625`）让 Linker 在 WasmPlugin 内复用；本次让 WasmPlugin 在 PluginManager 内复用。execute 热路径仅剩 Store 新建（状态隔离必需）+ Component 实例化（per-call，绑 Store）。
- **PluginManager 无 Debug derive** → WasmPlugin（含 wasmtime 类型，非 Debug）可作字段，无冲突。

## 验证

- `cargo clippy --all-targets -D warnings`：clean
- `cargo test`：lib **383 passed / 0 failed** + 全集成 0 失败，含：
  - `wasm_plugin_execution`（echo roundtrip / ping / unknown-command）——行为保持
  - `perf_plugin_wasm`（`wasm_execute_echo_latency_acceptable` 延迟回归门）——复用后仍达标
  - `test_metrics_counts_failures`——隔离 + 重跑稳定通过
- 注：首次全量偶现 `test_metrics_counts_failures` 失败为**测试并行 flaky**（observability::crash 测试的 panic hook 干扰，预存问题，非本次回归；隔离运行 + 重跑均稳定通过）。

## 收益

WASM 插件的第 2+ 次 execute 省去 Cranelift AOT 编译（首次仍编译）。对高频调用（如格式化器每 keystroke）累积收益巨大——编译是 WASM 路径最大开销。具体幅度由 `criterion --bench plugin_execute` 量化（既有 bench，现测量的 execute 已是「实例化+执行」，缓存后首次外的调用将进一步降至「仅实例化+执行」）。
