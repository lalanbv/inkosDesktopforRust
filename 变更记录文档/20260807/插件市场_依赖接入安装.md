# 插件市场：依赖解析接入安装流

> 日期：2026-08-07
> 范围：`src-tauri/src/commands/registry.rs`
> 依赖：依赖解析（`913ec658`）

## 变更

`cmd_install_from_registry` 消费 `resolve_dependencies`，端到端按序装依赖：

- **无依赖**（`entry.dependencies.is_empty()`）→ 原**直接安装**流程（避免为 deps-free 插件无谓拉取注册表）。
- **有依赖** → `fetch_registry_index` 拉取注册表 → `resolve_dependencies` 后序拓扑 → 按**序**（依赖在前、entry 最后）对每个条目 `download_verify_extract` + `install_plugin`，**跳过已装**（`installed_ids` 集判断）→ 返回 entry 自身 metadata。

## 设计

- **deps-free 优化**：常见插件无依赖，走原流程不拉注册表（省一次网络往返）。仅有依赖时才拉取 + 解析。
- **已装跳过**：循环前快照 `installed_ids`（list_plugins）；依赖已随先前的插件装入则跳过。`resolve_dependencies` 自身去重（每 id 一次），故无重复安装。
- **锁粒度**：每依赖单独取 `manager` 锁安装（不持锁跨网络下载，同 update_config H1 守则）。
- **update 不重解析依赖**：更新某插件时其依赖通常已随初装在场；`cmd_update_plugin_from_registry` 仅覆盖该插件本身。若需「更新连带升级依赖」，为后续增强。

## 插件市场依赖能力（完整）

声明（`RegistryEntry.dependencies`）→ 解析（`resolve_dependencies`：传递闭包 + 后序拓扑 + 环检测 + version_req 匹配）→ 安装（按序装依赖，跳过已装）。发布侧 `publish-plugin` 从 `plugin.toml` 的 `[dependencies]` 表自动带入 `RegistryEntry.dependencies`。
