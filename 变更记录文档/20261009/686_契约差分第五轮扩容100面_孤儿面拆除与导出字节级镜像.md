## 六、教训

1. **镜像是「行为面」的镜像不是「端点存在性」的镜像**：TS 删掉的端点若 Rust 还挂着，管线的 legacy 分叉比 404/200 状态码分歧严重得多——孤儿面的考古时间线（谁加、谁删、何时删）是裁决的第一证据。
2. **typed 重序列化面与裸透传面的差分覆盖天然不对等**：GET story-graph（透传）绿不代表 export/html（typed 重序列化）绿——serde Option=null vs JSON.stringify undefined 是 TS↔Rust 边界的系统性陷阱，凡 re-serialize 面必查；`skip_serializing_if` 与 TS `.optional()` 集合要逐一核对而不是模式化补。
3. **测试基建的「未设=关闭」默认必须解析级验证**：`"".split(",")→Number("")→0` 让 env 未设静默变成「注入 0 分」，差分/走查的默认形态被反转——环境敏感的红先查基建默认值，stash 往返二分是因果裁决的最短路径。
4. **差分绿不等于行为一致，可能只是「双方同错」**：685 的三连绿建立在错误注入态的等价分叉上；注入态/无注入态双态复跑是验证差分结论鲁棒性的便宜手段。
5. **豁免备案的扩面要给出「为什么不是 bug」的活体证据**：lens totals 备案前先核验窗口判定/活跃集/保护分类三层非根因，再以 528 边缘命中同源实录定性——豁免=已定性差异，不是默认放行。
