## R32 关键发现与裁决修正

1. **本仓压缩是三体系**（v6 未展开）：①写作链预算制（composer.ts，441 号，
   `available = window − reservedOutput`，protected 不可压超限 throw，
   compressible 交 compiler 编译）；②故事稿确定性摘录（>6000 字符→标题
   索引 80×220，零 LLM；影游整图注入不摘录=编辑安全裁决）；③会话
   transcript 恢复（仅事件包装）。
2. **①的公式与上游 shouldCompact 同构**（`> window − reserve`）——差异仅
   reserve 语义与触发时机。R32 目标修正：**不替换、三体系分工保持，只补
   会话面缺口**（轮间 usage 阈值压缩/切点回溯/迭代摘要链）+ 溢出
   compact-and-retry 一次 + 参数常量统一（16384/20000 实锤）。
3. 上游 token 口径=**usage 优先**（totalTokens||四项和；getLastAssistantUsage
   倒序回溯），估算只用于切点累积——与本项目 estimate 优先形成口径分叉，
   裁决：聊天轮间 usage 优先/无 usage 退化 estimate，写作链维持 estimate。
4. protected 不可压语义（作者意图/焦点/硬状态/伏笔证据）为上游无的产品
   优势，原样保留入档（R32d）。
5. 施工项拆 R32a-d，**实施顺序修订：R30→R31→R33→R32**（R32a 依赖 R30
   后的上游原语且需与 R36 树化协同，R33 纯投影层风险最低先行）。
