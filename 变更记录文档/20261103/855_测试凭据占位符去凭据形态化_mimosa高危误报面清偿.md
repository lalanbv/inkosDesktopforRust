日期：2026-11-03。前置：854 号（其提交被本钩子拦截，本轮回填后 854 号补提）。

## 一、事件与归因核实

854 号提交触发 Mimosa PreToolUse 硬门禁：项目面 **57 高危（硬编码凭据）+ 29 中危**，全部 `packages/*` 测试文件与 `scripts/` 冒烟脚本。逐文件核实：**全部为测试占位符**（`sk-test` / `sk-google` / `sk-mock` / `sk-live` / `sk-env` 等短语义拼接值，≤20 字符、provider 名或 test/mock/bad 字样、无随机熵）——无任何真实凭据泄露，实质误报。但**占位符与真实凭据同形态**（`sk-` 前缀正是行业凭据特征、CLI 自身脱敏守卫同款 `/^(sk-|sess-|rk-|pk-)/`），扫描器按形态报警并非无理；豁免不可取（846/848 教训：放行面必须=定性面，给扫描器开豁免即恒绿族同型）。

## 二、处置：形态根治，非豁免

全量 20 文件（11 core 测试 + 4 studio 测试 + 5 冒烟/走查/契约脚本）两式收敛：

1. **非 apiKey 字段的字面量**（stubEnv 值、Bearer 断言等）：`"sk-x"` → `"test-key-x"` 直接改名（断言两侧同改恒等）。
2. **apiKey / INKOS_LLM_API_KEY 字段赋值**：改「env 注入 + 非凭据回退」惯用形——`process.env.INKOS_TEST_LLM_KEY ?? "test-key-placeholder"`（各处常量化）。真实凭据只走 env/密钥服务的约束从此在**测试面同样成立**（测试可用 env 指向真实 staging 键），回退值为非凭据形态、永不触发特征。冒烟/走查脚本同式；walkthrough 人工提示文案 `Key(...)` 与 fixture 写入值恒等同步。

## 三、过程发现（两坑）

- **钩子规则比前缀宽**：`apiKey:` / `INKOS_LLM_API_KEY:` 字段名 + 字面量即报（与值内容无关）——前缀改名对该形态无效，必须走惯用形 2；非 apiKey 字段（stubEnv/Bearer）改名即可。
- **Edit 旧串定位过窄产生残缺重复块**：`llm-retry-behavior.test.ts` 首次编辑以 hoisted 块为旧串但新串携带了后续函数，产出未闭合 makeClient + 重复副本（模块级函数重复声明=语法错误）——全量跑测前先 Read 全文复核修复。
- **`.env` 内容串中段残留**：`"INKOS_LLM_API_KEY=sk-env"` 形态（sk- 在串中段）不被 `"sk-` 前缀模式命中，而断言侧已被批量改名——两侧不一致测试必挂。修复 3 处（llm-env 1 + config-loader 2）。**教训：批量前缀替换必须配「子串中段」残留扫。**

## 五、教训

- **测试占位符不要复用真实凭据的形态特征**——形态即信号：占位符与真凭据同形（`sk-` 前缀、高熵随机串）会让凭据扫描器永假阳性，长期逼出「豁免/降级」压力，最终损害的是真凭据的可见性。`test-key-` 前缀 + env 注入回退是测试键的终局形态。
- 豁免不是误报的解法——把误报的**成因**（形态撞车）消除才是；与 850 号（禁入清单过期条目摘除）同哲学。
