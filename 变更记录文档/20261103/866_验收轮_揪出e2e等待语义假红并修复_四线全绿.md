## 二、判别与根因

1. **隔离复跑** `cargo test --test e2e_write_next_contract`：**210 passed 全绿**（同一二进制）——非回归，**全量并行负载下的时序敏感**（bench-gate-load-noise 的测试侧同族：满载假信号，隔离回真）。
2. **根因**（tests/e2e_write_next_contract.rs:264/489）：事件等待循环外层 30s deadline + 内层 `tokio::time::timeout(5s, recv())`，而内层超时走 `Err(_) | Ok(Err(_)) => break`——**5s 静默即 break，外层 30s deadline 形同虚设**。write-next 管线多段 LLM 往返（planner→writer→auditor→composer→state-validator），全量并行下段间静默超 5s 即假红。
3. **族扫**（848 号修洞按族扫）：同形状恰 **2 站**（264/489，同文件同构）；8830 daemon 测试为另一形态（10s 窗+显式超时 panic 消息，失败模式诚实）不属本族。

## 三、修复（断言强度零弱化）

```rust
Err(_) => continue,      // 静默=回外层 deadline 的轮询节拍，非致命
Ok(Err(_)) => break,     // 广播关闭=订阅源消失，真终止
```

仅修正等待语义：事件序列断言（write:start → write:complete/error、负载字段、快照落盘）原样保留，失败模式诚实化为真正的 30s deadline。

## 五、教训

1. **满载假红判别法**：源码同一树 + 测试红 → 先隔离复跑判确定性，再谈回归（bench-gate-load-noise 测试侧同型落地）。
2. **「外层 deadline + 内层静默 break」= deadline 失效反模式**：内层超时应作轮询节拍（continue），只有通道关闭才 break——否则实际容忍窗=内层窗，外层数字是装饰。
3. 修复不引入新问题：断言零弱化 + 族扫限定 + 双层验证（隔离/并行）。
