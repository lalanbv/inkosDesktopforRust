## 背景

518–521 弧线的契约差分器只对照 **API 响应面**；双引擎落盘的**工件内容**（章节正文/真相文件/结构化 state/runtime 留痕）从未对照——519/520 备案的摘要措辞差异根源正在此。本号在差分器双腿环境上建立「落盘工件内容面对照」。

## 实现（engine-contract-diff.mjs）

fixture 后对双腿 `books/镜花水月/` 工件树对照：
- **存在性**：全量相对路径集合 diff（豁免 `memory.db*` 二进制/WAL 伴生、`audit_drift.md` 时序敏感、`.trace/.run/.context.json` 时戳态）。
- **内容**：豁免外逐文件比对；`.json` 先键排序归一化（TS 对象序 vs serde 结构体序的键序噪声非契约，缺键/值差异才是）。
- **本轮信息性输出**（不进 divergences 计数）：已定性备案项清偿后逐项转硬门禁。

## 过程教训：一次错误的「修复」

正文尾换行 1B 差曾按「Rust 补末尾换行」修复——**方向错误**：node 落盘正文本就无尾换行（0002 为证），补 `\n` 反而在 GET chapters/2 API 面（此前一直绿）制造了 rust 尾换行分歧。0001 的尾换行来自 fixture 直写形态而非管线产物。已回滚。**工件内容面的「对齐」必须先确认双端产物的自然形态与读取路径，不能只看单侧文件差。** 同库手工对照亦因双引擎先后写同一目录产生混合态而不可作证据——差分器双腿独立环境才是标准。
