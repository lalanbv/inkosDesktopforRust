# 521 号：BM25 分词器对齐专项——Rust 换 icu_segmenter，双端 token 序列 golden 锁死

日期：2026-09-18　分支：develop　基线：85a40a0b（520 号）

## 背景

520 号差分器实证 hybrid-search 双端 BM25 分数系统性漂移（同 query 首条 score 2.201 vs 1.999）+ 边缘命中 1 条抖动。本号解剖双端分词实现，定位根因并根治。

## 根因解剖

- **TS 分词**（`tokenizeSearchText`）：NFKC + toLocaleLowerCase → `Intl.Segmenter` word 粒度（ICU **词典分词**：中文复合词整词切出，如「核心」「冲突」「试炼」）→ 短 Latin/N 丢弃 → 相邻 Han 单字 bigram 补位 → 连字复合词追加。
- **Rust 分词**（`tokenize_search_text`）：NFKC + lowercase → `unicode-segmentation::split_word_bounds`（UAX#29 **不拆汉字序列**，靠 Han 字符预插空格强制单字）→ bigram 补位。
- **漂移机制**：文档侧 token 分布不同（ICU 整词 vs 单字+bigram）→ BM25 的 tf/df 与长度归一化全不同 → 分数与排序边界抖动。query「苏檀 碎镜」双端序列一致（探针实证），差异全在长文档侧放大。

## 修复

`engine-rs/src/utils/local_search.rs`：分词器换 **`icu_segmenter` 2.3（compiled data，与 JS Intl.Segmenter 同源 ICU 语义）**——`WordSegmenter::new_auto` + `iter_with_word_type` 滑动窗口还原片段，`WordType::is_word_like` 对齐 TS `part.isWordLike`；bigram/连字复合词追加与短 token 过滤保留。手写 `is_word_like` 死函数删除；文件头注释更新。

**行为变更**（更正确而非回归）：「核心冲突」旧近似切「核心/冲突/心冲 bigram」，新分词整词「核心」「冲突」无 bigram——既有断言「心冲」更新为词典整词断言 + 新增 ICU 词典行为测试。

## 双端 golden 锁死（对齐项目共享 golden 惯例）

- `packages/core/src/__tests__/golden/search-tokenizer-vectors.json`：5 组典型向量（纯中文 query / 词典复合词 / 长中文正文 / 连字复合词 / 中英混排），TS `tokenizeSearchText` 生成。
- TS 锚面：`golden-tokenizer.test.ts`（6 断言绿）；Rust 锚面：`tests/golden_search_tokenizer_diff.rs` 读同一 json 差分（1 断言绿）——分词漂移从此被双端门禁拦截。
- `tokenizeSearchText` 补入 core 顶层导出（Rust 测试与未来消费方可达）。

## 教训

1. **近似分词是打分漂移的根**：「UAX#29 + 强制单字」只能保证 query 侧相似，文档侧长文本的 token 分布差异经 BM25 放大——分词一致性必须在 token 序列层锁死，不能只看「都能召回」。
2. icu_segmenter 的迭代 API 是边界序列（`(usize, WordType)`），需滑动窗口还原片段——直接按「片段迭代器」直觉写会连续编译错（本号三试：元组索引/字段访问/模块路径）。
