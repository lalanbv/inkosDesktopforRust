## 三、教训与备案

1. **活覆写位认知纠正**：pnpm 11 起 overrides 唯一活位=pnpm-workspace.yaml；package.json 侧（含 cli 顶层 overrides 键）均为死配置。改依赖版本必须双位同改，否则全图覆写兜底会把直接依赖拉回旧版。
2. **interface union 与 Record guard narrow 不兼容**：TS 对 `X is Record<string,unknown>` 型 guard 过滤 union 时，interface 成员被剔、条件类型成员保留——混合成 union 后 narrow 结果失真。transcript 反序列化域的运行时形状检查应走"宽取域（unknown→Record）+出口断言"，不做类型面 narrow。
3. **转换链上的保守降级在依赖升级后变真缺陷**：system→user 降级在 0.73 是合理防御，0.87 transcript 原生携带 system 后就是系统提示词丢失。升级审计要盯"为旧依赖弱点打的补丁"。
4. **mock 合规性是被上游严格化暴露的**：缺 finish_reason 的 mock 在 0.73 宽容下长期潜伏（walkthrough-mock 同样缺但 smoke 未覆盖聊天链所以没爆）。升级后先怀疑 fixture 不合规，再怀疑产品退化——探针双形态对照是快速裁决手段。
5. **vi.mock 工厂 hoisting**：工厂不能引用文件顶层非 hoisted 变量；跨模块面（主入口+子路径）共享桩用 vi.hoisted。子路径 mock 的桩行为必须与真实消费链匹配（空流桩=永久等待）。
6. R30b 备案：compat 四函数正统化（streamSimple/completeSimple→`./api/*`、getModel→`getBuiltinModel` 双参、getEnvApiKey→providers/all）+删除时钟盯上游 ModelManager 迁移；R31-4 备案：estimatePiContextTokens 前后同值断言。
7. npmmirror 镜像同步滞后（type-fest 5.9.0 缺包）可作为 install 失败的优先排查项，`--registry` 单次官方源绕过不动全局配置。
