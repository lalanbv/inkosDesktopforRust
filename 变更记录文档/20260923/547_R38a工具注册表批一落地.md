## 一、目标与定位

R38 的目标是把 dsh（deepseek-harness）工具面的「定义即注册」模式收拢到 InkOS：工具的
schema、执行器、变更面定性此前分居多处（schema 在 `interaction_tools()` /
`book_file_tool_schemas()`，执行在 `execute_tool()` / `execute_book_file_tool()`，同名
read/ls/grep 双作用域族靠 `ChatToolRouter` 尾部的 `matches!` + 分发顺序隐式消解）。
批一将文件三件（read/ls/grep）双作用域族迁入注册表，schema 与执行改为注册表单一事实源。

对应 dsh 三重经验（544 号施工图对勘结论）：

| dsh 概念 | InkOS 批一形态 |
| --- | --- |
| ToolDefinition（name/description/parameters/execute 同址） | `ToolDef` trait（ZST 实现体静态装配） |
| scope layers「最近层胜出」 | `ToolScope` 双层 + `execute_shadowed` 显式遮蔽 |
| restrictions 变更面定性 | `MutationKind` 枚举（接线留 R38b） |

## 二、改动清单

### 新增 `engine-rs/src/interaction/registry.rs`

- `MutationKind`（ReadOnly / ProjectWrite）：`PRODUCTION_MUTATION_TOOL_NAMES` 字符串集的
  枚举化前置形态；ProjectWrite 批一暂无构造点（全族只读），`#[allow(dead_code)]` 备案，
  R38b 编辑族注册后由 suppressProductionTools 面消费。
- `ToolScope`（Project / BookSession）：作用域层；同名工具最近层胜出。
- `ToolDef` trait（async_trait，Send+Sync）：`name/description/parameters/mutation_kind/execute`；
  六个 ZST 实现体（ProjectRead/Ls/Grep、BookRead/Ls/Grep）委托既有自由函数
  （`tool_read` 等），行为零重写。BookRead 描述随 `INKOS_AGENT_ALLOW_SYSTEM_READ`
  分流（与 TS 逐字语义一致，两分支均为 'static 字面量）。
- `ToolRegistry::global()`：`OnceLock` 静态装配（ZST 单元 Vec，构建一次，无 Box::leak、
  无静态堆引用——对齐 202–204 号出清后的纪律）；查找 `&str` 线性扫（层内 ≤3 项零分配）；
  声明序 = schema 投影序（Vec 保证确定性，不踩 536 号 HashMap 随机序教训）。
- 分发面：`execute_book_file`（原 execute_book_file_tool 语义）、`execute_project_file`
  （原 execute_tool 文件三件分支语义）、`execute_shadowed`（ChatToolRouter 尾面：
  book_session=true 书层先查，未命中落项目层，两层皆未命中 → None 留给 material/未知原链）。
- 测试 5 条：项目层投影序与形状、书层投影 TS 逐字（含缺省描述分支）、全族只读定性、
  书会话遮蔽生效（books/ 相对路径可达 + 项目根文件按书层语义不可达且失败为非错误文本）、
  未收族不劫持（propose_action 双层落空）。

### `engine-rs/src/interaction/project_tools.rs`

- `interaction_tools()` / `tools_payload()`：schema 转注册表项目层投影
  （`ToolEntry` 保持 `&'static str` 字段，`InteractionTool` 形态与消费面不变）。
- `book_file_tool_schemas()`：转注册表书层投影（read 描述分流逻辑随 BookRead 迁移）。
- `execute_tool()`：文件三件转 `execute_project_file`，material 双件与未知工具原链保留。
- `execute_book_file_tool()` **删除**：唯一调用方（agent_route 尾面）改接注册表后零引用，
  按 537 号零引用纪律清除；书层分发语义由 `registry::execute_book_file` 承接并有测试锁定。
- `allow_system_read()` 改 `pub(crate)`（BookRead 描述分流同源复用）。

### `engine-rs/src/server/agent_route.rs`

- `ChatToolRouter::execute` 尾面：原
  `matches!(name, "read"|"ls"|"grep") && book_edit_deps.is_some()` → `execute_book_file_tool`
  + 兜底 `execute_tool` 的两段式，改为 `execute_shadowed(root, name, book_edit_deps.is_some(), args)`
  + 兜底 `execute_tool`。分发语义逐字等价（见下节证明）。

## 三、行为语义保持证明

1. **书会话（book/edit）** `read/ls/grep`：旧链 `matches!` 命中 → `execute_book_file_tool`
   书族；新链 `execute_shadowed(book_session=true)` 书层先查命中同一实现体。
2. **非书会话** `read/ls/grep`：旧链 `matches!` 不命中（无 book_edit_deps）→ 尾部
   `execute_tool` 项目族；新链 `execute_shadowed(book_session=false)` 直落项目层，同一实现体。
3. **material 双件（ingest/retrieve）**：两层皆不收 → `execute_shadowed` 返回 None →
   兜底 `execute_tool` 原链，全会话可达性不变。
4. **未知工具**：双层落空 → 兜底 `execute_tool` → `Unknown tool: {name}` 文本不变
   （agent_loop 文本启发式 `starts_with("Unknown tool")` 错误卡判定不受影响）。
5. **schema 面**：投影由注册表生成，字段与原字面量逐字一致（既有
   `tools_payload_shape` 测试与新增书层投影测试锁定；`book_file_tool_schemas` 消费方
   agent_route.rs:1031 装配面零改动）。
6. **ProjectToolExecutor**（agent_loop 测试与文件工具回环适配）：经 `execute_tool` →
   注册表项目层，既有三测试原样绿。
