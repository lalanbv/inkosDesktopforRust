# 480 号：双引擎 PUT 端点 body 语义系统对照——30/30 零漂移

日期：2026-09-15　分支：develop　基线：291d5ee4（479 号）

## 选题背景

478 号坐实的 Node 回退端 director 保存断裂（客户端与 Rust 均发 `{patch}`、TS handler 读顶层键，静默 no-op）提示一类系统性风险：**同名端点在 TS 回退端与 Rust 引擎上的 body 语义漂移**。418 号对照的是"前端消费 API 面 vs Rust 路由"，未覆盖 TS↔Rust 双引擎行为等价——本号系统审计该风险面。

## 审计方法与覆盖

对 TS server.ts 全部 **30 个 PUT 端点**逐一提取 handler body 键读取（`body.xxx` / `payload.get(...)`），与 Rust 对应 handler 的反序列化结构（typed struct + serde rename）或显式 `get()` 读取逐键对照；嵌套包裹层（wrapper key）、camelCase rename、可选字段语义三方面核对。Rust 侧另覆盖 TS 无对应的 put_notify（/project/notify 双端都有）、update_genre（POST 面不在此列）。

## 审计结论：零漂移（478 修复后）

30/30 全部一致，按域归档：

- **书籍域**：timeline（Typed Schema 双端）/ director（{patch}，478 已修）/ workspace brief {brief} / chapters/:num {content} / anti-ai-rules {rules} / experience {entries} / style-binding {profileName,enabledIds,disabledIds,maxGuidanceChars（rename_all camelCase）} / best-of-n {enabled,candidates,minScore} / codex {cards} / series-id {seriesId} / series canon {entries} / chapter-review-mode {mode} / timeline-auto-beats {enabled}；
- **项目域**：project（全量合并含 temperature/stream→llm 旁路注释）/ detection {detection} / model-overrides {overrides} / default-model {defaultModel,service} / research-search {researchSearch} / chapter-review-mode {mode} / notify {channels}；
- **服务域**：services/config {services,defaultModel,configSource,service} / services/:s/secret {apiKey} / cover/config {service,model,baseUrl,…} / cover/secret {apiKey}；
- **会话/玩法域**：sessions/:id {title} / play-mode {playMode}（normalize 双端镜像）/ play image-settings {actors,moments,instructions 三 bool}；
- **其他**：task-routing {routing} / asset-library upsert {asset} / prompt-packs {content} / project artifacts {content} / genres/:id {profile,body}。

**根因定性**：Rust handler 普遍带逐字镜像注释（如"TS `const p = body.profile`（undefined.name → TypeError → 500）"），移植纪律第 4 条（端点契约测试）在大部分域生效——唯一漏网是 director（353 号 Rust 实现正确、TS handler 后期演化为读 patch 时回退端未同步）。该类漂移的系统性防线见下。
