## 1. 缺陷：Rust 引擎写章永不压缩（移植漏线，非书面决策）

**发现路径**：440 号走查备案「压缩留痕分支未验证」→ 本循环追预算来源时发现 `BooksRuntime::ctx()`（books_routes.rs）与 `run_compose` 两处生产构造点硬编码 `context_budget: None`，且全仓无 `Some` 构造点——composer 里完整移植的预算/编译机制（35 号，golden 守门提示词俱全）在 Rust 生产链是**死分支**。

**TS 对照（口径）**：`contextBudgetFromClient`（composer.ts:764）读 `client._piModel.contextWindow`；而 `createLLMClient`（provider.ts:354）`contextWindow: modelCard?.contextWindowTokens ?? 128_000`——**TS 预算恒活**（内建卡两层查，miss 缺省 128k），超预算即走编译压缩。Rust 恒 None = 长章上下文无压缩安全阀，真实模型窗口可能被打爆；桌面端 164 号起默认 Rust 引擎，暴露面全量。

**排除书面决策**：查变更记录无「预算不镜像」备案（386 号式书面决策不存在）；write_next.rs:1790 忠实透传 `ctx.context_budget`，服务端却从不给值——典型移植漏线。

## 2. 修复（TS 逐语义镜像）

1. **`lookup.rs` 新增 `builtin_context_window(service, model)`**：内建卡两层查（Layer 1 精确 + Layer 2 全局优先级，复用 `lookup_model` + `builtin_endpoints()`），miss → `128_000`（TS `?? 128_000` 逐字）。
2. **`LlmEndpointConfig` + `context_window_tokens: u64`**（0=显式关闭）；`AgentRouter` 增 `default_context_window()` / `default_max_tokens()` 访问器。16 处 lib 测试构造点 + 71 处集成测试构造点（e2e_write_next_contract 70 + strangler_duel 1）以 128_000 补齐，bin 直启路径增 `INKOS_LLM_CONTEXT_WINDOW` env（缺省走卡查找），agent_route 覆盖端点按覆盖模型查卡。
3. **`resolve_effective_llm_studio`** 注入 `contextWindowTokens`（生效服务+模型查卡）；**`effective_router`** 读之写入路由缺省配置（缺项回退卡查找）。
4. **两生产点接线**：`WriteNextPorts::build` 构造 `ContextBudget { context_window_tokens, reserved_output_tokens: default_max_tokens }`（窗口恒 >0 故恒 Some）→ `ctx()` 携带；`run_compose` 同口径构造传入 `compose_governed_chapter`。
