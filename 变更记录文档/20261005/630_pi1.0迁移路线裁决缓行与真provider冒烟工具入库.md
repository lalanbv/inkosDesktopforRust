## 二、风险登记分支实测：0.99 观察线降险预设被否定

施工图风险登记原预案「真 provider 冒烟不可得则迁移改双号（先 0.99 观察线）」。0.99.2 tarball 实测 dependencies：**`openai@7.19.0`（SDK 大版本跳升在 0.99 线即已发生）**、`@anthropic-ai/sdk@0.124.0`、typebox 1.3.27——观察线与 1.0.2 同等传输风险（唯 anthropic SDK 略旧 0.124 vs 0.129），且为两天即被 1.0 取代的死线孤儿 pin。降险价值为零，该分支裁决否定。

**传输层风险实锤佐证**：两个 openai 适配器均以 `new OpenAI()` + `client.chat.completions.create().withResponse()` / `client.responses.create().withResponse()` 为传输层（anthropic-messages 侧 PiAnthropic extends Anthropic SDK）——SDK 7 的重试/超时/流式解析默认值直接进入本仓请求路径，mock 门禁（自绘 wire 假端点）覆盖不到。

- 缓行代价可控：pi-ai 仅服务 Node 回退端/CLI（桌面默认 Rust 引擎自有 provider 实现不触达）；0.87.1 已含空 text 保护补丁（629 号）；注册表刷新/anthropic 凭据链改进对回退端非关键。
- **复启条件**：任一真实 key 可得 → 先跑 provider-smoke 三适配器矩阵 → 全绿后按施工图七步执行。

## 四、工程化交付：scripts/provider-smoke.mjs

缓行不是纯等待——把施工序第 6 步做成一键工具入库，key 就位即可开跑：

- **用法**：`node scripts/provider-smoke.mjs --service <name> --model <id> [--api-format chat|responses] [--base-url] [--max-tokens 16] [--skip-stream] [--timeout-ms 60000]`。
- **双链覆盖**：A 非流式（请求构造+响应解析，content 非空+usage 可读）；B 流式（SSE 逐帧 onTextDelta ≥1 且拼接非空——SDK 7 头号风险面）。均走 core `createLLMClient` → pi-ai 三适配器之一（`resolveServicePreset` 推导 family/api，可 `--base-url` 覆盖）。
- **key 解析**：复用 core `getServiceApiKey`（secrets.json → env `{SERVICE}_API_KEY`），绝不打印值。
- **退出码契约**：0 全过 / 1 往返失败 / 2 key 缺失（给双注入路径可行动指引）/ 3 参数错误。`retry:false`（doctor 探针先例：快速 pass-or-fail）。
- **三适配器覆盖矩阵**（脚本头注释）：anthropic-messages→anthropic/claude-sonnet-4-5；openai-completions→deepseek/deepseek-chat；openai-responses→openai/gpt-5。

## 五、验证链（诚实协议：当前可验证面全部真跑）
