# 486 号：一致性套件扩展双引擎对照双跑——同套断言活体差分

日期：2026-09-16　分支：develop　基线：8045eda5（485 号）

## 选题与实现

485 号固化的 `node-fallback-smoke.mjs` 扩展为**双引擎对照双跑**：`--engine node|rust|both`（默认 both）——同一套断言（fixture 全链 + director{patch}/task-routing/no-store 缓存头/run-log 计数）分别打 Rust 引擎（`target/debug/inkos-engine-server`，env INKOS_PORT/INKOS_PROJECT_ROOT/INKOS_STATIC_DIR/INKOS_LLM_BASE_URL 须带 /v1）与 TS 回退端（tsx），每腿独立临时根，输出带引擎前缀的可比断言行。

降级策略：cargo 链接受阻（Xcode 许可）导致二进制缺失时，rust 腿自动跳过并告警、不算失败——套件永远可跑，护栏不因环境僵死。修一个生命周期缺陷：共享 mock 原挂在腿内清理列表里，node 腿结束即被误杀（rust 腿 fixture 立即报 mock 不可达）——拆分共享/腿内子进程列表。

## 活体结果（双跑全绿）

- **node 腿 8/8**：引擎启动/fixture 全链/director{patch}/task-routing/双 no-store/run-log 计数；
- **rust 腿 8/8**：同一套断言全过（既有 9/15 二进制，行为面与当前 Rust 代码一致——其后仅注释改动）；
- 有价值的对照观察：write-next 前的 run-log 基线 Rust=3 vs TS=6——内部 LLM 调用次数不同（TS governed 管线多一轮规划调用）而**外部行为等价**（同断言全过），正是本套件"锁外部契约、放内部实现"的设计意图。
