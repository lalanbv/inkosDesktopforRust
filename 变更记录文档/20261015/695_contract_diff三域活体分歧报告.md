# 695 号：contract-diff 三域活体分歧报告（守卫整包豁免升级为迁移进度实时度量）

日期：2026-10-15。类型：feat(scripts)。前置：694 号（d285a607）。

## 一、缺口

688 号给 contract-diff 加的契约源守卫是**整包豁免**：TS 腿=上游 2.0 时直接 exit 0，门禁输出不含任何分歧数据——「迁移进展如何」只能靠人工分析回答；守卫语义（TS 恢复 fork 契约自动复活）虽诚实，但豁免窗口内的门禁是哑的。

## 二、实现（整包豁免 → 三域活体报告）

- **域定义**（687 fork server 与 2.0 server 路由面机械比对生成，691 后现状）：
  - **①共享面缩减集**（8 端点，双端在位、零/轻 fixture 依赖：books/sessions/skills/asset-library×3/project-notify/doctor）——活体逐端点对比（状态码+归一化 body+firstDiffPath），**0 分歧=迁移完成态的本 face 验收线**；
  - **②fork-only 域**（52 路由，仅 Rust 在位=TS 退役面/迁移回收清单）——活体确认 Rust 有/TS 404；TS 200 即报「TS 已复活=迁移进展」；双缺=「Rust 面回归须查」；
  - **③上游新增域**（11 路由，仅 TS 在位=Rust 2.0 待办）——活体确认反向成立；深链段（:artifactId/:revisionId，无真实工件必双 404）静态声明不计数。
- **关键判别器**：404 二分——路由缺失=Hono 默认纯文本「404 Not Found」，资源缺失=typed JSON 错误体。上游新增域靠它区分「TS 面回归」与「集合为空的正常缺失」（episodes/:id 在空集合下双 404 是常态非回归）。动态段以双端 /books（及 TS /works、/episodes）首个真实 id 实例化。
- **fixture 容错**：报告模式下 TS 腿 fixture 部分失败（2.0 严格 schema 拒 fork 段）不致命——文件级播种先行落盘，共享面 GET 照常。
- **门禁语义不变**：TS=fork 契约 → 严格全量表对跑（原路径零改动）；TS=2.0 → 报告 + 豁免记账 exit 0；守卫自动复活特性保持。

## 三、实测输出（迁移进度首份度量）

- 共享面 8 对比 / **6 分歧**——即时产出的真实迁移工项清单：/books 与 /doctor 的 bookCount（fixture 格式 2.0 化工项）、/skills 形状、asset-library 三库种子正文措辞（双端种子目录措辞漂移，值得随迁移对齐）；
- fork-only **52/52** 声明确认（无漂移=Rust 面零回归）；
- 上游新增 **9/9** 确认（+2 深链静态声明；episodes/:id 靠 404 二分正确判为「路由在位、资源缺失」）；
- exit 0，豁免记账完整。

## 四、教训

1. **豁免要有数据，哑豁免是进度黑洞**：整包 exit 0 的守卫只保证「不撒谎的红」，三域报告让门禁输出从「通过/拦截」升级为「结构化进度」——豁免窗口期正是最需要度量的窗口期。
2. **404 不是一个状态**：路由缺失与资源缺失共用 404，活体探测必须用响应体形态二分，否则空集合场景的假阳性会淹没真信号。
3. **探测用真实 id**：捏造 id 在空集合下必然双 404 假阳性——先取父集合首 id，深链段无真实工件时静态声明退避，不硬测。
