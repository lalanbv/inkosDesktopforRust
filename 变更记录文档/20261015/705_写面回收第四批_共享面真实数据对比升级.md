### 2.3 contract-diff 探针升级（本号方法论核心）

## 三、真分歧三处（升级后立即暴露，全部修于 Rust 侧向 fork TS 契约源收敛）

### 3.1 deconstruct 响应包络（桌面产品活体 bug）

Rust 返回 `{result:{...}, path:"books/...", publishedMaterialId:null|id}`，fork TS 契约=顶层 `{dossiers, pacing, markdown, path:".inkos/../books/...", publishedMaterialId?}`。**DeconstructPanel（BookDetail.tsx:655 挂载）消费顶层 `data.markdown`**——Rust 引擎下拆书面生成成功但面板空白。修=Rust 显式构建顶层包络（不含 index 内部字段）+ fork path 格式 + publishedMaterialId 省键非显式 null。

### 3.2 materialId 清洗语义（中文书名常态输入分叉）

TS 清洗正则 `[^\w-]` 的 `\w` 是 **ASCII 口径**（无 u 旗标），Rust `char::is_alphanumeric` 是 **Unicode 口径**——中文拆书名跨端 materialId 分叉（TS `decon-b1------` vs Rust `decon-b1-拆书-发布`），发布落盘文件名双端不一致。修=Rust 改 `is_ascii_alphanumeric` 镜像（684 号 RFC 6266 ASCII 兜底名哲学同向）。

### 3.3 quality-trend 缺分键形状（686 号教训第三实例）

Rust `averageScore: null`（`Option` 无 `skip_serializing_if` + **空库早退 `json!` 字面量硬编码**双点）vs TS `JSON.stringify` 省键；`points[].overallScore` 同型一并修。golden 向量 null 键同步去键——TS 侧 `normalizeTrend` 的 null→undefined 映射使向量形态变化无感（共享向量两侧消化逻辑不对称，改动须双侧推演）。修复后共享面真实数据对比 0 分歧（该分歧在旧 400/400 伪绿探针下被完全掩盖）。

### 3.4 连带拆除

`ExperienceMergeResult.added` 响应键（PUT experience）无消费方无测试锁定——Rust 侧省键镜像 fork TS `{ok, entries}`。

## 六、教训

1. **共享面对比先问「探针真的打到 handler 了吗」**——中间件拦截让 400/400 伪绿持续多轮，真实 id 实例化是共享面对比的入场券；探针升级本身就是分歧探测器（升级一轮即抓出被掩盖的真分歧）。
2. **fork TS 正则的 `\w` 是 ASCII 口径**——Rust 镜像用 `is_alphanumeric` 是 Unicode 口径，清洗类语义跨端镜像必须逐字符类核对，中文输入是常态而非边界。
3. **golden 向量的 null 双语义**——「值缺失」与「键缺席」在 JSON 里是两个契约；HTTP 面镜像修 serde skip 时向量同步去键，且共享向量的两侧消化逻辑（TS normalizeTrend vs Rust 直值对比）不对称，任何形态改动须双侧推演。
4. **「缓办」标签要定期核销**——quality-debts status 过滤 702 已做、writing-stats-rows 经定案非工项；清单失真误导排期。
5. **无消费方无测试锁定的响应键是私自形状**（added/result 嵌套）——镜像裁决先找消费方与测试锁定，都没有就向契约源（fork TS）收敛。
