## 做了什么

应用户要求，对两个 AI 长篇小说创作开源项目做源码级调研（均浅克隆至 /tmp/ref-repos），与本仓逐域比对后产出改进规划：

1. **调研对象**
   - [lingfengQAQ/webnovel-writer](https://github.com/lingfengQAQ/webnovel-writer) v6.2.1（Claude Code 插件，Story System 合同提交链 + 三层记忆 + 五维审查）
   - [ExplosiveCoderflome/AI-Novel-Writing-Assistant](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant) v0.4.19（Electron + LangGraph + Qdrant，17 阶段自动导演 + 8 级质量判定 + 写法引擎/拆书工作台）
2. **本项目基线核实**（读源码非转述 README）：写-审-改循环、时序事实库、含因果依赖的伏笔账本、FTS5 检索、批量调度、38 工具聊天 Agent、影游/剧本/翻译多形态、forecast 分支预测、Rust 直启等均已就位。
3. **比对结论**：底子不弱于两对标、多域更强；真实差距集中四处——语义检索（仅 FTS5）、上下文来源优先级契约缺失、质量债务/分级判定缺失、写法与拆书资产化深度不足。

## 规划要点

- **P0 快赢六项**：上下文优先级契约+golden 断言、聊天 AI 实况、作者友好三段报告、防呆写出方言、恢复手册、雷达"选后再析"。
- **P1 引擎双端七项**：质量债务账本+8 级判定+每书治理方案、写法引擎资产化（特征池/绑定/试写/专名泄露检测）、信息差账本+泄密机检、实体名册+新专名确认卡、承诺账本运营化（节奏债/弱钩告警）、续跑语义显式化、按任务模型路由。
- **P2 大件**：sqlite-vec 内嵌语义检索（可选 embedding，降级 FTS5）、拆书工作台、自动导演产品化（方向候选/运行模式/驾驶舱）、best-of-N 关键章、严格模式、项目经验记忆、Prompt 工作台增强。
- **明确不采纳**：Electron/Qdrant/Prisma 重栈、Claude Code 宿主形态、状态去文件化、衍生工坊铺新线、无限重试、闸门默认全开、大版本重写分支。
- **纪律**：Phase B/C 每项 golden 向量先行 + duel 双端 diff=0 + bench:gate 不回退；独立大件另行立项归档至同目录。

## 影响面

纯文档新增，不触碰任何源码与构建产物。后续各阶段启动时按规划文档条目独立编号推进。
