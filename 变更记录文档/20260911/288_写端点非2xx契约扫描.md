## 一、方法与覆盖

对 UI 可触发校验/缺失路径的**写端点**（POST/PUT/DELETE）做双端非 2xx 分支比对，聚焦三类：字段校验 400、写目标缺失 404、畸形载荷处理。

## 二、比对结果（9 端点全部 TS 忠实）

| 端点 | 分支 | 双端判定 |
|---|---|---|
| `PUT /books/:id/truth/:file` | 白名单外文件 → 400 `{error:"Invalid truth file"}` | ✓ 逐字 |
| `POST /books/:id/chapters/:num/approve` | NaN 章节 → **静默 200**（`chapterNumber:null`）| ✓ 逐字（连 TS parseInt 静默语义都保留并注释） |
| `POST …/reject` | 同上模式 | ✓ |
| `DELETE /sessions/:sessionId` | 先标记删除再中止/删除 | ✓ 流程逐字 |
| `POST /genres/create` | 畸形 JSON → 500 | ✓（TS 无 catch 同 500） |
| `DELETE /genres/:id` | 危险 id → 400 `INVALID_GENRE_ID` | ✓ 逐字 |
| `DELETE /skills/:skillId` | 缺失 → 404 `SKILL_NOT_FOUND` | ✓ 逐字（含「access 失败一律 404」语义注释） |
| `PUT /prompt-packs/:promptId` | 非 JSON → 400 `INVALID_PROMPT_PACK_PAYLOAD` | ✓ |
| `POST /project/language` | 畸形 JSON → 500 平铺；任意值透传 | ✓（注释显式引用 TS catch 语义） |

## 三、结论

「UI catch 掩盖契约差」缺陷类**读写两面均已穷举清零**（读面 287 号 / 写面本批）。移植纪律在错误路径上保持逐字级——后续此类缺陷若再现，更可能来自**新增端点**而非既有面，新增端点的 e2e 应包含错误形状断言（281 号教训的制度化）。
