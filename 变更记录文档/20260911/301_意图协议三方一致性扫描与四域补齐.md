## 一、扫描方法

LLM 意图协议三方比对：①系统提示词宣传的意图（chat_prompts，12 个 camelCase 字段）②propose_action 工具 schema 实际宣传的结构化属性 ③`RequestedIntent::parse` 白名单（18 个 snake_case 意图，含 button/slash 专用项）。

## 二、发现：Rust schema 缺四个创建域（真缺口）

| 层 | fanficCreate / continuationImport / spinoffCreate / imitationCreate |
|---|---|
| TS 工具 schema（agent-tools.ts L379-424） | ✓ 四域齐全（Optional 对象 + 字段级描述） |
| TS 执行器 payload 映射（L583-593） | ✓ |
| **Rust 工具 schema** | ✗ **四域全缺**（仅宣传 8 个域） |
| **Rust 执行器 domains 表** | ✗ 四 action 不产 payload 子域 |
| **Rust 严格载荷校验器** | ✗ 顶层键白名单不含四域 → `Unrecognized key` 拒绝 |
| 提示词（两端逐字同文） | ✗ 却指示 LLM「必须同时填进对应结构化字段」含四域 |

**后果**：默认 Rust 引擎下，聊天驱动 fanfic_init / continuation_import / spinoff_create / style_imitation 四动作时——LLM 按提示词填结构化字段 → 严格校验 `Unrecognized key` 直接拒绝；不填则丢失 parentBookId/sourcePath 等关键执行参数。UI 直连端点（/fanfic/init 等）不受影响，故此前走查未暴露。

## 三、修复（三层同步）

1. **工具 schema**：补四域属性块（TS 描述逐字，含 mode/platform/language 枚举）。
2. **执行器 domains 表** +4 行（action ↔ args 键 ↔ payload 键）。
3. **严格载荷校验器**：顶层白名单 +4；四域字段 schema（.strict() 同 TS）；两条跨字段 refine 逐字移植（`fanficCreate requires sourceText or sourcePath` / `imitationCreate requires referenceText or referencePath`）。
4. **必填断言**：fanfic→title、continuation→sourcePath、spinoff→title+parentBookId、imitation→title+storyIdea（对齐 TypeBox required）。
