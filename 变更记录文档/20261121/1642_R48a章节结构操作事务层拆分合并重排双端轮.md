## 实现面

### 事务核心（双端镜像）

- **Rust**：`engine-rs/src/interaction/chapter_structure.rs`（新文件，edit_controller 事务族同位）：
  - **纯函数面**：`chapter_set_revision`（章集合指纹=sha256 前 16 hex of `[[number,wordCount,updatedAt],...]` 号升序 JSON——双端逐位一致）、`renumber_after_split/merge`、`reorder_plan`（双射三重校验：长度+Set 去重+集合相等——`[1,2,2]` 重复数漏洞 TS 版首版漏过 Rust BTreeSet 天然免疫，golden 锁定后双端同语义）、`split_utf16`（UTF-16 code unit 契约=前端光标语义；代理对中间切点非法）、`merge_content`。
  - **staging 两相事务**：受影响章文件 + runtime/drafts 产物整体 rename 入 `chapters/.tmp-structure/`（失败即中断零落盘）→ 按新号回名 + 前段/新章原子写（`write_file_atomic`）+ 索引原子替换**最后落盘**；任一步失败→本轮新写文件删除→staging 全量还原（合并路径 trash 内产物先归位再整体还原，零丢失）。**快照与 .versions 冻结历史不迁移**（entity-rename 先例同语义）；runtime/chapter-NNNN.* 与 drafts 前导号产物属当前章工作面**随号迁移**；被删章（合并）正文+产物进 `.trash/`（永不硬删，pick_available_name 重名规避改 pub(crate) 复用）。
  - **归档先于落盘**（chapter-replace 惯例）：拆分/合并前旧稿归档 `.versions/`（新来源 `ChapterVersionSource::Structure`/"structure"——TS 联合类型+VERSION_ID_PATTERN 正则同步扩）。
- **TS**：`packages/core/src/state/chapter-structure.ts`：事务构造为**单一 commitAtomicFileSet**（writes=新名文件与 index、deletes=旧名与被删章原路径；rename=write new+delete old）——两相 journal 保证失败恢复。**轮内真 bug**：不变号产物 write+delete 同路径被 atomic set 拒绝（`ATOMIC write and delete same path`）——修复=next===old 产物跳过（留原位；Rust staging 机制天然免疫此面）。
- **负路径契约（双端逐字）**：split offset 缺失/越界 400 `"Split offset must be inside the chapter content."`、merge 非相邻 400 `"Merge requires adjacent chapters."`、reorder 非双射/恒序 400 `"Reorder produces no change."`、章缺失 404、NaN 章号 500（PUT chapters 同款）、revision 冲突 409 `{error, code:"CHAPTER_SET_CONFLICT"}`（缺省跳过校验——逐步采纳面）。

- 三 POST 端点：`/books/:id/chapters/:num/split`、`/books/:id/chapters/:num/merge`、`/books/:id/chapters/reorder`（双端注册；Rust mod.rs + TS Hono；TS 端 acquireBookLock 持锁，Rust 进程内锁面=manager 备案的暂缓件）。响应 `{ok, op, splitFrom/newChapter/mergedInto/removedChapter, renumbered:[{from,to}], revision, touchedFiles, summary}`（camelCase 逐键对齐）。

## 轮内真 bug 与教训清偿

1. **atomic set write+delete 同路径拒绝**：TS 事务首版把不变号产物也构造 write+delete → commitAtomicFileSet 拒绝（`cannot write and delete the same path`）——修复=移位集过滤；Rust staging-rename 机制天然免疫（同族两面形态差异备案）。
2. **reorder_plan 双射校验洞**：TS 首版 `every(has)` 漏 `[1,2,2]` 重复数形态——Rust BTreeSet 天然免疫；golden invalid 向量逼出后双端同语义（Set 去重大小校验补齐）。
3. **e2e 断言三连错位**：fixture49 索引 title=第N章（非文件名 title）→ 文件名断言三处错；负路径 call 错位成真合并（「非相邻 400」注释配了相邻合法 call）→ 404 连环误判；SsePayload 字段形态（event/data 非元组）。**教训**：fixture title 与文件名 title 是两套值，断言前先对 fixture 派生面。
4. **reorder_plan 返回序契约**：首版按 order 迭代序、测试期望旧号升序——统一为 **from 升序**（双端确定性，golden 锁定）。
5. **split 号冲突检查是设计错误**：中段拆分新号必然与后章冲突但重编号先腾位——首版预检误报；删除（重编号语义天然保证）。
