> 定位：用户面检索缺口收口——引擎新只读端点 `GET /api/v1/books/:id/search?q=&scope=&limit=`（Rust 先行 + Node 回退端对称镜像），四过滤轴 chapters/entity/hook/truth，UI 双入口（书籍详情「搜索」面板 + ⌘P 正文命中档）。

## 实现面

### 引擎（双端）

- **Rust**：`engine-rs/src/server/search_routes.rs`（新文件）+ `engine-rs/src/utils/global_search.rs`（纯函数核）。chapters 轴走 `.inkos/chapter-search.db` 持久 FTS5 投影（materials `.inkos/retrieval.db` 同惯用形：content_hash 去重增量、热查零重 tokenize；spawn_blocking 惯例 765 号）；entity/hook/truth 轴直读名册（entity_codex.json 文件卡 + entity_roster.md 派生卡，同 name 遮蔽）/承诺账本（memory.db + pending_hooks.md kind 补齐，与 Rust promises 端点同源投影）/真相文件（行级扫描，枚举复用 `truth_search_files`——从 truth_list 提取的单一来源）。注册于 `server/mod.rs`（truth 路由族旁）。
- **TS**：`packages/core/src/retrieval/global-search.ts`（高亮/分词纯函数镜像）+ `server.ts` GET handler（Hono）。**同端同源纪律**：TS 各轴镜像本端既有端点数据源——chapters 走 `state.loadChapterIndex`（works/<id>/source 正典双根布局）、entity 同 get_codex 文件卡+派生卡、hook 同 promises 正典派生（hooks.json + 台账 kind）、truth 复用 `listTruthSearchFiles`（truth_list 枚举提取）。分词单源：`search-tokenizer.ts`（从 local-search.ts 原样抽出——前端 bundle 安全面，global-search 的浏览器消费不能拖 node:sqlite；local-search 反向 re-export 保 API）。
- **契约**：响应 `{query, scope, hits:[{kind,id,title,source,score,snippet,matchStart,matchLength,chapterNumber?}]}`（camelCase，chapterNumber 仅 chapters 轴）。负路径：空 q 400 `"query is required"`（hybrid-search 同文案）、非法 scope 400 `"invalid scope"`、超长 q 按码点裁 200、limit 正整数字面解析回落 20（`3.7`/`-1`/` 3` 双端同规则）+ clamp 1..50。

- **⌘P 正文命中档**：QuickOpenKind 增 `"match"`；`buildMatchQuickOpenItems` 纯函数（quick-open.ts）；QuickOpenPalette 增 `activeBookId` prop（App.tsx `deriveActiveBookId(route)`——只搜当前书防全书并行扫描），≥2 字符 250ms 防抖检索 limit 8，命中档置顶。
- **chapter-focus**（`lib/chapter-focus.ts`）：一次性 nonce 传递模块——HashRoute 不扩（序列化面+全消费点成本高，深链场景不存在），⌘P/SearchPanel 设焦点 → ChapterReader `takeChapterFocus` 定位首个命中段落 scrollIntoView 居中 + 2.6s 高亮闪烁；不匹配消费防陈旧重放（语义测试锁定）。

## 轮内真 bug 清偿（测试逼出）

1. **useI18n t() 不稳定引用 × effect deps 无限循环**：SearchPanel 初版把 t 放 effect deps——hook 每渲染新引用 → effect 无限重触发 → vitest worker 挂死（三次复现：mock 不稳定引用同患）。修复=t 移出 deps（文案投影可接受陈旧一帧）；真实应用同患（网络风暴面），测试先行逼出。
2. **前端 bundle 拖 node:sqlite**：global-search.ts 初版 import local-search → vite build rollup 失败（node:sqlite 无法浏览器打包）。修复=search-tokenizer.ts 纯函数单源抽取（原样搬迁防漂移，local-search 反向 re-export）。
3. **双根布局第一误判**：search-fixture 初版只播 books/（Rust 布局）——TS 腿 state.bookDir=works/<id>/source 正典四轴全空（活体差分 node hits 空、rust 有命中镜像暴露）；修复=双布局播种。**教训**：「TS studio=works 双根、Rust 引擎=books/」双根事实在 contract-diff fixture 层面同样成立。
4. **truth 轴枚举交集约束**：TS TRUTH_FLAT_FILES 9 项无 story_bible.md，Rust flat 白名单 15 项有——查询词若落在 Rust-only 文件（story_bible/entity_codex）必 DIFF。fixture 查询词「之谜」收进双端白名单交集文件 current_state.md，Rust-only 文件文本避开查询词。
5. **TS 白名单 buildMatchQuery 64 截断缺失**：抽取时发现 TS 无 64 cap 而 Rust 有（`take(64)`）——既有漂移（golden 未覆盖 buildMatchQuery），本轮原样保留不扩面（改 cap 属分词单源行为变更，须另立 vectors 面认证）。
