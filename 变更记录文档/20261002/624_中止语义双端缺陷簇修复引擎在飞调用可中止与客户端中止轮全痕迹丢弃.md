# 624 号：中止语义双端缺陷簇修复——引擎在飞调用可中止 + 客户端中止轮全痕迹丢弃

日期：2026-10-02
类型：fix(engine-rs)+fix(studio)+test(双端)
触发：自主持续开发目标（623 号活体走查方法论延伸至**未覆盖的异常路径**——中止/换向/上游故障）

## ① 走查方法与故障注入技术

沿用 623 号「真人式 GUI 走查抓 jsdom 不可达竞态」方法论，本次聚焦聊天**异常路径**（623 集中在成功路径）。关键技术：**SIGSTOP/SIGCONT 冻结 mock-llm**——不改动任何代码即可让 POST /agent 无限挂起（引擎 first_event 预算 120s，冻结窗口安全），为「流式中换向」「停止按钮」「在飞中止」提供了确定性复现窗口。

## ② 走查抓获：中止语义缺陷簇（四缺陷同根）

**复现序列**（真机 100% 确定性）：mock 冻结 → 发送第一轮（挂起，无增量无工具）→ 流式中发送第二轮（ChatPage onSend 的换向语义：先 `abortSession` 再 `sendMessage`，ChatPage.tsx:621）→ SIGCONT。

**修复前实测**（真机）：
- **D-A（引擎）**：`run_agent_loop` 的 abort 旗标只在轮间检查（agent_loop.rs 旧 163 行），`chat.chat().await` 在飞期间完全不响应——用户点了停止/换向，引擎把第一轮**完整跑完**：白烧 LLM 调用、照常 `commit_chat_turn` 落盘、200 返回（服务端 transcript 实测两轮都在）。
- **D-B（客户端）**：被中止轮的 200 响应走成功路径**照常上屏**——UI 消息序变 [用户1, 用户2, 回复1, 回复2]（配对错乱：用户2 先看到回复1），与服务端 transcript 序 [用户1, 回复1, 用户2, 回复2] 分叉。
- **D1（潜伏竞态，D-A 修复后暴露）**：旧轮 500 "aborted" 拒绝时新一轮已同步置 `isChatStreaming=true`（action.ts:540），旧 catch 的「isChatStreaming=false 才记失败」判定（698 行注释前提）被打破 → `rememberFailedSend` 误记 → **幽灵重试按钮**（重试一条用户已主动放弃的消息）。
- **D2（同窗口）**：旧 catch `hasStream=false` → `addErrorMessage("✗ aborted")` 追加在**消息数组尾部**（第二轮用户消息之后）→ 尾部伪错误消息；且裸英文 "aborted" 非双语。

**同构考古定性**：TS/upstream（pi-agent-core agent-loop.js:274）把 `signal` 直通 `streamFunction`——在飞 LLM 请求随 abort 即断；Rust 只查轮间 = **真实双端同构缺口**（非设计差异）。

## ③ 修复

**引擎（engine-rs/src/interaction/agent_loop.rs）**：`chat.chat(&messages, tools)` 包 `tokio::select!`——abort 轮询臂（50ms 间隔，`abort.is_some()` 前置条件）置位即取消在飞调用，按 `aborted: true` 轮出约（217 号既有契约：`fail_chat_turn`→request_failed 不落盘、500 AGENT_ERROR "aborted"）。轮间快查保留。

**客户端（packages/studio/src/store/chat/）**：
- `types.ts`：SessionRuntime 增 `chatAbortedAt?: number`（运行时字段，不入盘）。
- `action.ts abortSession`：记 `chatAbortedAt: stoppedAt`。
- `action.ts sendMessage` catch 路径：失败判定**之前**先判 `chatAbortedAt >= streamTs`（单调时间自过期，无需清除）——被中止轮直接 `discardAbortedStream` + return：不记重试（D1）、不写错误消息（D2）。
- `discardAbortedStream`（新 action）：移除无工具卡的流气泡（服务端从未持久化部分增量，刷新后本就消失）；**有工具卡时保留**——abortSession 已标「已由用户停止」，是用户需要的停止反馈。
- 成功路径不加守卫：「停止恰在完成瞬间」的 200 是合法已落盘回复，与 TS/upstream 的 abort() 竞态语义对齐，不可丢。

## ④ 可证伪单测（621 号协议：先旧码转红再修复转绿）

- Rust `abort_interrupts_inflight_llm_call`：InflightAbortChat 桩 chat() 内置位 abort 后 pending 永不返回，5s timeout 包裹——旧码精确 5.01s 超时红（挂死变可证伪红），新码 0.06s 绿；`abort_stops_before_first_round`（轮间中止）不受扰。
- TS 三个新测试（action.test.ts）：steering 竞态（无 ✗ aborted/无 lastFailedSend/第二轮回复正常渲染）、停止时部分气泡回收（气泡移除且无 ✗）、标记不泄漏（中止后的下一轮真实失败照常记录 ✗+重试）——旧码（旁路 abortedRound 守卫）三测试全红，恢复后 39/39 绿。

## ⑧ 教训

1. **中止语义的正确性必须在「新轮已启动」的窗口里验证**——isChatStreaming 是共享可变状态，跨轮判定全部不可靠；确定性标记（chatAbortedAt+streamTs 单调比较）才是跨轮判定的正确形态。
2. **轮间检查 ≠ 在飞检查**：async 循环的取消点必须显式 select 注入，await 链不会自动响应旗标；对齐上游时查「signal 流到哪一层」而非「有没有 abort 函数」。
3. **SIGSTOP 冻结依赖 = 零代码改动的确定性竞态复现器**：比加延时开关干净，比 mock 秒回有观察窗；配合 SIGCONT 可把任意「挂起中的轮」投放到任意后续状态窗口。
4. **abort 修复会揭开被它掩盖的下一层竞态**（D-A 的 200 掩盖 D1/D2 的 500）——修一个缺陷时问「修复后这条路会改走哪个分支」，该分支的守卫要同步审。
