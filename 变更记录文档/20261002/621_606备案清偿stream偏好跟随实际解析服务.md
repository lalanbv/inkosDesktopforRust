## 考古：备案真实剩余面（620 快照勘误）

620 快照记「606 Node stream 半边维持备案（渲染链/解析链架构演进后随批）」——复核发现该表述已过期：613 号已补 text_delta 渲染链适配、607 号已落 streamPreference 接线，备案前提（「若后续 Node streamFn 架构支持非流式，随批补齐」）**两半均已成立**。

但 607 的落地存在一处**平行链缺陷**：streamPreference 解析（`reqService ?? secrets 首个有 key 服务`）与模型解析（层 1 显式 → 层 2 defaultModel+config services[0] → 层 3 secrets 首个有 key 且有文本模型 → 层 4 legacy）是两条独立链。多服务且流式设置不同时：

- **层 2 命中**：偏好读 secrets 首个有 key 服务（≠ config services[0]）；
- **层 3 后跳**：首个有 key 服务无文本模型被跳过、实际选中第 N 个时，偏好仍读第 1 个。

Rust 对照：`AgentModelOverride.stream` 从**实际选中服务的层内**解析（层 1 `resolve_configured_service_stream(service)` / 层 2 `first.stream` / 层 3 选中服务同函数）——Node 与之不同构。

## 修复（双处）

1. **`packages/studio/src/api/server.ts`**：层 1-3 各自记录 `resolvedServiceId`（层 4 legacy 不记），偏好改从 `resolveConfiguredServiceEntry(root, resolvedServiceId)?.stream` 读取（该函数与 Rust `resolve_configured_service_stream` 逐行同构：config llm.services 按 key 查 entry.stream）——偏好**跟随实际解析出模型的服务**。顺带消除 607 块的重复 `loadSecrets` 调用。
2. **`packages/core/src/agent/agent-session.ts`**：`CachedAgent` 补 `streamPreference` 字段+缓存逐出比较——streamFn 闭包在 Agent 构造时捕获 config，常态下 transcriptChanged 每轮恒真（R32a）掩盖陈旧，但**失败轮未 commit 时 seq 不推进**，此处是「服务流式开关切换后偏好生效」的唯一通路。tracker 家族（15 个既有字段）补齐缺员。
