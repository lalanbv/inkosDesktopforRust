## 行为变更与依据

原行为：`selectedModel` 为空 → 前端硬拦「请先选择一个模型」。该拦截的理由（后端不能兜底）已被本会话实测链条消除：596 号后端 secrets 静默兜底落地（首个有 key 服务，与 Rust 四层解析第三层同构）+ 593/596 双端零显式直发成功实证。

新行为：移除前端拦截——**有已配置服务与密钥时，未选模型的消息直接发送**，后端自动使用首个可用服务（Rust/Node 行为一致）；**零配置时后端返回双语可行动错误**（层 1「请先为 X 配置 API Key」指引 + 590 注解），经 send 的 catch 显示——引导不劣于原拦截。聊天页「配置模型 →」按钮与模型标签选择器保持不变（显式选择仍可用）。

## 实施

`action.ts` send() 移除 `if (!get().selectedModel)` 拦截块（含探测版残稿）；错误显示由既有 catch 路径（545 行 addErrorMessage(err.message)）承接后端双语错误。

## 验证

- gate:ts 七步全绿（首跑 test 步一次瞬态红，`pnpm -r test` 复跑全绿后整门禁复跑通过）；
- **真机探针**（新环境 4599+mock 4319，**不配置模型、不选模型**直接发）：消息正常发送、模型 chip 自动出现「Mock · lm-mock-model」（后端兜底解析回填）、mock 回复渲染、无拦截文案——零配置直发全链贯通。

## 决策记录

行为变更说明：配置了服务+密钥的用户不再被强制手动选模型（自动用首个可用服务=与 Rust 默认后端一致的既有语义）；需要精确控制模型时仍可显式选择。零配置用户获得双语配置指引。589 提案三选项至此全部闭环（C=590、B=596+598、A 为原始基线）。
