## 缺口定案：供应链审计门禁不对称

audit:npm 在 gate:ts 第 3 步强制（改 npm 依赖即红），而 **audit:rust（RustSec，双 Cargo.lock）是孤立脚本**——不在任何复合门禁内，Cargo.lock 变更无拦截点。历史佐证：517 号 rustls 0.23.45 漏洞清零靠的是当时**手动**跑审计；若 audit:rust 在门禁内会随依赖变更即刻现形。

## 交付

`scripts/cargo-test-gate.mjs` 前置哨兵步：全目标测试之前固定跑 `audit-rust.mjs`（spawnSync，stdio inherit），非零即停（漏洞清单透传给调用方）；cargo-audit 缺失按 audit-rust 自身纪律 exit 3 不静默绿灯（脚本头「前置与环境」同步注明）。语义=cargo:testgate 从「全目标测试门禁」升格为「Rust 全量门禁（审计+测试）」，与 audit:npm 在 TS 门禁内的地位对称。

接线活体验证：audit 先行（双 lock 0 漏洞）→ engine 45 目标 1893 绿 → src-tauri 全绿，整体 exit 0。负样本叙事=517 号 rustls 事件史实（当时的漏洞在门禁内必被拦截）。
