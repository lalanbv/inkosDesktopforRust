## 背景与目标

394 号打通了 kind 的产出到持久化（settler/architect 产出 → 台账 14 列 → 归并），但 R23 指令链的
消费侧三件——「timeline 按类过滤、回收提示带类型、UI 选择器」留作尾链。本批补齐，使规范分类
真正到达写作提示（LLM 侧）与运营视图（人侧）。

## 改动清单（TS 与 Rust 1:1 镜像）

### A. 回收提示带类型（LLM 侧，4 处 × 双端）

1. `planner-context` `formatRecyclableHooks`：陈旧 hook 账行尾追加 `[kind=<id>]`
   （英文规范 id，双端同字面；无 kind 省略），置于 `[核心]` 之前。
2. `planner-context` `formatRelevantThreads`（TS）/`extract_relevant_threads`（RS）：
   hook 行首列拼接 `kind=<id> | ` 前缀。Rust 端走 raw 表格路径，从台账第 14 列
   `normalize_hook_kind` 归一后显式化，词表外保持原样不臆测。
3. `composer` hookEntries excerpt：首位插入 `kind=<id>`（Context Lens 可辨）。
4. `composer` buildHookDebtEntries：Hook Debt 简报首行在 type 后附 `，kind=<id>`。

数据可用性：检索层 hooks 走 markdown/结构化真相源（`structuredHooks?.hooks ??
parsePendingHooksMarkdown(...)`，394 号已解析 14 列），故 planner/composer 侧 kind 天然在位。

### B. promises 端点透传 kind（sqlite 投影不落 kind，台账补齐）

- `promise-ledger`（双端）：`PromiseTimelineEntry` 增可选 `kind`，从
  `StoredHook.kind` / `PromiseHookInput.kind` 透传；无 kind 不出键（TS spread 条件 +
  RS `skip_serializing_if`，序列化形状一致）。
- 端点层（TS `server.ts` / RS `ops_routes.rs` 的 GET `/books/:id/promises`）：
  sqlite 投影无 kind（358 号真相源单点先例），读 `story/pending_hooks.md` 台账解析
  hookId→kind 映射补齐；缺文件/缺列优雅降级。TS 侧 core index 补导出
  `parsePendingHooksMarkdown`（此前只有 Rust 侧 pub，TS 未导出——暗坑补齐）。

### C. UI 三件（studio）

1. `truth-display.ts`：`parsePendingHooks` 增解析「分类」列（header 名定位，抗列序变化），
   `normalizeHookKind` 归一，词表外 → undefined。
2. `PendingHooksView`：kind 徽标（7 类配色映射）+ 分类筛选 chips（选择器——动态收集
   台账实际出现的分类，空类不占位，点击切换/再点回全部）。
3. `PromiseTimelineCard`：timeline entry 显示 kind 徽标 + 同形态分类过滤 chips。

## 共享向量扩展

`golden/promise-ledger-vectors.json` timeline 组新增第 3 用例 `kind-passthrough-mixed`：

open → advancing → fulfilled）；无 kind 的期望条目不出 kind 键。
