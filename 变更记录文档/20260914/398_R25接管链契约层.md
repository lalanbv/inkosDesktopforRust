## 背景

v5 五轮规划（396 号立项）P0 首件。ANWA 0.4.20/21 的「结构化调用重试次数 + 备用模型 failover」对本项目构成确定性缺口：345/346 号按任务模型路由只解析**单模型**，任务调用失败即整链失败。本批为**契约层**（schema + 纯函数 + 双端 golden）；调用缝 failover 循环（可重试错误白名单、接管事件留痕）为下一批接线。

## 做了什么

1. **schema 扩展**（TS `TaskModelOverrideSchema` / Rust `TaskModelOverride`，逐字镜像）：
   - `retryCount?: 1–5`——当前模型单次尝试内重试次数，缺省 1 = 现行为；
   - `backupModels?: string[]（≤3）`——按序接管的备用模型（与主模型同端点）。
2. **层级合并承载**：`overrideFields`（TS）/ `compose_task_override` 合并环（Rust）承载两新字段，book > project 覆盖语义与既有四字段一致；**不进 sources**（来源标注面保持四字段，既有 resolve 向量零扰动）。
3. **链解析纯函数** `resolveTaskModelChain` / `resolve_task_model_chain`：
   - attempts[0] = primary（走既有 `resolveTaskModel` 逐字段回退，**service 只随 primary**——备用模型与主模型同端点运行，链条目仅以 model 标识）；
   - backupModels 按序追加，与链中已有 model **精确重复者剔除**，总长封顶 `TASK_MODEL_CHAIN_MAX_ATTEMPTS = 4`；
   - 零配置 → `[primary] + retryCount=1`，行为与现版本逐字节一致（迁移兼容）。
4. **契约面扩展**（三处同步：JSON contract 组 + TS 测试字面量 + Rust `task_routing_contract()`）：新增 `chain` 节（chainFields/maxAttempts=4/maxBackupModels=3/retryCountRange=[1,5]/defaultRetryCount=1/dedupe 口径）。
5. **共享向量** `task-routing-vectors.json`：新增 `chain` 组 5 条——满配去重、project.defaults 备用继承、缺省迁移兼容、备用与 fallback 主模型重复剔除、封顶 4 条。

## 兼容性决策

- **不进 sources**：来源标注是排障/设置面展示口径，链字段属于运行策略而非字段回退语义；保持 sources 形状不变，既有向量与消费端零扰动。
- **service 只随 primary**：备用模型与主模型共享端点与服务配置，链条目仅以 model 标识，避免为每个备用杜撰 service/temperature 组合。
- **封顶 4 = 1 primary + 3 backup**：与 zod `backupModels.max(3)` 对齐；Rust 端无长度校验（沿用既有镜像先例），链函数封顶保证双端行为一致。
