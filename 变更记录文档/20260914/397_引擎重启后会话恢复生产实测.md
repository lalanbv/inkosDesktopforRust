# 397 号：引擎重启后会话恢复端到端生产实测（217 号修复的恢复面实证）

日期：2026-09-14
类型：真实用户路径验证（零代码批）

## 背景

217 号修复了「聊天轮工具消息不落盘」（TS persistAgentEvent 逐消息持久化，
Rust 当时只写纯文本——derive 恢复丢全部工具卡；补
assistant(toolCall)+toolResult 落盘）。该修复当时有单测/e2e，但「杀引擎→
重启→会话工具卡恢复」的端到端生产实证未做过——对应桌面真实用户场景：
重启应用后打开旧会话，历史与工具卡完整且可继续聊。

## 生产环境

release bin + 自定义极简 mock（/tmp 不入库：末条 user 一律返回
propose_action 工具调用——walkthrough-mock 的 agent 关键词分派序在
propose 之前，聊天 system prompt 含「同人」会先命中 canon 分支产不出
工具卡，故本批换分派免费的 tools-only mock）+ 空工作区。会话 chat 型
（无 bookId）。

## 实测序列与结果（全过）

1. **建会话**：POST /api/v1/sessions `{"sessionKind":"chat"}` → 服务端
   自生成 sessionId（331 号教训：响应字段是 `sessionId` 不是 `id`）。
2. **聊天产工具卡**：POST /api/v1/agent → assistant 消息带
   `toolExecutions` 数组（propose_action→create_book 结构化 args 全在）。
3. **落盘形态**：`{project_root}/.inkos/sessions/{sessionId}.jsonl`。
4. **杀引擎→重启（同 project_root）→GET /sessions/:id**：
   - 消息数组与重启前**逐字节一致**（4 条，sort_keys 归一化对比）；
   - 含 toolExecutions 的工具卡消息完整恢复（args/completedAt/details）；
   - sessionId 不变。
5. **恢复后同会话续聊**：第二轮 200，消息 4→6，工具卡累计 2 张，
   响应正常——恢复面不只是只读回放，会话可继续。

## 结论

217 号工具消息持久化修复的**恢复面**首次端到端实证通过：工具卡落盘→
重启→恢复→续聊四环节全通。无代码改动。
