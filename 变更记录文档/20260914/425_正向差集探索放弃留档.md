# 425 · 「TS server 未消费端点」正向差集探索——结论放弃留档

日期：2026-09-14　性质：轻量质量面复核（探索未果留档）

## 探索结论

尝试机械提取「TS server 188 条路由中前端零消费的候选死端点」三次均不可靠：

1. 前端 API 路径以**反引号模板串**为主（`` `/books/${id}/promises` ``），
   双引号正则抓不到；改抓模板串后参数段形态（`${…}` / `:p` / 编码段）与
   静态段混杂，「段数+尾段」特征匹配仍产生大量误报（把被消费判成未消费）；
2. 可靠方案需 AST 级解析（ts-morph 等），超出轻量复核的性价比；
3. 该方向的实际收益本就有限：418 号消费端口径已证明前端消费的 172 条
   主链路全部被 Rust 覆盖，TS server 超出前端的端点属 server-internal
   或外部脚本消费面，删除风险大于仓容收益。

## 决定

放弃自动化正向差集；死端点发现回归人工路径——414 号式的
「对照工具报警 + 人工核实」继续有效（check-routes 仍管 Rust 侧）。
