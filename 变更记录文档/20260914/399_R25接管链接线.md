# 399 号：R25 失败接管链接线——调用缝 failover 循环双端行为测锁定（2026-09-14）

## 背景

398 号契约层（retryCount/backupModels + `resolveTaskModelChain` 链解析）之后的接线批：把链解析接到**实际 LLM 调用缝**，瞬态失败按链切换备用模型。设计要点（v5 规划 §4 风险对策）：接管包在既有同模型瞬态重试**之外**（不重复造轮子——TS provider 层 `withTransientLLMRetry`、Rust `chat` 内环 205 号语义原样保持）；非瞬态错误不重试不切换。

## 做了什么

### TS 端（四文件）

1. **`llm/model-chain.ts`（新）**：`runWithModelChain(run, options)` 链执行器——每链目 model 跑 `retryCount` 轮；分类用 `isRetryableLLMError`；零配置（无 chain 或 [primary]+1）单次直通。`onEvent` 观察点（fail/success+model/attemptIndex/round）供 logger 留痕与 R26 运行遥测挂接。
2. **`llm/provider.ts`**：`isRetryableLLMError` 加 export（原模块私有；分类语义不变）。
3. **`agents/base.ts`**：`AgentContext` 增可选 `modelChain`；`chat`/`submitStructured` 经链执行器调用 `runWorkerAgent`/`runWorkerAgentTool`（技能注入提到链外只做一次）；接管事件 `logger.warn` 留痕。
4. **`pipeline/runner.ts`**：`resolveModelChain(agent)`——显式 `modelOverrides` 钉死不接管（用户指定端点/模型）；无路由/任务不映射返回 undefined；`agentCtxFor` 单漏斗下发（`agentCtx` 死方法未动）。

### Rust 端（agent_router.rs）

1. `resolve_chain(agent)`：显式 override 钉死 → 单元素单轮；无任务映射/无路由 → [默认模型]；有任务路由 → `resolve_task_model_chain`（retryCount clamp 1–5）。
2. `chat` 重构为链循环：每模型 `chat_transient`（原 205 号瞬态环**逐字节保持**：2 次预算+800/1600ms 退避；`INKOS_LLM_TRANSIENT_RETRY=0` 关的是同模型重试、不影响跨模型接管）——返回分类为 `ChainFailure::Fatal`（非瞬态立即失败不切换）/`Transient`（瞬态耗尽，可重试轮/切换备用）；接管成功 `tracing::warn!` 留痕（agent/model/chain_idx/round）。
3. `chat_once` 增 `model` 参数（端点仍按 agent 解析——备用与主模型同端点）。
