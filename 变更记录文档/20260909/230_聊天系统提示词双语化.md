## 一、演进缺口

TS 有完整的双语系统提示词体系（按 sessionKind × 语言分支，涵盖工具使用指引/生产动作纪律/边界规则），而 Rust 聊天面是硬编码中文一句话（「你是 InkOS Studio 的创作助手…」）——**en 项目用户的 LLM 收到中文系统提示词**，与 Node 回退端行为漂移；且中文一句话缺少 TS 版的结构边界与动作纪律（如「章节生产必须落盘」「writer/reviser/auditor 不可互换」「resync 的 allowNewHooks 语义」）。

## 二、移植内容（新模块 `interaction/chat_prompts.rs`）

- `build_chat_prompt(is_zh)`：普通聊天面——工具清单（propose_action/research_web/ingest/retrieve/import，与 Rust 注册面一致）、生产动作清单与 propose_action 纪律、指令自包含要求、语言字段自然语言名称、play mode 映射、输出要求。
- `build_book_prompt(book_id, is_zh)`：书籍会话——结构边界（session 绑定/不臆造权限/sub_agent 指令保真）+ 动作边界（writer/reviser/auditor 不可互换、多章一次启动、章节必须落盘、patch/replace/resync 分工、**resync allowNewHooks=false 语义（225 号旋钮的提示词消费端）**、参考材料不入正典）。
- `build_edit_prompt(book_id, is_zh)`：外部编辑面——工具清单（含角色卡路径说明）、无绑定书分支、只处理明确编辑边界。
- `common_output_rules`（无 emoji/直接回答/不虚报结果）。
- `build_system_prompt(session_kind, book_id, is_zh)` 分发：Book→book（需 bookId）、Edit→edit、Chat 及其余确认生产面兜底→chat；play 由调用方先行覆盖（80 号专属提示词保留）。

## 三、e2e mock 适配（230 号提示词改变了 system 形态）

11 个 e2e 的 mock LLM 按 system 关键词分发响应，两轮适配：①聊天锚点统一扩展为「创作助手∨写作助手∨普通聊天助手∨Play 助手」（含 12721 行否定复合条件的优先级修正）；②sub87/88 域链分支加 `is_chat_surface` 前置守卫——聊天提示词现在含「审稿」「审」等普通词汇，域链关键词分支（审/修稿编辑）须排除聊天面后生效。所有适配只改 mock 判定，不断言链。
