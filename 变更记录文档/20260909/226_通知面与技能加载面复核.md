## 一、notify 通知面（dispatcher 235 行 + format 62 行）

| 审计点 | 结论 |
|---|---|
| 四通道形态 | ✓ Telegram（parse_mode 仅 markdown）/飞书（text/interactive 卡片）/企微（text/markdown）/webhook（HMAC-SHA256 签名 + 事件订阅过滤）逐字对齐 TS |
| 失败语义 | ✓ 失败只记 stderr 不抛（"notification failure shouldn't block pipeline"） |
| webhook 签名 | ✓ `X-InkOS-Signature: sha256={hex}` HMAC-SHA256 逐字 |
| 配置解析 | ✓ parse_notify_channels 非法条目整组忽略（保守侧） |
| **发送超时** | **缺口（已修）**：`reqwest::Client::new()` 无总超时——write-next 章节完成收尾**同步 await** 派发，上游 IM API/webhook 挂起会把收尾路径拖住分钟级（SSE write:complete 与任务快照延迟） |

**修复**：`notify_client()` 统一 10s 超时（`post_and_expect_ok` 与 `send_webhook` 共用）——通知是 best-effort，10s 足够外部 IM API 响应；超时走既有的失败不阻断路径。
