## 缺陷清偿（三处，全部 live/回归红转绿）

### ① merge 重编号路径丢章（双端镜像 bug，R48a 残留，最高危）

- **现象**（live 探针逼出）：3 章书 split 第 2 章后 merge 回并（removed=3、4→3 重编号）→ Rust index 只剩 {1,2}、TS 甚至 []——**重编后恰好落到 removed 号的章被索引丢弃**，而文件面 rename 正确（0003_收束.md 在位）= index/文件面发散。
- **根因**：双端同构顺序错误——TS `buildNextIndex(index, mapping).filter(number !== removed)`（chapter-structure.ts:436-437）↔ Rust `apply_renumber(&index, &mapping).filter(number != removed)`（chapter_structure.rs:814-817）：先应用映射（原 removed 行保持原号 + 后章改名落到 removed 号，同号并存），再按号过滤把**重编后的章一并滤杀**。
- **为何既有门禁漏过**：golden vectors 只锁 renumberAfterMerge 纯函数映射（映射本身正确）；lib/e2e 单测 merge 恰选 removed=末章（无重编号路径，1641 e2e 两章书、1641 lib 三章书 merge 3→2 同为末章）；duel 对拍断言归一化后章清单**相等**——双端同样地错 → 相等通过=**回声室**；状态码级断言全部绕过章集合。
- **修复**：先滤被删行、再应用重编号映射（双端同构改法）。
- **回归**：Rust lib `merge_with_renumber_keeps_shifted_chapter_in_index`（removed=2 触发 3→2：index=[1,2]+标题[风起,收束]+重编文件在位+trash）+ TS 同款 + e2e `merge_with_renumber_keeps_shifted_chapter`（两章书一拆成三再并回，断言 renumbered+index 集合+revision=盘上指纹）——修复前红（丢章）后绿。

### ② export-save chapterFilter 工具面接线（1645 备案「批二」的真相=契约谎言）

- server.ts export-save 把 body 解析出的 chapters 算成 chapterFilter 后**死在半路**（从未传入 tool parameters）；工具 typebox schema 无 "md-zip" 字面量、无 chapters 参——**用户传勾选子集被静默全量导出**。Rust export_save 同款（body chapters 不解析，chapter_filter 硬编码 None）。双端 md-zip 落盘名还会拼出 `.md-zip`（GET 面正典=.zip）。
- **修复**：TS 工具 schema 扩 md-zip+chapters+approvedOnly 透传 writeExportArtifact；server export-save parameters 带 chapters/approvedOnly、扩展名正典化（md-zip→zip）；Rust export_save 解析 chapters（正整数过滤同 GET 面先例）+ `ExportFormat::extension()` pub(crate) 化取正典扩展名。
- **顺带逼出同族三洞**：③ approvedOnly 能力在 TS 整链遗失（fb8c8e3e 状态机替换时误删，Rust 47 号移植体一直保留=同端点 GET `?approvedOnly=true` 行为漂移——ExportPreviewCard「approvedOnly 由既有参数承接」注释为错误归属）→ 回填：readBookExportSource 加索引层 select（先过滤后读盘，镜像 Rust），approvedOnly 与 chapterFilter 互斥优先级同 Rust；④ TS 空子集静默产出空工件（Rust 报 "No chapters to export."）→ 同语义回填（GET/export-save 双面）；⑤ TS export-save 500 错误体带 "Error: " 前缀（String(e)）vs Rust 裸消息 → e.message 裸形态对齐。
- **源一致性校验面保全**：409 CHAPTER_EXPORT_SOURCE_MISMATCH 校验面对全量索引（部分导出不豁免未导出章对账）——首版把过滤后索引喂进校验=子集外章误报 unindexed，回归测试逼出后修正。

## 定性与备案

- **revision 跨引擎不可比**：指纹含 updatedAt=各引擎墙钟——duel 只对归一化章清单比对（1642 同口径），链式乐观并发在引擎内闭环。探针初版误断言跨引擎相等，定性为探针 bug 非产品缺陷。
- **merge UI 不带 expectedRevision**（handleMergeIntoPrevious body 无 revision）：缺省跳过逐步采纳（R48a 设计面），响应 revision 仍回填链——备案不改语义。
- **导出源严格性双端差**（pre-47 遗产非本轮面）：TS 对 index/文件不一致 409 CHAPTER_EXPORT_SOURCE_MISMATCH，Rust 静默跳过缺失章（continue）——duel 走干净夹具不触面，保持现状备案。
- **探针工具链坑**（/tmp 脚本教训）：fetch 助手签名双参误用（post(body) 传进 path 位 → JSON.stringify(undefined)=undefined → 全部 POST 空 body，服务器行为正确探针错）；Mimosa 把「tsx 源路径+重定向」误判写源码——拆 /tmp 引导脚本规避。
