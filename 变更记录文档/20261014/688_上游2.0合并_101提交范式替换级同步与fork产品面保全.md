## 七、教训

1. **范式替换级同步先定性再动手**：先量「路由面增删/共享面存活/核心循环存活」（write-next 存活是本号敢合并的前提），再定「谁承载产品」——Rust 承载产品、TS 跟上游，让不可调和变成可分离。
2. **monorepo 类型解析链有陈旧产物陷阱**：跨包 typecheck 读的是 dist 不是 src，merge 后先 `pnpm build` 被依赖包再查依赖方，否则诊断被假象带偏（本号最贵的一课）。
3. **合并静默删除要主动审计**：`git diff --cached --name-status develop | grep ^D` 逐行过一遍——上游删除 × fork 未改 = 静默消失，GenreManager/genres 种子就是这么丢的；凡 fork 运行时读的路径（genres/skills 根/golden 向量）必须逐个核验。
4. **加法合并优先于重写合并**：schema 新事件（branch_moved）、类型字段（SessionRuntime optional 扩展）、exports map 子路径、i18n 键——能加法并集的不裁剪，fork/上游双侧测试都有活。
5. **孤儿文件用消费图判定**：文件该删该修看「谁还 import 它」，不看它多重要——chat-tool-set（重要但零消费）、model-chain（重要但仅测试消费）退役零风险；backup 分支保证可复活。
