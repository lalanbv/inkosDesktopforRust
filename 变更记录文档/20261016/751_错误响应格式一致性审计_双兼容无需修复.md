# 751 号：错误响应格式一致性审计（双格式混用——前端已双兼容，无需修复）

> 目标线：自主持续开发。TS 续查第七面：engine-rs 错误响应格式一致性审计
> （扁平 `{error:"msg"}` vs 嵌套 `{error:{code,message}}`）。

## 一、扫描实证

| 代码库 | 扁平 `{error:"msg"}` | 嵌套 `{error:{code,message}}` |
| --- | --- | --- |
| engine-rs/server | 129 处 | 21 处 |
| studio server.ts | 104 处 | 30 处 |

**双端均为扁平主导**，嵌套用于需要结构化错误码的场景（LLM 配置错误等）。

## 二、前端兼容性（已双兼容）

`use-api.ts` 的错误提取链**双格式均处理**：

```
if (typeof json.error === "string") → localizeKnownRuntimeMessage(json.error)
if (json.error && "message" in json.error) → localizeKnownRuntimeMessage(json.error.message)
```

用户看到的错误消息一致，不受后端格式差异影响。

## 三、结论

**无需修复**。格式不一致是代码风格问题而非功能缺陷——前端已双兼容。
改进路径（如统一为嵌套格式）涉及 129+104 处修改，无功能收益，回归风险
> 格式一致性收益。新代码建议优先嵌套格式（可携带错误码），但不追溯。
