> 日期：2026-10-16（708 号同日续号）
> 范围：packages/core（models/book.ts + models/project.ts）/ packages/studio（server.ts 四路由 + 测试）/ scripts（contract-diff 域表）

## 一、起因：UI 活消费盘点中实锤潜伏自毁键（比路由回收更优先）

为定向第七批扫描 2.0 UI 的 API 消费面时，发现 **701/707 批嫁接存在潜伏自毁键**：

- 2.0 `BookConfigSchema` 是 `.strict()` 且无 `writing/seriesId/series/governance` 键；
- 701 best-of-n PUT 写 `governance.bestOfN`、707 auto-beats PUT 写 `writing.autoTimelineBeats`、707 series-id PUT 写 `seriesId`——落盘后 `StateManager.loadBookConfig`（`BookConfigSchema.parse`，state/manager.ts:382）对含这些键的 book.json **ZodError 拒收 → 整本书在 TS 回退腿不可加载**；
- contract-diff 探针未发现它：写面探针只比状态码、且回归测试直读文件不回读加载器——「写入成功」与「写入产物可被本引擎再消费」是两个契约面；
- Rust 引擎同场景无恙：`models/book.rs` BookConfig 本就带 `series_id/writing/governance/series`（serde 容错）。

同型风险第二处：2.0 `ProjectConfigSchema` strict 根无 `writing` 段，而 **Rust 引擎把 `writing.reviewMode` 写进 inkos.json**（project chapter-review-mode PUT）——Rust 触碰过的项目在 TS 回退腿 `loadProjectConfig` 即崩。706 号 walkthrough-env boot 崩（「boot 配置带 writing 段被 strict 拒」）正是该投毒向量的实证，当时只修了 env 脚本、没修 schema。

## 二、修复：schema 向 Rust 模型收敛（Rust 为真源）

1. **models/book.ts**：`BookWritingSchema`（reviewMode/revisionGate/autoTimelineBeats/sceneBeats，fork 189/R11 注释逐字回植）、`BookSeriesSchema`（180 号）、`BookGovernanceSchema`（G3/337 + bestOfN G11/371）复位为可选键 + 根 schema 增 `seriesId`——与 Rust `BookConfig` 字段集一一对应；根保持 `.strict()`（键已覆盖双引擎写集，核心身份字段严校不变），子对象保持 fork 非严格口径（serde 容错同水位）。
2. **models/project.ts**：`ProjectConfigSchema` 增可选 `writing` 段（reviewRetries/reviewMode/revisionGate）——Rust `WritingConfig` 镜像（serde default retries=1/mode=auto/gate=strict → 子键全 optional）。
3. **连带正向语义**：`legacy-book-migration.ts` 的 `BookConfigSchema.strip().parse` 此前会把 writing 键从迁移产物中静默剥离（用户审核模式设置丢失）；收敛后已知键保留。`legacy-migration.flow.test.ts:81` 断言从 `'writing' in config === false` 改为 roundtrip 断言（strip 语义 = 2.0 化过渡期产物，与 Rust 永不剥离的行为收敛）。

## 五、教训

1. **「写入成功」≠「写入产物可被再消费」**——写面探针只比状态码+回归测试直读文件，双双对「本引擎加载器拒收自己刚写的文件」盲；写面嫁接的验收必须含 roundtrip 锁（写入 → 强类型加载器回读）。
2. **strict 化是键级别的契约裁剪**——2.0 合并把 fork 键从 schema 裁掉时，所有写这些键的面（含 Rust 引擎的写入）都成了投毒向量；schema 差异要在「谁会写这个文件」的完整清单下审计，不是「TS 不用就是安全的」。
3. **回归锁要钉正典布局**——2.0 StateManager 读 works/{id}/source，嫁接路由写 books/（697 号迁移边界既定双栈妥协）：测试锁哪个加载器就造哪棵树的夹具，混用会假红。
4. **contract-diff 域表编辑要双向核对**——本轮回共享面时 FORK_ONLY 残留一条 book-level 条目（25/26 漂移行活体暴露），漂移行是域表一致性的活体审计器，出现即查。
