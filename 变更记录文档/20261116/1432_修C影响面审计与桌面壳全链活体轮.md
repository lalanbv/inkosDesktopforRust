## 修 C 影响面逐功能审计（stdio 消费面普查）

`supervisor::spawn` 调用方=生产 sidecar（main.rs Rust 直启/Node 回退同经此口）+
lifecycle 测试（sleep 子进程，stdio 无关）。三个 stdio 功能性消费嫌疑面逐一排除：

1. **health_probe**（supervisor.rs:200）=纯 HTTP（reqwest GET `/health`，2s 单次
   超时轮询）——stdio 零关联；
2. **diagnostics**（observability/diagnostics.rs:72）=读 `EngineBackendState`
   运行态（spawn_sidecar_task 写入内存），不读 sidecar 输出流；
3. **Node bootstrap**（main.rs 回退段）=进度走 `with_progress` 回调（app 自身
   eprintln），bootstrap 结果进 [main] 日志——bootstrap 输出面不经子进程 stdio。

**定案：功能性消费零**——修 C 功能零回归。备案级可观测损失：Node/Rust sidecar
自身诊断输出（引擎 4 处低频 eprintln / Node server 控制台行）不再入 app console
（1431 已备案），app 侧 [main]/[node] 关键节点日志保留，排障走引擎 HTTP 面+app
日志+引擎侧独立直跑形态。
