## 做了什么

1. **数据文件**（`packages/core/src/data/author-errors.json`，双端 include
   同一文件）：条目 `{code, severity(auto-handled|needs-review|must-handle),
   patterns[], messageZh/En, nextActionZh/En}`；patterns 为小写关键词
   （对 `${event} ${message}` 小写串 includes 匹配）；目录顺序即优先级；
   末条 `unknown-error` 无 patterns 作兜底（must-handle）。首批 3 条：
   task-busy-or-aborted（auto-handled）/ llm-upstream-unavailable
   （needs-review）/ unknown-error（must-handle）——语义对齐 334 号
   classifyEngineIssue 三分类。
2. **目录纯函数双端**（`author-error-catalog.ts` / `.rs`）：
   `loadAuthorErrorCatalog` / `resolveAuthorError`（首条命中条目生效，
   message/nextAction 随语言切换）/ `nextActionFor`（severity→下一步，
   未知走兜底）。
3. **三面接线**：
   - **author-report**：`classifyEngineIssue` 内联正则重构为目录驱动
     （`ReportIssue` 加可选 `nextAction`）——通知中心经 `buildTaskReport`
     自动跟随；
   - **Doctor**：`DoctorView` 书籍级 issue（state-degraded→must-handle，
     其余→needs-review）渲染目录 nextAction 行；
   - 通知中心 = author-report 单点（334 号架构），零额外改动。
4. **golden**：`author-error-catalog-vectors.json`（resolve×4 含双语与
   兜底 + nextActionFor×3 + catalog 数据契约×1）；TS
   `golden-author-error-catalog.test.ts`（3 用例）与 Rust
   `golden_author_error_catalog_diff.rs`（3 差分）读同文件全绿（第二十二
   守门域）。

## 兼容性决策

- classifyEngineIssue 输出形状向后兼容（category/message 原语义保留；
  nextAction 为新增可选字段，旧消费者无感）。
- 目录扩充（新 code/新 patterns）只改数据文件，双端零代码变更；
  DoctorView 语言暂默认 zh 文案（页面无 language prop，随 G15 UI 窗口补）。
