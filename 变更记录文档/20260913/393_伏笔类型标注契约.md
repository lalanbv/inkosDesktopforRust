## 做了什么

1. **HookKind 枚举双端**（7 类不做数量战，对标蛙趣 8 类伏笔生命周期的
   取精版）：promise/suspense/crisis/artifact/information/emotion/
   worldview（承诺/悬念/危机/物品/信息/情感/世界观）。TS zod 严格枚举
   `HookKindSchema` + Rust serde lowercase 枚举（ts export）。
2. **HookRecord.kind 可选字段双端（零迁移）**：TS `kind: HookKindSchema.
   optional()`；Rust `Option<HookKind>` + serde default/skip_serializing_if，
   手写 Deserialize 的 Raw 结构与构造段同步补齐。**存量 hook 无 kind
   完全兼容**；非法 kind 值双端一致整记录拒收（zod 严格枚举 = serde
   严格反序列化语义对齐，共享向量锁定）。构造点编译器驱动补齐 21 处
   （行首 13 处脚本插入 `kind: None,` + 非行首 8 处 rustc E0063 驱动
   降序补丁）。
3. **hook-kind 纯函数双端**（`utils/hook-kind.ts`/`utils/hook_kind.rs`
   1:1）：`normalizeHookKind`——trim+小写化后别名表精确匹配（zh 别名
   承诺/约定/誓言、悬念/谜团、危机/险局/威胁、物品/信物/道具、信息/
   情报/秘密、情感/感情/关系、世界观/设定；en mystery→suspense、
   secret→information、relationship→emotion、lore→worldview 等），
   未知 → undefined 绝不臆测归类；`hookKindLabel` 双语标签；`HOOK_KIND_IDS`
   规范序。
4. **共享 golden（第 30 守门域）**：`golden/hook-kind-vectors.json`——
   normalize 42 例（含大小写不敏感/空白 trim/未知 null）、labels 14 例
   （7×2 双语）、recordRoundtrip 3 例（无 kind 零迁移解析/带 kind 保留/
   非法 kind 拒收）。TS 3 断言 + Rust 3 测试**首跑全绿**。

## 设计决策

- **可选 kind 与自由 `type` 并存**：`type`（自由字符串）保持原样不动
  ——存量数据零迁移的底线；kind 是新增的规范维度，由 settler/architect
  在接线批（394 号）经 normalizeHookKind 产出。
- **未知自由文本绝不臆测归类**：别名表精确匹配，查不到就是 undefined
  ——宁可缺类型也不给错类型。
- 契约批不含 prompt/持久化/端点/UI 变更——settler 提示词改动会牵动
  golden prompt 快照（239 号 REGEN 纪律），与 timeline 过滤（388 规划
  R23 交付面）一起归 394 号接线批。

## 教训

- **Edit 工具连续两次弄坏枚举尾部换行**（old_string 以 `{\n` 结尾而
  new_string 以 `{` 结尾）——改动前必须 Read 确认现场，编辑后立即
  核对受影响行；第二次直接放弃了 Edit 改为整块替换。
- 构造点批量补丁的可靠流程定型：**行首形态正则先扫一轮（插入位置与
  字段序无关，开括号行后插入即安全），再 cargo check --all-targets
  抓 E0063 收尾**——`-> HookRecord {` 是函数签名不是字面量，正则
  `^(\s*)HookRecord \{\s*$` 天然排除，剩余靠编译器。
- cargo 输出 grep 文件行号会把 warning 位置混进来——错误定位必须
  先 `grep -A 2 "E0063"` 过滤。
