## 做了什么

1. **AntiAiRule 双端同形**（`rule-experience-engine.ts` / `.rs`）：
   `{id(snake_case), type(phrase|structure|rhythm|cliche), pattern 1–200,
   isRegex, severity(critical|warning|info), message, replacement?, enabled}`；
   `validateAntiAiRule` 含 isRegex 时正则可编译性检查（双端一致）。
2. **三面消费契约**：
   - 写作预防：`composeAntiAiGuidance`——enabled 规则 → 禁则块（severity
     前缀 + replacement「改为：…」+ maxChars 截断），注入 340 号
     StyleBinding→guidance 同管道（接线批挂 composer）；
   - detect 消费：`scanAntiAiRules`——仅 enabled；字面 indexOf 计数（按
     pattern 长度步进防重叠）/ regex matchAll；excerpt=首个命中 ±20 字
     窗口；排序 severity→count 降序→ruleId 码元序；
   - fix 消费：`renderAntiAiFixGuidance`——命中清单 + 「建议改法」节
     （replacement），无命中 undefined。
3. **G13 经验条目**（/learn 语义）：`ExperienceEntry {id, chapter(来源章，
   0=书级), kind(technique|hook|pacing|dialogue), text ≤200, enabled,
   createdAt}`；`mergeExperienceEntries`（同 text(trim) 去重保序，已有
   条目保留原 id）；`renderExperienceGuidance`（enabled 过滤 + 章号升序
   稳定 + ≤10 条 + maxChars）注入同管道 guidance。
4. **golden**：`rule-experience-vectors.json`（validate×3 + scan×3 +
   fixGuidance×3 + antiAiGuidance×2 + experience×3，共 14 例）；TS
   `golden-rule-experience.test.ts`（5 用例）与 Rust
   `golden_rule_experience_diff.rs`（5 差分）读同文件全绿（第二十守门域）。

## 兼容性决策

- 契约层批次：管线接线（composer 注入预防块、detection 扫描挂点、reviser
  修复块、审查后经验沉淀链）留 366 号接线批；存储形态（.inkos/ 逐书 JSON）
  随接线批定。
- Rust maxChars 截断按字符计数（中文场景与 TS UTF-16 码元一致；emoji 场景
  差异可忽略——双端 golden 锚定值均为中文/ASCII）。
