- 日期：2026-09-13
- 类型：评测集 + 脚本（防提示词漂移护栏）
- 规划依据：[355 二轮规划 §4 R8](../../开发时SpecCoding'sPlan/inkosDesktop/07_产品演进规划/对标调研分析与改进规划_v2.md)（continuity/reviser/settler 三 agent 的 fixtures 断言，mock LLM 确定性回放，`pnpm eval` 本地跑）

## 做了什么

1. **共享 fixtures**（`__tests__/eval/eval-fixtures.ts`）：样章文本（含钩子
   动静/对话）、settlement 输出（delta JSON + TENSION_METRICS 双节完整
   形态）、audit 响应（critical+structural 路由 + info 局部）、AgentCtx 与
   书目录构造 helper。
2. **三 agent 评测**（10 用例）：
   - **continuity.eval**：结构编辑角色/repair_scope 路由/输出格式模板/
     稀疏 memo 合法性锚点；mock 回放 → AuditResult（passed=false/
     overallScore=62/repair_scope=structural/severity 归一）；memo fixture
     流入审查 prompt（对全部消息拼接断言，memoBlock 拼装位置随实现）。
   - **reviser.eval**：审稿问题注入/修订 TAG 模板/rewrite 局部优先护栏
     （「优先保留原文的绝大部分句段」「禁止整章推倒重写」）；mock 回放 →
     ReviseOutput（fixedIssues/revisedContent）。
   - **settler.eval**：TAG 纪律/章号规则 8/TENSION_METRICS 节/铁律节锚点；
     回放 delta 解析（chapter/chapterSummary/张力分）+ legacy 全量输出回退
     解析 + legacy 无张力节。
3. **脚本**：core `package.json` 增 `"eval": "vitest run src/__tests__/eval"`
   ——`pnpm -F @actalk/inkos-core eval`（根 package.json 为并行会话在途
   文件不触碰）。

## 兼容性决策

- 评测文件命名 `*.eval.test.ts`（vitest include 模式 `**/*.test.ts` 既能
  被全量 vitest 收集，也能被 eval 脚本按目录过滤）——单一事实两用，不引
  第二套运行器。
- 回放断言对「实现细节」取锚点而非逐字节（如 memoBlock 拼装位置、模式
  段语言），防止把实现钉死的同时仍能抓住语义漂移。
