## 做了什么

1. **BookConfig.seriesId 双端**（TS zod refine `^[a-z0-9_]{1,64}$` /
   Rust `Option<String>` serde skip_serializing_if）——**与既有
   `series{name,order}`（180 号 C3-a 展示分组）互补不耦合**：seriesId
   是存储键（指向 `.inkos/series/{seriesId}.json`），series.name/order
   仍是展示面。Rust 构造点 16 处编译器驱动补齐（lib 4 + tests 12，
   按行号降序补丁规避插入位移）。
2. **G2 层级注册双端**：`codex-series/` → user-reference（40，与
   codex/ 同层）；共享 golden context-priority-vectors tier 组 +1
   （34 例）。
3. **composer 双层注入双端**：`loadCodexEntries`/
   `load_codex_entries` 增 seriesCanonFile 参数（调用方解析路径）——
   book 卡块（既有行为不变）+ series 幸存条目块（mergeCodexLayers
   同名覆盖后 match→renderSeriesCodexBlock，source=`codex-series/
   <首卡名>`）。生产调用方三处全真解析（TS runner composeGoverned+
   Rust write_next prepare_write_input + books_routes compose 端点，
   零一处 None 遗留）；缺失文件零打扰。行为测试双端各 1 组
   （同名覆盖/跨书注入/缺失降级，TS 3 用例）。
4. **端点六件双端**：GET/PUT `/api/v1/series/:seriesId/canon`
   （isValidSeriesId 守卫+parseSeriesCanonFile 净化+原子写
   temp+rename）+ GET/PUT `/api/v1/books/:id/series-id`（book.json
   raw 读改写+write_file_atomic，null=解绑；空串双端一律 400）。
5. **UI**：SeriesCanonPanel 挂书籍详情——系列 ID 绑定/改绑 + 共享
   条目 chip 选择 + 别名/摘要/跨书正典事实编辑 + 新增条目，全量 PUT。

## 教训

- **批量补丁脚本按行号升序处理同一文件多构造点会产生插入位移**
  （第一版 agent_production.rs 两处升序插入侥幸命中但不可靠）——
  同文件多行号必须降序处理。
- 端点双端口径逐分支对齐：TS `{seriesId:""}` 返 400，Rust 初版误写
  成 filter 空串=解绑，提交前自查纠正——「缺省解绑」与「非法 400」
  是两个分支，不得合并。
