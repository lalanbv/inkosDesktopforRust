## 一、决策①A：外部技能来源信任门（双栈）

- **信任库**（新）：TS `skills/trust-store.ts` / Rust `skills/trust_store.rs`
  逐字镜像——状态落 `{projectRoot}/.inkos/trusted-sources.json`
  （`{version:1, entries:[{path, confirmedAt}]}`，durable 原子写；路径按
  env 配置串归一（trim+去尾分隔符）原样比对，不做符号链接归一——双端
  读同一 env 串跨端一致；坏 JSON/缺文件容错为空=保守面）。
- **载入闸**：`loadConfiguredAgentSkills` 对 `source==="external"`
  （INKOS_SKILL_DIRS 显式）目录查信任库——未确认 → 技能不入列、仅
  diagnostic"pending trust confirmation"（人侧可见）；user/project 惯例
  目录默认信任不受闸影响。双端同构（TS/Rust 测试互为镜像）。
- **信任路由**（双栈同形）：`GET/POST/DELETE /api/v1/skills/trust`——
  GET 列表；POST `{path}` 校验（绝对路径+目录+SKILL.md 在）后入库；
  DELETE `?path=` 撤销；写后 broadcast `skills:change`（面板热刷新）。
  注册位在 `:skillId` 参数路由之前防吞并。
- **studio UI**：ProjectSettings 技能卡新增「外部 Skill 来源信任」块——
  已信任清单+撤销按钮+绝对路径输入确认；skills:change 热刷新联动；
  待确认来源经既有诊断列表可见。

## 四、实施期实锤缺陷（首轮测试红→修正，均双端同规）

1. **core 顶层 index 精选导出表漏项**：767/768 新符号未入
   `src/index.ts` 导出表——studio server.ts（tsx 直跑源码）import
   undefined → **服务起不来**。duel 10 测全灭"60s 未就绪"（TS sidecar
   崩溃，现场日志 /tmp/duel-tsx-err.log 实锤 `does not provide an export
   named 'addTrustedSource'`）。修复=导出表补 8 符号+重建 dist。
   **教训=core 顶层 index 是精选导出面，新 pub 符号消费跨包时必查；
   duel 是唯一活体覆盖 TS sidecar 启动的门禁（早退跳过≠真跑，INKOS_DUEL=1
   下才暴露）**。
2. **Rust 信任库写读键名不对称**：serde 默认蛇形 `confirmed_at` 写、
   读取按 camel `confirmedAt` → 回读恒空。`#[serde(rename="confirmedAt")]`
   对齐 TS 写面。**教训=双栈 JSON 文件的 serde 结构体默认手写 rename 对齐
   TS camelCase 惯例（books域既有先例），不加即埋写读分裂**。
3. `write_file_atomic` 不建父目录：Rust write_entries 补
   `create_dir_all(.inkos)`（TS 侧 writeEntries 本就有 mkdir recursive）。
