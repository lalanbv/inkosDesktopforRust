## 四、基建改动（atomic_file_set.rs）

1. `atomic_tmp_path` 抽取：async/sync 两形态共用一个进程级 AtomicU64 序号——
   并发写同一目标时临时文件互不碰撞；同目录保证 rename 不跨文件系统。
2. 新增 `write_file_atomic_sync(&Path, &[u8])`：play_graph File 后端的
   `with_transaction`/`flush` 是同步事务闭包（rusqlite 同款同步接口）无法
   `.await`；命名/EPERM+EBUSY 重试决策/失败清理与 async 版逐字对齐，
   退避用 `std::thread::sleep`。
3. 新增 3 测：sync 全量替换且无 tmp 残留 / sync 失败路径无残留 /
   tmp 路径同目录+逐次唯一。

快照清理面安全核验：互动影像 rev 清理按 `{i64}.json` 解析文件名，
`.N.json.tmp-*` 不匹配后缀直接忽略；其余消费面均按扩展名过滤，零误伤。

## 六、教训

1. **韧性惯用形收敛要扫「调用面」而非「定义面」**：审计「是否有原子写」时
   grep 助手定义会得到假绿；必须反查「承载型写点里有多少绕过助手」。
2. **护栏改变风险形态**：panic→fallback 的韧性修复会把数据丢失从「响亮崩溃」
   变成「无声丢失」，两者必须成对设计（本批即护栏的补全）。
3. **同文件双轨是最可靠的漏网信号**：inkos.json（221 号修一处漏一处）、
   翻译域（142 号事务一处裸写三处）——下次惯用形审计先找「同文件混用」。

## 七、软件演进分析与路线建议（用户指令②）

当前健康面（本批实测）：双栈 2019 测全绿 + clippy/audit/TODO/契约差分零异常 +
上游 1247 领先零落后 + 0GC/unwrap/a11y/i18n/安全审计多线收口。架构面
TS(2.0 基底)+Rust(产品引擎) 定线稳定，duel 契约锁持续在位。

按「真实需求×杠杆」排序的候选路线：

1. **落盘持久性升级（fsync）**：现原子写=rename 原子性（防撕裂），未 fsync——
   掉电场景 macOS APFS/ext4 仍可能零长文件。给 `write_file_atomic` 加
   `sync_all` 开关（密钥/配置类开、高频工件类关），一行语义补全。
2. **TS 腿对齐**：Node 回退路径的 `fs.writeFileSync` 同类裸写是否与 Rust 腿
   持久性对齐——不影响契约（文件内容相同）但影响双栈行为一致性，值得一轮
   巡检定性。
3. **ops/server 剩余同步 IO 清偿**：本批顺手清了 2 处 async handler 内同步写，
   同型 `std::fs` 调用面（181 处 grep 粗计）值得一次专项定性（小文件本地 IO
   实际风险低，按热路径分级而非全量改写）。
4. **可扩展性主轴**：genre/skill/剧本域的插件化面已具雏形（skill_routes+
   SKILL.md 惯例），下一大版本可把「第三方技能包=目录约定+manifest 校验」
   正式化为公开扩展点。
5. **性能基线常态化**：bench:gate 已在门禁内，建议对读链（chapters/7 类
   热端点）建固定静默窗基线台账，防 0GC 收益被后续无感回吐。
