# 659 号：审改循环六分支矩阵集成套件固化——`pnpm review-matrix` 一键回归护栏（650–658 手工验证自动化）

日期：2026-10-06。类型：chore(scripts 走查基建)。前置：650–658 号的审改循环六分支验证全部靠手工 env 组合（AUDIT_SCORES/SCOPE/REVISE_BLOAT/REVIEW_RETRIES 四个 env 的记忆组合），无自动化回归面。

## 一、套件设计（`scripts/review-cycle-matrix.mjs`，`pnpm review-matrix`）

四场景各起独立 walkthrough-env 实例（不同端口/root 串行），自动断言 env 日志关键词+落盘正文痕迹+promises：

| 场景 | 注入 | 断言要点 |
| --- | --- | --- |
| B 达标退出 | local "45,91" retries=1 | 轮 1/1→复审 91 达标退出；落盘含 PATCH 替换句 |
| C 未净提升退出 | local "45,47,91" retries=2 | 「修复轮次 1 未净提升（45 → 47），退出循环」；落盘**不含**替换句（修订被丢弃） |
| D 净提升+多轮上限 | local "45,55,91" retries=2 | 轮 1/2→轮 2/2→达标退出；落盘含双 PATCH 痕迹 |
| E restore 回退 | local "45,91" + REVISE_BLOAT | 「回退到最高分版本（45 分 vs 当前 91 分）」；落盘不含替换句（超长修订被回退） |

每场景 26 断言级别（B/C/E 6、D 8），全绿输出矩阵汇总、任一失败退出码非零。基线直通形态（structural 无注入）由 gate:ts 的 node-fallback-smoke 常态覆盖；「未产出新内容」分支以 650 首跑实录/655 红 1 为手工证据（需 mock 直通形态，不入套件）。首跑四场景全绿（各 ~40s，总 ~3 分钟）。

## 二、实现要点

- env 子进程 stdout+stderr 双捕获（logWarn 走 stderr——首版只捕 stdout 致「未净提升/回退」断言全空，一条修正两场景转绿）。
- 端口偏移（base-port 每场景 +2）+root 用 mkdtemp 隔离；收尾 SIGTERM+按端口 SIGKILL 清理。
- 不入 gate:ts（全矩阵 ~3 分钟太重）；作为 chapter-review-cycle 管线重构时的按需回归工具（`pnpm review-matrix`）。

## 三、备案

- 「未产出新内容」分支（mock 修稿直通形态）未入套件——需 mock 加直通 env，随需扩。
- 场景 D 的净提升判定复用 655 双对（轮 2 PATCH2），轮 3+ 未覆盖（maxReviewIterations 上限由 655 的 retries=2 锁定）。

## 四、教训

1. **手工验证矩阵的自动化时机=验证矩阵收官后的下一个动作**：六分支收官（656/658）后若不固化，分支回归就只能靠记忆组合 env——套件把「记忆组合」变成「一条命令」，护栏成本降一个量级。
2. 子进程日志断言的双流捕获（stdout+stderr）要在套件骨架期就定——管线日志的 logStage（stdout）与 logWarn（stderr）分属两流，只捕一流会让一半断言空转（首跑两场景同因失败）。
