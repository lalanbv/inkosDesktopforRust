- 规划依据：[355 二轮规划 §4 R3](../../开发时SpecCoding'sPlan/inkosDesktop/07_产品演进规划/对标调研分析与改进规划_v2.md)；契约层见 [360 号](./360_质量趋势与紧迫度契约.md)

## 做了什么

1. **MemoryDB review_metrics 表双端**：DDL（chapter 主键/overall_score 可空/
   passed/三档 severity 计数/content_hash/recorded_at）+ CRUD：
   - `recordReviewMetric`：**contentHash 幂等**——同章同内容重放跳过返回
     false（TS 测试日志 `[review-metrics] chN 同内容重放，幂等跳过`）；
     修订后 hash 不同 → 覆盖返回 true（最新内容赢）；
   - `listReviewMetrics`：章号升序，quality-trend 端点数据源。
2. **audit 链沉淀双端**：TS runner（`resolvedStatus` 计算前）+ Rust
   write_next（落盘前）——severity 计数（critical/warning/info）+
   `AuditResult.overallScore`（Rust 侧 u32 直接转 i64）+ 360 号
   `reviewMetricContentHash` → 沉淀；**失败仅告警不阻断管线**。
3. **端点双端**：GET `/api/v1/books/:id/quality-trend` →
   `{trend, urgency, currentChapter}`——review_metrics → 360 号
   `buildQualityTrend`；hooks 过滤未兑付 → `resolvePromiseUrgency`
   （targetChapters 读 book.json，currentChapter=已记录末章+1；urgency
   降序 + hookId 码元序）；库缺失返空不报错（quality-debts 先例）。
   TS server.ts + Rust ops_routes.rs（mod.rs 注册）。
4. **UI**：`QualityTrendCard` 挂书籍详情（TensionCurveCard 先例）——
   审查分数折线（y 轴 60–100，80 分参考线）+ 未过章红点 + 均值/记录数/
   未过章 chips + 承诺紧迫度列表（high 玫红/medium 琥珀/low 灰，显式/
   推断/无目标置信标注，取前 6 条）；审查器未评分时降级为仅通过状态。
5. **幂等单测双端**（各 2 例）：同 hash 重放跳过 + 修订覆盖 + 升序清单 +
   缺分行保留。

## 兼容性决策

- 幂等键 = contentHash（360 号契约，不含 recordedAt）——同章多次重跑
  （重试/续跑/回灌）不会重复计分污染趋势；修订后自然覆盖为最新。
- 沉淀失败（库锁/磁盘）仅 warn 不阻断——review_metrics 是运营面加速
  数据，非真相文件。
