## 做了什么

1. **配置模型**（zod / serde 双端同构，全部字段可选 = 部分覆盖）：
   - 五类任务枚举：`writing / review / repair / detect / analysis`；
   - `TaskModelOverride`：model / service / temperature / maxTokens 任选；
   - `TaskModelRouting`：`defaults`（全任务缺省覆盖）+ `tasks`（按任务覆盖）；
     project 与 book 同构，**book 级逐字段覆盖 project 级**。
2. **解析决策表** `resolveTaskModel`（逐字段三层回退，golden 锁死）：
   `book.tasks[task] > book.defaults > project.tasks[task] > project.defaults >
   fallback`（fallback = 现有 effective-llm-config 全局解析产物，model 必填兜底）；
   每字段带来源标注 `task/defaults/fallback`（排障与设置面展示用）。
   数值防御：非有限 temperature / 非正整数 maxTokens 视为未覆盖。
3. **配置迁移兼容**：旧 inkos.json / book.json 无 routing 字段 → 五类任务全字段
   解析为 fallback，现有行为逐字节不变（迁移测锁定，五任务逐一断言）。
4. **共享 golden 向量** `task-routing-vectors.json`（12 例：全 fallback、project
   task 覆盖、任务独立性、defaults 垫底、book 覆盖 project task、book defaults 垫底
   project task、部分字段合并、负值钳制等）+ 契约冻结。TS 4 项 + Rust 差分 3 项
   全绿——**解析一致 duel 达成**（第十三守门域）。
5. **实现质量备注**：Rust 首版含匿名 struct 参数（Rust 不支持）与残留占位闭包，
   均在编译期暴露并修正为具名参数结构 `ResolveTaskModelParams`；向量先行再次
   抓出两处向量自身手算错（JSON 尾逗号/缺括号、maxTokens 来源标注）。
