- 规划依据：[355 二轮规划 §4 R4](../../开发时SpecCoding'sPlan/inkosDesktop/07_产品演进规划/对标调研分析与改进规划_v2.md)；契约层见 [362 号](./362_三库资产契约首批.md)

## 做了什么

1. **推进模式种子×3**（双端逐字镜像）：钩子循环推进（章末强钩→真实承接→
   代价→新钩，类型轮换）/ 升级循环推进（赌注逐轮升级+代价前置+债滚债）/
   三幕卷结构（25-50-25 比例+两幕间转折+中点翻转）；每个含 body/
   expectations×3/taboos×3/samples×1。golden 追加 progressionSeeds 组
   （TS 6/6 + Rust 差分 6/6）。
2. **三库存储层双端**（`.inkos/asset-library/{kind}.json`，每库一文件，
   形状 `{version:1, kind, assets[]}`）：
   - 文件缺失/损坏/版本不符 → **内置种子兜底（内存态，seeded=true），
     不自动落盘**——用户数据文件只在首次写入时创建；
   - TS `packages/studio/src/api/asset-library-store.ts`（server 域模块，
     首个带单测的 api 模块）+ Rust `asset_library.rs` store 函数；
   - upsert 走 362 号 merge 幂等；删除只作用于已落盘数据（内置种子不可删）。
3. **端点五件双端**（全局级，不带 bookId）：
   - `GET /api/v1/asset-library/:kind` → {kind, assets, seeded}
   - `PUT /api/v1/asset-library/:kind/assets`（body={asset}）→ upsert
     （validate 失败 400 errors）
   - `DELETE /api/v1/asset-library/:kind/assets/:id`（种子 400/未找到 404）
   - `GET /api/v1/asset-library/:kind/export` → 便携包（attachment 下载）
   - `POST /api/v1/asset-library/:kind/import`（raw 包 JSON）→ merge 落盘
     → {added, skipped, overwritten, errors, assets}
4. **单测双端**：TS store 5 例（种子兜底/幂等 upsert 落盘/覆盖+非法拒绝/
   删除守卫/kind 校验）+ Rust store 3 例（roundtrip+幂等+删除守卫）。

## 兼容性决策

- 端点挂项目级（workspace 级复用），与 style-profiles 同域但按 kind 分文件，
  后续 364 号世界样本库零新增端点（复用同五件，仅 kind=world-sample）。
- 种子兜底不落盘：避免「读一次就生成用户文件」污染用户数据目录；
  export 时种子随当前快照导出（用户可得完整可迁移包）。
