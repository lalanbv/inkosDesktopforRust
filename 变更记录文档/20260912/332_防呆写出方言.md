# 332 号：防呆写出方言——平铺 front matter/块列表/危险值加引号/BOM 剥除（328 号规划 P0/G7c）

- 日期：2026-09-12
- 类型：引擎增强（TS + Rust 双端）
- 规划依据：[328 号对标调研改进规划](../20260911/328_对标调研分析与改进规划.md) P0 项 G7c（WNW v7 防呆方言的采纳部分；"每条一文件"作为设计准绳不追溯改造既有文件布局）

## 做了什么

1. **盘点双端 truth files 写出器**：真实 front matter/meta 写出点共四处（双端镜像）——
   TS `runner.ts` importCanon（parent_canon.md）+ `fanfic-canon-importer.ts`
   （fanfic_canon.md）；Rust `server/style_routes.rs` + `agents/fanfic_canon_importer.rs`。
   原形态为嵌套缩进块（`meta:` + 两空格缩进）+ **盲目插值加引号**——书名/文件名含
   `"` 即破引号；且 BOM 只在读取侧剥除，写出侧无保证（LLM 输出可携带 BOM 进真相
   文件）。核实无解析器消费这些 meta 块、无测试锁定形状，改形安全。
2. **新增方言模块** TS `utils/truth-dialect.ts` / Rust `utils/truth_dialect.rs`：
   - `renderFlatMetaBlock`：`---` + 顶层 `key: value` 平铺单行标量，禁嵌套缩进；
   - `renderTruthValue`：平铺（CRLF/CR/LF/Tab→空格+trim）→ 危险判定 → 双引号转义
     （19 个 YAML 指示符开头、含 `: `/行尾 `:`/` #`/`"`/`\`/`|`、空串、布尔/数字形）；
   - `renderTruthBlockList`：`- ` 前缀每条一行，逐条过方言渲染；
   - `stripUtf8Bom`：写出前剥一个前导 BOM（中间 BOM 是内容不动）；
   - 机器可读契约对象（zod/serde 双端锁形状）。
3. **共享 golden 向量** `golden/truth-dialect-vectors.json`（53 例：39 标量 + 4 meta
   + 5 块列表 + 5 BOM）+ 契约冻结。TS 断言 `golden-truth-dialect.test.ts`（6 项）；
   Rust 差分 `golden_truth_dialect_diff.rs`（6 项）——本仓第五个共享向量守门域。
4. **四处生产写出点全部接线**：meta 块改方言渲染（含引号书名自动转义，ISO 时间戳
   等安全值保持无引号），LLM 正文进真相文件前剥前导 BOM。
5. **e2e 断言对齐**：`e2e_write_next_contract.rs` 三处旧形状断言（`meta:` 嵌套头、
   `parentBookId: "parent"` 盲引号、`fanficMode: "canon"`）更新为方言形状。

## 行为变更说明

- `parent_canon.md` / `fanfic_canon.md` 尾部 meta 块：嵌套缩进 → 平铺；引号从"总是
  加"变为"危险才加"（含引号值现在被正确转义而不是破块）。纯信息性块，无消费方。
- BOM 剥除仅影响带前导 BOM 的输入，正常输出逐字节不变。
