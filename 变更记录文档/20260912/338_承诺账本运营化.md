- 类型：双端引擎增强（TS core + Rust 引擎）+ studio 运营视图
- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G10（WNW W7 承诺统一账本思想采纳）

## 做了什么

1. **盘点**：hooks 账本已存承诺全生命周期字段（startChapter 开启 /
   lastAdvancedChapter 推进 / status 兑付 / coreHook 核心承诺 / expectedPayoff 预期章），
   既有 stale/health 检测不分 core/普通且无运营视图——G10 增量收敛为：core_hook
   专属节奏债、hookActivity 强度信号、承诺时间线投影。
2. **纯函数模块** `utils/promise-ledger.ts` / `utils/promise_ledger.rs`：
   - `detectPacingDebts`：只盯 coreHook 且未兑付的承诺，搁置章数
     （current − max(lastAdvanced, start)）≥ 阈值（默认 5）即告警，按搁置时长降序；
   - `hookActivityStrength`：三档强度（none：空/"无"/破折号；strong：hookId 记号
     或钩子动词[埋/推进/回收/兑现/hook/resolve…]；weak：其他非空）；
   - `detectWeakHookRuns`：按章号升序扫描，**章号严格连续**（缺章即断段），
     非 strong 连续段 ≥ minRun（默认 3）才报；
   - `buildPromiseTimeline`：状态机 fulfilled/overdue（期望章 ≤ 当前章）/advancing/open，
     overdue 置顶→open→advancing→fulfilled，summary 截断 40 字。
3. **共享 golden 向量** `promise-ledger-vectors.json`（31 例：强度 12 + 节奏债 5 +
   弱钩段 4 + 时间线 2 + 契约冻结；向量内含排序/截断/缺章断段边界）。TS 5 项断言 +
   Rust 差分 6 项（第八个共享守门域）。**向量先行两次立功**：①抓出实现缺陷——
   "连续弱钩"必须校验章号连续性（2,4,5 缺 3 不应合并 4 章段）；②抓出 Rust 差分
   测试的 `WeakHookSummaryRow` 缺 camelCase rename（hookActivity 静默反序列化为空串，
   全部案例误判 none）。
4. **数据与端点**：`MemoryDB.getAllHooks()` 双端（时间线需含已兑付，getActiveHooks
   不够）；双端 `GET /api/v1/books/:id/promises`——返回 `{timeline, pacingDebts,
   weakRuns, currentChapter}`（currentChapter = 最大摘要章 + 1；库不存在返回空投影
   不建文件）。Rust 端 PromiseHookInput 自足（MemoryDb::StoredHook 不含 coreHook
   持久化列，调用方从内存对象/扩展列提供——与既有 upsert_hook 8 列边界一致）。
5. **运营视图（S）**：`PromiseTimelineCard` 挂书籍详情（自取数据）——节奏债红色
   告警行（核心承诺已搁置 N 章）、连续弱钩琥珀段、时间线列表（已逾期红/已开启灰/
   推进中蓝/已兑付绿 chip + 开启/推进/期望三段）；全空整卡隐藏。
