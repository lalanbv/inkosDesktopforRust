## 做了什么

1. **输入契约** `DeconChapter`：chapter / characters[]（settle 链 chapter-analyzer
   产物）+ events（本章事件梗概）+ chapterType（章型）+ hookActivity（伏笔动静）——
   三条既有链（materials ingest / chapter-analyzer / fanfic-canon-importer）的产物
   均可归一为此形态进拆书面。
2. **证据回溯索引** `buildEvidenceIndex`：角色 → [{章, 证据}]（章号升序稳定）+
   全局章型序列；TS 用对象插入序、Rust 用 Vec 保**首次出现序**（BTreeMap 码元序会
   破坏双端一致——向量直接抓出）。
3. **四档人物档案** `deriveCharacterDossier`（brief/standard/deep/full）：
   - brief：出场章列表（证据 0 条）；
   - standard：+证据前 3 条；
   - deep：+出场率（一位小数）+ 最长连续缺席 + 证据前 10 条；
   - full：+全部证据原文。
   向量先行抓出向量手算错（林动 ch3 亦出场 → appearances [1,2,3,4]、深档证据 4 条）。
4. **节奏/卖点统计** `analyzePacingStats`：章型计数（无章型计入 untyped）+ 最长连续
   同型（章型+长度）+ 强钩密度（hookActivity 非空占比，一位小数）。
5. **参考资料导出** `renderDeconstructionExport`：渲染为带 `## Extracted content`
   标记的 markdown——**与 reference-context.extractMaterialContent 的消费格式
   对齐**，拆书产物可直接发布到参考资料供 G1 混合检索召回（zh/en 双语）。
6. **共享 golden 向量** `deconstruction-vectors.json`（13 例：chapters 输入 +
   索引 1 + 四档 4 + 节奏 1 + 导出双语 2 + 契约冻结[档位/证据上限/导出标记/消费方]）。
   TS 5 项 + Rust 差分 5 项全绿（第十五个共享守门域）。
