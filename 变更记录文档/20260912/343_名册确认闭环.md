## 做了什么

1. **确认写回纯函数** `applyRosterConfirmation`（双端）：三选动作的落库口径——
   - new-entity → 追加 `entity-N+1`（registeredAt = 确认时章号，kind 默认 person）；
   - alias → candidate 并入 targetName 实体的 aliases（去重）；
   - typo → 不入册（笔误修正属正文修订范畴，kind=typo-ignored）；
   - 重复确认（实体/别名已存在）→ duplicate-ignored。
   共享 golden 向量新增 confirm 组 4 例（追加/别名合并/笔误忽略/重复忽略），
   TS 7 项 + Rust 差分 7 项全绿。
2. **自动比对接线（拉模式闭环）**：双端
   `GET /books/:id/roster-candidates`——MemoryDB 章摘要 characters →
   `extractCharacterCandidates` → 名册比对（342 契约）→ 确认卡数组 +
   `GET` 数据源含 rosterExists/currentChapter；
   `POST /books/:id/roster/confirm`——三选确认 → `applyRosterConfirmation` →
   渲染写回 `story/entity_roster.md`。
   选择拉模式而非改 settle 内部时序：settle 落盘摘要后端点自然可见，
   零侵入既有写章链时序（与 promises/quality-debts 端点同款模式）。
3. **确认卡 UI（S）**：`RosterCandidatesCard` 挂书籍详情——候选列表（疑似笔误→
   指向名 / 可能别名→指向名 / 未登记）逐条三选按钮（新实体·绿 / 记为别名·蓝 /
   忽略·灰），确认即写回名册并移除该卡；无候选整卡隐藏。
