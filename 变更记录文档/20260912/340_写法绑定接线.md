# 340 号：写法绑定接线——持久化+写作链注入+detection 泄露参与+管理面（G4 续）

- 日期：2026-09-12
- 类型：双端接线（TS core + studio + Rust 引擎）
- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G4 后半；契约层见 [339 号](339_写法引擎资产化契约.md)

## 做了什么

1. **绑定持久化**：档案池 = 项目级 `.inkos/style-profiles/{name}.json`（StyleProfile 全文，
   sourceName 即档案名）；书级绑定 = `books/{id}/story/style_binding.json`
   （profileName + enabledIds/disabledIds/maxGuidanceChars）。双端四条端点：
   `GET/POST /api/v1/style-profiles`（列表/保存）、
   `GET/PUT /api/v1/books/:id/style-binding`（读取/保存，保存时校验档案存在 404）。
2. **写作链注入（双端 compose）**：`loadStyleBindingEntry`（TS）/`load_style_binding_entry`
   （Rust）读绑定 → `resolveStyleBinding` → 产出 Selected Context 条目
   `{source: "style/<档案名>", excerpt: guidanceZh}`——source 前缀 `style/` 在 G2/336
   上下文分层中即 **style-asset（20，垫底参考层）**：写法特征自动排在事实/章纲/记忆/
   参考资料之后，且经过预算压缩不受保护。绑定缺失/解析失败一律零打扰。
3. **detection 泄露参与（双端）**：`DetectionConfig.protectedNames` 新增（optional）；
   `detectChapter` 在 AI 味评分外跑 `detectProperNounLeak`——命中即 fail
   （泄露无法靠降 AI 味修复），结果携带 leaks 明细。
4. **studio 管理面（轻量）**：`StyleBindingCard` 挂书籍详情——档案池下拉 + 绑定到本书 +
   当前绑定展示；特征池数据来自文风页分析产物（POST style-profiles 端点亦可写入）。

## 行为变更说明

- 无绑定时写作链与检测行为逐字节不变（binding 文件缺失即零注入）；
  配置绑定后：Selected Context 多一条 style-asset 条目（可被预算压缩），
  detection 命中受保护专名即判不通过。
