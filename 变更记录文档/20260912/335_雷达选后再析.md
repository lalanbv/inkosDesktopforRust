- 类型：引擎增强 + 前端（TS core + studio + Rust 引擎双端端点镜像）
- 规划依据：[328 号对标调研改进规划](../20260911/328_对标调研分析与改进规划.md) P0 项 G14a（ANWA A10 市场雷达体验的采纳部分）

## 做了什么

1. **盘点**：双端都有 `/api/v1/radar/scan`（桌面默认 Rust 引擎 → 新端点必须双端镜像）；
   旧 `scan()` 把免费抓榜与 LLM 分析绑死在一次调用；RadarView 单按钮一气呵成；无勾选、
   无拥挤度/差异化信号概念。
2. **扫榜与分析拆分**：
   - TS：`fetchRankings()`（免费纯抓榜）、`filterRankingsBySelection()`（纯函数）、
     `RadarAgent.scanRankings()` / `analyzeRankings(rankings, selection)`；`scan()` 保留
     为组合入口（daemon tick 与既有调用方零破坏）；`PipelineRunner.runRadar({selection})`。
   - Rust：`fetch_rankings()` / `filter_rankings_by_selection()` / `run_radar_analyze()`
     1:1 镜像，`run_radar` 改组合；prompt 同步加勾选范围声明与信号卡输出要求。
3. **双端新端点**：`POST /api/v1/radar/rankings`（免费，不调 LLM、不落历史）+
   `POST /api/v1/radar/analyze`（body 带勾选 `selection`，可省 = 全量；落历史 +
   radar:start/complete/error 广播对齐 scan）。Rust 侧挂 server/mod.rs 路由。
4. **信号卡**：`RadarRecommendation` 新增 `crowding`（high/medium/low 拥挤度）与
   `differentiation`（差异化机会一句话）——LLM 输出 JSON 整体透传（Rust 侧
   `Vec<Value>` 宽松天然携带），旧历史记录缺字段时 UI 自动隐藏。
5. **RadarView 两段式交互**：免费扫榜 → 榜单分组预览 + 平台/分类 chip 勾选（i18n 新增
   12 个 radar.* key）→ "分析所选范围"（空选 = 全量）→ 信号卡渲染（拥挤度三色 chip +
   💡 差异化机会行 + 既有置信度/对标书）。
6. **Selection 过滤语义**（双端一致）：platforms/categories/titles 三维度独立、空 =
   不过滤该维度、分类/标题子串匹配、过滤后空源整源剔除。
