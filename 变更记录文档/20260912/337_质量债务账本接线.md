# 337 号：质量债务账本接线——quality_debts 表+scheduler 治理+债务清单展示（G3 续）

- 日期：2026-09-12
- 类型：双端持久化 + scheduler 治理接线 + studio 展示（Phase B 批次一 G3 续）
- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G3 后半；契约层见 [336 号](336_质量债务账本契约.md)

## 做了什么

1. **MemoryDB `quality_debts` 表双端**（对齐 facts/hooks 表先例）：
   - DDL：debt_id 主键 + book_id/chapter/issue_category/severity/status/created_at/
     follow_up_note；idx_debts_status + idx_debts_book 两索引（TS migrate 与 Rust
     migrate 同 SQL，节点内建库自动迁移）。
   - CRUD：TS `recordDebt`（INSERT OR REPLACE 幂等）/ `listDebts(bookId?, status?)`
     （新章在前）/ `updateDebtStatus`（附跟进备注，返回是否命中行）；Rust
     `record_debt` / `list_debts` / `update_debt_status` 1:1 镜像 + 单测往返。
2. **scheduler 每书治理接线（verdict 驱动）**：
   - 配置面：`BookConfig.governance`（book 级）+ `SchedulerConfig.governance`（项目级），
     `resolveGovernancePolicy` book 覆盖 project。
   - `handleAuditFailure` 改造为判定驱动：失败计数入表后构造
     `resolveQualityVerdict` 输入（completion-first 默认下行为分层）——
     failures ≤ maxAuditRetries：重试（现行温度提升路径，不变）；
     `local-patch-plan`/`patchable-obligation-gap`：沿用重试并留痕；
     `defer-and-continue`：记债（status=deferred）+ 清零失败计数 + **本书继续写下一章**；
     `replan-required`：记债（open）+ 暂停 + onPause 原因带 verdict；
     `stop-for-replan`：记债 + 暂停。
   - **默认行为兼容性**：默认 maxAuditRetries=2 与 maxConsecutiveDebts=3 下，
     1–2 次失败重试、3 次暂停——与改造前一致；只有书级把上限调大（如 5）时
     才出现"第 3、4 次失败记债继续"的新分层行为。
3. **债务清单端点双端**：`GET /api/v1/books/:id/quality-debts?status=...`
   （TS server + Rust ops_routes；库不存在返回空清单不创建文件）。
4. **dashboard 展示（S）**：新组件 `QualityDebtsCard`（自取数据、零配置）挂书籍详情页
   头部——只列未决债务（open 红 / deferred amber chip + 章号 + 类别 + 跟进备注），
   resolved 收进摘要计数，无未决债务时整卡不渲染（零噪音）。

## 行为变更说明

- 批量调度默认治理（completion-first/3）与旧行为等价（1–2 重试、3 暂停），
  但第 3 次失败的暂停原因现在携带 `verdict=replan-required`，且每次判定失败
  都在 `quality_debts` 表留痕（原：无任何账面记录）。
- 书级配置 `governance: {policy, maxConsecutiveDebts}` 为新增可选字段，
  旧 book.json 解析不受影响（zod optional）。
