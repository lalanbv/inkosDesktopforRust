- 规划依据：[355 二轮规划 §4 R2](../../开发时SpecCoding'sPlan/inkosDesktop/07_产品演进规划/对标调研分析与改进规划_v2.md)；契约层见 [358 号](./358_张力曲线契约层.md)

## 做了什么

1. **提示词（双端）**：`buildSettlerOutputFormat` 增 `=== TENSION_METRICS ===`
   节（conflictLevel/revealLevel 各 1–10 整数、双语说明、只输出两行）；
   en 输出靠既有 LANGUAGE OVERRIDE，TAG 不变。
2. **注入（双端）**：settle 输出解析后 `parseTensionMetrics` 一次性提取，
   **分数由代码注入 delta.chapterSummary**（不进 LLM 的 delta JSON 模板，
   规避 LLM 列数/键名漂移）；TS `WriteChapterOutput.tensionMetrics` 同步
   携带（Rust 结构体对齐）。
3. **渲染（双端）**：delta 主链 `renderChapterSummariesProjection` 8→10 列；
   fallback append 路径（TS renderAppendedChapterSummary / Rust
   append_chapter_summary）兜底表头 10 列 + LLM 8 列行尾由代码补两列。
   快照/JSON 面：ChapterSummaryRow 双端加可选字段；Rust 侧
   `skip_serializing_if` 对齐 TS undefined 丢键语义。
4. **告警入审计（双端）**：persistence 后读 chapter_summaries.md →
   `analyzeTensionCurve` → 只保留 chapters 含当前章的告警（区间扩展中报
   一次，连续章不重复入账）→ AuditIssue category=tension-curve + 日志
   `[tension]`。Rust 挂 write_next 审计聚合段（hook 健康之后）。
5. **端点（双端）**：GET `/api/v1/books/:id/tension-curve`——读
   chapter_summaries.md 真相源 → parse → analyzeTensionCurve →
   `{curve, warnings}`；文件缺失返空曲线不报错。TS server.ts + Rust
   ops_routes.rs（mod.rs 注册）。
6. **UI**：`TensionCurveCard` 挂书籍详情（RecallTestCard 先例）——SVG
   双折线（冲突=玫红实线/揭示=天蓝虚线，1/5/10 参考线）+ 图例与评分覆盖
   数 + 告警行（琥珀底 description+suggestion）；缺分书显示引导文案。
7. **sqlite 零改动**：chapter_summaries 表 8 列不动（memory-retrieval
   重建投影从 markdown/结构化 JSON 走，分数自动跟随）。

## 兼容性决策

- LLM 只需在独立节给两个数字（可靠性远高于 10 列表格）；分数缺失
  （旧书/解析失败）行为与旧版逐字节一致。
- 告警按章去重：只有告警区间触及当前章才入账，同一平坦段不逐章刷屏。
