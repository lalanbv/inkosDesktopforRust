# 334 号：作者友好报告契约——三段式通知+异常三分类（328 号规划 P0/G8b）

- 日期：2026-09-12
- 类型：core 契约 + studio 通知文案层（TS+S 单端，G8b 规划范围）
- 规划依据：[328 号对标调研改进规划](../20260911/328_对标调研分析与改进规划.md) P0 项 G8b（WNW W2 报告契约的采纳：三段式定序+异常三分类+禁裸 JSON/traceback）

## 做了什么

1. **盘点**：通知中心 `{level, title, detail}` 单行 detail；通知桥此前对
   `write:complete` 只报"第 N 章已写完"、对一切 `:error` 报裸事件名（"任务出错：
   write:error"）——正是 WNW 批评的裸 traceback 级体验。收尾事件 payload 本身已富
   （write:complete 带 bookId/chapterNumber/status/title/wordCount；daemon:chapter 带
   bookId/chapter/status），无需引擎侧改动。
2. **core 新契约模块** `utils/author-report.ts`：
   - 异常三分类 `auto-handled`（busy/中止等自我恢复）/ `needs-review`（LLM/网络/配额
     等上游依赖）/ `must-handle`（数据状态类与未知），`classifyEngineIssue` 事件+消息
     双重判定；
   - `buildAuthorReport` 三段式定序（完成情况 → 问题与异常耗时 → 下一步建议），
     问题段按三分类分组标注；耗时超 60s 阈值在问题段标注"比通常更久"；
   - `collapseToLine` 单行折叠（去换行/多空白 + 200 字符截断）——禁裸 traceback 的
     落点；
   - `buildTaskReport(event, data)`：引擎 SSE 收尾事件 → 通知的单点契约，覆盖 23 个
     收尾事件名（写章/草稿/审改/修订/重写/文风/导入/同人/雷达/批量/建书），完成类
     出人话完成行（如"《夜港》第 3 章 · 2100 字"），失败类按三分类给口径化下一步
     建议；未知事件返回 null 不通知。
3. **studio 通知桥接线**（App.tsx）：内联 if/else 文案全部替换为 `buildTaskReport`
   单点调用（语言取 `getAppLanguage()`，ja 回退 en），payload 宽松读取、缺字段自动
   降级；error 级别映射：must-handle=error、needs-review=warn（对齐通知中心
   info/warn/error 三级）。
4. **契约导出**：core index 导出 buildTaskReport 等 7 函数 + 4 类型，聊天面/通知面
   可共用同一报告契约（规划"通知中心与聊天共用"落点）。

## 验收

- core：tsc 干净；vitest 205 文件 / 1936 用例全绿（新增 author-report 契约 7 项：
  三段式定序、三分类分组、异常耗时阈值、分类判定矩阵、traceback 折叠、耗时格式化、
  事件→通知映射与未知事件忽略）。
- studio：tsc 干净；vitest 90 文件 / 793 用例全绿（通知桥回归零破坏）。
- 引擎侧（core/rust）零改动——收尾事件 payload 兼容读取，双端广播不变。
