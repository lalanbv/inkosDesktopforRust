# 341 号：信息差账本——truth 类目+泄密机检+废笔机检入 continuity（G7a，Phase B 批次二）

- 日期：2026-09-12
- 类型：双端引擎增强（TS core + Rust 引擎，golden 向量先行）
- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G7a（WNW W5 信息差登记+泄密机检的采纳）

## 做了什么

1. **新 truth 类目** `story/info_gaps.md`（作者可手改，每条一节 + 平铺 key: value 行，
   对齐防呆方言）：
   - `secret` 秘密内容；`knows` 知情角色（逗号/顿号分隔）；`readerKnows` 读者是否已知；
     `registeredAt` 登记章；`keywords` 泄密扫描关键词。
   - `parseInfoGapsMarkdown`（手改容错：坏节跳过/缺字段空值）+ `renderInfoGapsMarkdown`
     （初始化/写回）双端互逆。
2. **泄密机检** `detectSecretLeaks`（维度 38 泄密机检的本地预扫描）：
   readerKnows=false 且已登记（registeredAt ≤ 当前章）的秘密关键词命中即候选；
   命中窗口（前后 24 字）含对白引号（「」『』“”‘’"）→ `inDialogue=true`
   （对白/内心戏泄密风险最高）；排序 inDialogue → 命中数 → gapId → keyword。
3. **废笔机检** `detectReaderRedundancy`（维度 39）：readerKnows=true 的秘密关键词
   再次出现即废笔候选（向读者复述已知信息）。
4. **continuity 审计维度接入（双端）**：
   - 维度表扩至 39：38 泄密机检 / 39 废笔机检（TS DIMENSION_LABELS + Rust
     dimension_labels 39 项，维度号 33–37 此前已被占用故顺延）。
   - `auditChapter` 并行读取 `story/info_gaps.md`；账本存在 → 维度 38/39 激活 +
     账本全文作为 `infoGapBlock` 注入审计 prompt（对齐 canon/memo 块模式）。
   - `renderInfoGapAuditNotes`：本地机检摘要的人话渲染（供审计上下文/聊天面），
     无命中返回 undefined。
5. **共享 golden 向量** `info-gap-vectors.json`（22 例：解析 3 + 渲染 1 + 泄密 4 +
   废笔 2 + 审计文本 2 + 契约[维度号/truthFile/对白窗口 24 字]）。TS 6 项 + Rust
   差分 6 项（第十个共享守门域）。

## 实现纪律修正（本号新增两条）

- **排序禁 localeCompare**：关键词含中文时 `localeCompare` 结果随运行环境 locale
  漂移，破坏双端 golden 一致性——统一纯码元比较 `comparePlain`。
- **全量 cargo test 禁同命令双跑**：本号复现 335 号"600s 超时"假失败——同一条
  shell 命令里两个全量 `cargo test` 管道串行实际并发抢锁。纪律：单次跑、输出
  落盘（/tmp 日志）再 grep 分析。
