## 做了什么

1. **MemoryDB `retrieval_chunks` 表双端**（对齐 quality_debts 先例）：chunk_id 主键 +
   source/fingerprint/dim/vector(JSON 数组文本——双端序列化一致最稳)/created_at +
   source 索引。CRUD：`upsertChunkVector`（幂等）/`listChunkVectors`（坏 JSON 行跳过）/
   `chunkVectorCount`。**关键发现**：FTS 索引与 MemoryDB 同库（story/memory.db）——
   混合检索在同一 SQLite 文件内完成，零跨库成本。
2. **混合检索端点双端** `POST /books/:id/hybrid-search` {query, k?, embedding?}：
   - FTS5 路径：LocalSearchIndex.search(scope=story-memory, limit=k×2)；
   - 语义路径（请求体带 embedding 配置时）：embed(query) → chunk 向量表载入 →
     topKBySimilarity → 排名；embedding 调用失败自动降级 fts5-fallback；
   - 347 号 RRF（k=60）融合，返回 `{fts, semantic, fused, mode}`。
   无 embedding 配置 → mode=fts5-fallback、纯词法结果——现有行为逐字节不变。
3. **Doctor 检索健康（双端）**：`checks.retrieval = { mode, embeddingConfigured }`
   ——inkos.json `llm.embedding` 配置存在 → semantic 能力，否则 fts5-fallback
   （retrieval trace/健康入 Doctor 的规划项落地）。
4. **召回测试面板（S）**：`RecallTestCard` 挂书籍详情——查询输入 → 混合检索 →
   模式标注（语义+词法混合 / 词法降级）+ 融合排名列表（RRF 分数 + 语义/词法
   来源标记），规划"召回测试面板"落地。
