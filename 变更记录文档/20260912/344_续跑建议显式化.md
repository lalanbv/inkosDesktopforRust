# 344 号：续跑建议显式化——五动作决策表+双端错误消息接线（G9，Phase B 批次三首项）

- 日期：2026-09-12
- 类型：双端契约层 + 消息接线（TS core + Rust 引擎，golden 向量先行）
- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G9（WNW W3 失败隔离原则采纳：
  正文已存→只补回灌；正文手改→必须确认，永不自动覆盖）

## 做了什么

1. **续跑建议决策表** `resolveResumeAdvice`（确定性、双端共享 golden）：中断现场 →
   五种显式建议（顺序即优先级）——
   1. 无正文 → `start-fresh`（从第 1 章开始）
   2. 正文手改 → `confirm-manual-edit`（**永不自动覆盖**，作者确认前不做任何自动动作，
      优先级高于重写与回灌——覆盖手改比重写半章更危险）
   3. 最后一章不完整 → `regenerate-chapter`（resumeFrom=本章，此前章节保留）
   4. 状态未回灌 → `resync-only`（只需 resync_chapter_state 补回灌，无需重写正文）
   5. 其余 → `continue-next`（resumeFrom=下一章）。
   每条建议携带可直接执行的 `resumeFrom` 章号与 zh/en 人话 title/detail。
2. **`formatResumeHint`**：只有"已有章数"时的最小建议文案（错误消息拼接场景）。
3. **双端错误消息接线**：已有章时的 resumeFrom 必填错误从"裸指令"升级为
   "现状 + 显式建议 + 执行指令"三段——TS `agent-tools.ts` import_chapters 校验、
   Rust `import_chapters_tool.rs` 与 `agent_production.rs` 同款消息。聊天面与任务流
   的该错误即续跑建议（12 章示例：「already has 2 chapter(s). Continue from the next
   chapter: … continue from chapter 3 (resumeFrom=3). …」）。
4. **chapter-state-recovery 扩展测**：新增桥接测试——state-degraded（正文已存、状态
   未回灌）→ `resync-only`（resumeFrom=下一章，detail 含 resync_chapter_state）；
   手改+落后+不完整并发 → `confirm-manual-edit` 门（阻断一切自动动作）。
5. **共享 golden 向量** `resume-advice-vectors.json`（15 例：决策表 11 例覆盖五动作
   全部 + 优先级交叉[手改 vs 回灌/手改 vs 重写] + 负数钳制 + detail 关键语义
   [never be overwritten / 无需重写正文 / 此前章节保留 / resumeFrom=] + hint 拼接
   2 例 + 契约冻结[neverAutoOverwriteManualEdit=true]）。TS 4 项 + Rust 差分 3 项
   （第十二个共享守门域）。
