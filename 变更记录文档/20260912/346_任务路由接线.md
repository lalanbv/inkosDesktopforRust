- 规划依据：[328 规划](../20260911/328_对标调研分析与改进规划.md) G16 后半；契约层见 [345 号](345_按任务模型路由.md)

## 做了什么

1. **agent → 任务映射契约** `TASK_AGENT_MAP`（TS）/`agent_task()`（Rust）：
   writer/planner/architect → writing；continuity-auditor/consolidator/
   state-validator → review；reviser → repair；radar/chapter-analyzer → analysis。
   detect 走外部检测服务（无 LLM model 概念），不在映射内。
2. **TS 管线接线**：`PipelineConfig.taskRouting`（optional）；
   `resolveOverride(agent)` 在**显式 modelOverrides 未命中**后查
   `resolveAgentModel`——路由给出 model 覆盖即替换全局 model（client 不变）。
   优先级：agent 显式覆盖（既有用户配置）> 任务路由 > 全局 model。
3. **Rust 管线接线**：`AgentRouter.task_routing` 字段 + `with_task_routing`
   builder；`resolve(agent)` 在 overrides 未命中分支先查
   `resolve_agent_model`（task_routing.rs 新增，含 agent_task 映射），
   命中即替换 default.model。effective_router 构造时读取
   `.inkos/task-routing.json` 注入（mtime 缓存键已有 inkos.json，
   routing 文件随 `.inkos` 变更走启动态/文件重读）。
4. **设置面集中管理（双端端点 + UI）**：
   - 端点：`GET/PUT /api/v1/task-routing`（读写 `.inkos/task-routing.json`，
     PUT 校验 routing 为对象）。
   - `TaskRoutingPanel` 挂项目设置页：五类任务各一行 model 输入
     （留空 = 全局模型），保存至项目级路由文件，新任务即时生效。
5. 配置迁移兼容由 345 号契约保证：无 routing 文件/字段时全部回退全局模型。
