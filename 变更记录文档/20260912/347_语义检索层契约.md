## 做了什么

1. **盘点**：既有检索 = FTS5 BM25 词法单内核（TS `retrieval/local-search.ts` ↔ Rust
   `utils/local_search.rs`，score = -bm25 双端镜像）；memory-retrieval 的语义精简层
   是 BM25+LLM 精选（244 号），无向量维度。sqlite-vec 扩展引入有依赖风险——
   **确定性替代设计**：单书向量量级（数千 chunk）下，内存余弦 + SQL BLOB 存储完全
   够用且零扩展依赖，混合召回语义不变。
2. **任务驱动查询构造** `buildTaskDrivenQuery`：由章任务单组装查询——goal 主干 +
   outlineNode + mustKeep + threadRefs/hook 记号；去重（大小写不敏感）、每段截 40 字、
   总长截 200 字、上限 8 术语、「；」分隔——不是拿章标题去搜。
3. **向量召回**：`cosineSimilarity`（零向量恒 0、维度不一致防御性 0）、
   `topKBySimilarity`（降序 + 并列按 id 码元序 + 维度不匹配跳过 + k 截断）。
4. **混合召回融合** `reciprocalRankFusion`（RRF k=60）：语义排名与 FTS5 BM25 排名
   融合，双路命中加成、来源标注（semantic/fts5）、分数降序并列 id 码元序。
5. **降级契约** `resolveRetrievalMode`：embedding 可用 → `semantic`（向量+FTS5 混合）；
   未配置或调用失败 → `fts5-fallback`（现有词法单内核行为逐字节不变）——绝不因
   语义层缺失而不可用。`EmbeddingClient` 端口接口已声明（实现后续号接入）。
6. **共享 golden 向量** `semantic-retrieval-vectors.json`（24 例：查询 5 + 余弦 6
   [正交/反向/零向量/维度不匹配/已知值] + topK 4[截断/并列 id 序/维度跳过/k=0] +
   RRF 3[双路融合/单路透传/双空] + 模式 3 + 契约冻结）。TS 6 项 + Rust 差分 6 项
   （第十四个共享守门域；浮点相似度按 1e-9/12 位容差断言，id 顺序严格相等）。
