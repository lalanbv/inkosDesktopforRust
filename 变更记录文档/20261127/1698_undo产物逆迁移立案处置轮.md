# 1698 号：undo 产物逆迁移（R63 立案处置）——runtime/drafts 前导号产物随 undo 逆映射迁回，双端同口径

## ① 实现（双端同构，undo 事务写面追加产物迁移段）

- **章号映射**（指纹配对）：`current` 章号 n → 目标 `tail.before` 章号 m（同指纹配对；仅不同号入映射）。
- **现盘产物随号迁回**：runtime（`chapter-NNNN.*`）与 drafts（`NNNN_*`）两子目录逐文件解析前导号——**不走 collectArtifactFiles/章解析器**（`chapter-NNNN.*` 非章文件名语法，解析器不识别→首轮实现 collect 空转的根因；改名 `chapter-0004.`+`.trace.md` 双点拼接缺陷也是本轮探针顺手抓出——见④）——`n→m` 的文件 rename 到目标名（runtime 后缀 `chars().skip(12)` 保持单点，与 Rust 同组装）。
- **merge 撤销的 trash 产物回位**：被删章（removed 号）产物在 `.trash/<sub>/`（批一随正文进 trash）——undo 时按前导号==removed 从 trash rename 回 `story/<sub>/`（trash 副本保留=永不硬删）。
- 无配对的产物原地保留（产物非正典，错位比丢失好）。
- TS 写进 `commitAtomicFileSet` 集合（writes+deletes 单提交）；Rust 直接 rename+回位失败 `rollback_undo`（与 undo 写面既有错误路径同款）。

## ② 顺手抓出批一真缺陷（TS 产物 runtime 命名双点）

undo split 交互测试探针实证：split 后产物落名 `chapter-0004..trace.md`（双点）——`paddedRuntimePrefix(next)`（自带尾点）+`name.slice(12)`（起始点）拼接所致；读侧 `chapter-NNNN.` 单点匹配不识别=产物孤儿。**三处同款组装全修**（split/merge/undo 段统一 `chapter-${pad4}${slice(12)}` 单点；Rust 侧 skip(12) 单点无此 bug 不动）。探针另证：runtime 残留双点文件说明**用户实际跑过 TS split 的项目可能已有双点产物文件**（读侧不识别——立案：双点产物文件迁移/清理面审计，暂不定性）。
