## 一、盘点方法

- 双端逐面对照：TS 六端点（server.ts /api/v1/translations*）× Rust 处理器
  （translation_routes.rs）；存储（core translation/*.ts 与 engine-rs translation/*.rs
  的路径与 JSON 模式）；管线语义（llm-model/runner/review/revision/export）；UI 读取面
  （TranslationManager.tsx）；既有测试与 golden。
- 关键事实二次核验（规划前亲查，防转述失真）：TS 详情章节带 translatedSegments/
  reviewSummary/observations（server.ts 8485-8487），Rust 章节带 status 无三字段；UI 读
  `manifest.chapters[].translatedSegments`（TranslationManager.tsx:433）——**默认 Rust
  后端译后仍显示「 segments · 0 observations」（960 号 GUI 走查即见该空计数）**。

## 二、结论摘要

- 六端点双端在位、形状大体同，但**数据源不相交**（TS works/、Rust translations/）且
  manifest 模式互斥（TS strict 拒 Rust 的 status、Rust 必需 status 拒 TS）——同一项目
  在两引擎下互不可见。
- 12 项差距（用户可见 6 项：G1 详情计数空、G5 标题不译、G6 段校验静默丢弃、G7 审校
  2.0、G8 修订域缺失；内部 6 项）。
- 五期：P1 契约补形（零存储迁移，967 号起）→P2 协议+校验+标题→P3 审校 2.0→P4 存储
  迁移（跨引擎互读为硬验收）→P5 修订/create 输入/导出。
