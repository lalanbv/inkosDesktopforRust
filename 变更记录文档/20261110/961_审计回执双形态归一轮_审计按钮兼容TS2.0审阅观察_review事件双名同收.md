# 961 号 · 审计回执双形态归一轮：章节审计按钮兼容 TS 2.0 审阅观察 + review:complete 事件双名同收

> 959 族扫备案出口②：上游 TS 2.0（fb8c8e3e「replace legacy quality state
> machine」）把 `POST /books/:id/audit/:chapter` 改为返回审阅观察
> `{summary, observations}` 并改发 `review:complete`，但**上游自己的**书籍页审计
> 按钮（c7ac2f23 起未动）仍读 `passed/issues`、事件面仍只收 `audit:complete`——
> 上游自身 UI/服务端不一致。Rust 默认后端返 1.x `{passed, issues, …}` 与 UI 一致；
> Node 回退端每次审计都弹「Audit failed: 0 issues」（无论审阅结果），且审阅完成
> 事件被 SSE 名单丢弃。
> 验证：studio audit-outcome 3/3（新）+use-book-activity/use-sse 17/17（含 golden）
> +typecheck 净+gate:ts 十步全绿+U+FFFD 净；Rust 零改动。

## 一、方案取舍

- 不改 Rust：Rust 单向收敛到 `{summary, observations}` 会立即破坏默认后端的
  审计按钮（UI 读 passed/issues），而 Rust 长篇审阅链产出 observations 需移植
  2.0 review_chapter 能力（独立大工程）。
- UI 侧双形态归一（两端都对）：新纯函数 `lib/audit-outcome.ts`——
  - `observations` 为数组（TS 2.0）：`assessment === "issue"` 计问题数（与上游
    翻译回执「review issue(s)」同口径），零问题即通过；
  - 否则（Rust 1.x）：`passed === true` / `issues.length` 原样——默认后端文案
    逐字不变；
  - 畸形回执（null/非对象/空观察元素）安全归一不抛。
- 事件面：`STUDIO_SSE_EVENTS`（+golden）与书籍视图/书目刷新集补
  `review:complete`（Rust 仍发 `audit:complete`——双名同收）。

  标记）→ 恰 2 红（2.0 形态两例均落回旧逻辑），复原后 3/3、残留 0。
- `use-book-activity.test.ts` 补 review:complete 触发书籍视图与书目刷新断言；

  （视图刷新断言+golden 精确快照），pop 后全绿。
