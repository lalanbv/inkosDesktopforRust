## 一、真根因链（活体探针逐层定位）

1. **startChapterNumber 必填缺失（产品 bug，本轮最大修复）**：studio write-next 处理器的 capability 调用不传 `startChapterNumber`，而 `WriteChaptersParams` 契约**必填**（"must match the next unwritten chapter"）→ TypeBox decode 恒拒 → **2.0 TS 腿 write-next 从未成功过**（698 号「TS 停在播种态」的一句话根因）。修复：处理器取 `state.getNextChapterNumber(id)`（durable 链权威）传入。修复后 node 写链全链打通（≤10s 产第 2 章，mock 12 工具调用全路由）。
2. **状态应用双层同名词路由（mock 修复）**：状态应用走 `submit_state_validation` **双层同名词协议**——①投影复查层（StateProjectionReviewToolSchema：corrections/observations，sys 含 "exact proposed record"）②和解判定层（StateValidationToolSchema：reconciliationRequired/reportMarkdown，sys 含 "reconciliationRequired="）——mock 单路由响应错层 → WORKER_SCHEMA_INVALID → 纠正 6 次全败 → "remained invalid" → 状态应用放弃（state 空/rows[]/lastApplied 0 实锤）。修复：按 sys 锚点双层分派。修复后状态落地（rows/chapter/lastApplied 全就位）。

## 二、连带组件

- **HarnessIdSchema 统一安全字符法**：旧 ASCII 正则拒中文书 id（镜花水月），同文件 WorkResourceIdSchema 与 rust 腿均接受——写链 episode/work id 派生自 bookId 时中文书恒拒（contract-diff 活体实证的第二层根因）。统一为「禁路径危险字符」语义（CJK 合法），双子 schema 不再分裂。
- **可观测性三件**：registry decode 失败带 rawInput+TypeBox 错误明细+schema JSON（裸 "Unable to decode" 无法排障）；server write 失败落栈日志；mock 兜底命中探针（WALKTHROUGH_MOCK_DEBUG=1）。
