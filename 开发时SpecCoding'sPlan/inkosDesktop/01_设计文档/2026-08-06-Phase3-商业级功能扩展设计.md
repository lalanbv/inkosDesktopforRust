# Phase 3: 商业级功能扩展设计

**日期**: 2026-08-06  
**版本**: v0.5.0-phase3

## 1. 目标与范围

### 1.1 核心目标

在 Phase 2 生产就绪基础上，构建三大商业级核心能力：

1. **工作区管理（Workspace）** - 多项目并行工作
2. **配置分层系统（Layered Config）** - 企业部署与个性化
3. **增量更新优化（Delta Updates）** - 降低流量成本 80%+

### 1.2 商业级要求

- **最佳扩展性**：模块化设计，API 版本管理，插件基础
- **最佳兼容性**：向后兼容单项目模式，降级策略
- **安全可靠**：沙箱隔离，权限最小化，审计日志
- **高性能 0GC**：栈分配，Cow 字符串，无堆分配热路径

### 1.3 技术约束

- Rust 0GC（栈分配、Cow、&str 优先）
- Tauri 2.x API（跨平台一致性）
- 向后兼容（Phase 2 用户零迁移）
- 响应时间：<50ms（UI 操作）、<100ms（后台任务）

### 3.1 工作区管理（Workspace）

#### 3.1.1 数据结构

```rust
// src/workspace.rs

/// 工作区 ID（UUID v4，创建时生成）
pub type WorkspaceId = String;

/// 工作区元数据
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Workspace {
    pub id: WorkspaceId,
    pub name: String,          // 用户可编辑名称
    pub created_at: i64,       // Unix 时间戳
    pub last_used: i64,        // 最近使用时间
    pub projects: Vec<String>, // 项目路径列表
    pub engine_version: Option<String>, // 独立 Engine 版本（None = 全局默认）

/// 工作区列表（workspaces.json schema）
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
pub struct WorkspaceList {
    pub workspaces: Vec<Workspace>,
    pub active_id: Option<WorkspaceId>, // 当前激活工作区
}
```


#### 3.1.4 向后兼容策略

- **迁移逻辑**：首次启动检测 `projects.json`（旧格式），自动迁移为默认工作区
- **单项目模式**：`workspaces.json` 不存在时，自动创建默认工作区（ID = "default"）
- **数据保留**：迁移后保留原 `projects.json`（备份），用户可回退旧版本

### 3.2 配置分层系统（Layered Config）

#### 3.2.1 三层配置架构

```
优先级（高 → 低）：
1. 项目级（project/.inkos/config.toml）
2. 工作区级（app_data/config/workspace-{id}/config.toml）
3. 系统默认（app_data/config/default.toml）

合并规则：高优先级覆盖低优先级，未定义键继承下层
```

#### 3.2.2 配置项定义


### 3.3 增量更新优化（Delta Updates）

#### 3.3.1 增量更新流程

```
1. 检查更新
   ├─ 获取 manifest.json（包含 delta 信息）
   ├─ 对比 current_version vs latest_version
   └─ 决策：增量 or 完整包

2. 下载增量包（fallback 到完整包）
   ├─ 优先：delta_{current}_{latest}.patch（2-5MB）
   ├─ 降级：full_{latest}.tar.gz（30MB）
   └─ 校验：SHA256

3. 应用增量（<100ms）
   ├─ bsdiff apply（engine/versions/{latest}/）
   ├─ 验证完整性（manifest.json + 二进制校验）
   └─ 原子替换（符号链接 current/ → versions/{latest}/）

4. 回滚保障
   ├─ 失败场景：校验不通过、应用失败
   ├─ 自动回滚：删除 versions/{latest}/
   └─ 降级重试：下载完整包
```

#### 3.3.2 数据结构

```rust
// src/updater/delta.rs

    pub full_checksum: String,        // 完整包 SHA256

```

## 4. 性能与安全

### 4.1 性能目标

| 操作 | 目标延迟 | 约束 |
|------|----------|------|
| 工作区切换 | <50ms | 栈分配，无 I/O |
| 配置合并 | <10ms | Cow，懒加载 |
| 增量下载 | 取决于网络 | 进度反馈 |
| 增量应用 | <100ms | 内存映射，流式处理 |

### 4.2 0GC 保证

- **工作区**：`Vec<Workspace>` 预分配容量（10 个），避免扩容
- **配置**：`Cow<'static, str>` 键名，`Cow<'a, Config>` 合并结果
- **增量更新**：`mmap` 文件，流式 bsdiff，无完整加载

### 4.3 安全措施

- **配置验证**：TOML 解析 + 类型检查 + 业务规则
- **增量完整性**：SHA256 校验（patch + 应用后二进制）
- **原子操作**：`tempfile` + `persist`（配置写入、Engine 替换）
- **审计日志**：工作区切换、配置修改、更新操作（tracing 集成）
