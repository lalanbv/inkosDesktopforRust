## §1 R50 批二：docx 导出——零新依赖最小 OOXML 路径

### 1.1 路径定案与证据链

- **定案**：双端零新依赖——Rust 复用 `StoredZipWriter`（method-0 stored 容器，`export_artifact.rs:367-448`，EPUB/MdZip 同款）；TS 复用 jszip 3.10.2（`generateAsync({compression:"STORE"})`，md-zip 链同款）。**不引入** docx npm / docx-rs（深化一 K2/K3：duel 逐位比对通道保全+供应链面零新增）。
- **证据链**：最小包=4 part（ECMA-376/LoC/Microsoft Learn 三源）；ZIP 规范允许 stored 条目且 Word 一般接受（社区实证：开档失败案例归因结构问题——缺 Content_Types/多包根目录——而非压缩方法）；EPUB 已用 StoredZipWriter 且阅读器接受=OPC zip 族先例。
- **退路**（个别阅读器拒开 stored 时）：TS 腿 jszip 切 DEFLATE；Rust 腿 StoredZipWriter 无压缩能力——**不对称面备案**：届时 Rust 端补 deflate 或 docx 格式只走 TS 腿（引擎端返回结构化 part 集由壳侧打包的形态备选，先不展开）。

### 1.2 产物结构（4 part，条目序固定=duel 逐位可比前提）

```
[Content_Types].xml        ← 声明 word/document.xml 主件 mime + rels/xml 扩展默认
_rels/.rels                ← officeDocument 关系 → word/document.xml
word/document.xml          ← w:document/w:body：卷=Heading1 段、章=Heading2 段、正文=Normal 段
word/styles.xml            ← Title/Heading1/Heading2/Normal 四样式 + rFonts w:eastAsia 中文字族声明
```

- 章内正文按空行切段（与 md-zip 的章文件形态对齐：一空行=一段）；不落 docProps（core.xml 书名元数据挂批三观察，先守最小集）。
- `chapter_filter` 复用 1645 尾参语义（approved_only 后二次过滤）；无 volumeId 时章全部 Heading2 直排（未分组不造 00_ 卷标题——与 md-zip 的 `00_ungrouped` 目录形态**有意不同**：docx 目录树无目录语义，未分组章直排更符合 Word 阅读习惯，此差异写入 duel 断言说明）。

### 1.3 纯函数双端镜像（沿 md_zip_entry_path↔mdZipEntryPath 惯例）

| 函数对 | 语义 | golden 组 |
| --- | --- | --- |
| `docx_escape_xml` ↔ `docxEscapeXml` | XML 五实体转义（`& < > " '`） | 中文正文/引号/连续实体/空串 |
| `docx_paragraph_xml` ↔ `docxParagraphXml` | (styleId, text)→`<w:p>` 串（pPr 样式引用+rPr eastAsia+转义文本） | 标题/正文/空段/多段拼接 |
| `docx_document_xml` ↔ `docxDocumentXml` | sections（卷/章/段树）→完整 body XML | 卷+章嵌套/未分组直排/chapter_filter 子集 |

- 转义/换段/样式三组各 ≥4 向量；向量含中英文混排（章标题含中文+数字）。
- **XML 生成纪律**：属性序固定（双端同序=字节可比）、无缩进无注释（最小产物）、UTF-8 无 BOM。

### 1.4 接线点清单（批二施工全量，含 1645 遗留缺口收口）

1. `ExportFormat::Docx` 变体 + `parse("docx" / "application/vnd.openxmlformats-officedocument.wordprocessingml.document")`（`export_artifact.rs:23,32-38`）；TS 字符串联合加 `"docx"`（`export-artifact.ts:40`）。
2. `build_export_artifact` Rust/`buildExportArtifact` TS 各加 Docx 分支（复用 MdZip 的卷分组投影——`md_zip_entry_path` 的卷序/分组逻辑在 docx 侧复用为 sections 树构建，不复制实现而是抽共享纯函数或调既有件）。
3. 端点零改动（`format` 透传既有 `ExportQuery`/server.ts query 链）；UI `ExportPreviewCard` 格式 radio 第五选 `docx`（`ExportPreviewCard.tsx:12-17`）。
4. **1645 遗留收口**：`createExportBookTool` format 三字面量扩 `md-zip/docx` + `chapters` 参数接线（`export-book.ts:6-11`；两处 export-save 调用点 chapter_filter 恒 None 的接线缺口一并清偿——`books_state_routes.rs:1161`、`sub_agent_tool.rs:528`）。
5. e2e/测试：export 既有面扩展 docx 用例（双端各 ≥2：全量/章子集）。

### 1.5 验收

- **golden 三组**（§1.3）；**duel**：双端同 fixture 书导出 docx→解 zip→条目集相等+逐条目字节相等（stored 无压缩=直接可比；条目序固定+无时间戳键沿 MdZip 先例——StoredZipWriter 时间戳字段形态以 duel 实跑结果为准，若写时间戳则比对剥时间戳字段）。
- **活体开档**：`textutil -convert txt out.docx`（macOS 本机自动可读性用例，进测试脚本）；Word/WPS/Pages 三端人工开档走查备案（变更记录定性描述，IAB 惯用形的文档面等价）。
- 中文面：`w:eastAsia` 声明后中文标题/正文渲染正确（人工走查项）；RFC5987 中文书名下载沿既有面零改动。
- 负路径：空书导出（零章=空 body 仍合法 docx）、chapter_filter 全排除。

## §2 R51：写作目标与日历——账本先行 + 月历热图

### 2.1 数据模型（三键，存量零迁移）

| 键 | 落点 | 语义 |
| --- | --- | --- |
| `targetWords` | book.json **顶层**（与 `targetChapters/chapterWordCount` 同族，`book.rs:169-172` 对称位） | 全书目标字数（可选；parity 快照扩展沿 1644 惯例——键集+存量行不出键双守卫） |
| `dailyGoalWords` | 应用设置面（全局默认，书级覆盖挂观察） | 日目标字数 |
| `deadline` | book.json 顶层可选 | 截止日（投影日需求用） |

- **不落 writing 段**（顶层同族惯例修正，v10 主文档 §2#6）；「组织不注入」红线自动满足（目标键不进装配）。

### 2.2 日产出账本（本轮新增设计——修正现状语义缺口）

- **现状缺口**：日聚合=当天 `updatedAt` 章整章 wordCount 求和（`writing-stats.ts:66-76`）——①改稿日整章重复计入（10 万字章改一段=当日 +10 万）②UTC 切日与写作者本地日错位（`dateOf` 取 ISO 前缀，`utc_now_iso` 基座）。
- **账本形态**：`books/{id}/.inkos/writing-log.jsonl` append-only（原子写惯例），每行 `{ts, chapterNum, before, after}`——章保存时对比上次 wordCount 追加（写点挂 persist chapter artifacts 统一收口；结构操作/纯保存零变化不记）。
- **日聚合语义**：`日净增 = Σ 该本地日记录 (after-before)`（可为负=删稿日；负日热图着色但 streak 判定按「达成=净增≥日目标」）。**本地日切分**：dayKey 由调用端本地时区计算后入参纯函数（纯函数不吃时区环境=可测性，时区边界 golden 用例直喂边界 dayKey 序列）。
- **隐私/体量**：仅元数据（无正文）；jsonl 滚动清理挂观察（满一年再定，M1 保留窗对照）。

### 2.3 纯函数双端镜像

| 函数对 | 语义 | golden 组 |
| --- | --- | --- |
| `daily_word_delta` ↔ `dailyWordDelta` | 记录流+dayKey→日净增表 | 跨日记录/负增量/同章多次/空流 |
| `goal_streak` ↔ `goalStreak` | 日净增表+日目标→连续达成天数 | 今日未写不计/断链重置/首日 |
| `expected_finish` ↔ `expectedFinish` | (当前字数,目标,日节奏)→预计完成日 | 超前/落后/已达成 |

- R13 面板既有聚合（近 30 天）不动——账本消费是**新增档**，WritingStatsCard 扩展不重构。

### 2.4 UI（WritingStatsCard 扩展，Dashboard 挂载点不变）

1. **目标进度条**：书字数/targetWords（NaNoWrMo 形态）+deadline 时显示「按当前 pace 的预计完成日 vs deadline」双线。
2. **月历热图**：当月日格=日净增数，达成日着色（档位=0/未达/达成三档起步，L3 月历先行）；hover=当日明细（标题/L2）。
3. **streak 数字**：连续达成天数直显（无徽章无积分——L4/L5 不采裁定）。
4. 目标设置入口：BookDetail 目标卡（targetWords/deadline 编辑）+设置面日目标。

### 2.5 验收

- golden 三组（§2.3，时区边界=本地 23:59/00:01 记录归日正确性由 dayKey 入参直测）；parity：`targetWords/deadline` 键进 book parity 快照双守卫（1644 惯例）；存量书零迁移（无键行为不变）。
- 交互测试：目标编辑保存/热图渲染（月首日偏移）/进度条边界（超 100% 封顶显示）。
- duel：writing-log 聚合端点双端同构（若新增聚合端点；或沿 writing-stats 双端异构声明——TS 聚合/Rust 行数据回退的既有形态，账本行数据走 Rust 端点扩展）。
