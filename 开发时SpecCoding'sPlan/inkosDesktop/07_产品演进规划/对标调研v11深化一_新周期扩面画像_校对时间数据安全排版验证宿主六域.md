## 证据分级（本轮新增纪律）

本轮取证中检索摘要两次与原始出处不符（Tauri#5680 被摘要称「已采纳 trash crate 结案」，原帖实为 2022 年至今 Open；vale「不支持 CJK」在官方文档 FAQ 查无此条）。为避免把摘要级信息写成事实，每款标证据等级：

- **A 级**＝一手出处已核（官方文档/issue 原帖/GitHub API/crates.io），或本仓文件直读。
- **B 级**＝检索摘要级（多源一致但未逐字核原帖）。
- **C 级**＝常识性产品知识或架构推断，未取证——只作背景，不单独支撑立项。

## O. 文本校对与规则检查（5 款 + 2 简提）——v8 十二域矩阵未设的域

### O1 vale（vale-cli/vale，开源 6.4k★，MIT，Go）——证据 A

- 定位：把写作规范变成「类代码 lint」的散文检查器（`.vale.ini` 选样式集，规则=YAML；被 AWS/Microsoft/GitLab 等文档团队使用）。
- 核心机制：**十二类检查**（官方文档目录核实：existence / substitution / occurrence / repetition / consistency / conditional / capitalization / metric / readability / spelling / sequence / script）+ 词表文件（接受/拒绝）+ 样式可打包分发（`vale sync`）。
- 判定：**改造采（检查类型学）**。其中 `existence`（词表命中）/ `substitution`（替换建议）/ `occurrence`（频次上限）/ `repetition`（叠词）/ `consistency`（写法一致）五类是纯字符串语义，不依赖分词与词性，可直接平移到中文——本仓以「用户词表 + 规则类型」的数据形态落地本地检查层。**不采本体**：Go 二进制 + 英文语料导向；「对无空格文字适配有限」在官方 FAQ 查无条目（已核），「token 级检查以空白切分为前提」属架构推断（C 级），不作定论。

### O2 LanguageTool（languagetool-org/languagetool，开源 15.3k★，LGPL-2.1，Java）——证据 A/B

- 定位：多语言规则型语法/拼写检查的事实标准（XML 规则模式 + n-gram）。
- 判定：**不采**。两条硬理由：①运行时=JVM，本机 `/usr/bin/java` 为 macOS 占位 stub、无 JRE（已实跑核实）；②中文规则集极薄（B 级：规则引擎按空格分词的 token 序列设计，中文需分词与拼音转换适配）。**佐证结论**：通用规则型检查器在中文面没有可借用的现成件——中文确定性检查只能自建词表层。

### O3 橙瓜码字（商业，中文网文码字工具）——证据 B

- 定位：面向网文作者的码字工具（实时同步/云备份、起名与大纲助手、时光机、离线备份、多维度统计等）。
- 核心机制：**章节敏感词/违禁词检测 + 自定义词库**（作者按平台要求自行添加关键词）——发布前自查的刚需形态。
- 判定：**采（需求形态）**。敏感词自查是国内网文作者发布链路上的硬需求；本仓以「本地词表 + 零 LLM + 零外发」落地，隐私面优于在线检测。「小黑屋强制锁定」「拼字比赛」属强制/游戏化面，**不采**（与 v8 L4/L5 裁定同向）。

### O4 网文平台审核生态（起点 / 番茄，商业平台案例）——证据 B

- 事实：章节违规→屏蔽/封禁；违规段落会在作家助手网页版被标记；存在第三方浏览器扩展「起点章节合规改写助手」做发布前自查；起点问答向作者推荐第三方检测工具。**未证实**两家官方 App 内置发布前敏感词检测（检索无直接证据，如实标注）。
- 判定：**采（风险面认知）**。平台审核是导出/发布链路的外部硬约束——本仓导出预览卡增加「发布前自查」结果 = 导出面（R50）与检查面（新 R）的交点。

### O5 pycorrector（shibing624/pycorrector，开源 6.5k★，Apache-2.0，Python）——证据 A/B

- 定位：中文文本纠错（音似/形似/语法），多骨干（Kenlm → MacBERT → Qwen2.5/7B 微调）。
- 判定：**不采**（模型内嵌与「本地推理运行时内嵌」不采裁定同向；Python 面）。**分工结论**：词表层做确定性、可解释、零成本的检查；语义级纠错（错别字/语法/搭配）留给既有 LLM 审校链——两层不重叠。

### O 简提

- **AutoCrit / ProWritingAid**（商业小说向编辑分析：重复词与短语、副词、被动语态、对话占比、节奏）——C 级；「重复短语/口头禅/标点统计」可并入词表层的统计型规则，整体报告面板不立项（与 R13 面板重叠）。
- **Hemingway Editor**（可读性分级）——英文可读性公式对中文不适用，**不采**。

## P. 时间维一致性（agent 记忆 + 故事时间线，7 款）

### P1 Zep / Graphiti（getzep/graphiti，开源 33.0k★，Apache-2.0）——证据 A/B

- 定位：agent 记忆的时序知识图谱（Zep 论文《A Temporal Knowledge Graph Architecture for Agent Memory》，2025）。
- 核心机制：**双时态**——`valid_at / invalid_at`（事实在客观上何时为真）与 `created_at`（何时被记录）分离；事实过期不删除，而是关闭其有效区间；LLM 负责抽取实体/关系/事件。（其 LOCOMO 基准数字为厂商自报，业界复测差异大——不引用。）
- 判定：**改造采（双时态语义本地化）**。小说事实天然带「剧情时间」：角色在第 N 章死亡、关系在第 M 章改变；账本若只有「当前态」，写到第 N 章时取不到「第 N 章当时为真」的事实。落点=事实的有效章区间 + as-of 章投影纯函数；**不采本体**（图数据库 + LLM 抽取管线——本仓账本是用户主导维护的既有形态）。

### P2 Mem0（mem0ai/mem0，开源 69.4k★，Apache-2.0）——证据 A/B

- 核心机制：轻量记忆层——LLM 从交互中抽取事实并归类为 ADD / UPDATE / DELETE / NOOP 四种操作后再写库。
- 判定：**改造采（记忆操作四分类）**。账本更新需要同样的幂等语义：新事实=ADD、改写=UPDATE 且旧值保留为失效区间、撤销=标记失效——P1 的区间模型靠这四种操作驱动。**不采本体**；评测不引用外部基准，自建 golden。

### P3 Letta（原 MemGPT，开源 25.5k★，Apache-2.0）——证据 A/B

- 核心机制：分层记忆（常驻核心块 / 归档记忆 / 召回）+ agent 自编辑记忆。
- 判定：**已对齐（形态等价）+ 不采自编辑**。本仓分层装配 + ContextLens 即「常驻 / 按需」两层；让 agent 自行改写账本与「账本用户主导」不合，**不采**。

### P4 Anthropic 上下文管理三件套（memory tool / context editing / compaction）——证据 B

- 核心机制：跨会话文件式记忆；`clear_tool_uses` 按阈值自动清理旧工具结果；近上限时摘要重启。
- 判定：**挂观察**。管线长链的工具结果膨胀是潜在的上下文成本面，但本仓尚无「单次写章上下文构成」的定量遥测——触发条件：1660 号用量账本显示 prompt tokens 占比异常时评估。

### P5 Chroma《Context Rot》研究（2025）——证据 B

- 核心机制：18 个模型实验——输入变长即降质，且与相关信息是否在场无关（干扰项与长度双因素）。
- 判定：**采（设计约束的实证依据）**。上下文不是越多越好，支撑分层装配与检索裁剪的既定哲学；对 v11 的新含义：**按剧情时间裁剪事实（P1 的 as-of 投影）同时也是上下文瘦身**——剔除「尚未发生」的事实即减少干扰项。

### P6 Aeon Timeline（商业）——证据 B

- 核心机制：事件**双序**——叙事序（故事里出现的顺序）与时间序（发生的先后）分离；Arc 弧线；实体以参与者/观察者身份挂到事件。
- 判定：**改造采（双序模型）**。本仓「章序=叙事序」天然存在，缺的是**剧情时间轴**——与 R57 场景一等化同族；v11 不新立 R，把「双序」语义补进 R57 的门控触发条件。

### P7 Plottr（商业）——证据 B

- 核心机制：可视化时间线（多情节线并行对比）、30–42 套节拍模板、大纲视图与场景模板。
- 判定：**不采**。规划工具域；本仓节拍 + 大纲已覆盖最小面，「模板数量战」是 v4 沿袭的不采项。

## Q. 数据安全与可恢复性（6 款 + 2 简提）——v8 十二域矩阵未设的域

### Q1 Scrivener 自动备份（商业）——证据 A

- 核心机制：默认「关闭项目时自动备份」，**仅保留最近 5 份**（"Only Keep" 可调或全留）；社区主要抱怨是 5 份偏少。
- 判定：**改造采**。「默认开启 + 保留上限」是写作软件的数据安全底线形态；本仓若做保留策略，默认值不照搬纯数量上限，取「时间窗 × 数量上限」双约束（见 Q5–Q7）。

### Q2 Obsidian 删除文件三选项（商业/个人免费）——证据 A

- 核心机制：删除去向三选一——系统回收站 / 库内 `.trash` / 永久删除；**已知缺陷**：「系统回收站」在 Linux 被忽略（实际永久删除）、Windows/Android 亦有同类报告。
- 判定：**采（库内回收站为主）**。系统回收站跨平台不可靠；库内回收站=纯文件操作、双栈对称、可审计、不依赖宿主能力。默认去向=库内回收站。

### Q3 `trash` crate（Rust 生态件，跨平台系统回收站）——证据 A/B

- 核心机制：Windows `IFileOperation` + `FOFX_RECYCLEONDELETE`；macOS `NSFileManager.trashItem`（另有 Finder 路径，两种各有取舍）；Linux 遵循 FreeDesktop Trash 规范；可选特性支持列出与还原。Tauri 自家的「move to Trash」需求（tauri-apps/tauri#5680）**自 2022-11 开放至今未结**（原帖已核为 Open；检索摘要称其「已采纳本 crate 结案」不成立）。
- 判定：**不采（本周期）**。只有壳腿/Rust 腿可用=双栈不对称面；库内回收站已覆盖主需求。挂观察：用户明确要求「进系统回收站」时作壳腿专属能力评估。

### Q4 VS Code Local History + 文件操作撤销（开源，MIT）——证据 B

- 核心机制：①资源管理器内删除/重命名可 **Ctrl+Z 撤销**（会话内操作级撤销栈）；②Local History 持久保存（用户目录 `History/`，Timeline 视图可恢复已删文件与旧版本）。
- 判定：**采（双层撤销语义）**。持久内容历史本仓已有（章 `.versions` + R53 浏览面）；缺的是**操作级撤销**——结构事务（拆分/合并/重排）提交后的一键回退。

### Q5 JetBrains Local History（商业）——证据 A

- 核心机制：默认保留 **5 个工作日**（按文件被实际修改的工作日计）+ 最大容量上限；跟踪外部改动、删除与重命名。
- 判定：**改造采（保留策略参数化）**。「时间窗 + 容量上限」双约束——`.versions` 当前无限累积的参照解。

### Q6 restic（restic/restic，开源 37.4k★，BSD-2-Clause）——证据 A/B

- 核心机制：`forget --keep-daily N --keep-weekly N --keep-monthly N` **代际保留**；`forget` 只删快照引用、`prune` 才回收数据（两步分离）；`--dry-run` 预演将删清单。
- 判定：**采（代际保留 + 预演语义）**。版本保留策略的执行面=「近 N 份全留 + 按日聚合 + 硬上限」，清理前 dry-run 报告。

### Q7 Syncthing 文件版本（syncthing/syncthing，开源 90.7k★，MPL-2.0）——证据 B

- 核心机制：被替换/删除文件的旧版存 `.stversions`；简单版本=`Keep Files`（保留份数）+ `cleanoutDays`（清理天数）+ 清理间隔。
- 判定：**改造采（cleanoutDays）**。与 Q6 互证：「份数 × 天数」双参数是行业惯例形态。

### Q 简提

- **Git**：版本控制的极端形态；正文正典为纯文本=用户可在外部用 git 管理，本仓不内嵌（既定）。
- **GitHub 删除恢复窗**（约 90 天内可恢复已删文件）——C 级常识，仅佐证「破坏性操作带恢复窗」是普遍惯例。

## R. 排版、打印与 EPUB 工具链（6 款 + 2 简提）

### R1 Tauri / wry 打印能力现状（tauri-apps/wry，开源 5.1k★，Apache-2.0）——证据 A

- 事实：wry#707《Add ability to print webview to pdf silently》2022-09-29 开、**至今 Open、无实现**（原帖已核）；2026-05 的评论点明要害：「silent print-to-pdf is three different code paths, not one feature」（macOS `WKWebView.createPDF` / Windows WebView2 `PrintToPdfAsync` / Linux WebKitGTK 无静默 API）。wry 文档：默认「允许全部下载以匹配浏览器行为」。
- 判定：**PDF 不走壳原生静默路径**（三平台三份代码=不对称面 + 维护面）；`window.print()` + 系统打印对话框「另存 PDF」是零依赖路径。

### R2 Typst（typst/typst，开源 57.4k★，Apache-2.0，Rust）——证据 A/B

- 核心机制：现代排版系统，Rust 实现可作库嵌入；中文面有社区维护的 clreq-gap 文档（对照 W3C 中文排版需求记录差距），并有 `cjk-unshrink` / `cjk-unbreak` 等社区包补断行问题。
- 判定：**不采（挂观察）**。编译期、产物体积、CJK 字体不随包三重成本，对比本仓需求量级=「投稿稿/打印稿」级排版。触发条件：打印样式表路径被真实反馈证明不够时。

### R3 Vellum / Atticus（商业排版工具标杆）——证据 C

- 核心机制：一键成书排版（印刷版 + 电子版），版式选项有限但精修。
- 判定：**不采**。专业排版域；本仓导出面的定位=「交给排版工具的无损中间格式」（docx / epub / md-zip 已齐）。

### R4 Affinity Publisher（2026 起免费）/ InDesign（商业）——证据 B

- 判定：**不采**。仅作「docx 是进入下游专业排版工具的通用门票」的生态佐证——R50 批二 docx 的价值不在本仓排版，而在打通下游。

### R5 Calibre / Sigil / EPUBCheck（开源 EPUB 工具链）——证据 A（星数/许可证）/ B（功能）

- 定位：Calibre 26.5k★（GPL）格式转换与 EPUB 编辑；Sigil 7.1k★（GPL）EPUB 编辑器；EPUBCheck 2.0k★（BSD-3）W3C 官方校验器（Java）。
- 判定：**改造采（验收件）**。本仓 EPUB 导出已做结构校验（mimetype 首位且 stored / container / OPF / spine，`scripts/export-epub-smoke.mjs`）——**未经官方校验器**；EPUBCheck 需 JRE（本机无，已核）→ 不进本机门禁，挂「发布前一次性校验」备案。Calibre 回读是 docx `textutil -convert txt` 的 EPUB 等价物（本机未装，观察）。

### R6 CSS 分页与中文断行（Web 标准）——证据 A/B

- 事实：`@page` 的 `size` 在 Safari/WebKit 处理不正确（mdn/browser-compat-data#23178）；页边距盒（`@top-center` 等）Safari 不支持；`line-break: strict` Safari 8 起支持（避头尾）；`text-spacing-trim` WebKit 未实现标点间隙压缩，Safari 18.4 起支持 `text-autospace`。
- 判定：**采（能力边界清单）**。打印样式表在 WKWebView 下的三条硬约束——页幅由打印对话框选（不靠 `@page size`）、不依赖页边距盒（页码另置）、避头尾用 `line-break: strict`、标点挤压不做。

### R 简提

- **LaTeX / ctex**：不采（工具链与体积）。
- **Paged.js**：观察——将来需要「确定性分页的屏幕阅读视图」时评估。

## S. 验证工程质量（变异 / 属性测试，3 款 + 3 简提）

### S1 cargo-mutant（sourcefrog/cargo-mutants，开源 1.4k★，MIT）——证据 A

- 核心机制：向源码注入小缺陷（变异）再跑测试，找出「实现可被替换而测试不红」的位置；`--in-diff <diff>` 只测 diff 触及的函数（`git diff origin/main | cargo mutants --in-diff -`）；`--baseline=skip`（基线已在外部验证时跳过）；等价变异是不可避免的误报；`#[mutants::skip]` / `--exclude-re` 排除；支持分片。
- 判定：**改造采（增量变异门）**。本仓假绿事故族（audit 汇总行在 stderr 被丢弃、check-routes 正则过匹配、clippy 不带 `-D warnings` 记成 0）共性=「解析/判定逻辑有测试引用，但断言杀不死变异」；1664 号路由覆盖守卫堵的是「零引用」，变异测试补的是「有引用 ≠ 断言有效」。`cargo install` 的开发机工具，不进 Cargo.lock=零供应链面。

### S2 StrykerJS（stryker-mutator/stryker-js，开源 3.4k★，Apache-2.0）——证据 B

- 核心机制：JS/TS 变异测试；vitest-runner 自 7.0 起提供，按被变异文件只跑相关测试；已知问题：Vitest 5 下按测试名过滤可能匹配为空，导致部分变异超时。本仓 vitest 为 `^5.1.0`（已核）。
- 判定：**改造采（先 spike）**。范围限定=双端镜像纯函数所在文件；Vitest 5 兼容性未证→半天 spike 定去留，不兼容则 TS 腿变异挂起、Rust 腿先行。

### S3 fast-check（dubzzz/fast-check，开源 5.3k★，MIT）/ proptest（proptest-rs/proptest，开源 2.3k★，Apache-2.0）——证据 A/B

- 核心机制：属性测试=随机生成输入断言不变量，失败自动收缩到最小反例，固定 seed 可复现；差分测试=两个实现对照同一组性质。
- 判定：**改造采（语料生成器升级）**。本仓 golden 向量目前为手写；改为 fast-check 生成不变量语料 → 落盘 golden → Rust 腿用既有 `golden_*_diff` 回放。**只增 TS 侧 devDependency（fast-check + `@fast-check/vitest`），Rust 侧零新增**；跨语言不要求随机数发生器对齐——落盘语料是唯一真源。

### S 简提

- **insta**（2,988★，Rust 快照测试）：本仓 golden JSON 文件形态与之等价，**不采**。
- **行覆盖率工具**：变异分数比行覆盖率更贴近「断言有效性」——先变异、后覆盖率。
- **cargo-test-prune**（用变异检测冗余测试）：观察。

## T. 桌面壳宿主能力与真壳测试（4 款）

### T1 Tauri WebDriver 官方路径 ——证据 A（官方文档逐字）

- 事实：直接驱动 tauri-driver 时「only Windows and Linux are supported on desktop, as macOS has no WKWebView driver tool available」；官方推荐 WebdriverIO + `@wdio/tauri-service`（「works on Windows, Linux, and macOS」），「By default the service runs an embedded WebDriver server inside your app」，由 `tauri-plugin-wdio-webdriver` 承载。该 crate 在 crates.io：2026-05-01 创建、2026-11-08 更新、13 个版本、稳定版 1.5.1、MIT（已核）。
- 判定：**改造采（真壳冒烟通道）**。macOS 上首次有官方路径能在真 WKWebView 里驱动 Studio。代价=插件进应用（须 debug/dev 构建 feature 门控，release 不编入）+ wdio 工具链（dev-only）。先 spike。

### T2 wry#584（JS 对话框 issue）——证据 B

- 事实：`prompt` 未接线；`alert`/`confirm` 依赖权限；早期版本用注入覆盖脚本实现，但同步语义难保真。
- 判定：**已对齐**。1650 号的源码取证（wry 0.57.3 的 `WKUIDelegate` 不实现 JS 面板方法）与社区结论一致；React 化 + 全仓守卫是正解，不回退原生通道。

### T3 tauri-plugin-dialog（官方插件，本仓壳已依赖）——证据 A（本仓）/ B（API）

- 事实：提供 `message / ask / confirm / open / save` 原生对话框，需 capabilities 授权。本仓 `src-tauri/capabilities/main.json` 已含 `dialog:default`，但 Studio 前端零 `@tauri-apps/plugin-*` 导入（已核）。
- 判定：**不采（前端通道）**。前端保持零壳 API 依赖——浏览器 / IAB / 桌面壳三宿主一致；原生对话框只在壳侧 Rust 代码使用。1650 号 React 化方向复证。

### T4 danielraffel/tauri-webdriver（社区 WKWebView WebDriver）——证据 A

- 事实：30★，2026-02-12 创建、2026-02-17 后无更新（GitHub API 已核）。
- 判定：**不采**。T1 官方内嵌路径已覆盖，社区件成熟度不足。
