## §1 v8 观察清单逐项复查（检索日 2026-11-21）

### 1.1 MCP server 面：观察 → **活跃观察**（本轮唯一处置升级）

- **v8 判定**：随上游 pi 生态定，写作链/手簿暴露为 MCP 工具待评估。
- **v9 新证据**：①MCP 从 Anthropic 提案（2024-11）升格为**事实标准**——DSN 2026 收录其工具生态的依赖/失效分析（学术定级）；②企业级自研 server 出现（Omnissa 终端管理 MCP server 等），商业桌面软件 MCP 化成为惯例路径；③行业叙事从「Prompt engineering」转向「**Context engineering**」——与本项目 composer 七层上下文/G1 检索/ContextLens 的既定哲学同向。
- **本仓地基现状**：R38 工具注册表（`ToolRegistry` + `debug/tools` 端点 + 参数哈希目录）已经是「工具面单源化」形态——MCP server 化的地基已在，缺的是协议适配层（stdio/HTTP transport + schema 投影）。
- **升级理由**：协议形态已稳定（不再是 v8 时的「待观察协议」），触发条件从「等生态定」改为「**等一个真实需求信号**」（如用户/社区请求外部 agent 驱动写作链，或上游 pi 生态发布 MCP 通道）。
- **处置**：活跃观察；触发即按 R40 目录生成器惯例出施工图（工具目录→MCP schema 投影是机械翻译，成本可控）。

### 1.2 Tantivy 嵌入检索：门控阈值不变

- **v9 新事实**：Tantivy 0.26.2（2026-09-08）持续活跃，Apache 2.0。
- **现状变化**：R47 已落地（1640 号）——搜索面用 SQLite **FTS5 持久投影**（`.inkos/chapter-search.db`，materials retrieval.db 同惯用形），P95 ≈32ms 冷/≈20ms 暖 << 200ms 线。
- **判定**：Tantivy 的触发条件收窄为单一「FTS5 量级超阈值」场景（万章级语料/多语言复杂分词需求）；0GC 兼容性（进程内嵌库）维持其作为唯一候选的地位。
- **处置**：维持观察，阈值量化为「章数 ≥5000 或 FTS5 P95 >100ms」时评估。

### 1.3 多端真同步（Yjs/Automerge）：维持观察

- **v9 新事实**：Automerge 3.0 正式发布（官方博客）。
- **判定**：无用户信号；R18 备份导入导出+恢复前快照已覆盖「换机迁移」语义；CRDT 服务的「实时协同」面仍属不采域。
- **处置**：维持观察（Automerge 3.0 为届时优先评估对象，Yjs 仅在实时协同需求出现时评估——仍属不采）。
