## 0. 结论先行

1. **新周期换轴：从「补功能」转到「守住已写出来的东西 + 让测试咬得住」。** v8 的九项功能三天落地，但同一时段路线外交付的 23 个非规划轮里有 9 轮以审查、修复、回座为主；暴露的缺陷里有数据丢失级的（1648 合并重编号丢章、1649 重排恒等成员文件永久丢失）。新周期 P0 因此不是新功能，而是数据安全三件（R58 / R60 / R61）。
2. **数据面有三处不可逆硬删，外加一个漂移缺陷**（均已对到行，见 §2.1）：「驳回」无确认、直接回滚，回滚链对被废章的正文、草稿、快照 `remove_file` / `remove_dir_all` 且忽略错误；「删书」整目录 `remove_dir_all`；结构操作写的章存档因 Rust 版本 id 正则缺 `structure` 而列不出、恢复不了。
3. **验证面补后三环**。1664 号的路由覆盖守卫堵住了「零引用」，它自己的注释写明「有引用不等于断言有效」。v11 按链条往后接：断言有效性（增量变异门）→ 不变量（属性测试语料）→ 真宿主（真壳冒烟）。全仓目前零变异测试、零属性测试、零覆盖率工具。
4. **产品面有两处「在位未接线」，属接线型小件**：事实模型早有 `valid_from_chapter / valid_until_chapter`，但 Rust 归约器改事实时直接删旧值、投影不按有效期过滤（TS 腿却过滤了）；敏感词函数带 `custom_words` 参数，两个生产调用点都传 `None`，且 TS 腿整个没有敏感词检查面。
5. **两条勘误**：v8–v10 文档反复引用的 `docs/catalog/r-slots.json` 登记机制从未建立（实际登记面只剩变更记录标题）；`docs/DESKTOP_WALKTHROUGH.md` 把 Studio Web 层列为「已知不在人工范围的面」，其前提（浏览器走查即可覆盖）已被 1650 号的对话框族证伪一类。

## 2. 差距再基线（1664 之后形态；锚点为本轮直读或子代理核查后经原文复核）

### 2.1 数据安全与可恢复性（最重）

- **驳回=硬删**：驳回钮直接 POST（`packages/studio/src/pages/BookDetail.tsx:1225`，无确认）→ `reject_chapter`（`engine-rs/src/server/books_state_routes.rs:418`）→ `rollback_to_chapter`（`engine-rs/src/state/manager.rs:472`）。回滚先恢复状态快照（只含真相文件与 state JSON，`manager.rs:376`，不含章正文），再对章号大于目标的正文、草稿 `remove_file`（`:510`）、快照目录 `remove_dir_all`（`:522`），错误以 `let _ =` 忽略。管线新写的章不入 `.versions`，被驳回后正文没有任何存档路径。TS 腿同形（`packages/core/src/state/manager.ts:683`；路由 `packages/studio/src/api/server.ts:5997`）。
- **删书=硬删**：`remove_dir_all(book_dir)`（`books_state_routes.rs:320`）；TS `rm(recursive, force)`（`server.ts:8607`）。回收站、`.versions`、快照、export-save 产物（落在书目录内，`books_state_routes.rs:1211`）一并消失，界面只有一个确认框。
- **删最新章是相对安全的路径**：正文 rename 进 `chapters/.trash/`（`engine-rs/src/state/chapter_delete.rs:106-111`）再走同一条回滚链；但没有恢复端点、没有保留期，回滚链仍硬删其后的草稿与快照。
- **结构事务提交后不可撤销**：提交前的 staging 原子保护在位（`engine-rs/src/interaction/chapter_structure.rs:388`），提交后无操作日志、无撤销入口；全仓未找到带「撤销」按钮的提示。
- **漂移缺陷**：Rust 版本 id 正则为 `manual|agent|revision|regeneration|restore`（`engine-rs/src/state/chapter_workspace.rs:83`），TS 为同一表达式外加 `structure`（`packages/core/src/state/chapter-workspace.ts:23`）。结构操作写入的正是 `Structure` 来源（`chapter_structure.rs:428`），于是 `parse_version_id`（`chapter_workspace.rs:269`）对这些存档返回 None——列表跳过、读取与恢复按非法 id 拒绝。
- **无上限累积**：章 `.versions`（`chapter_workspace.rs:139`）与状态快照（`manager.rs:557`）都没有保留或清理逻辑。
- **备份纯手动**：R18 四端点（`engine-rs/src/server/mod.rs:387`）只在恢复前自动留档，未找到定时或事件触发的备份（子代理核查）。

### 2.2 验证工程

- 全仓 manifests 对 `fast-check / proptest / quickcheck / stryker / mutant / coverage / insta` 零命中；`scripts/` 下 36 个脚本无变异、无覆盖率工具。
- 双端镜像纯函数的 golden 向量均为手写（R51 19 向量、R55 两组等）。
- 1664 号路由覆盖守卫：218 条路由 / 184 有引用 / 34 零引用，基线钉 32 条只许缩短；它只堵「零引用」。

### 2.3 宿主能力

- `docs/DESKTOP_WALKTHROUGH.md` 的前提是「Web 层已有三轮真机走查覆盖，本清单只覆盖无法自动化驱动的壳原生面」，§6 把 Studio Web 层列为「已知不在人工范围的面」。
- 壳侧没有任何下载、拖放、剪贴板处理器（`src-tauri/src` 检索零命中）；capabilities 仅四项（`src-tauri/capabilities/main.json`：`notification:default` / `dialog:default` / `core:window:allow-start-dragging` / `window-state:default`）；Studio 前端零 `@tauri-apps/plugin-*` 导入。
- wry 文档口径是默认允许全部下载以匹配浏览器行为，但「导出下载在真壳内可用」在文档面零取证记录；1650 号对拖放的定性（需原生 drag session）也只在浏览器级半程验证。

### 2.4 文本校对

- 非 LLM 规则层存在但只嵌在写作管线里：`validate_post_write`（`engine-rs/src/agents/post_write_validator.rs:264`）的生产调用点仅两处（`pipeline/write_next.rs:796`、`agents/writer.rs:2016`）；章节审计端点是纯 LLM。
- 敏感词：`analyze_sensitive_words`（`engine-rs/src/agents/sensitive_words.rs:120`）做本地子串计数，内置三张写死词表，带可选自定义词表参数；两个生产调用点都传 `None`（`pipeline/merged_audit.rs:69`、`pipeline/write_next.rs:920`），无界面。TS 腿对敏感词零命中。
- 可配置规则面已有两处可借力：`AntiAiRule`（正则、严重度、启停；端点 `engine-rs/src/server/mod.rs:1090`；界面 `AntiAiAndExperiencePanel.tsx`）与 `bookRules.prohibitions / fatigue_words_override`（`engine-rs/src/models/book_rules.rs:112`，只能改原始 markdown）。
- 未找到中文标点检查；术语表只存在于翻译域。

### 2.5 时间维一致性

- 事实模型带有效期：`CurrentStateFact` 有 `valid_from_chapter` 与 `valid_until_chapter`（`engine-rs/src/models/runtime_state.rs:252-258`），但 Rust 腿没用起来：归约器按别名匹配后直接删旧事实（`engine-rs/src/state/reducer.rs:395-402`），投影取值不按有效期过滤（`engine-rs/src/state/projections.rs:314`）。TS 腿过滤了（`packages/core/src/state/state-projections.ts:100-101`）。
- 按章查询 `get_facts_at`（`engine-rs/src/state/memory_db.rs:318`）只有测试在调用；事实装配取整份当前态（`engine-rs/src/utils/memory_retrieval.rs:280`），而摘要与伏笔是章节感知的（`:819`、`:387`）。
- 伏笔有时间性（`HookRecord` 的起止章与五态）；实体卡只有 `first_chapter`，无存活状态与关系历史（子代理核查）。
- 时间线界面是「情节线 × 章号」网格（`engine-rs/src/models/timeline.rs:12`），时间轴只有章序，没有剧情时间。

### 2.6 导出 / 排版 / 打印

- 五格式在位（`engine-rs/src/interaction/export_artifact.rs:23`），但 `BookDetail.tsx` 还留着一个只有 txt/md/epub 的旧下拉（`:123`、`:249`、`:1021-1045`），与五格式的 `ExportPreviewCard` 并存。
- 打印面零存在（无 `window.print` / `@media print` / `@page`，只有 PDF 导入）。
- EPUB 是最小结构（mimetype / container / OPF / 章 xhtml），全部条目 stored，无 CSS、无封面、无字体；冒烟只做结构校验（`scripts/export-epub-smoke.mjs:73-86`）。

## 4. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 回滚链由删改移后，中途 rename 失败造成「部分已移」 | 逐项 rename 同卷原子；失败即回位已移项并报错，不静默降级为硬删；测试夹具注入失败验证回位 |
| 回收站被备份导出或整书导出带入 | 施工时核对 R18 与 R50 的 glob 排除 `.trash`；duel 条目集断言不含 |
| 回收站与书目录不同卷导致 rename 失败 | 回收站落在 books 根同级（同卷），不引入可配置路径 |
| 结构指纹跨语言可比 | 沿 `chapter_set_revision` 既有形态：sha256 前 16 hex（`sha2` 已在 `engine-rs/Cargo.toml:82`，双端 golden 已锁）；哈希只在结构操作时计算，不进每次保存 |
| 真壳自动化插件进发布包 | cargo feature 默认关；发布打包脚本加断言「依赖树不含该插件」 |
| 新 devDependency 进供应链 | fast-check 与 wdio 都只进 dev/test 面，落在既有 audit:npm 闸覆盖内；Rust 侧零新增 |
| 变异测试耗时与误报 | `--in-diff` 限定 diff 触及函数 + `--baseline=skip`；首版只报告、missed 数只许下降；等价变异逐条标注 |
| as-of 端点语义不一致 | 以 TS 既有语义为准（失效章等于当前章时仍有效），golden 锁边界 |
| 自定义词表规模大时子串计数变慢 | 首版沿用既有扫描；词表超万条的真实反馈出现时再评估多模式匹配 |
| 打印样式表在宿主间有差异 | 明确声明为非 duel 面；页幅由打印对话框选、不用页边距盒、不做标点挤压 |

## 6. 勘误与顺带发现

1. **r-slots.json 幽灵机制**：`docs/catalog/r-slots.json` 最早是 dsh 深化文档里 `next-change-no` 工具的设计提案输入项，文件从未建立（`docs/catalog/` 目录不存在，且 `docs/*` 在 `.gitignore` 内）。v8 深化三、v9 深化三、v10 主文档与 1638、1640 号变更记录把它当作既存机制引用。实际登记面只剩变更记录标题：`scripts/next-change-no.mjs` 虽有 R 段占用表分支，但它从提交主题按 `（NNN号）` 提取，而近期提交主题是 `fix(1664):` 形态，该分支恒为空（实跑核实）。处置：深化二 §0 立 R 登记总表作为文档面的事实登记；后续文档不再引用该文件。
2. **走查文档前提失效**：见 §2.3。处置进 R59a。
3. **双导出入口**：`BookDetail.tsx` 旧三格式下拉与 `ExportPreviewCard` 并存。处置进 R66。
4. **Rust 版本 id 正则缺 `structure`**：见 §2.1。本轮为纯文档轮，未改源码；处置进 R58。
5. **TS 腿无敏感词检查面**：见 §2.4。处置进 R64（以 Rust 为源补镜像）。
6. **检索摘要与原帖不符两处**（Tauri#5680「已结案」、vale「不支持 CJK」）：均已按原帖或官方文档更正，见深化一证据分级。
7. **编号脚本的 git log 源形态漂移**：`scripts/next-change-no.mjs` 的 `numberMatch` 正则期望 `（NNN号）`，与近期提交主题 `fix(NNNN):` 不匹配，于是「git log：0 个」与「仅在目录、未在 git log」告警恒鸣（告警疲劳会淹没真漏记），R 段占用表也恒空。处置建议：改正则兼容圆括号形态，归下一个代码轮（一行改动加必红夹具）。
