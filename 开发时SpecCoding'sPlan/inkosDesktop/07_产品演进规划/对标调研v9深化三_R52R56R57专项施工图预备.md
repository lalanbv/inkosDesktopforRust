## §1 R52 实体高亮层——实现级施工图预备

### 1.1 技术方案定稿：backdrop 镜像层（非 contentEditable、非编辑器替换）

- **外部证据**：textarea 高亮 = 经典 backdrop 技术（codersblock《Highlight Text Inside a Textarea》：透明文字 `<textarea>` 叠在带 `<mark>` 的镜像 div 之上；CSS-Tricks 同族两篇用 `<pre>`/overlay）；现成件 `react-highlight-within-textarea`（npm）存在。
- **现成件评估结论**：**不引入，自研**（估 ~200 行组件）。理由：①依赖供应链新增面（audit:npm 闸负担）与本仓「高亮+排除短语+悬停卡+viewport 裁剪」的定制需求错配；②样式同源化控制权必须在本仓（错位=功能失效）；③组件体量小，自研维护成本低于第三方行为的追查成本。
- **分层形态**：
  ```
  <div class="hl-container">            /* 相对定位容器 */
    <div class="hl-backdrop" aria-hidden> /* 镜像层：<mark> 命中渲染，scroll 同步 */
    <textarea class="hl-input">           /* 原 textarea，color: transparent + caret-color 正常 */
  </div>
  ```

### 1.2 五个工程要点（按风险排序）

1. **同源样式单源化**：字体/字号/行高/内边距/边框宽度从 CSS 变量单源读取（`styles` 层新常量模块），textarea 与 backdrop 共享同一组值——任何一处硬编码即漂移=错位。现有 ChapterReader 的 textarea 类名样式迁移进常量模块，fmt/视觉回归走 IAB 走查像素级用例。
2. **滚动同步**：textarea `scroll` → backdrop `scrollTop/scrollLeft` 同步，rAF 节流；章节切换重置。
3. **astral 码点偏移**：命中区间（matchStart/matchLength）若以码点计则渲染层需 UTF-16 索引换算——**直接复用 1640 号 R47 高亮裁剪 golden 的 astral 码点偏移向量**（10 向量组，含中文/emoji），换算函数与 R47 侧同源（`search-tokenizer` 单源惯例的姊妹件）。
4. **命中集与排除短语**：命中=名册/实体卡条目名扫描（复用 Codex tracking 语义）；**排除短语/大小写敏感按条目级配置**（v8 B1 对标项在此落地）；命中计算 `useMemo`（Zustand selector 纪律：不进 store 派生）。
5. **viewport 裁剪与性能闸**：只渲染可视区±缓冲行（虚拟化切片）；大章（>2 万字）自动禁用并提示；scroll 帧率 bench 前端锚点（v8 验收条维持）。

### 1.3 交互面与验收

- 悬停卡：`<mark>` `mouseenter` → 实体卡摘要浮层（只读）+「编辑」跳 CodexPanel；触屏退化为 tap 长按（IAB 手势探针惯例）。
- 开关：书级默认开、全局可关（v8 定稿维持）。
- 验收清单：①golden——码点/UTF-16 换算（复用 R47 向量）+排除短语匹配+viewport 切片三组；②交互测试——滚动同步/中文英文重叠命中/大章禁用/开关持久化；③bench——scroll 帧率锚点不回退；④IAB 活体走查（滚动中高亮不错位、悬停卡定位正确）。
- **批次**：v8 排期批四（与 R53 同批）不变，本预备文档直接作为届时施工输入。

## §2 R56 翻译 TM——实现级施工图预备（门控解除即施工）

### 2.1 形态：三层记忆（外部证据：OmegaT 机制面）

| 层 | 内容 | 数据形态 |
| --- | --- | --- |
| exact TM | 归一化全等原文 → 既有译法建议 | SQLite 表 `tm_segments(id, source_norm, source_raw, target_raw, lang_pair, work_id, created_at)`，append-only |
| fuzzy TM | 相似度 ≥ 阈值（行业惯例 **75%** 起步，显示百分比） | 同表检索 + 相似度纯函数 |
| 术语层 | 已有 glossary 工件（`run_store.rs` terms 数组）——**不重复建** | 维持现状 |

- **match propagation（匹配传播，OmegaT 语义）**：同一原文句段在多处出现→建议同一条译法（exact 命中自然满足，无需独立机制）。
- **TMX 互操作**：导入导出最小子集（`<tu>/<tuv xml:lang>/<seg>` 结构）；**导入只落 TM 层、不写 glossary**（防双真相源，v9 主文档风险条）。
- **相似度算法**：编辑距离族单源纯函数（`tm_similarity.ts` ↔ `tm_similarity.rs` 逐字镜像，沿 R47 `global_search` 双端镜像惯例）；归一化规则（空白折叠/标点）与检测链既有归一化单源对齐，禁第二份实现。

### 2.2 接线点与边界

- 写入点：翻译 runner 产出句段落库时 append（`translation/runner.rs` 锚点）；revise 采纳结果回写更新（版本不丢，TM 永远指向最新采纳译法）。
- 消费点：翻译请求组装时命中条目进 prompt 参考面（与 R41 计量联动，TM 注入计入上下文计量）；审校面显示命中档位（exact%/fuzzy%）。
- 双语交错导出（v8 观察项并入）：EPUB 导出扩展选项——段落级原/译交错（Immersive Translate 形态），复用翻译域 epub 结构链。
- 隐私边界：TM 落 `.inkos/` 域本地文件（正文内容零外发——与既有翻译域同边界）。
- 验收：golden（相似度函数/归一化/TMX 解析往返三组）+ duel 双端 TM 查询同构 + 增长闸（库 ≥1 万句段时查询 P95 入 bench 锚点）。
- **门控不变**：触发条件维持 v8（真实翻译使用反馈），本预备使解除后单轮可施工。

## §3 R57 场景一等化——评估深化（三路径对比）

### 3.1 路径对比（H 类对标加持后）

| 路径 | 形态 | 侵入面 | 对标参照 | 判定 |
| --- | --- | --- | --- | --- |
| ①节拍扩展 | R11 scene beats 数据结构增强（节拍→场景分组、组内状态） | 最小——prompt/装配面增量，章文件正典不动 | NovelCrafter Scene Beats 生态位 | **优先**（门控解除后按此出正式施工图） |
| ②scene 实体化 | chapter→scenes[] 一等存储实体 | 大——动摇 `NNNN_标题.md` 文件=章正典形态，R47 搜索/R48 结构操作/R49 卷层全部以其为地基 | bibisco/NovelCrafter scene 一等结构 | **不采**（地基动摇成本 > 收益；v8 已定「卷是组织不注入」同理） |
| ③storylet 化 | 内容图按世界状态全局调度 | 互动影视域专用（play_graph 增量） | Yarn Spinner 3 storylets+saliency | 门控挂互动影视域（非正文域——v9 深化一 H3 判定） |

### 3.2 结论

维持数据门控；门控解除后的唯一施工路径=①（节拍扩展）；②路径钉死不采（写入本档作为后续会话的防翻案锚）；③路径与正文域 R57 解耦、独立挂互动影视门控。Sudowrite Scenes（B2）与 bibisco（A5）的「场景一等」形态在②的否决下不再构成路线压力——它们没有「章=文件正典」的地基约束，本仓有，且该地基是 R47/R48/R49 三项 P0/P1 投入的共同前提。
