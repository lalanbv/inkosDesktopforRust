# 对标调研 v8 深化三：R47 排期路线图

> 日期：2026-11-21 ｜ 主文档：[对标调研分析与改进规划_v8](对标调研分析与改进规划_v8.md) ｜ 差距依据：[深化二](对标调研v8深化二_按域差距矩阵.md)
> 立项口径沿用 v3–v5 惯例：每项含设计要点/双端成本/验收；**R 编号即占用即登记**（`docs/catalog/r-slots.json` 机制，R47 起为 v8 段）。施工时行号以符号锚点为准；契约面验证必跑 `INKOS_DUEL=1`（duel 早退不计 pass 先例）。

## 1. P0（结构域确定性缺口，先行为主）

### R47 全局搜索面

| 项 | 内容 |
| --- | --- |
| 设计要点 | 引擎新只读端点 `GET /api/v1/books/:id/search?q=&scope=`（loopback 守卫既有面内）：BM25 命中（复用 G1 检索内核与分词单源）+ 高亮片段（前后窗裁剪）+ 过滤轴（scope=chapters/entity/hook/truth）；实体/伏笔命中走名册/承诺账本索引不重新分词；Rust 先行、Node 回退端对称镜像（≤1 轮惯例）；UI：侧面板「搜索」页 + ⌘P 结果加「正文命中」档（Enter 跳章并滚动到命中行） |
| 双端成本 | TS+R+S（端点小件；UI 面中件） |
| 验收 | golden：分词/高亮裁剪/排序纯函数三组；duel 双端搜索结果同构（同 query 同命中集）；大书（≥300 章 fixture）搜索 P95 < 200ms 入 bench 锚点；空 query/超长 query 负路径 |
| 对标源 | A3 novelWriter 全项目搜索、A6 Obsidian 双轨检索（深化一） |

### R48 章节结构操作批一（拆分/合并/重排）

| 项 | 内容 |
| --- | --- |
| 设计要点 | 三操作全部实现为**引擎事务**（state 管理器内）：①拆分=按分隔符（可预览光标点）切两章，后章起全量重编号；②合并=两章拼接（可配置分隔）删次章；③重排=拖拽/上移下移→批量重编号事务。重编号沿用 `chapter_filename.rs` 正典形态与数值识别单源；快照/草稿/runtime 产物随事务同迁（对齐 manager.rs:468 回滚的产物面清单）；乐观并发：携带预期章集合版本，冲突安全拒绝 |
| 双端成本 | TS+R+S（事务面大件；UI 拖拽中件） |
| 验收 | golden：重编号/拆分边界（首章/末章/中段）/合并分隔三组；事务中断原子性（任一步失败零落盘）；duel 双端操作结果逐位对齐；UI 交互测试（React 拖拽事件形态沿 IAB 惯用形） |
| 对标源 | B1 NovelCrafter 大组织更新（插入/拆分/移动全操作） |
| 风险对策 | 并行会话写同书→乐观并发拒绝+UI 提示重试；重编号窗口期 SSE 事件风暴→事务完成后单事件广播 |

### R49 卷/幕组织层（元数据分组）

| 项 | 内容 |
| --- | --- |
| 设计要点 | 章→可选 `volumeId` 字段+组内排序键（state 面 work/book 元数据，**不移动文件路径**）；卷=有序列表（新建/改名/重排/删空卷）；未分组章归「正文」默认卷；composer/检索/伏笔时间线全消费者按卷分组展示但注入行为不变（卷是组织面非上下文层——不进 G2 分层）；series canon（R20）语义不重叠：卷=书内组织，series=跨书正典 |
| 双端成本 | TS+R+S（元数据小件；UI 面中件） |
| 验收 | golden：卷排序/默认卷归属/删空卷迁移三组；schema parity 键面快照双守卫（volumeId 进跨语言快照）；存量书零迁移（无 volumeId 字段行为不变） |
| 对标源 | A1 Scrivener binder、B1 NovelCrafter act 层（元数据化改造） |
| 风险对策 | 卷层被误当上下文层→文档+UI 文案明确「组织不注入」；与 series 命名混淆→source/文案分立 |

## 2. P1（体验补强，随批穿插）

### R52 编辑器实体高亮层

| 项 | 内容 |
| --- | --- |
| 设计要点 | textarea 镜像 overlay：背后同字体行高的 div 层，按实体名册命中集（Codex tracking 语义：大小写敏感+排除短语条目级）渲染 `<mark>`；悬停出实体卡摘要浮层（只读，跳转 Codex 编辑）；viewport 裁剪（只渲染可视区+缓冲行）；大章（>2 万字）自动禁用；关闭开关（书级默认开、全局可关） |

## 5. 显式不采清单（v8 新增 + 沿袭裁定）

| 项 | 理由 |
| --- | --- |
| 富文本/WYSIWYG 整体替换（TipTap/Lexical/ProseMirror/BlockNote 四款评估后全否） | 纯文本正典是存储/解析/0GC/双栈差分器/VCS 五面根基；编辑器内核替换收益（注解高亮）可用 overlay 层以 1/10 成本达成（R52） |
| 协作多人实时编辑 | 单机定位；Yjs/Automerge 仅挂多端同步观察 |
| AI 生图/角色图像（NovelAI 路线） | 非文本创作域定位 |
| 本地推理运行时内嵌（KoboldCpp 路线） | 体积/维护/供应链三重不划算；Ollama 走自定义服务已覆盖 |
| 服务端网关形态（one-api/new-api/Open WebUI/Dify/Langfuse 自托管） | 单机 BYOK 定位；对应机制已本地化落地（R25/R26/R8/R41） |
| GEPA 自动 prompt 进化 | 需训练集与评测回路规模；版本化+回归门（R54）是单机可承受的纪律面 |
| 划词翻译/PDF 翻译输入（pot/PDFMathTranslate/BabelDOC 输入面） | 非写作域；翻译域输入面是 works/EPUB |
| 发布管线/云端 SaaS/订阅计费/自研模型/模板数量战/上下文军备赛 | v4 沿袭裁定，本轮 30 款横向复核无翻案信号 |
| Electron 迁移/CI-workflow 引入 | 既定裁定（113k★ Tauri 生态 2026 已成熟佐证选型；fork-and-own 本地发版） |

## 6. 实施顺序与批次建议

1. **批一（R47+R48a）**：全局搜索端点+UI 与拆分/合并/重排的 Rust 事务层同批开工（互不触碰文件，检索只读/结构写面分离）。
2. **批二（R48b+R49）**：结构操作 UI（拖拽）+卷元数据层（同挂书籍详情组织面）。
3. **批三（R50 批一+R51）**：导出 zip+目标日历（两个独立小件同批）。
4. **批四（R52+R53）**：编辑器 overlay+章历史页（同挂章工作区，UI 面集中）。
5. **批五（R54+R55+R50 批二）**：工程深化+docx。
6. 每批独立编号、门禁群全绿收口；R 编号占用即登记 r-slots.json；R56/R57 维持门控。

## 7. 与既定裁定的兼容性复核（本轮显式再确认）

- studio 四区结构不重构：R47 搜索挂侧面板、R49 卷挂书籍详情、R53 挂章详情——全部以「新面挂活动栏/详情页」惯例落，不新开一级导航。
- `docs/` 三语随大件走：R47–R55 各自的用户可见面落地时同步 USER_GUIDE/QUICK_START/TROUBLESHOOTING（578 号先例）。
- 契约纪律：所有新端点进端点目录生成器（R40.1），新 SSE 事件进事件目录；跨语言 schema 键面进 parity 快照双守卫（1604 号）。
- 真实反馈缺位：R56/R57 与自动快照节奏三项维持数据门控留白。
