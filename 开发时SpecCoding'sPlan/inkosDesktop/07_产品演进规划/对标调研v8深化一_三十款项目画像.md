# 对标调研 v8 深化一：三十款项目画像

> 日期：2026-11-21 ｜ 主文档：[对标调研分析与改进规划_v8](对标调研分析与改进规划_v8.md) ｜ 证据分级与检索日期见主文档 §1。
> 每款固定字段：定位 / 形态与规模 / 核心机制（只列与本项目相关的）/ 对本项目判定（**采** = 有落地价值；**改造采** = 需按本项目约束变形；**不采** = 显式裁定）。判定细则与处置编号见深化二/三。

## A. 长篇写作软件（传统形态面，6 款）

### A1 Scrivener（Literature & Latte，商业）

- 定位：长篇项目管理金标准（Nov 2025 官方博客与 2026 教程确认仍为 3.x 形态）。
- 形态：桌面商业软件；macOS/Windows/iOS。
- 核心机制：①binder 三层结构（文件夹/文档/子文档任意嵌套重组）；②**Compile** 终态编译（多节合成单稿、按格式链输出、章节过滤/元数据页/批注剔除）；③**Snapshots** 章快照（基线版本+内联 diff+逐段恢复）；④project targets（书目标+日目标+截止日+进度条）；⑤corkboard/outliner 双视图；⑥split editor 任意两文件对照。
- 判定：Compile→**改造采**（R50，只做 zip+docx 两格式起步）；Snapshots→**改造采**（R53，本仓章快照已有回滚语义，补浏览/比较面）；project targets→**采**（R51）；binder/corkboard→**不采**（studio 四区结构不重构，组织层用卷元数据 R49 替代）。

### A2 Ulysses（商业）

- 定位：「无杂物感」写作（Scrivener 论坛定性："Scrivener is a toolbox; Ulysses is based on a deep sense of clutter-free design"）。
- 形态：Apple 全家桶订阅制；Markdown 原生。
- 核心机制：①sheet（片段）→组→书的三层但 UI 极简；②写作目标（字数/时限）与 productive 统计；③发布管线（WordPress/Medium/静态站直发）。
- 判定：目标面→**采**（并入 R51）；发布管线→**不采**（本项目导出走文件，远端发布非定位）；极简哲学→**采**（R51/R52 的 UI 纪律参照）。

### A3 novelWriter（vkbo/novelWriter，开源 3.2k★，GPL）

- 定位：纯文本+类 Markdown 极简语法写长篇，元数据（标签/引用）结构化。
- 形态：Python/Qt 桌面；单机文件即项目；对 VCS 友好（与本项目「纯文本正典」哲学同构）。
- 核心机制：①`@char/@poc/@location` 引用语法在正文内直写实体标签；②写作统计（每小时/每日字数直方图）；③全项目搜索（正文级）。
- 判定：统计→**采**（R51 已含）；全项目搜索→**采**（R47）；引用语法→**改造采**（观察——本仓实体卡走注入链而非正文内语法，双轨会分裂真相源，仅观察不立项）。

### A4 Manuskript（olivierkes/manuskript，开源 ≈3.2k★）

- 定位：开源 Scrivener 替代；大纲/卡片/人物档案。
- 核心机制：①Snowflake 方法论内置（一句话→一段→大纲→正文逐级展开）；②corkboard 索引卡视图；③人物 profile sheet。
- 判定：**不采**（corkboard 与四区结构冲突；Snowflake 的分层展开本仓导演驾驶舱+建书链已等价）；profile sheet→**已对齐**（实体卡）。

### A5 bibisco（开源+商业双轨）

- 定位：场景驱动 + 人物访谈式设定。
- 核心机制：①场景为一等结构（章节→场景）；②人物「访谈问卷」式设定（引导式提问生成角色卡）；③故事架构分析（三幕/英雄之旅模板检查）。
- 判定：访谈式设定→**改造采**（观察清单——与建书向导/导演灵感卡同方向，待反馈决定是否增强为问答式）；场景一等化→**门控**（R57 同源）；架构模板检查→**不采**（模板数量战裁定）。

### A6 Obsidian（商业，个人免费；百万级用户）

- 定位：本地 markdown vault + 链接知识库 + 插件生态。
- 核心机制：①Properties/Bases（2026：属性驱动的 List/Table/Card 数据库视图，本地数据）；②quick switcher（⌘O 标题级）+ 全文检索（⌘⇧F）；③Canvas（2026-11 起支持 multiplayer 协作）；④插件市场数千量级。
- 判定：全文检索与 switcher 的「标题级/正文级双轨」→**采**（R47 的交互形态参照）；Bases 属性视图→**改造采**（观察——创作库 works 列表/三库资产的表格化视图候选）；Canvas/协作→**不采**（单机裁定）。

## B. AI 创作工具（商业 + 开源，7 款）

### B1 NovelCrafter（商业）

- 定位：2026 年对标主力（v3–v5 已深度对标 Codex/Scene Beats）。BYOK+订阅双轨。
- 本轮新证据（changelog 至 2026-10-19）：①**09-24 大组织更新**——act/chapter/scene 三层的创建/插入（before/after/in-between menu）/拆分/上下移动全操作 + Outline 折叠；②**03-21 Codex tracking 控制**——条目级大小写敏感+排除短语（"Don/May/Will" 假阳性治理）+多自定义类目；③一次性模型进 Chat（无需建模型集合）+「Recently released」模型区；④AI thinking 偏好（prefer/avoid）实验项；⑤docx 列表导出（01-27）。
- 判定：结构操作→**采**（R48 直接对标）；排除短语→**改造采**（小件，可挂实体卡 tracking 侧，并入 R52 批次）；docx→**采**（R50）；thinking 偏好→**不采**（本项目 provider 层已有 thinkingBudget 备案，产品面不暴露）。

### B2 Sudowrite（商业）

- 定位：创意 fiction 优先的 AI 写作（2026 Forbes/Medium 横评仍居前列）。
- 核心机制：①Story Bible（引导式世界观/角色圣经）；②**Scenes**（2026 新推——章节级场景化生成）；③Muse/Muse 1.5 自研写作模型；④Series Folders 多书共享正典（v4 已对标→R20 已落地）。
- 判定：Scenes→**门控**（R57 同源）；Muse→**不采**（自研模型裁定）；Story Bible 自动更新→**已领先**（settler→名册自动沉淀生产化，v4 确认维持）。

### B3 NovelAI（商业）

- 定位：续写式 AI 创作始祖级产品；Erato 自研文本模型 + 图像生成。
- 核心机制：①Lorebook（2026 完全重设计）：关键词激活注入、条目可**嵌入/导出为图片分享**、自定义条目类型生成、Quick Access 快搜条；②上下文串+记忆+作者注三层经典结构。
- 判定：条目分享格式→**已对齐**（R15 三库市场包便携格式，确认维持）；关键词激活→**已对齐**（实体卡命中注入）；图像→**不采**。

### B4 DreamGen（商业）

- 定位：fiction-first 的角色扮演/故事共创；2026 横评新贵。
- 核心机制：①场景设定（plot/setting/characters/style 四件套预置）后「导演 AI 共写」；②BYOK 多模型路由。
- 判定：四件套预置→**已对齐**（建书链+导演灵感卡）；BYOK→**已对齐**（38 preset+自定义服务）；无新增可采项（定位重叠度低，作生态参照）。

### B5 SillyTavern（开源 35.9k★）

- 定位：LLM 前端「Power Users」形态；角色卡/世界书生态事实标准。
- 核心机制：①World Info 关键词触发注入（递归扫描/顺序/概率/深度位置等细粒度控制）；②**Vector Storage 与 World Info 级联**——向量检索命中文本可反激活关键词词条（「Include in World Info Scanning」两段式：先检索后激活）；③Data Bank 文档 RAG 独立于会话记忆；④会话记忆向量化。
- 判定：检索→激活级联→**改造采**（观察清单——本仓 G1 混合召回已覆盖「检索」，条目激活是关键词面，级联形态可在 R57 施工图评估）；细粒度注入控制→**已对齐**（G2 七层+排序器）；角色卡生态兼容→**不采**（与 AgentSkills/OpenClaw 兼容路线冲突，不双标）。

### B6 KoboldCpp（LostRuins/koboldcpp，开源 12.4k★）

- 定位：单文件零安装本地 GGUF 推理 + KoboldAI UI（续写形态）。
- 核心机制：①本地推理一体化（无需云端）；②world info/记忆经典三层。
- 判定：**不采**（本项目 BYOK 走外部服务，不内嵌推理运行时——体积/维护/供应链三重不划算）；本地 Ollama 用户走自定义服务接入已覆盖。

### B7 Pagekin 书童（开源，EthanYoQ/Pagekin，新项目）

- 定位：开源 AI 长篇/网文写作应用（前 AI Novel Writer）；Windows 安装包，本地优先 BYOK。
- 核心机制：①**拆解仿写**（decompose-and-imitate——拆范文→仿写，中文网文套路化生产）；②**读者已知信息**作为记忆结构维度（与角色知悉分离）；③技能包导入（去AI味 skill，与 AgentSkills 目录形态兼容）；④设定→蓝图→草稿→审稿→定稿全流程。
- 判定：读者知识维度→**已领先**（G7 信息差覆盖，确认）；拆解仿写→**改造采**（观察——本仓 G5 拆书已覆盖「拆」，仿写=风格克隆面，文风域 compileStyleGuide 已对齐；不单独立项）；全流程→**已对齐**。

## D. LLM 工程（8 款）

### D1 LiteLLM（BerriAI/litellm，开源 63.6k★）

- 定位：AI 网关事实标准；**2026 已转 Rust core + Python SDK**（「fastest, litest AI Gateway」——与本项目 Rust 引擎路线同向）。
- 核心机制：①virtual keys（per-key/per-model 双层预算与限流）；②budget fallbacks（预算耗尽触发 key 自带 fallback 链，免改 config）；③provider failover（可重试错误分类后切换）；④per-team spend 追踪与重置窗口。
- 判定：failover 错误分类→**已对齐**（R25 可重试白名单同语义）；预算→**改造采**（R55——本地无计费，做软顶警戒+超额确认）；Rust core 转向→**已对齐**（本仓 Rust 引擎先行的佐证）。

### D2 one-api（songquanpeng，开源 37.5k★）

- 定位：中文圈 LLM 分发系统鼻祖；渠道池+负载均衡+令牌额度。
- 判定：**不采**（服务端分发形态与单机 BYOK 定位不符）；渠道分组概念→**已对齐**（服务分组筛选）。

### D3 new-api（QuantumNous，开源 52.3k★）

- 定位：one-api 增强分支；模型路由/访问控制/用量成本核算。
- 判定：同 D2 **不采**；用量核算→**已对齐**（R13/R26/R41）。

### D4 Open WebUI（开源 159.2k★）

- 定位：自托管 AI 界面第一梯队；本地优先+RAG 可配置性最强。
- 核心机制：pipelines/functions 插件系统、RAG 管道自定义（本地 embedding 选项）、企业级管理面。
- 判定：RAG 管道可配置性→**已对齐**（G1/G2/R6 排序器）；插件→**已领先**（WASM 沙箱强隔离 vs 其进程级 pipelines）；无新增可采项。

### D5 LobeChat（lobehub/lobe-chat，开源 85.9k★）

- 定位：2026 已转型「Super-Agents on Your Team」（会话前端→智能体平台）。
- 判定：**不采**（产品方向分叉）；其转型佐证「会话工具→编排平台」的行业趋势（主文档 §0.2）。

### D6 Dify（langgenius/dify，开源 161.6k★）

- 定位：Agentic workflow+RAG 平台第一梯队。
- 核心机制：①**Knowledge Pipeline**（知识库处理模板化：抽取/清洗/分块/索引/**接入前先测检索**）；②workflow 节点编排（含 Knowledge Retrieval 节点）；③多数据源知识库。
- 判定：「检索先测后接线」→**改造采**（并入 R54——prompt/知识变更先过 R8 评测锚点再生效的门槛语义；R8 已有基建，本项是流程纪律化）；workflow 编排→**已对齐**（pipeline 链+导演模式）。

### D7 DSPy（stanfordnlp/dspy，开源 39.2k★）

- 定位：prompt 工程化框架；GEPA 反思式 prompt 进化（优于 MIPROv2 10%+，梯度免费、90x 便宜）。
- 核心机制：①优化产出的 **prompt 版本化 artifact**（对比/回滚如发版）；②评测先行（test-driven prompt 部署，2026-03 生产化实践）；③GEPA 用自然语言反思执行轨迹进化指令。
- 判定：版本化+评测门→**改造采**（R54——不做自动进化，做「prompt 变更=版本 artifact+R8 回归门+回滚」的纪律面）；GEPA 自动优化→**不采**（需要训练集与评测回路规模，超单机写作场景）。

### D8 Langfuse（langfuse/langfuse，开源 37.7k★）

- 定位：2026 定位已扩为「AI Gateway + agent observability + evals + prompt/skill 管理（基于 OpenTelemetry）」。
- 判定：**不采**（自托管服务形态与单机定位不符）；其 observability/evals/prompt 管理三面与本项目 R26/R8/R54 的对应关系是「外部平台 vs 本地内建」的形态差——本地内建是本项目优势，无动作；OTel span 语义→**已对齐**（R33 `inkos.ai.request`）。
