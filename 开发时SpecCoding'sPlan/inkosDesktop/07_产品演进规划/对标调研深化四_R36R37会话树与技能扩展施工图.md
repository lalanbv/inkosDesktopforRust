## 一、上游实证（源码级事实）

### 1.1 会话树（session-manager.ts）

**条目模型**：`CURRENT_SESSION_VERSION = 3`；首行 `SessionHeader { type:"session", version, id, timestamp, cwd, parentSession? }`，其后每条目继承 `SessionEntryBase { type, id, parentId, timestamp }` 构成树。11 种条目：

| 条目类型 | 关键字段 | 语义 |
|---|---|---|
| `message` | `message: AgentMessage` | 消息体（进上下文） |
| `thinking_level_change` / `model_change` | thinkingLevel / provider+modelId | 会话内设置变更，沿路径生效 |
| `usage` | kind/provider/model/usage | 用途化用量（如 cache_warm），独立于消息 |
| `compaction` | `summary` + **`firstKeptEntryId`** + tokensBefore + details? + usage? + fromHook? + **`systemMessage?`** | 压缩边界：切点按 id 引用 + 边界处完整 prompt/工具状态快照 |
| `branch_summary` | `fromId` + summary + details? | 分支弃用路径的桥接摘要（进上下文） |
| `custom` | customType + data | 扩展私有状态持久化，**不进上下文**（buildSessionContext 忽略） |
| `custom_message` | — | 扩展注入内容，**进上下文**（v2→v3 由 hookMessage 改名 custom） |
| `label` | — | 用户书签 |
| `session_info` / `context_edit` | — | 元信息 / 对更早模型可见条目的分支局部编辑 |

**分支模型（R36 核心事实）**：`branch(branchFromId)` 是**纯内存 leaf 指针移动**（`this.leafId = branchFromId`），文件树一字不动；此后 `appendXXX()` 一律写 `parentId = 当前 leafId` 的新条目，新枝自然成形。`branchWithSummary()` 额外追加 `branch_summary` 条目（fromId=弃用前 leaf），使 LLM 知道被放弃的路径讲过什么。`resetLeaf()` 置空 leaf=从根重写。读取面 `getBranch(fromId?)` 沿 parentId 反向回溯出 root→leaf 路径；`buildSessionContext()` 沿该路径解析消息并处理路径上的 compaction/branch_summary。**leaf 指针不落盘**——重启后 leaf=最后一条，分支持久性靠「branch 后必有 append」成立。

**迁移先例（R36 迁移策略锚）**：`migrateV1ToV2` 在加载时 in-place 补 `id/parentId`（顺序链化：`entry.id = generateId(); entry.parentId = prevId`），顺带把 compaction 的 `firstKeptEntryIndex`（数组下标）换算成 `firstKeptEntryId`（树内稳定引用）；`migrateV2ToV3` 仅改 role 名。header.version 递进、幂等、读时迁移。

**存储与读取形态**：单 JSONL append-only；header 扫描缓冲 4KB/上限 1MB；会话列表并发装载上限 10；`loadEntriesFromFile` 逐行解析容错。

### 1.2 技能系统（skills.ts）

- **Frontmatter**：`{ name?, description?, disable-model-invocation? }`；name ≤64、description ≤1024——**与本仓 AgentSkillSchema 限制逐字一致**（双源趋同，惯例已收敛，无对齐成本）。
- **渐进披露**：`formatSkillsForPrompt` 只向系统提示投 `<available_skills><skill><name/><description/><location/>` 三元组；SKILL.md 正文由模型在任务匹配时自行 `read`（或 bash）加载。相对路径按技能目录解析。
- **装载序与冲突**：user（agentDir/skills）→ project（cwd 的 CONFIG_DIR/skills）→ 显式 paths；同名**首胜** + collision diagnostics；symlink 经 canonicalizePath 去重；目录过滤支持 .gitignore/.ignore/.fdignore。
- `disable-model-invocation: true` 的技能对模型隐藏（仅人侧可调）。

### 1.3 扩展宿主（core/extensions/，7 文件）

`jiti-loader`/`jiti-static-loader`/`virtual-modules`/`wrapper`/`runner`——运行时 TS 模块加载执行扩展代码，即 **全信任进程内代码执行**。印证 v6 不采纳裁决：InkOS 的声明式权限 + WASM 沙箱方向是安全优势位（docs 可显式宣传），Pi 扩展模型不作移植目标。

## 二、本仓现状写实

### 2.1 transcript 面（interaction/session-transcript*.ts）

- 存储：`{projectRoot}/sessions/{sessionId}.jsonl`，**appendFile-only**（session-transcript.ts:80）；`{sessionId}.json` 为会话元数据。
- 事件 schema（session-transcript-schema.ts，zod 判别联合，6 类）：`BaseEvent { version: z.literal(1), sessionId, seq, timestamp }` + `session_created` / `session_metadata_updated` / `request_started` / `request_committed` / `request_failed` / `message`。
- **关键既有原料**：`MessageEvent` 已带 `uuid` + `parentUuid`（消息粒度链，Claude 系形态）——消息级引用在、**事件级树语义无**（无分支 API、无 head 指针、恢复=线性回放 `restoreAgentMessagesFromTranscript`，agent-session.ts:1121）。
- request 三事件包装（started/committed/failed）是上游没有的语义层：分支/重试边界天然有锚。

### 2.2 技能面（skills/ + agent/skill-tool.ts）

- external-loader.ts：SKILL.md 装载，目录序 `INKOS_SKILL_DIRS`（env，显式）→ `~/.openclaw/skills` → `~/.agents/skills`（user）→ `{projectRoot}/.agents/skills` → `{projectRoot}/skills`（project）；name ≤64 / description ≤1024 / manifest ≤2MB；诊断收集。registry.ts：`createSkillRegistry`（dedupe by id）+ `resolveSkills`（disabled/requested/forced/used/available，确定性序已由 536 号修毕）。
- **装载时点**：会话创建时 `loadAvailableAgentSkills({ projectRoot })`（agent-session.ts:1056）——**会话粒度天然热载**：新会话自动拾取新落盘技能；进程内运行中会话的 registry 冻结。
- use_skill 激活链（skill-tool.ts 344 行）：529–536 号已双端 golden 锁死（激活面序/usedSkills 预置/段级元数据/工具卡预览）。

### 2.3 Rust 镜像面

- `engine-rs/src/server/skill_routes.rs` + `skills/mod.rs`：external_loader 镜像（mod.rs:6 注释自证对齐面）；读面已对齐，**写面无**。
- `engine-rs/src/server/session_routes.rs`：8 端点（list/get/create/put_play_mode/rename/delete/abort/get_interaction_session）——transcript 读写双端共享同一磁盘形态，schema 变更必须 serde 镜像（518 号 normalizeCodexCards 教训：`#[serde(default)]` 对齐 zod default）。
- 写入工具先例：`write_truth_file`（agent-tools.ts:3335，`assertSafeTruthFileName` 校验 + 确定性工具落盘）= R37 作用域写工具的直接模板。

## 三、R36 施工图：transcript 树化设计稿（只出设计稿）

### 3.1 价值判定（对准真实需求）

InkOS 的分支价值不在通用聊天，而在**创作分支**：章节重写回溯（弃稿不丢）、方向 A/B 对照（508b 已选方向回显的延伸）、节拍/结局多分支试写。这些场景共同要求「从第 N 轮重开但保留弃用路径可回看」——正是 Pi leaf 指针模型的语义。request 三事件 + uuid/parentUuid 既有原料使本仓树化成本低于上游当年 v1→v2 重构。

### 3.2 Schema 演进：**零版本增量的加法式设计（v6「schema v2 草案」修正）**

v6 预设「持久化 schema v2 草案 + 迁移策略」。源码对勘后修正：**不需要 v2**。

- `BaseEventSchema` 加法扩展：`parentSeq: z.number().int().nonnegative().nullable().optional()`。**缺省语义 = 线性链（parentSeq = seq − 1 的前序事件）**——旧文件零改写照常解析（zod optional 加法向后兼容），新写入恒带值。对照 Pi：当年 v1→v2 是破坏式重构（无 seq 基础，须补 id/parentId 全表）；本仓 seq 天然提供全序，只需补「分支时偏离线性」的单一信息位。
- 判别联合加法扩展：`branch_moved { type, fromSeq: number|null, toSeq: number }`（toSeq=null 等价 resetLeaf；fromSeq 记录弃用前 head，供 branch_summary 类桥接与审计）。
- **版本字面量保持 `z.literal(1)` 不动**：加法字段无需版本递进；若未来出现破坏式变更再启用 v2，递进通道（Pi header.version 先例）保留在案。
- Rust 镜像：serde 结构体加 `#[serde(default)] parent_seq: Option<u64>` + 新事件变体——518 号 default 对齐教训直接适用。

### 3.3 head 语义与持久性

- branch 操作 = 写一条 `branch_moved` 事件（append-only 不破坏）+ 服务器内存 head 更新；此后 message 事件写入时 `parentSeq = 当前 head`。
- 与 Pi「leaf 不落盘、靠 branch 后必 append」不同：InkOS 会话是**服务端长生命周期对象**（跨引擎进程重启、双引擎切换），head 必须可重建——`branch_moved` 落事件流，重启时 replay 重建 head（O(n) 一次，装载路径已有全量读取）。
- 恢复读面：`restoreAgentMessagesFromTranscript` 升级为「沿 parentSeq 链 root→head 回溯 + 反转」，替代 seq 全序扫描；`request_started/committed` 沿链生效（未 committed 的 request 分支在回溯时自然剪除）。

### 3.4 与 R32 压缩切点协同（v6 既定要求）

- 未来 compaction 事件（R32a 会话面缺口补齐时落）携带 `firstKeptSeq`（= Pi `firstKeptEntryId` 等价物）+ summary + tokensBefore；**切点沿树路径解释**：恢复时取 root→head 路径上最近一条 compaction，`firstKeptSeq` 之前的路径前缀以 summary 顶替。
- 树化先行使 R32 切点天然获得「分支各自的压缩状态」——同会话不同分支可各有 compaction 边界，互不污染。此为 Pi 形态的真实红利，设计稿先行锁定字段位（`firstKeptSeq`），避免 R32 落地时二次迁移。

### 3.5 不做清单（边界裁定）

- **不做** UI 树浏览器/图渲染（本轮只立事件面；studio 呈现另立项）。
- **不做** 跨文件会话谱系（Pi `parentSession` 语义；单文件树 + 既有 sessions 目录已覆盖当前需求）。
- **不做** labels / context_edit / custom / custom_message / usage 条目类型（无消费方；判别联合开放，后续按需加法扩展）。
- **不做** thinking_level/model_change 类设置条目（InkOS 模型/思考配置走会话元数据 json，语义已覆盖）。

### 3.6 开工清单（另立编号执行）

1. schema 加法扩展 + 双端 serde 镜像（TS zod / Rust serde，golden 快照锁旧文件解析不变）。
2. `branch_moved` 写入 + head replay + 恢复读面链式回溯（双端同改，差分器加 transcripts 维度）。
3. REST 面最小暴露：`POST /sessions/:id/branch { toSeq }` + GET 列表透出 head/分支计数（契约差分器入清单）。
4. 恢复单测：线性旧文件 / 单分支 / 多分支 / branch 后重启 replay 四态；duel 双跑。
5. studio 呈现（可选后续）：会话页分支切换器消费 branch_moved 列表。

## 四、R37 施工图：自扩展技能创作链

### 4.1 采纳判定

三段基建全活且已对齐上游惯例（SKILL.md 限制逐字同构、目录扫描、registry resolve、use_skill golden）——**唯一缺口是「agent 为自己写技能」的写入链与治理门**。上游靠全信任扩展宿主兜底，本仓以受控链路实现同等自扩展能力，安全模型相反（这是优势位）。

### 4.2 链路设计（四段）

1. **生成**：聊天/导演 agent 经系统提示得知「可为当前项目沉淀技能」（prompt 段复用 formatSkillsForPrompt 的 XML 形态描述产出规范：name ≤64 / description ≤1024 / 正文 Markdown 指导）。
2. **写入**：新作用域工具 `author_skill { name, description, body }`——模板照抄 `write_truth_file`：安全名校验（`^[a-z0-9][a-z0-9-]{0,63}$`，禁路径分隔与保留前缀 `builtin:`/内置技能 id 撞名防欺骗）→ 落盘 `{projectRoot}/skills/{name}/SKILL.md`（既有 project 源目录，external-loader 零改动即拾取）→ 返回结果文本。**不给 agent 通用文件写权**（agent-tools 现无 write_file，维持）。
3. **确认门**：写盘前走既有确认链（对齐 studio 人审交互；`disable-model-invocation` 默认 false 但用户可手改 frontmatter 隐藏）。
4. **热载**：当前会话 registry 冻结（**防同会话自我即时劫持**：技能指导未经过人审循环不该影响当轮）——下一会话经 agent-session.ts:1056 装载路径自动生效；ops/管理面如需即时生效，按 449 号 mtime 校验缓存先例加显式 reload 端点（`POST /skills/reload`），人侧触发而非 agent 触发。

### 4.3 治理面

- 名称保留表：内置技能 id + `builtin`/`user`/`external` source 保留字；collision 时 author_skill 返回失败文本（registry dedupe 首胜不改，写端拒绝）。
- 描述即信任边界：description 进系统提示（渐进披露位），author_skill 校验非空 ≤1024 并要求「描述用途而非诱导激活」——审查口在 description（上游同位）。
- 审计：author_skill 调用写入 RunLog（R33 schema `inkos.skill.authored` 预留键）。
- 删除/停用：人侧删目录或 frontmatter 加 `disable-model-invocation: true`（复用上游同名字段，零发明）。

### 4.4 双端对齐与验收

- 写面先 TS 落地，Rust 侧备案（同 498→500 导演灵感卡先例：语义 TS 先行、Rust 补偿清偿）；读面双端已对齐不受影响。
- golden：use_skill 激活面既有 golden（531 号 18 键）**不动**——author_skill 不改变激活链语义，只新增技能来源。
- 新 e2e：author_skill → 新会话装载 → resolveSkills 可见 → use_skill 激活全链；非法名/撞名/超长三拒绝态；门禁矩阵全量（gate:ts + 差分器 + node-fallback-smoke + duel 真跑）。

### 4.5 不做清单

- **不做** jiti 式 TS 扩展/代码技能（全信任模型反向裁定，v6 已裁）。
- **不做** ignore 文件目录过滤（本仓目录面窄：env+home+project 五目录固定，无上游用户任意挂载场景）。
- **不做** symlink 去重与多源 collision 诊断扩展（registry dedupe 已覆盖正确性；诊断面按需再补）。
- **不做** agent 自删/自改他人技能（author_skill 只增不改不删；修改走人侧）。

## 五、与既定路线衔接

- 0GC 核对：R36 恢复回溯为 O(n) 一次性装载路径行为，非热路径（bench:gate 不涉）；R37 author_skill 为低频写工具，均无 Rust 热路径改动。安全核对：树化不扩攻击面（append-only 不变）；author_skill 三重门（安全名+确认+会话冻结）。兼容性核对：旧 transcripts 零改写解析（zod optional / serde default 双端同构）；技能面零 schema 变更。
