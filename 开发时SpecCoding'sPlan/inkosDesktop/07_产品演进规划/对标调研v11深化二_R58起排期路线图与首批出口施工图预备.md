## §2 批二（可恢复）

### R60 回收站与保留期

| 项 | 内容 |
| --- | --- |
| 设计要点 | **回收站=文件级找回，不是撤销操作**（撤销整笔结构操作归 R61）。章级回收站已在位（`{bookDir}/chapters/.trash/`，`chapter_delete.rs` 的 rename 进 + 防撞后缀），R58 扩展出批次子目录；书级回收站由 R58 引入。目录即真源，不设索引文件。**恢复只把文件移回，不动索引、快照与状态**；自动清理不做，首版只报告 |
| 端点（双端） | 书级三件：`GET /api/v1/trash/books`、`POST /api/v1/trash/books/restore`、`POST /api/v1/trash/books/purge`。章级三件：`GET /api/v1/books/:id/trash`、`POST /api/v1/books/:id/trash/restore`、`POST /api/v1/books/:id/trash/purge`。恢复时目标路径已存在→409 拒绝，不覆盖；书 id 已被占用→409。purge 为真空删除 |
| 纯函数双端 | `trash_batch_name`（R58 已立）；`trash_entry_list↔trashEntryList`（目录扫描→条目表：相对路径 / 大小 / 批次 / 时间）；`trash_prune_plan↔trashPrunePlan`（条目表 + dayKey + 保留天数 + 批次上限 → 将删清单；只出计划不执行） |
| 保留策略 | 默认 30 天 + 单书 20 个批次（Syncthing `cleanoutDays` 与 `Keep Files` 的双参数形态）。打开书时计算计划，通知表提示「回收站 N 项 / M 字节可清理」，由用户触发清空 |
| UI | 书详情「回收站」卡（列表 / 恢复 / 清空，清空走 `ConfirmDialog`）；Dashboard 书架的「已删除」入口挂观察 |
| 双端成本 | TS+R+S 中件；回退腿=TS 六端点镜像与扫描纯函数 |
| 验收 | golden 三组；**duel**：列 / 恢复 / 清空六端点同构（同 fixture）。**活体**：驳回→恢复→被废章正文逐字节回到原路径；恢复目标冲突 409 且原文件未动；删书→恢复→书架重现且章数一致。**不变量**：恢复后索引与状态文件字节不变 |

### R61 结构事务不变量守卫 + 操作日志 + 撤销上一笔

| 项 | 内容 |
| --- | --- |
| 背景 | 1646 / 1648 / 1649 三轮返工，共性是「事务提交后成员集合与预期不符」，且每次都是走查或逐功能验证才逼出 |
| 设计要点 | ①**提交前不变量断言**（进入事务时采集一次操作前指纹清单，提交钩子校验；失败即从 staging 全量回位并报错）②**操作日志**（append-only）③**撤销上一笔**（仅一笔，下一笔结构操作后作废） |
| 不变量 | **重排**：`{sha256(章内容)}` 多重集前后相等，章数相等。**合并**：新章内容 = `merge_content(a, b, sep)`，章数减一，被删章正文在 `.trash`。**拆分**：两片拼回等于原文，章数加一。**通用**：索引条目数等于 `chapters/` 下章文件数；`.versions` 存档数不减少 |
| 指纹 | 沿 `chapter_set_revision` 既有形态：sha256 前 16 hex（`sha2` 已在 `engine-rs/Cargo.toml`，双端 golden 已锁）。只在结构操作时计算 |
| 接线点 | `engine-rs/src/interaction/chapter_structure.rs` 三事务 `split_chapter` / `merge_chapter` / `reorder_chapters` 与 TS 镜像 `packages/core/src/state/chapter-structure.ts`；日志文件 `{bookDir}/story/structure-ops.jsonl`（原子写惯例，与 writing-log 同族；每行 `{ts, opId, kind, before, after, undone}`，只有章号 / 文件名 / 指纹，无正文）；端点 `POST /api/v1/books/:id/chapters/structure/undo` |
| 撤销语义 | 当且仅当日志末笔 `undone:false` 且其 `after` 指纹与当前盘面一致（其后没有编辑改写）时允许；执行本身是一笔新的结构事务（也记日志），原笔标 `undone:true`。回位来源=现存文件、`.trash`、`.versions` 的 `structure` 存档（依赖 R58 的正则修复）；存档缺失则拒绝并说明原因 |
| 纯函数双端 | `content_fingerprint↔contentFingerprint`；`structure_invariant↔structureInvariant`（操作类型 + 前后指纹清单 → 通过 / 违反项）；`undo_eligible↔undoEligible`（日志尾笔 + 当前指纹 → 可撤销判定与原因） |
| UI | 结构操作成功的通知带「撤销」按钮（VS Code 文件操作撤销语义）；书详情结构区显示「可撤销的上一笔操作」 |
| 双端成本 | TS+R 中件 + UI 小件；回退腿=TS 三事务的断言与撤销端点镜像 |
| 验收 | golden 三组；**故障注入**：夹具在提交钩子前制造「成员丢失」，断言事务回位、零落盘、错误点名缺失项；**duel**：撤销端点同构；**属性**：随机重排恒通过、随机丢一章恒违反（语料由 R62 生成器出）。**负路径**：无日志、末笔已撤销、`after` 指纹不符、存档缺失 |
| 对标源 | Q4 VS Code（会话内操作撤销）、Q6 restic（计划与执行分离）、S3 属性测试 |

## §3 批三（测试咬合力）

### R62 属性测试语料升级

| 项 | 内容 |
| --- | --- |
| 设计要点 | fast-check（+ `@fast-check/vitest`）作 TS 侧 devDependency；生成器出不变量语料并落盘为 golden；Rust 腿用既有 `golden_*_diff` 回放。**只增 TS 侧 dev 依赖，Rust 侧零新增**；跨语言不要求随机数发生器对齐——落盘语料是唯一真源 |
| 不变量清单（首版） | ①`docxEscapeXml`：`unescape(escape(x)) == x`，输出不含裸 `&` `<` `>` ②`dailyWordDelta`：对记录流置换不变；全表求和等于 Σ(after − before) ③`goalStreak`：结果不超过表长，且计入的每一天净增不小于目标 ④`mdZipEntryPath`：不含 `..` 段、不以 `/` 开头、不含反斜杠 ⑤`usageProjection`：各服务之和等于全部行之和 ⑥`expectedFinish`：目标不大于当前字数时为空；节奏越大完成日不晚 ⑦`shiftDayKey`：`shift(+n)` 再 `shift(−n)` 等于原值 ⑧`structureInvariant`：随机重排通过、随机丢成员违反 |
| 语料形态 | 每组不少于 200 个样本；文件头记录 `{seed, generatedAt, sampleCount}`；总体积控制在 1 MB 内 |
| 双端成本 | TS 小件（一次性 dev 依赖，落在既有 audit:npm 闸内） |
| 验收 | 每条性质的 fast-check 原生断言通过；落盘语料双端回放全绿；**必红自检**：临时破坏一个镜像（例如去掉 `>` 的转义）→ 语料回放变红，证明语料有咬合力 |
| 对标源 | S3 fast-check / proptest |
| 风险对策 | 语料膨胀→样本上限与体积上限；性质写错造成假红→每条性质先用手写向量复核 |

| 第二步·as-of | 纯函数 `facts_at↔factsAt`（事实表 + 章号 → 该章有效的事实）。接到两个消费点：①修订与重写较早章节时的上下文装配（`engine-rs/src/utils/memory_retrieval.rs` 的事实段由整份当前态改为「截至目标章」）②事实表的「生效章—失效章」展示。`get_facts_at`（`memory_db.rs`）已有而只有测试调用，可作参考实现 |
| 价值 | 其一，改旧章时不再注入「尚未发生」的事实（一致性）；其二，减少干扰项（Context Rot 的实证结论）；其三，为后续按有效区间扫描后文矛盾留出数据基础 |
| 端点语义 | 以 TS 既有语义为准：失效章等于当前章时仍有效（`validUntilChapter >= chapter`），golden 锁端点 |
| 双端成本 | TS+R+S 中件；回退腿=TS 侧已具备过滤，只需补 `factsAt` 与装配接线 |
| 验收 | golden（区间端点、重叠区间、无失效值、同章多次改写）；**duel**：事实投影同构；parity 键面不变（字段已在，快照应零差异） |
| 对标源 | P1 Graphiti（双时态）、P5 Context Rot、P6 Aeon（双序） |
| 风险对策 | 与 R61 的撤销链不交叉（事实属于状态快照，不随结构事务迁移）；`fact_ops` 的 Rust 侧缺口不在本项范围，挂观察 |

## §5 批五（收口）

### R66 打印导出与导出面收口

| 项 | 内容 |
| --- | --- |
| 设计要点 | ①**打印路由**：按卷 / 章渲染纯阅读版式并调用 `window.print()`，由系统打印对话框「存储为 PDF」。产物由宿主打印管线生成，**属宿主能力面，声明为非 duel 面**（与 RFC5987 下载同族）②**EPUB 最小样式**：增加一个样式 part（正文字族、行高、段首缩进、标题层级）并在 OPF manifest 引用；stored 零压缩与条目序固定的逐位可比通道不变③**退役旧导出入口**：`BookDetail.tsx` 的三格式下拉下线，统一走五格式的 `ExportPreviewCard` |
| WKWebView 下的硬约束 | 页幅由打印对话框选（不依赖 `@page` 的 `size`）；不用页边距盒（页码另置）；避头尾用 `line-break: strict`；标点间隙压缩不做（WebKit 未实现 `text-spacing-trim`）；章起分页用 `break-before: page` |
| 双端成本 | S 为主；EPUB 样式为 Rust + TS 各一个小改动；回退腿=TS 的 EPUB 分支同款 |
| 验收 | **真壳走查**：打印对话框出页、章首页分页正确、避头尾生效（进 R59a 清单第①项的延伸）；EPUB 结构校验扩展（样式 part 在位且被 manifest 引用）+ duel 条目集含新 part；旧入口退役后 export-save 调用面无回归 |
| 备案 | W3C EPUBCheck 需 JRE，本机无 → 不进本机门禁；发布前在具备环境的机器上对导出物跑一次，结论记入变更记录 |
| 对标源 | R1 wry#707、R5 EPUBCheck / Calibre、R6 CSS 分页与中文断行 |
| 风险对策 | 宿主差异→明确非 duel 声明 + 真壳走查；样式 part 改变既有导出字节→golden 与 duel 断言同步更新，不豁免 |

## §8 与既定裁定的兼容性复核

- **studio 四区结构不重构**：回收站卡挂书详情、回收站入口挂 Dashboard、检查结果挂导出预览卡与规则面板——全部沿「新面挂详情页」惯例。
- **纯文本正典不动**：回收站、操作日志、词表都是旁路文件或规则节，不改正文存储形态。
- **隐私红线**：回收站只是本地文件移动；操作日志只记章号 / 文件名 / 指纹；检查层零外发。
- **双栈纪律**：每项列纯函数双端与回退腿；新增端点进端点目录生成器并自动受路由覆盖守卫约束；跨语言键面有变的（R64 的 `bookRules` 新节）进 parity 快照双守卫。
- **无 workflow 不变**：变异门、属性语料、真壳冒烟都是本地脚本。
- **`docs/` 三语随大件走**：R58 的驳回确认、R60 的回收站、R64 的发布前自查属用户可见面，落地时同步 USER_GUIDE / QUICK_START / TROUBLESHOOTING。
