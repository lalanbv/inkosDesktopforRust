## 0. 结论先行（TL;DR）

1. **R50 批二 docx 走零新依赖路径定案**：最小 docx = ZIP 容器 + 3 个 XML part（`[Content_Types].xml` + `_rels/.rels` + `word/document.xml`，样式再添 `word/styles.xml` 共 4 件）。ZIP 规范允许 stored（不压缩）条目，Word 的开档失败案例几乎全是结构问题（缺 Content_Types / 多包一层根目录）而非压缩方法——本仓 Rust `StoredZipWriter`（method-0，EPUB/MdZip 同款）+ TS jszip（`compression:"STORE"`）双端零新依赖即可产出；v8 深化三「docx 走 npm 供应链需过 audit:npm 闸」的风险条**整体解除**（docx npm / docx-rs 两款现成件评估后不引入，理由见深化一 K2/K3）。
2. **R51 的真实缺口在数据语义而非 UI**：现状日聚合=「当天 `updatedAt` 的章整章 wordCount 求和」（`packages/studio/src/lib/writing-stats.ts:66-76`）——改稿日整章字数重复计入、UTC 切日与写作者本地日错位。施工图新增**日产出账本**（append-only 写作日志，净增语义+本地日切分）小件，UI 面（月历热图+进度条+streak）反而是薄层。
3. **R53 成本降级修正**：v8 深化三预估「TS+R 端点小件 + S UI 中件」——本轮核查发现 versions 列表/单版本读/恢复**三端点双端已在位**（`engine-rs/src/server/books_state_routes.rs:503-527`、`packages/studio/src/api/server.ts:3080-3105`），且 `series-backfill-diff.ts` 的 LCS 行级 diff 纯函数可直接复用。R53 实际=**S 为主纯 UI 件**（历史页挂章详情 + diff 投影接线 + 「浏览只读，恢复走既有 restore」引导），引擎面零改动或仅排序/分页小补。批次可提前（批四与 R52 同批维持，但不再是批内瓶颈）。
4. **R54/R55 两处设计与内部现状错位修正**：①prompt 覆盖文件实为 `{root}/prompt/{seg}/{name}.md` 三级加载（`engine-rs/src/prompts/prompt_pack.rs:115-120`），v8 深化三写的 `.inkos/prompts/versions/` 落点不存在——版本化 artifact 届时按 `prompt/.versions/` 或 `.inkos/` 域重新设计；②「per-service 软顶消费既有聚合」不成立：RunLog 无 token 字段（隐私红线「只记元数据」）、ChapterMeta.tokenUsage 无 service 维度、全仓 per-service 聚合零命中——R55 施工前须先立**用量账本**（append-only，记 LLM usage 响应的精确 token 值而非 TokenMeter 启发式估算值，仍是元数据级不破隐私红线）。
5. **观察清单无翻案**：NovelCrafter changelog 复查（2026-11-22）最新条目仍 2026-10-19，无 11 月新条目；v9 全部判定维持。增量证据一条：NovelCrafter 2026-01-27「List support for Word export」——其 Word 导出已迭代到列表级，本仓 docx 最小集（标题层级+正文段落）后，**列表/表格支持挂 R50 批三观察项**。

## 3. 风险与对策（本轮新增面）

| 风险 | 对策 |
| --- | --- |
| stored 容器 docx 个别阅读器（老版 WPS 等）兼容性 | 验收加**活体开档验证**：macOS `textutil -convert txt` 自动可读性用例 + Word/WPS/Pages 三端人工开档走查备案（IAB 惯用形的文档面等价）；若真有个别拒开，退路=TS 侧 jszip 切 DEFLATE（Rust 侧 StoredZipWriter 无压缩能力——不对称面备案，届时 Rust 端补 deflate 或 docx 只走 TS 腿） |
| docx 双端逐位可比性 | 沿 MdZip 先例：part 条目序固定、无时间戳键；duel 双端导出→解 zip 逐条目字节比对；XML 生成纯函数双端镜像 golden 三组起步 |
| R51 日账本写入点遗漏（章保存路径之外的写面） | 写点挂 `persist chapter artifacts` 统一收口（章节保存唯一正道）；事务性结构操作（拆分/合并）不产 token 写入不记账本（只记 wordCount 净变化），语义=写作产出而非文件操作 |
| R53 恢复入口与既有 restore 端点语义混淆 | UI 只读+引导文案（v8 风险条维持）；「恢复前快照」语义已在 restore 端点内，历史页不另做恢复通道 |
