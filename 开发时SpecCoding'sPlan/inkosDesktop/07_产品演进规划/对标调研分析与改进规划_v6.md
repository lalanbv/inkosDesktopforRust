## 1. 对标对象概览

Pi 是 TypeScript monorepo 形态的 agent 工具箱（"self-extensible coding agent" 家族），12 包：

| 包 | 职责 | 成熟度 |
| --- | --- | --- |
| `pi-ai`（packages/ai） | 统一多 Provider LLM API（流式/工具调用/Context-Model 抽象） | 生产（本项目在用） |
| `pi-agent-core`（packages/agent） | 有状态 Agent：AgentMessage 与 LLM 消息分离、`transformContext→convertToLlm` 管道、结构化事件流（agent_start/turn_start/message_update…）、订阅式消费 | 生产 |
| `pi-coding-agent` | 交互式 coding agent CLI：extensions（TS 模块：registerTool/命令/事件拦截/自定义压缩/热载 `/reload`）、Agent Skills（SKILL.md）、会话 JSONL v3（id/parentId 树、分支、自动迁移）、compaction（阈值公式+切点回溯+迭代摘要+溢出 compact-and-retry）、RPC/JSON 事件流模式 | 生产（CLI 形态） |
| `pi-protocol` | 协议 v8：CBOR 定长帧、版本握手、serverId/sessionId/attachmentId 路由、关联请求/取消/订阅、严格载荷校验（拒未知字段/非 JSON/环）、上限 16MiB/1M 元素/64 层 | **实验性、无兼容保证** |
| `pi-durable` | Pico runtime：持久会话/任务/文档记录契约 + 分离式内存存储 | 早期（pico-v5 设计稿） |
| `pi-telemetry` | 厂商中立遥测契约：显式 TelemetryContext/Span（回调式）、NOOP 默认、内存参考实现、适配器一致性测试、可序列化 schema | 生产（契约层） |
| `chord` | 服务组合 runtime：服务编目/复制状态 Delta 编解码/RPC | 实验性 |
| 其余（client/server/tui/evals/session-backends/sqlite-node） | 客户端-服务端 agent 架构拆分、TUI 库、行为评测、SQLite 会话后端（runtime 工厂注入，核心包零原生依赖） | 各异 |

**供应链立场（值得全文照抄的一页）**：直接外部依赖精确 pin + `save-exact` + `min-release-age=2`（拒当日新发版）+ 发布物内附 shrinkwrap + 生命周期脚本白名单 + 定时 npm audit + 推荐 `--ignore-scripts` 安装。安全立场：**无内置权限系统**，明示「以启动用户权限运行」，给出三种容器化方案将隔离责任转移给部署方。

## 2. 头号事实：pi-ai 传输层已停在废弃终点（P0 兼容性事件）

npm registry 实测（2026-09-22）：

- `@mariozechner/pi-ai` **latest = 0.73.1 且该版本即废弃版**，官方弃用公告：*"please use @earendil-works/pi-ai instead going forward"*。scope 整体迁移，旧 scope 永停。
- `@earendil-works/pi-ai` latest = **0.87.0**（另有 legacy-node20 = 0.74.2），API 已演化（`createModels` 工厂、`providers/anthropic` 子路径导出等）。

本仓现状：`@mariozechner/pi-ai: 0.73.1` 精确双 pin（packages/core + packages/cli，499 号 typebox 迁移后落定）。直接 import 面共 **15 个文件、全部在 packages/core**（源 12：pi-stream/provider/llm-stub/agent-session/worker-agent/skill-tool/forecast-tools/film-authoring-tools/context-transform/agent-tools/service-resolver + provider 及测试 3），studio 与 src-tauri 零引用；Rust 引擎传输层完全原生（engine-rs/src/llm/*），**不受影响**。

定性：**风险不在今天的功能（0.73.1 稳定且已被 503 号活体回归背书），而在时间**——废弃包不再有修复；新 Provider 能力、新模型适配、安全修复都只进新 scope。每拖一轮，未来迁移的 API 断裂面越大。消费缝小、边界清晰、双引擎差分门禁齐备，现在是迁移成本最低点。

## 5. 0GC 与性能口径（本轮要求的显式解释）

- **Rust 引擎（默认后端）**：零 GC 天然成立；热路径（SSE 解析、FTS/BM25、prompt 装配、差分器）由 bench:gate 9 基准守住，维持「负载先辨源、严禁 --update 洗基线」纪律。本轮 R30–R37 无 Rust 热路径改动，bench:gate 随门禁复验。
- **TS 回退端**：非默认路径，不追求 0GC；性能纪律=传输层单缝适配（R30 不新增每消息分配形态）+ 既有 20s fetch 超时/进程组清理（515 号）不变。
- **Studio**：React/vite 形态无 0GC 语义；以交互测试与 UI 门禁守护，不引入 Pi 的 TUI 差分渲染概念。
