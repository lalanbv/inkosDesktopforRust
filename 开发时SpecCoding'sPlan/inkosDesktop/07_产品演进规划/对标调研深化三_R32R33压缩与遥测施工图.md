## 1. R32 现状立体化：本仓压缩三体系（v6 未展开，实测源码）

| 体系 | 落点 | 机制 | 事件留痕 |
| --- | --- | --- | --- |
| ①写作链预算制（441 号） | `agents/composer.ts:224-305` | `availableInputTokens = contextWindowTokens − reservedOutputTokens`；总量估算超预算→**protected 不可压**（作者意图/当前焦点/硬状态/活跃伏笔证据，超限直接 throw）→compressible 交 compiler 在 `compileBudget = available − protected` 内编译；全事件 start/end/error 带 protectedTokens/compressibleTokens/budgetTokens/sources | `ContextCompressionEvent`（story_context 类） |

**关键发现**：①的预算公式 `available = window − reserve` 与上游 `shouldCompact` 的 `contextTokens > contextWindow − reserveTokens` **同构**——差异只在 reserve 语义（本项目=预留输出 token；上游=压缩余量）与触发时机（装配前 vs 轮间）。R32 的正确目标因此修正为：**不是引入 Pi 压缩替换现有，而是三体系分工保持 + 只补会话面缺口 + 参数常量统一**。protected 语义（不压作者意图）是上游没有的产品优势，必须原样保留。

## 2. 上游 compaction 实现实测（agent-core 0.87 dist/compaction.js）

- `DEFAULT_COMPACTION_SETTINGS = { enabled: true, reserveTokens: 16384, keepRecentTokens: 20000 }`——v6 引述文档的数值全部实锤。
- `shouldCompact(contextTokens, contextWindow, settings)` = `contextTokens > window − reserveTokens`（`enabled=false` 短路）。
- **token 口径是 usage 优先**：`calculateContextTokens(usage) = totalTokens || input+output+cacheRead+cacheWrite`；`getLastAssistantUsage` 倒序找最近一条有效 assistant usage（stopReason 非 aborted/error 且 usage>0）。**估算只用于切点累积**（`estimateTokens(message)`，图片按 4800 字符当量）。
- `findCutPoint`：先枚举**轮次边界合法切点**，自尾向头累积估算 token 至 ≥keepRecentTokens，取首个 ≥ 当前下标的切点；切点前若紧邻上一压缩条目则并入（迭代摘要链的落点）。
- 上游另有 `generateSummaryWithUsage`（摘要调用本身带 usage 回传）与 branch-summarization 全套导出。

## 4. R33 遥测 schema：RunLogEntry × 上游 pi.ai.request 映射矩阵

上游 schema 定义格式实测（`AI_TELEMETRY_SCHEMA = { version: 1, spans: { "pi.ai.request": { description, parents, startAttributes, endAttributes } } }`，属性键含 `type/required/values/description`，如 `pi.ai.operation ∈ [stream, fetch_deferred, cancel_deferred, generate_images]`、`pi.ai.provider/model/api/streaming/deferred`；endAttributes 如 `pi.ai.response.model`）。本仓 `RunLogEntry`（403 号）九字段映射：

| InkOS 字段 | 上游对应 | 判定 |
| --- | --- | --- |
| model | `pi.ai.model` / end `pi.ai.response.model` | 镜像语义键 |
| —（provider 在 client 层） | `pi.ai.provider`、`pi.ai.api` | 补两键（service-resolver 已有 piProvider 映射可填） |
| durationMs | span 时长（start/end 天然承载） | 镜像 |
| ok | status ok/error | 镜像 |
| agent / attemptIndex / round / tookOver / errorKind | 无上游等价 | `inkos.*` 扩展键（inkos.agent/inkos.attempt_index/inkos.round/inkos.took_over/inkos.error_kind） |

**裁决**：定义 `inkos.ai.request` span schema——语义重合键镜像 `pi.ai.*` 命名（未来 OTel/跨工具互通零成本），域扩展用 `inkos.*`；schema 文件为双端共享 JSON（golden 第 31 守门域，Rust serde 侧只投影不引运行时）；实现采上游模式：显式 TelemetryContext 传参 + `NOOP_TELEMETRY_CONTEXT` 默认 + InMemory 参考实现；run-log 环形缓冲维持为存储投影，隐私红线不变（只元数据）。验收：schema JSON 双端加载一致 + golden 载荷比对（走差分器工件面机制）+ NOOP 缺省下零行为变化回归。

## 5. 风险与门禁

- agent-core compaction 原语依赖 0.87 的 AgentMessage/entries 形态——**R32a 排在 R30 之后**（R30 未落地前不得引上游运行时，先出 Rust+golden 版）；Rust 侧切片点/摘要链算法须与 TS 消费的原语行为逐一对表，防「同一公式两种实现」漂移。
- 摘要格式是压缩输出非 prompt 输入，与 18 键 prompt golden 分文件，无 REGEN 连锁（v6 已判，维持）。
- usage 缺失场景（stub/部分 provider）：口径退化路径 golden 显式覆盖。
- 门禁矩阵沿 R30 惯例：gate:ts + golden + 双引擎差分 + smoke 双腿 + duel + audit:npm；Rust 侧新增逻辑走 cargo+clippy 全量。

## 6. 维持与后续

R30/R31 施工图（542 号）不变；R34–R37 不变；0GC 口径不变（压缩/遥测均非 Rust 热路径，bench:gate 随门禁复验）。实施顺序裁决修订：**R30→R31→R33→R32**——R33 只增投影层风险最低先收，R32a 依赖 R30 后的上游原语与 transcript 形态决策（与 R36 树化预研协同）放后。下一号自 544 起。
