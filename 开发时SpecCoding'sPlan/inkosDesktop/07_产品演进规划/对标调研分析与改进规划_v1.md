# 对标调研分析与改进规划（webnovel-writer × AI-Novel-Writing-Assistant）v1

> 日期：2026-09-11 ｜ 编号关联：变更记录 328 号
> 调研对象：
> - [lingfengQAQ/webnovel-writer](https://github.com/lingfengQAQ/webnovel-writer)（v6.2.1，Claude Code 插件，下称 **WNW**）
> - [ExplosiveCoderflome/AI-Novel-Writing-Assistant](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant)（v0.4.19，Electron 桌面 + Express/LangGraph/Qdrant，下称 **ANWA**）
> 方法：两仓浅克隆源码级调研（README / docs / SKILL / 核心模块源码），对照本仓 `packages/core`（TS 引擎真源）、`packages/studio`（UI）、`engine-rs`（Rust 引擎）逐域比对。

---

## 0. 结论先行（TL;DR）

1. **本项目的底子不弱于两个对标，多域更强**：写-审-改闭环（`pipeline/chapter-review-cycle.ts`，85 分阈值+修复）、时序事实库（`state/memory-db.ts`，事实带 valid_from/valid_until）、伏笔账本（hooks 表含 status/last_advanced/expected_payoff/depends_on 因果链）、AI 痕迹检测、敏感词、批量调度（scheduler + qualityGates）、38 工具聊天 Agent + propose_action 确认链、多形态生产（影游/剧本/分镜/翻译/短篇/同人/衍生）——这些对标两项目要么没有、要么更弱。**不存在"推倒补课"，只有"定点增强"。**
2. **真实差距集中在四处**：①语义检索层（本项目仅 FTS5 词法，两对标均有向量 RAG）；②上下文组装缺"来源分层与冲突优先级"显式契约；③质量治理缺"质量债务"账本与分级判定（ANWA 的 8 级判定 + 双治理方案）；④写法/拆书两类长期资产的产品化深度。
3. **产品体验面借鉴 ANWA**：自动导演"一次创作选择 + 运行模式 + 检查点跟进"、AI 实况（token/耗时/思考流）、按阶段恢复手册；**流程纪律面借鉴 WNW**：作者友好三段报告契约、防呆方言、来源不可覆盖章纲约束、失败隔离只补跑失败步。
4. **落地纪律**：本项目是 TS 真源 + Rust 全量移植双端结构，新增引擎能力 = 双倍实现 + golden/duel 验收。路线图按"studio-only 快赢 → 双端引擎增强 → 大件（RAG/拆书/导演产品化）"三阶段排布，先吃低成本高确定性项。

## 1. 对标项目画像

### 1.1 WNW：长篇一致性的"流程纪律教科书"

**定位**：跑在 Claude Code 上的网文创作插件；核心命题"写到几百章仍记得住设定、接得住伏笔、守得住大纲"。

**架构**：8 个 Skill 命令（init/plan/write/review/query/learn/dashboard/doctor）+ 4 个子代理（context/reviewer/data/deconstruction）+ Python 脚本层。v6 主链 = `.story-system/` 合同与提交链 → accepted CHAPTER_COMMIT → 派生五视图（state.json / index.db / summaries / memory_scratchpad / vectors）+ projection_log 排障。

**精华（值得学）**：

| # | 机制 | 细节 | 对本项目的启示 |
|---|---|---|---|
| W1 | **写作任务书五段定序** | 本章硬性约束 → 节点(CBN/CPNs/CEN) → 禁区 → 风格指引 → dynamic_context（仅参考，"不能覆盖章纲约束"） | 本项目 ContextPackage/RuleStack 已有分层，但"参考资料永不覆盖章纲"未成为显式契约（见 G2） |
| W2 | **作者友好报告契约** | 最终回复固定三段式（文件与完成情况/问题与异常耗时/下一步建议），异常三分类（已自动处理/建议确认/必须处理），禁止裸 JSON/traceback | studio 聊天与通知中心可直接采纳（P0 快赢） |
| W3 | **失败隔离与续跑** | 审查缺失→只重跑审查；投影失败→只补投影；`run-ledger write-resume` 给续跑建议；正文被手改必须停下来问，永不覆盖作者手改 | 本项目有 `chapter-state-recovery.ts` + `resync_chapter_state`，缺"从哪里继续"的显式 UI 语义与手改检测门槛（G9） |
| W4 | **防呆方言** | 系统写出的结构化文件：一律平铺 front matter、列表块格式、危险值自动加引号、"每条一个文件"防一格写坏全废 | truth files 是本项目真源且作者可手改，写出格式应固化为防呆方言（G7，低成本） |
| W5 | **信息差登记 + 泄密机检** | 只登记"值得管理的信息差"（每条一文件，知情人/读者已知/关键词），机检扫描对白内心是否泄密、是否向读者复述已知信息 | 本项目完全没有此概念，长篇群像戏高价值（G7） |
| W6 | **实体名册 + 新专名确认** | 名册防"同人异名/同名异人"；settle 时比对正文新专名，未登记的进确认卡（新实体 or 笔误） | 本项目有 rename_entity，无"新专名入账前确认"闭环（G7） |
| W7 | **承诺统一账本思想** | 伏笔/悬念/感情线/爽点统一为"对读者的承诺"，章节 front matter 记录 开启/推进/兑付 三类动作；配套节奏债（高承诺搁置超限告警）、连续弱钩上限 | 本项目 hooks 表数据模型已覆盖且更细（因果依赖），缺的是**运营指标**（节奏债/弱钩告警）与章节级动作归因（G10） |
| W8 | **best-of-N 关键章** | 卷首/转折/高潮章可配 N 稿（草稿-A/B/C）+ 评审选优 | 聊天面/批量面均可做"关键章多稿"（G11） |
| W9 | **项目经验记忆（/learn）** | 与剧情记忆分账：`project_memory.json` 存"这本书里验证有效的写法经验" | 本项目 style-profile 管风格、不管"经验"；可在写法引擎里加"经验条目"（G13） |
| W10 | **升级原则：脚本 < 模型 < 作者** | 能数的不让模型估，能模型判的不打扰作者；作者界面单位是"决策卡"不是命令 | UI/通知设计的通用准绳，写入设计规范 |

**糟粕（明确不学）**：
- **宿主形态**：绑定 Claude Code 插件生态 + Python 依赖，桌面产品不可复用；
- **v6 状态全 JSON/db 化**：作者不可手改（其 v7 spec 自己都把"文件即真相、敢手改"列为第一不变量——本项目 truth files 天然满足，不要倒退）；
- **v7 冻结弃坑教训**：重写分支（v7）冻结不发、再开 v8——大版本重写风险高，本项目坚持绞杀式渐进（engine-rs 先例）；
- **七重闸门默认全开**：preflight/合同树/write-gate×3/充分性闸门对休闲用户过重，应做成可选"严格模式"。

### 1.2 ANWA：AI 长篇生产的"产品化与资产化教科书"

**定位**：面向新手的"AI 导演式"整本生产系统；一句灵感→方向候选→世界/角色/卷章规划→章节执行→审核修复→状态回灌。

**架构**：pnpm monorepo；React+Vite+Plate 客户端，Express+Prisma+LangGraph 服务端，SQLite 主存 + Qdrant 向量库；Electron 桌面壳（Windows 优先）。17 阶段自动导演管线，全部可暂停/可恢复/可换模型重试。

**精华（值得学）**：

| # | 机制 | 细节 | 对本项目的启示 |
|---|---|---|---|
| A1 | **资料来源分层与冲突优先级** | 本书事实 > 本书规划 > 用户资料 > 拆书结论 > 写法资产 > 临时对话；"RAG 让系统知道更多，而不是让外部资料拥有最高决策权"；新增任何上下文来源必须声明优先级 | 本项目上下文来源更多（materials/references/truth/radar），缺显式优先级契约与守卫测试（G2，P0） |
| A2 | **任务驱动 RAG 查询** | 查询由章节任务单构造（目标/期待/必须推进/冲突/出场角色/结构化大纲），不是拿章标题去搜；向量+文本混合召回；facets 过滤；chunk hash 去重；单文档召回测试；retrieval trace 排障 | 本项目 FTS5 内核在，缺语义召回与任务驱动查询构造、召回测试面板（G1，Phase C 大件） |
| A3 | **质量判断 8 级分类 + 质量债务账本** | accepted / continue_with_warning / local_patch_plan / patchable_obligation_gap / draft_obligation_unmet / defer_and_continue / replan_required / stop_for_replan；局部问题≠全局失败，债务记录、展示、跟进 | 本项目 review cycle 是"分数+修复"二元循环，批量场景缺债务账本（G3，P1） |
| A4 | **问题治理两方案（每书可配）** | 连续完成优先（局部问题降级为债务继续）vs 质量优先（停在已保存章节边界等显式恢复）；治理决定结构化，执行器不写死分支；人工暂停不被后台轮询清除 | scheduler 已有 qualityGates，升级为每书策略枚举（G3） |
| A5 | **写法引擎资产化** | 样本→特征提取→可见特征池（逐项启停/组合）→规则重编译→绑定小说→试写→参与生成/检测/修正全链 | 本项目 style-analyzer + StyleManager 只到"档案"，升级为特征池+绑定+试写（G4，P1） |
| A6 | **拆书工作台** | 四档人物档案（简要/标准/深入/完整）、角色形象演变（按覆盖率增量扫描+阶段形象图）、章节证据回溯、token 预算守卫、稿件诊断 | 本项目 materials ingest + chapter-analyzer + fanfic-canon-importer 分散存在，无统一拆书面（G5，Phase C 大件） |
| A7 | **自动导演产品化** | 唯一必选创作点（确认书级方案）+ 运行模式（就绪/全书/范围）+ 灵感卡 + 方向候选批量生成/单方案修订/标题组重做 + AI 驾驶舱状态投影 + 导演跟进页 + 按阶段恢复手册 | BookCreate 是表单式，缺候选批量与检查点跟进产品面（G6，P1-P2） |
| A8 | **AI 实况** | 思考过程与正文分开完整展示；总耗时/首包耗时；输入/输出/思考/合计 token；近期实况本机留存 | studio 聊天缺统一实况面（PlayHud 仅影游）（G8，P0 快赢） |
| A9 | **专名泄露审核** | 生成后检查是否泄露参考作品专名/地点/标题/标志性桥段 | 与 A5 拆书配套；本项目 imitation 链路应加（G4 附属） |
| A10 | **市场雷达体验** | 扫榜（免费）与 AI 分析（付费）分离；勾选范围后分析；信号含"差异化机会/拥挤度/榜单证据"；信号→自动导演开书交接 | 本项目 radar（番茄/起点）已同构，补晋江源与"选后再析"交互（G14，P2） |
| A11 | **按阶段恢复手册** | 恢复矩阵：阶段×表现×先看哪里×恢复入口×何时重规划；"很多停住其实是 checkpoint" | 纯文档，立即可抄（P0） |
| A12 | **文档纪律** | 模块文档配真实截图；术语中文+技术别名对照表；checkpoint/tip/warn 提示块 | docs 体系对齐参考 |

**糟粕（明确不学）**：
- **重栈**：Electron + Qdrant 外部服务 + Prisma；本项目 Tauri2+Rust 直启在体积/内存/启动/分发全面占优，**绝不回退**；
- **RAG 依赖外部向量库**：采用 sqlite-vec 内嵌方案，embedding 服务可选（含 ollama 本地），无服务也能跑；
- **衍生工坊先行**（漫画/短剧在主链未稳时铺开）——本项目已有影游差异化赛道，不追漫画面；
- **scope creep**：其 README 自述"95% 以上编写都是 AI 完成"，迭代快但 34 篇文档里大量"恢复/排障/修复记录"说明链路脆弱面大；本项目以 golden/duel/bench 纪律换稳定性，不换。

## 2. 本项目基线（调研核实，非 README 转述）

| 域 | 现状 | 证据 |

## 4. 采纳清单（G1–G16，按优先级）

> 每项标注：来源 ｜ 本项目落点 ｜ 双端成本（TS=packages/core，R=engine-rs，S=packages/studio）｜ 验收方式。

### P0 快赢（低风险、单端为主，1~2 周当量）

| # | 事项 | 落点 | 成本 | 验收 |
| --- | --- | --- | --- | --- |

## 6. 路线图与里程碑

```text
Phase A（快赢，P0 六项）
  ├─ 上下文优先级契约 + golden 断言（G2）
  ├─ 聊天 AI 实况（G8a）／作者友好报告（G8b）
  ├─ 防呆写出方言（G7c）／恢复手册（A11）／雷达选后再析（G14a）
  └─ 出口标准：全部 studio 单测绿 + 上下文 golden 新向量 + 冒烟
Phase B（引擎双端增强，P1 七项，每项独立编号推进）
  ├─ 批次一：G3 质量债务与治理方案 → G10 承诺账本运营化（同域，先判定后指标）
  ├─ 批次二：G4 写法引擎 → G7a/G7b 信息差与名册（审计域扩展）
  └─ 批次三：G9 续跑语义 → G16 模型路由
  出口标准：每项 golden 向量先行，duel 双端 diff=0，bench:gate 无回退
Phase C（大件，P2，逐项立项）
  ├─ G1 语义检索（sqlite-vec + 任务驱动查询 + 召回测试/trace）
  ├─ G5 拆书工作台 → G6 自动导演产品化（依赖 G1/G3 就位）
  └─ G11/G12/G13/G15 择机穿插
  出口标准：独立设计文档（本目录二级归档）+ 双端验收 + 生产实测冒烟
```

**排布依据**：Phase A 全部单端/文档级，先建立"契约与体验"地基；Phase B 是对标精华中"数据模型已就位、缺运营与治理"的部分，双端成本可控且互相独立可并行排队；Phase C 的三个大件存在依赖（拆书产物→RAG 召回→导演消费），按序绞杀。

## 7. 目标拓展（可持续发展）

1. **资产生态**：写法包 / 题材包 / 世界样本包做成可导入导出的便携资产（JSON+样本文本），与既有 WASM 插件 marketplace 同渠道分发——对标 ANWA 的题材基底库/推进模式库/世界样本库，但走插件化而非内置。
2. **Agent 评测体系**：为 continuity 审计、写法特征提取、泄密机检建立标注样例集（借鉴 WNW evals 思路），CI-less 本地跑 `pnpm eval`，防提示词漂移。
3. **文档纪律延续**：新能力一律"中文界面名 + 技术别名对照"（ANWA 经验）；恢复/排障文档随特性走（A11 起步）。
4. **上游与发版**：fork-and-own 不回合并上游（既定）；本地脚本发版纪律不变（149 号）；每阶段收官走 release 档冒烟双验证（326 号先例）。
5. **性能预算**：新检索/上下文能力纳入 bench:gate 基线（注意满载误报纪律：隔离复跑，严禁 --update 洗基线）。
