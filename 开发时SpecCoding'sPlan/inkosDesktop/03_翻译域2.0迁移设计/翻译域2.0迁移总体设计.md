## 1. 现状盘点

### 1.1 HTTP 面（六端点双端在位）

| 端点 | 双端状态 | 差异 |
|---|---|---|
| GET /translations | 双在 | 形状同；**数据源不相交**（TS 扫 works/、Rust 扫 translations/） |
| POST /translations/upload | 双在 | 对齐（80MB 上限、.inkos/uploads/translation/） |
| POST /translations/create | 双在 | 参数/错误同；Rust 成功多 projectDir |
| GET /translations/:id | 双在 | **章节对象分叉**：TS 带 translatedSegments/reviewSummary/observations，Rust 带 status 缺三字段 |
| POST /translations/:id/run | 双在 | TS 回执 {kind,workId,projectId,translatedSegments,reviewedChapters,reviewSourcePaths,observations,reportPath,total/completed/pendingSegments,skillIds}；Rust {projectId,translatedSegments,reviewedChapters,reportPath,skillIds}；错误码 TS 500 INKOS_TRANSLATION_ACTION_FAILED / Rust 502·500 TRANSLATION_RUN_FAILED |
| POST /translations/:id/export | 双在 | Rust 多 400 INVALID_FORMAT 先验；结果缺 exportSourcePaths |

修订（revise_paragraph）在 TS 仅为代理工具（无 HTTP 面），Rust 全缺。

### 1.2 存储

- TS 2.0：works/<id>/source/{manifest.json, source/chapter-NNNN.json, translated/chapter-NNNN.json, glossary.json, review-report.md} + works/<id>/work.json（WorkManifest：artifacts+lineage）；manifest 章节带 translatedSegments/reviewSummary?/observations?、**无 status**；zod `.strict()`。
- Rust：translations/<id>/{manifest.json, source|translated/chapter-NNNN.json, glossary.json, review-report.md, status.json(ProductionRunSnapshot)}；章节带 status、缺三字段。
- **跨引擎互读=零**：列表数据源不相交；TS strict 拒 Rust manifest（多 status/缺 translatedSegments），Rust serde 必需 status 拒 TS manifest。桌面默认 Rust、故障回退 Node——同一项目在两引擎下互不可见（876 号「跨引擎读同一文件=差分器盲区」同族）。

## 3. 分期施工图

### P1 契约补形（G1/G2/G3）——零存储迁移
- 详情：manifest 章节与 chapters 均补 `translatedSegments`（按译文段非空计数，现场计算=对既有项目即时生效）、`reviewSummary`、`observations`（Rust 审校 issues 映射 `{assessment:"issue", …}` 并随审校落 manifest 可选字段，serde default 前向兼容）。
- run 回执补 kind/total/completed/pendingSegments/observations。
- 错误码对齐 TS `INKOS_TRANSLATION_ACTION_FAILED`；上游失败 502 为 Rust 刻意增强保留（备案）。
- 验证：translations70_e2e 扩断言；TranslationManager 交互测试；IAB 活体「N segments」非空。

### P2 协议+校验+标题（G4/G5/G6）
- 结构化提交：AgentRouter 工具调用面（或 JSON-schema 引导+校验重试兜底）；段号严格校验（空/未知/重复/缺失即错，不静默丢弃）；chapterTitle 入端口与落盘。
- 验证：双端共享校验 golden 向量（非法段号形态→错误码/消息）；mock-LLM e2e。
- 风险：Rust 路由工具调用能力与流式解析；回滚=保留 JSON 文本协议开关。

### P3 审校 2.0（G7）
- 新 engine-rs/src/translation/review.rs：独立源读批次、成对引证 observations、manifest reviewSummary/observations、报告格式对齐。
- 验证：移植 translation-review.flow 场景；报告 golden 逐行比对。

### P4 存储迁移 works/<id>/source + work.json（G9/G12）
- manifest 模式对齐（三字段+status 映射/退役）、路径重写、列表改 works 扫描、translations/ 既有数据一次性迁移（备份域 works/ 已覆盖，迁移前快照）。
- 验收=**跨引擎 golden**：TS 服务端列/读 Rust 建的项目、Rust 列/读 TS 建的项目（876 号同款金标准行）。
- 次序：P1-P3 之后（迁移的 manifest 一次到 2.0 完整形态）。

### P5 修订+create 输入+导出（G8/G10/G11）
- revision.rs+revise_paragraph 工具面、sources/sourceText/glossary 输入、exportSourcePaths 与 EPUB 生成对齐。
- 验证：移植 translation-runner 修订用例；修订后导出 e2e。

## 4. 原则

1. TS 2.0 为真源；Rust 偏离须为刻意增强并备案（如上游 502 分类）。
2. 每期双端 golden/差分探针先行，必红三形（Rust env 中和、TS stash、UI stash）。
3. 存储迁移最后做且带回滚：迁移前快照、读面兼容旧布局一个版本周期。
4. 跨引擎互读是 P4 验收硬门槛（桌面「默认 Rust+故障回退 Node」的真实运行形态）。
