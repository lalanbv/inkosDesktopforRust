## 二、W-C3 系列书导入回填向导（对标 Sudowrite Story Bible）

### 对标拆解

Sudowrite 的价值链：**系列书从既有正文自动回填设定**（人物/世界观/伏笔跨书一致），向导化体验是「选源 → 抽取 → 预览 → 确认写入」。

### 需求分解（按可自主落地度排序）

| 切分 | 内容 | 依赖 | 自主可落地 |
| --- | --- | --- | --- |
| **C3-a 数据面** | book.json 加 `series?: { name, order }` 字段（TS/Rust 双端同名键加法变更）；Dashboard 书卡按 series 分组显示；duel 不涉契约面 | 无 | ✅ 完全自主 |
| **C3-b 回填引擎管道** ✅ **已落地（184 号）** | 「从既有书抽取设定」：读源书 story/story_bible.md + 世界观 + 人物 truth 文件（已有 materials/truth 域），经 LLM 摘要为「可回填设定集」（结构化 JSON）；目标书确认后写入对应 truth 文件。建议落 ImportManager 新 tab「系列书回填」 | C3-a（或独立） | ✅ 引擎管道 + 测试可自主；LLM 输出质量需真实模型验证 |
| **C3-c 向导化体验** ✅ **已落地（184 号）** | 选源书 → 抽取进度（确认式生产任务复用，检查点/可停止 174 号现成）→ 回填预览 diff → 确认/逐项取舍 | C3-b | ✅ 复用 174–176 任务卡基建 |

### 风险与决策点（需用户确认的仅一项）

- 回填**写入目标**的粒度（整文件替换 vs 追加合并）需产品决策；建议默认「预览 + 逐项勾选」，用户不确认则零写入——其余全部可自主。

## 三、W-C4 时间线视图（对标 Plottr）

### 对标拆解

Plottr 的核心是 **plotline × chapter 网格**：行 = 情节线（主线/支线/人物线），列 = 章节，单元格 = 该线在该章的 beats。规划先行、可视化拖拽是其体验核心；本项目是生成式（正文由引擎产出），时间线的价值定位应为**回顾型可视化 + 写作前后的一致性参照**，而非先行规划编辑器。

### 需求分解

| 切分 | 内容 | 依赖 | 自主可落地 |
| --- | --- | --- | --- |
| **C4-a 只读时间线视图** | BookDetail（或独立页）新增「时间线」tab：行=情节线，列=章，数据来源**先用章节 index 现有字段 + 情节线推断的临时方案**（单线兜底），纯前端渲染网格；深链可分享章节定位 | 无 | ✅ 完全自主（纯 studio 前端，零引擎改动） |
| **C4-b 数据面** | ✅ **已落地（181 号）**：`books/{id}/story/timeline.json`（version 1）+ 双端 GET/PUT 端点 + BookTimeline 多线渲染（缺省回退单线）；生成端点默认关闭待产品决策 | C4-a | ✅ |
| **C4-c 编辑与回写** | ✅ **已落地（182/183 号）**：单元格弹窗编辑（乐观更新/失败回滚）+ 新建节拍占位格 + 添加/重命名/删除情节线 + 「按此节拍写下一章」（context 注入 write-next，183 号双端接线） | C4-b | ✅ |

### 风险与决策点

- C4-b 的「生成端点」会让每次写作多一类 LLM 产物（token 成本↑），建议做成**默认关闭的设置项**——此项与「手动标注先行」的先后需产品决策；C4-a/C4-b 存储面无争议可先行。

## 四、下一批推荐（180 号）

**推荐 W-C4-a 只读时间线视图**：纯 studio 前端、零引擎契约改动、零 LLM 依赖、用现成章节 index 数据，一个批次内可完成「视图 + 单测 + duel 无涉」全闭环；且是 C4-b/c 的必要地基。C3-a（series 字段）作为同批次的小型附带项（数据面 + 分组显示）亦可行。

次选：W-C3-b/c 回填向导（价值更高但涉及 LLM 产物质量与写入粒度决策，宜在 C3-a 落地后与用户确认「逐项勾选」交互再动）。

## 五、不做的事（边界登记）

- 不做 Plottr 式拖拽规划编辑器（生成式定位不同，回顾型优先）。
- 不做跨项目系列管理（series 先做 book.json 内字段，跨书聚合视图留待真实需求出现）。
- 时间线不做日历语义（Plottr 有日期轴；本项目章节驱动的虚构时间轴暂不建模，待真实写作流反馈）。
